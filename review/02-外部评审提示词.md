# 给外部模型的评审任务

请担任《超GAG机器人大战：万机残响》的外部编剧与游戏叙事评审。你的任务是帮助本项目写出框架内合乎情理、能调动情绪、值得追读、也适合玩家亲手参与的故事。请独立判断，不以维护既有流程或增加文档为目标。

仓库地址：https://github.com/Rayz17/super-gag-robot-war ，资料分支为`codex/review-materials-20261022`。你可以读取本仓库全部资料。先按`review/01-阅读指南与当前资料.md`阅读当前故事与提案，再针对问题查询原始设定、人物模型、机体/IP资料和失败实验。2026-10-26另增补了`review/04-美术风格与已定资产.md`及`review/art/README.md`，请实际看关键图片。不要把数千份文件一次塞进上下文，也不要只读旧README就判断最新稿。

## 要保有的作品精神

这是机器人文化、跨界精神投射、热血、笑料、冒险、机体拥有感、成人亲密关系与群像政治交织的长篇游戏。合体、变形、必杀、宿敌、改装、舰内生活、玩具与创作者生态，都应能产生作品本身的快乐和戏剧，不只是为制度讨论配插图。

世界可以残酷，人物可以犯错、背叛、分离和承担无法补偿的损失；胜利也必须有真实所得。请检验作品能否让人既想赢、想救、想恋爱，也害怕失去。不要将所有冲突都化为双方说开后继续做朋友，也不要为情绪强度机械地杀人或给每章附加一场灾难。

现有机体/IP素材是创作资源。熟悉原作的玩家可以从可辨识的名场面、人物特征和情绪结构获得先验理解；没看过原作的人仍应看懂本次欲望与选择。原创人物和核心因果则需要本作完整建立。指出哪些包只出现了名字，哪些真正借到了IP的情感与机体魅力。

## 请分三次形成判断

### 1. 首读判断

先读指定C01-C04和27号，暂不读作者审查答案。记录：你能复述的主要事件、最在意的5个人、最想继续看的3条线、最强5场，以及最无聊/最不可信3处。引用具体原文，不替梗概补成尚未写出的感人场面。

### 2. 根因与全剧设计

再查设定、玩法与方法，优先回答：

- 问题最早发生在作品幻想、世界/总冲突、全剧事件选择、章节发动机、人物关系与知识、场面组织、对白，还是剧情转玩法？分别给证据。不要只说“加强情绪”。
- 人物有没有主动追求，最亲近的人是否真正改变彼此的选择？吸引、快乐、嫉妒、利益、背叛与悲痛是否是场面，而非结尾一句状态说明？索琳枪杀的原因存在，是否已经足以产生情绪重量？
- 大清噪、纪存与父亲、索琳及远征历史的揭示，是否逐步改变玩家对既往事件的理解？哪些只在增加说明，哪些真的迫使人物换立场？
- 主要势力能否各自行动、利用成功、作出阴谋或公开布局，并共同造成谁也无法完全掌控的结果？外敌是否神秘、强大、组织化而又只能部分理解？不要靠展开外敌内阁来消除异质感。
- 全剧是否重复环状空间、多机依次接力、越界后受罚、胜利马上被否定、讲理后修复等场型？要比较实际事件，不只统计关键词。
- 机体首登、合体、变形、升级、分离、再援、独立去向和巨物尺度，是否真的参与剧情和战斗？哪些原定IP/人物值得恢复，哪些应暂存或删并？注明原作与版本。
- 现有画风、人物母稿、整机/组件/三视是否支撑这些故事动作和玩法？识别度、职业、人物性格和机体精神有没有实际表现？把世界米数、正常战棋显示比例和规则占格分开检查。逐图确认范围见资产清单；授权派生、旧画法例图及否决反例不能当作已定主体。建议新增资产时，说明故事收益、复用与成本，不用任意换头、换主体或修复缺臂来掩盖问题。
- 父亲赴约/隐瞒与地球/远航四种历史，是否保有不同的在场、知识、信任与调查后果？有限与全面终局是否有可见可争取的条件，还是作者按钮？
- 总案与后续战斗设计有哪些真实冲突？玩家能否选择有效办法，仍亲手获得机器人战斗快感？哪些角色固定决定不应伪装成可否决选项？
- 现行主笔/Runtime/审稿流程哪里实证有用，哪里只增加成本？请区分旧方法诊断正确、执行缺失、执行失败和方法本身有害。

查证后，把每条重要意见标为：原文缺失、已有但表达不成立、版本误读、事实冲突或创作建议。事实争议先定位到路径与段落；找不到依据就承认不确定。

### 3. 可执行的修改方案与小规模证明

按影响和收益排序，给出“保留 / 定点改 / 重建 / 暂存”方案。每项说明要改哪个实际事件、保住什么、谁因此会做不同的事、为何更有力量，以及会影响哪几章/哪些玩法。

上层设定与母盘也允许提出更好的候选，但先说明与已有事实的差异。若两个方案都能成立却导向不同人物命运或伦理位置，给2-3个清楚选项与推荐，不将其中一个写成已经获批准。

不要直接重写C01到终局来证明方法。先选择最能暴露病灶的一个完整场面或一话，在同一前情和事实边界下写样稿，并给简短玩法构思。样稿应能单独阅读，不夹UI、Phase、工程步骤和审稿说明。随后另写游戏解构，交代玩家看见什么、如何操作、至少两种有效办法、失败怎么继续、成果保留在哪里。

如果你认为问题必须改发生过的事才能解决，先写明改动与代价，再另附替代样稿。新稿放`reviews/`，保留原文。不要用内部PASS、更多字段或一段被夸过的短样宣称已解决整部作品。

## 建议交付

1. 一页有取舍的总判断。
2. 有证据的问题账，按最早责任层与严重度排序。
3. 少量能改变实际故事的改稿方案，附全剧影响与玩法影响。
4. 一个完整样稿、独立游戏解构及与现稿的具体比较，附已有美术复用与需要新增的状态/动作/场景说明。
5. 可移植给下一位主笔的方法：如何选择素材、查知识、写场面与对白、处理容量、发现无聊并停止无效补强；附一份实际使用过的简报/提示词，不只给理论。

若无法访问媒体、运行游戏或隔离冷读，请说明实际输入与限制。你可以强烈否决故事选择，但不要把自己的判断伪装成玩家测试或项目用户验收。
