## 效力顺序（冲突时，上面赢）

1. 用户的话。日志里“用户的原话”一栏照抄的那些。
2. 基线里【已定】的条目。
3. 基线里【默认】的条目。
4. 仓库正典 `docs/superpowers/specs/`。
5. 小说的三稿现稿（2026-11-23）。

## 状态词

- 【已定】用户亲口说过。要改，得用户再开口。
- 【默认】助手提议，用户没有反对，目前照此执行。可以提出更好的方案，但要在日志里写明替换的是哪一条。
- 【待定】还没有结论。
- 【已撤】曾经有效，已经撤回。留在日志里，是为了让别的平台不要再把它捡回来用。

## 写日志的规矩

1. 只追加，不删、不改旧条目。新条目加在最上面。
2. 编号用 `NB-YYYYMMDD-两位序号`。
3. “提出方”写清平台：用户、Codex、ZCode、Antigravity。
4. 用户说过的话照抄进“用户的原话”，不要转述，不要把助手自己的判断写成用户的要求。
5. 助手提的方案只能标【默认】或【待定】。只有用户的话才能标【已定】。
6. 数字先量再写。

## 这个目录不做什么

- 不改 `docs/` 下的正典。要改正典，在 `01_共享基线.md` 第十节按 Living Canon 的格式提出来，等用户定了再动。
- 不替用户验收任何稿子。
- 游戏侧的设计、美术、玩法不在这里。这里只管四十章小说的修订。
