# 04. 结构化资料库说明

本卷是第二步：把第一版正文拆成可检索的数据层。所有表格放在 [data](./data) 目录，采用 TSV 格式。TSV 的好处是能容纳中文、日文、英文作品名，也不容易被作品名里的逗号和冒号弄乱。

## 表格清单

| 文件 | 用途 |
| --- | --- |
| [data/titles.tsv](./data/titles.tsv) | SRW 主要作品年表、平台、分期、串联模型、系统特征 |
| [data/roster_matrix_modern.tsv](./data/roster_matrix_modern.tsv) | 代表性作品的参战矩阵，优先填现代作与剧本口碑关键作 |
| [data/crossover_story_index.tsv](./data/crossover_story_index.tsv) | 原作剧情在 SRW 中被采用、改写、串联的索引 |
| [data/franchise_roles.tsv](./data/franchise_roles.tsv) | 参战作品家族在 SRW 里的功能分类 |
| [data/community_sources.tsv](./data/community_sources.tsv) | 官方、媒体、B 站、YouTube、机核、玩家社区资料入口 |

## 可信度字段

`source_grade` 使用四档：

| 等级 | 含义 |
| --- | --- |
| official | 官方页面、官方新闻、说明书、PV、制作人访谈 |
| database | Akurasu、SRW Wiki、攻略站等可交叉核验资料 |
| media | 机核、RPG Site、The Verge、RPGamer、4Gamer 等媒体 |
| community | B 站、YouTube、Reddit、Steam、论坛、弹幕/评论 |

`confidence` 使用三档：

| 等级 | 含义 |
| --- | --- |
| high | 多源一致，或官方明确 |
| medium | 攻略/百科一致，但仍需逐话文本核对 |
| low | 玩家观点、梗点、口碑印象，需标注为社群观点 |

## 当前填充策略

第二版不追求“一口气列出每一作全部参战作品”，那会变成低质量抄表。当前优先填三类信息：

1. **主干年表**：先让每作有可定位的分期和串联模型。
2. **关键参战样本**：优先选 V/X/T/30/Y、Alpha、W、UX、Z 等对剧情串联有代表性的作品。
3. **剧情改写索引**：记录“这部原作在这作里承担什么叙事功能”，而不是只写“参战了”。

后续扩展时，建议每次只推进一个主题，例如“完整补齐《W》所有参战剧情采用表”或“完整补齐《Y》本体+DLC参战矩阵”。

## 使用建议

- 想查系列演进：先看 `titles.tsv`。
- 想查某个原作在 SRW 里的常见功能：看 `franchise_roles.tsv`。
- 想查“为什么这作串得好”：看 `crossover_story_index.tsv`。
- 想继续写百科正文：把 TSV 中 `plot_function` 和 `crossover_mechanism` 字段扩成段落。
