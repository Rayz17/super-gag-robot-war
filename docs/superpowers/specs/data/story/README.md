# 《超GAG机器人大战：万机残响》剧情数据说明 v0.1

本目录承接 [剧情线场景扩写](../../2026-06-19-chao-gag-storyline-scene-expansion.md)，目标是把主线剧情拆成后续可编剧、可关卡化、可数据驱动的结构表。

跨文档口径、节点关系和风险清单见 [设定图谱数据说明](../design_graph/README.md)。

## 当前上游创作入口

- 第一至第四层涉及长期人类角色、驾驶员、作者NPC或归航角色时，先读 [V35前三层全球角色与陈旧母题根因审计](../../剧情梗概/V35前三层全球角色与陈旧母题根因审计-2026-07-21.md)，再查 `v35_global_cast_identity_protocol_v2.tsv` 与 `v35_global_cast_identity_registry_v2.tsv`。写纪存、纪文山、佐伯七海、Evelyn Voss/白鸢、唐启明/唐胶、窦晓宁/兜灯、Heng Lu Mwangi/陆衡等核心角色时，还必须读取`v35_core_cast_nationality_name_baseline_v1.tsv`。中文显示名、原文/法定名、国际转写、笔名/呼号、公民身份、文化成长和视觉生产口径必须分栏；中文名加拼音不计作全球演员身份。
- 创作普通机体主体性、岛卫线、敌方学习、纪存能力、G.A.G.文明、远星归静或终局支援时，必须查 `v35_upstream_motif_lexicon_migration_v1.tsv`。`慢半拍/错拍`已退出Current机制；`合唱/声部/节拍/唱歌`只留给莉歌、星翼、真实演唱、战队唱名、合体歌、配音剪辑或具有明确物理周期的单次场面。
- 当前岛卫三号使用`本地指挥权交还`：撤销中央自动齐射，把开火、停火和撤离优先级交还三个地方席位，并允许其为保护驾驶员主动放弃外圈阵地。不得再用“慢半拍即人格”替代这一战斗与政治选择。

## 使用顺序

1. 用 `story_threads.tsv` 确认某个场景属于哪条长期剧情线，避免章节只服务局部事件。
2. 用 `story_chapter_diagnostics.tsv` 确认本章不与相邻章同题反复，并明确玩家要做的事。
3. 用 `gag_capability_boundaries.tsv` 检查 G.A.G.、索引天使、清算封存和机魂实体化是否有载体和代价。
   - 写索引、索引天使、清噪、最优模板、C07原典、C08白名单或C09反攻时，继续查 `index_influence_expression_grammar.tsv`，确保玩家能通过症状、好处、损失和反制识别索引影响。
   - 写C10远星、迟到回信、方舟T通信、灯槽窗口或远星深潜时，继续查 `far_star_lightslot_communication_rules.tsv`，确保旧时代迟到回信和当前短窗超距通信并存，且每次通信都有载体、带宽、代价和漂移。
   - 写陆衡、方舟T、C03幽默参数或C10远星AI陪伴时，继续查 `luheng_fangzhou_t_relationship_grammar.tsv`，确保关系通过工况、日志、校准、过滤冲突和日志烧蚀表现，而不是女性AI恋爱、秘书AI或普通冷笑话机器。
4. 用 `antagonist_personal_scene_seeds.tsv` 检查反派是否有个人欲望、压力和后果，而不只是系统代言人。
5. 写第9-12章时，用 `finale_expression_grammar.tsv` 把抽象概念转成地图规则、UI语言、物件和台词。
6. 用 [全游戏逐话剧情梗概](../../剧情梗概/全游戏逐话剧情梗概-v01.md) 和 `全游戏逐话剧情梗概索引.tsv` 反查历史46话拆分；72个场景块是材料，不等于72话，当前V20不直接按v01扩写。
7. 重写50项整改方案或新版梗概前，先用 `issue_deep_revision_targets_v10.tsv` 和 v10文档确认问题本身的专属解法、v10.1创造性补强和50项v10.3场面池；不要再用逐话表或人物弧线表替代问题方案。
8. 再用 `issue_lock_integration_v10.tsv` 对照 `../canon/character_mecha_art_locks.tsv`，确认每个问题涉及的角色、机体、美术状态、canon缺口和禁止项。
9. 再用 `issue_drama_energy_diagnosis_v11.tsv` 判断每个问题缺的是哪种戏剧能量，避免把v10场面池机械平均塞进逐话梗概。
10. 再用 `issue_construction_constraints_v12.tsv` 把诊断转成逐话硬约束，确认该问题进入哪类话、由什么承载、不能怎么写。
11. 再用 `issue_living_canon_review_v13.tsv` 判断当前问题是否被旧canon压小：哪些要保留为硬锚，哪些应迁移为新工作设定，哪些旧口径要降级为历史参考或候选材料。
12. 再用 `issue_legacy_integration_v14_1.tsv` 和 [50项问题继承整合v14.1](../../剧情梗概/全游戏逐话剧情梗概-50项问题继承整合-v14.1.md)，确认v05-v14中哪些好总结、结构和场面池必须保留、升级或合并，避免只读v14时丢失旧版本遗产。
13. 再用 `issue_creative_rebuild_v14.tsv` 和 [50项问题创作重整v14](../../剧情梗概/全游戏逐话剧情梗概-50项问题创作重整-v14.md)，把问题转成后续逐话可调用的创作弹药：大场面、关系爆点、机体生态、G.A.G.异常、梗点变奏、系统资产影响和canon迁移建议。
14. 再用 `issue_drama_explosion_v15.tsv` 和 [50项问题爆破升级v15](../../剧情梗概/全游戏逐话剧情梗概-50项问题爆破升级-v15.md)，检查每项方案是否仍然太温、太小、太像KPI，尤其要把梗点校准为玩家能识别的机战/机器人名场面原创变奏，把爽点校准为合体、后继机、量产逆袭、宿命英雄等类型快感，把成人擦边限定在成年角色的卖相和危险关系场。

## 设计原则

- 每个主线场景至少承担一个剧情功能、一个角色功能和一个玩法或变量功能。
- 每个主线话至少要有可复述的戏剧碰撞、情绪句柄、关系场面或名场面梗点，不能只完成章节论点。
- 字段完整不等于有趣；关键话必须能回答玩家为什么继续、PV级机体画面是什么、哪段关系有情绪事件、宏大阴影如何可见、抽象议题如何变成戏剧动作。
- 模型盒、展签、框体、维修单、说明书、证词展台、留言墙等是非计数锚件，不能冒充每话机体密度；它们必须触发、限制、修复或解锁真实机体/支援/敌方/Boss/场景巨机才有机战承重。
- 真实爱好者证词可以直接进入剧情和展柜，但必须有来源、尊重边界和发布前授权/署名复核；真实故事负责让玩家相信“机器人文化被人认真生活过”，不能被消费成廉价催泪按钮，也不能替代参战机体、玩法、IP投射和主角决策。
- 顶层价值必须落成场面、玩法、敌方收益和角色选择；所谓共同语言，必须让具体人物和机体保留姓名、身体差异、独立地址、拒绝权、退出路径与自己的行动目标。粗糙译本、热爱责任、非人尊重、反唯一模板和小物件文明尺度至少在关键话中可见，不能再靠抽象的音乐隐喻一句话代替。
- 功能模块、规则机和场景机关可以丰富关卡，但不能长期替代参战包级主机体、宿敌、后继机、隐藏机或代表性支援单位；每台新机体进入剧情时都要带着IP母题、故事冲突、名场面/台词锚点和玩法位置。
- 战斗场景不默认以全灭为目标，优先使用保护、撤退、非致命、阵列防守、说得、改写代价等目标。
- 感动必须先建立关系，再放大到战争、时间、宇宙和结局。
