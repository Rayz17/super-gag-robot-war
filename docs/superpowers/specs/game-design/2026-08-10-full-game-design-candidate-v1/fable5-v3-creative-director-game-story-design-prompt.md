# Fable 5 创意总导演委托｜重新找到《超GAG机器人大战》最强的游戏与剧情共同发动机

> 请在当前项目工作区内完成本任务。  
> 本轮不是对V2做小修，也不是在04／05／07中投票；你被委托为本作的创意总导演、战棋主策与RPG系统主策。  
> 最终目标只有一个：设计出一款**只有《超GAG机器人大战：万机残响》才能成立，普通玩家能够理解，目标玩家会强烈想玩，而且能通过玩家亲手操作充分兑现燃、爽、笑、爱、色、痛、惊与感动的完整游戏**。

## 一、本轮真正要解决的问题

上一轮V2提高了事实正确性、故事兼容性和规则收敛度，却也把04／05最有生命力的部分削弱了：

- “活的机器人争着重新登台”变成了低频谏言与愿／虑／拒状态；
- 战中的舞台、见证、蓄势与爆发，退成战后文字回响；
- 绝活从读懂一台机器、为它创造时机的传奇事件，变成动作链检查；
- 角色重新接近情报、权限与工程服务模块；
- 深潜、策展、修复、收藏和生活被抽象成通用语法，具体游玩欲望变弱；
- “承接／力线”从一种有力的身体战术语言，被提升成整款游戏唯一的产品幻想；
- 游戏削掉了许多奇观和奖励，却仍保留了较高的操作与认知负担。

04／05也不是可直接恢复的答案：它们有很强的舞台感、机魂主动性、名场面欲望、角色特技和长线想象，但同时存在AI替玩家解题、系统膨胀、资源过多、人物卡牌化、非战棋全部兑换战力、逐章百科和引用History故事等问题。

因此，本轮不能走两个极端：

1. 不能为了规整、低风险和兼容，把梦想继续删掉；
2. 不能为了热闹，把每个好点子都做成常驻系统。

你要找到的是：**一个可靠的游戏身体，装得下真正有欲望、有奇观、有生活、有爱情、会哭会笑的灵魂。**

## 二、你的创作权限

### 2.1 玩法机制拥有充分自由

所有现有玩法文档与外审均为Candidate输入。你可以：

- 保留、反转、融合、降频、删除或彻底替换00c、04–08中的任何玩法；
- 重新决定玩家身份、主战棋结构、时间制、行动结构、机体主动性、角色能力、敌人玩法、奖励成长、万机馆循环与非战棋模式；
- 设计此前没有出现过的新机制；
- 在充分说明收益后，提出一套与现有Candidate完全不同的游戏骨架；
- 必要时提出Working故事或设定迁移候选，而不是为了“零迁移”替平庸玩法辩护。

文档已经写得很多，不构成必须继承它们的理由。`承接`、力线、确定物理、短全队同步、C2、举手、残响、清噪、锚件、收录律、精神指令、回馆一晚等都只是候选，不是预设答案。

### 2.2 先发散，再替用户作出主策取舍

在写最终总案前，你必须先真正推导至少三种**快乐发动机明显不同**的方向。三种方向都先写成一段可玩的60秒循环，回答“看见什么—连续做什么—怎样升温—怎样爆发—为什么立刻还想再来一次”。它们至少要在以下三项中的两项不同：

- 玩家反复扮演的身份；
- 每分钟反复执行的核心动词；
- 战中从压抑到爆发的正反馈方式；
- 机器人主动性与玩家作者性的关系；
- 战斗、万机馆和剧情怎样互相供能。

三种方向中最多只能有一种以“承接、交棒、搬运力线”为总发动机；其余两种不能只是把同一底盘换名词。

你应自行比较并收敛成**唯一主推荐**。不要把三套平级大案丢给用户代替主策决断。09号文件保留半页“60秒原型对比”，让用户看得见你确实探索过不同快乐；随后只展开胜出的一个主案。

### 2.3 允许真正高能的野机制

本轮不再默认禁止：资源、能量、关系状态、特殊章节玩法、独特界面或高风险高潮机制。判断标准不是“有没有新增名词”，而是：

```text
它创造的独特欲望与快乐
÷
玩家认知、操作、内容生产和长期维护成本
```

允许保留一到两项贯穿全剧、只有本作才配拥有的**常驻野机制**，前提是它们：

- 在玩家手里反复产生真实选择，而非只提供设定说明；
- 能替代若干低能流程，而不是叠在所有旧系统上；
- 十章以后仍能通过角色、身体、敌人和关系发生变化；
- 不能靠刷取、重复劳动或文书审批维持存在感。

逐章一次性的规则翻面、Boss特殊界面、变形／合体高潮和庆典式玩法不计入这个数量，只要它们复用已学会的基础输入、服务该章幻想，并在结束后不留下永久系统债。

## 四、创作中必须保护的体验功能

以下是必须兑现的体验功能，**不是要求恢复某个旧机制名**。

1. **机器人是群像主角。**它们会主动争取、炫耀、害怕、抬杠、误判、改主意、拒绝，也会给玩家惊喜或制造麻烦；不能只剩服从状态灯。
2. **玩家是名场面的作者。**机体可以表达欲望、局部机会和身体直觉，但不能把完整最优路线递给玩家。空间、时机、对象、风险和连携必须由玩家亲手组织。
3. **战中有明确的正反馈波形。**玩家能预感某个大场面正在接近，并通过准备、冒险和取舍亲手让它爆发；高潮不能只在战后发一段文字。
4. **机器人身体真的有戏。**体积、姿态、损伤、变形、合体、武装、量产差异、旧伤和修复会改变玩家动词，但不能把所有机体都写成搬运不同重量的工具。
5. **偏爱会得到回报。**冷门机、量产机、手修、锚件、收藏、长期陪伴和玩家自己的用法，会改变身体、共同动作、剧情位置和终局作用。
6. **万机馆是家也是主角机。**玩家要看见它的空间、住民、展陈、伤痕、航路、身份和形态持续变化，并期待它终有一天亲自登台。
7. **关系改变共同创作。**人物关系应改变彼此愿意提出、完成、中止、隐瞒或共同承担什么，不只是Buff、好感数字或减少审批。
8. **选择会延迟回来。**玩家曾保存、偏爱、答应、放弃、误判或失去的具体对象，会在后期以改变命运的方式回来。
9. **允许完整快乐。**每一部都要有庆典、炫技、生活、亲密和真正的胜利。先让玩家喜欢、拥有并庆祝，再让代价追上来；不能把每个爽点立即开成罚单。
10. **敌人也是机器人大战的一部分。**需要可辨认的身体、风格、招牌、驾驶者或人格、宿敌关系与进化；不能长期只打装置、力线和制度障碍。

## 五、燃、爽、笑、爱、色、痛、惊与感动怎样进入玩法

这些是体验目标，**禁止直接机械地做成八色货币、八条情绪槽或每关打卡表**。每一项重要体验都要追踪：

```text
欲望怎样被预热
→ 玩家为它准备什么
→ 玩家承担什么风险或放弃什么
→ 哪个具体操作兑现它
→ 演出怎样把操作放大
→ 人物与世界怎样承认是玩家促成
→ 留下什么状态
→ 以后如何回收
```

- **燃**：玩家把不可能一步步搭成可能，人物与机魂最后自愿把自己交进方案；不是过场突然开必杀。
- **爽**：熟练、准备、收藏和偏爱获得清晰的大规模兑现；本作必须允许干净利落的胜利、反杀与炫技，而非永远只赢一半。
- **笑**：机体性格、错版身体、模玩／商业荒唐、战场规则和人物关系发生可玩的碰撞；不能只靠战后插段子。
- **爱**：时间、注意、照料、信任、放手、共同承担和允许对方拒绝，真实改变人与人、人与机、人与家怎样一起行动。
- **色**：仅限明确成年角色；由身体距离、驾驶服与战损照料、维修空间、相互欲望、危险边界和选择制造性感。它不兑换战力，不涉及儿童与少年，也不把人物降为奖品。
- **痛**：来自玩家亲手作出的选择、真实失去和不能兼得；不能用永久惩罚把每次高光都变成后悔税，也不能取消此前胜利。
- **惊**：出现一种去掉本项目就不成立的新图像、新规则或命运翻面；不是简单把数量和尺寸翻倍。
- **感动／暖**：由玩家曾亲手做过、留下、修好、错过或坚持的具体事延迟回收；不能用BGM、告白或角色复述作者主题代替因果。

每章只需要一到两个主情绪，其他能量负责衬托。全剧必须形成“快乐—依恋—胜利—诱惑—失去—重新选择—终局回收”的波形，而不是每场全音域轰炸。

不得为一个情绪标签单造一个系统。优秀机制或场景往往会自然叠加多种体验，例如“手修一台嘴硬旧机”可以同时带来笑、爱、色与后期感动；不必硬凑数量。正文只深证当前阶段最重要的体验，其余放进全剧波形，不做逐项报表。

## 六、游戏设计与剧情设计必须共用同一条因果

每一个重要高光都必须回答：

1. 玩家此前亲手准备或促成了什么？
2. 人物、驾驶员、机魂或机器人自主选择了什么？
3. 玩家在高潮当刻具体按、拖、选、组合或放弃了什么？
4. 演出负责让玩家看清什么，而不是替玩家完成什么？
5. 结果永久改变了哪台身体、哪段关系、哪个房间、哪条航路、哪个敌人或哪项世界事实？
6. 以后在什么情境下会再次回来？

不得让过场夺走玩家搭成的高潮，也不得为了玩家作者性把角色变成遥控木偶。关系、喜剧、色气、泪点与机器人奇观必须改变同一条主因果，不能作为外挂插曲。

## 七、主战棋需要重新回答的设计题

你可以继承、修改或放弃现有物理与时制方案，但最终必须给出清楚答案：

- 玩家一分钟内反复做的最好玩判断是什么？
- 玩家究竟控制什么，机器人／驾驶员自主决定什么？
- 地图、身体、敌方意图、信息不完整与角色关系怎样共同制造选择，而不是依次增加流程？
- 普通动作怎样快速完成；何时才值得进入协商、授权、主体拒绝或高风险确认？
- 怎样让机器人主动表达而不替玩家解题？
- 怎样形成蓄势、转折和爆发，又不沦为刷能量？
- 怎样同时容纳拳战、射击、追逐、擂台、救援、工程、变形、合体、宿敌、量产机逆袭、舰战、全员支援与百机大战？
- 身体损伤怎样关闭或改变有趣动词，而不是只增加维护痛苦？
- 敌人怎样拥有打法、身体、欲望与学习，而非只是关卡障碍？
- 失败怎样让故事变厚，同时不把完整胜利压缩到稀有事件？
- 玩家为什么在第十局仍会发现新的方案，而不是重复处理更大的同类问题？

作为默认目标，普通决策段应聚焦于一个主要问题和少数真正困难的决定；常规校验、重复移动和无戏审批应被预设、自动沿用或合并。你可以突破这个目标，但必须证明额外负担本身就是快乐。

### 7.1 两个必须写完整的战斗证明

1. **普通中盘任务**：不是Reader高潮，也不是一次性奇观。用它证明核心玩法重复十局仍有变化、两种以上有风格的方案、敌人会反应、角色与机体会带来惊喜，而且操作不会变成文书工作。
2. **招牌高潮任务**：可以锚定Current C01–C03或C04有效素材。用它证明玩家能亲手搭出预告片级的燃爽名场面，并让笑、爱、痛或感动与战术因果相连。

两例都必须写清：

- 玩家第一眼看见什么；
- 每一步具体点、拖、选、排或确认什么；
- 为什么会犹豫；
- 至少两种责任、身体用法、节奏或欲望明显不同的有效方案；
- 人物、驾驶员、机魂、机器人与敌人各自怎样介入；
- 即时画面、声音和规则反馈；
- 局部失败、不行动与主动撤退怎样继续；
- 任务后立即得到什么“马上想试”的奖励；
- 哪些后果会进入下一场、返馆和后期回收。

不要用“剧情里本来就发生了”证明玩法好玩，也不要用未来UI、Build或真人测试替代当前规则说明。

## 八、人物、机魂与角色招牌

纪存、七海、白鸢、索琳，以及C02、C03各一组代表性的当地人与机群，都必须拥有主体性和可辨认的玩法身份；但不要逐人制造六套系统。

只深做2–3组最能代表本作化学反应的**关系共同体**，例如“纪存—七海—白鸢”“纪存—索琳”“地方人物—当地机群”。每组用一段战斗或生活事件回答：各自想要什么、谁主动发起、谁会犯错或拒绝、玩家如何介入、关系变化后新增或失去什么共同动词、不在场时真正少了哪种玩法。其余对象用紧凑角色卡说明独占判断、主动性、失效方式和终局回归即可。

卡片、席位、精神指令、提案气泡或技能可以是界面，但人物不能被还原为功能牌。只有能长期制造独特玩家判断的关系共同体才值得专属机制；其他人物的主体性可由行动、拒绝、生活与剧情选择成立。

## 九、万机馆、非战棋与RPG长循环

先决定万机馆循环为何本身值得玩家期待，而不是只问它怎样给下一场战斗加成。探索、调查、修复、改装、策展、收藏、舰内生活、世界地图、关系与成人内容可以分别被设计为：

- 高频核心循环；
- 中频支持模式；
- 低频高光玩法；
- 纯演出／叙事承载；
- 删除或合并。

不要求它们都使用同一种点击语法，也不允许每项都发展成独立小游戏。每个保留项目必须说明：

- 玩家为什么会主动想进入，而非因为有红点或战斗Buff；
- 第一眼看见什么、实际操作什么；
- 两种选择各放弃什么；
- 不做会怎样；
- 怎样改变人物、机体、万机馆空间、收藏、世界、下一站或结局；
- 十小时后它如何比第一次更有意思。

至少给出两段完整操作例：

1. 一段收藏／调查／手修／策展相关的具体玩法；
2. 一段生活／关系／成年人亲密张力相关的具体玩法。

第二段不能只是一组对白选项。它应让玩家通过在场、照料、共同工作、保密、让位、邀请、拒绝、承担或放手改变关系。其结果可以只改变人、家、记忆、世界回应或结局，不必兑换战斗强度。

## 十、奖励、成长与长期欲望

请分别设计：

- 10–30秒内的触感与视听奖励；
- 一个战术周期内的局部成功；
- 一次任务结束后马上想试的新东西；
- 2–3场后的身体、招牌、关系或队伍变化；
- 一部结束后的万机馆形态、阵容和世界位置变化；
- 十小时以上的收藏、宿敌、爱情、What-if、家园和终局期待。

不强制刷级、数值膨胀、装备海或技能树；但若不用它们，必须提供同等强度的获得感，例如：

- 新机体与真正不同的身体；
- 新动作或绝活变体；
- 关系合奏和联合操作；
- 生涯件与可见修复；
- 万机馆房间、展陈、航路和形态变化；
- 敌人因玩家过往行为产生的新对局；
- 玩家偏爱的冷门机在后期获得不可替代的位置。

“世界记得你”和“你欠下一项责任”不能承担全部奖励。玩家必须经常得到值得期待、值得炫耀、想立刻拿去玩的正向成果。

## 十一、幻想兑现与反幻想审计

以L1八项玩家幻想为准，为最终方案建立一张简明矩阵：

```text
作品承诺
→ 玩家反复亲手做什么
→ 游戏立即怎样证明
→ 2–3场后怎样成长
→ 中后期怎样形成高潮
→ 剧情与世界怎样承认
→ 哪种设计会产生相反体验
→ 本方案如何防止
```

重点检查：

- 真正参加机器人大战，而不是一直做救灾物流；
- 万机馆既像家又像不断变化的主角机；
- 能把机器人动画的遗憾重新打出新结果；
- 梗、模玩、名动作与经典精神进入玩法，不是换皮引用；
- 收藏、手修与偏爱能改变巨大真实身体；
- 成年人物会相爱、争吵、嫉妒、欲望、伤害、互救与失去；
- 多种玩法真的改变局势与故事，而非菜单换皮；
- 这份爱好最终抵达群星、文明与终局，而非后盘突然换题。

若某项幻想不适合成为核心循环，应诚实说明它是支撑幻想、低频高潮还是邻接内容，并提供足够强的替代满足。不能再次把八项都写成“已覆盖”，也不能为了收敛把大部分幻想降为战后文字。

## 十二、故事适配与迁移自由

先选出**体验最强的唯一主案**，不得把迁移量作为第一排序。随后说明它在哪些Current故事范围内可直接适配、哪些地方必须迁移，以及不迁移时还能成立到什么程度。保守兼容版只能作为降级替代，不能反过来挤掉主案。

- **Gameplay Candidate**：可自由删除、重组或替换。
- **C01–C03**：故事主体、人物和机体的关键行动、胜负与章末去向已验收；具体关卡、操作、UI、时制、数值、调查、Hub承载、镜头和L6表达仍可大胆重做。若理想玩法必须改变已验收事件，单列故事迁移提案。
- **C04**：当前L4／L4.5与passed单话是有效生产输入，但尚无用户整章验收；可以比C01–C03更自由地提出重基，同时列出将失效的story-chain阶段。
- **L1–L3／H0 Working**：允许提交更强的迁移方案，但不能只指出旧承诺碍事；必须给出更能满足玩家幻想、全剧发动机与世界边界的新答案。
- **Hard Canon**：不得静默改写；可以提出迁移建议并标明对象、理由、消费者与重建范围。
- **History**：只打捞高光，不恢复旧状态链。

每项迁移写清：

```text
当前事实
→ 为什么阻碍更强体验
→ 新设计
→ 获得的快乐／情感收益
→ 代价与风险
→ 影响的章节与文档
→ 不迁移是否仍有可接受版本
→ user_decision_required
```

C01–C04只需证明兼容、增强或迁移价值；不要再做13话百科式适配。C05–C22只做5–7个系列阶段，说明每阶段新增的机器人幻想、战术变化、人物／关系变化、万机馆变化、敌方回答、快乐减压点与长期回收。不要把六部写成同一个动词不断放大。

## 十三、复杂度与内容成本纪律

复杂度不是系统越少越好，也不是输入设备没有新增就等于负担下降。每个常驻机制必须登记：

- 它制造的独特欲望与有趣判断；
- 出现频率；
- 同屏信息、操作步骤、需要记忆的规则和长期状态；
- 新手怎样借助人物、视觉和情境自然理解；
- 十章后的变奏来源；
- 内容与演出成本；
- 它替代或删除了哪些低能流程；
- 如果删掉，哪项核心幻想会真正消失。

普通行动不得反复经过多人审批。同意、权限、责任、撤回与主体边界，只在真正有戏、会改变风险或关系的时刻进入前台。

不要用“以后让UI、教程、Build或真人测试解决”掩盖规则不清；但本轮也不需要写Schema、测试矩阵、制作BOM、代码、Runtime、平衡小数点或原型计划。当前交付是**核心游戏设计、剧情共同设计和玩家可读的操作说明**。

四个操作实例中，至少一个必须让喜剧改变玩家判断、战场状态或关系，而不是只改对白。成人关系实例还必须展示一条跨章节的“吸引—试探—边界—亲密或错失—后期回收”链；色感来自双方主体性、距离和选择，不兑换战力。

不要另外创建裁决表、迁移表、逐章附件、Schema或第三份总结。必要表格直接嵌入上述两份。

## 十五、反失误红线

- 不把“承接／救援／工程”或任何单一动词吞掉机器人大战的全部快乐。
- 不让机器人替玩家给出完整解法，也不把它们降成服从灯；双方都必须对名场面有不可替代的作者性。
- 不删光舞台、奖励、惊喜与爆发，却保留大量几何、审批和维护负担。
- 不把角色、关系、回响与非战棋玩法做成战后文字、服务模块或同一种菜单换皮。
- 不用故事兼容、设定名词、未来技术或“有动画就会爽”代替可操作的玩法因果。
- 不把情绪逐项做成资源；也不让每次胜利立即反噬。必须有纯粹值得庆祝的阶段。
- 不让成年人情欲侵占未成年角色，不把任何人物的身体写成玩家奖励。
- 不让六部只是同一机制扩大规模；系列统一来自角色、世界、后果与玩家幻想，不来自重复。

## 十六、最终质量检查

交付前只用以下七问否决弱稿；它们是整体验收，不是正文的七张报表：

1. 玩家30秒后最想再做什么，一小时后期待什么，十小时后舍不得什么？
2. 普通中盘战是否本身好玩，第十局是否仍有新判断？
3. 玩家能否复述一个“只有我这局才发生”的燃、笑、爱或痛的故事？
4. 是否既有毫无歉意的完整胜利，也有由玩家亲手选择造成的遗憾？
5. 关系、收藏、手修和偏爱是否真的改变共同动作、巨型身体与终局位置？
6. 预告片能否截出三张只能属于本作、且都由玩家操作促成的画面？
7. 去掉这些角色、机魂、万机馆、锚件和机器人身体后，机制能否原样换皮；普通用户又能否不懂内部术语仍看懂操作与所得？

若答案不够强，不要用“未来验证”结案；先在纸面上重新设计。也不要声称任何方案已经获得用户批准、成为Canon或证明实际乐趣。你的职责是交出一份足够有创造力、足够具体、值得用户真正裁决的最佳Candidate。

完成后，聊天回复只需要：

1. 一句话说明最终选择的快乐发动机；
2. 两份新文件路径；
3. 最希望用户先裁决的三件事。
