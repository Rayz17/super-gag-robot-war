# 第一次调查／工程实证：15分钟《偏航装卸台》

> 当前状态：`Candidate / current_supporting_module_example_investigation / derived_from_00b / core_design_review / user_not_decided`
>
> 这页只说明一种轻辅助玩法：观察实体、比较证据、配置安全试验、看见物理反馈，再把结果带进下一段行动。它不绑定任何章节，也不代表“知识门控”或四种小游戏都应保留。

## 共用操作语法

轻探索、Hub和调查／工程实证都用同一条操作语法：

`聚焦对象 → 记录事实 → 比较方案 → 主提交 → 返回`

本场的主提交键别名是`请求开始`；试验前的走动、取证、拖动证据和改配置都是草案操作。`返回`可以带着当前不完整结果离开；试验已开始时，同一键按住则是请求主动中止。

## 先用二十秒想象这段玩法

三只密封箱必须通过一座会向左偏摆的装卸台。现场的人只知道它最近开始失准，不知道是左侧支撑变软，还是控制增益过高。

玩家不需要解密码，也不需要搜满发光物。玩家会：

1. 走到装卸台旁看三个真实迹象；
2. 在现场手册里把事实连成两个候选解释；
3. 配置一次低风险测试；
4. 在“把唯一便携地面支撑架暂留现场、准时通过”和“把支撑架带走、慢一格通过”之间选择；
5. 下一场行动立刻读取时间和工具差异。

目标时长是 12–15 分钟。熟悉规则后的同类小案应压到 6–10 分钟，不能每次都重新上一堂工程课。

本例所说的“世界时间1格”是返馆、旅行和任务截止共用的长期 `T` 格；它不等于主战术中的8秒决策窗，也不会按调查现实分钟数自动折算。

这段调查从 `T0` 开始。观察、翻手册和修改尚未提交的配置不会单独跳格；第一次合法实体试验一旦完成或被安全中止，本次现场时段就结算为 `T0 → T1`。之后只有确实需要下一班运输窗口的做法才会再走到 `T2`：

| 结果 | 下一段行动从何时开始 |
| --- | --- |
| 快速承力成功 | `T1`，算准时 |
| 保留工具、两次半载完成 | `T2`，比准时晚1格 |
| 首次试验不足，在同一现场缓冲内修正为快速承力并成功 | 仍是`T1`；修正本身不再加长期格 |
| 首次试验不足后保守离开，交给本地人工慢运 | `T2`；故事继续，但失去准时入口 |

这里的“一次修正不加格”不是无限重试。它只代表现场排程预留了一次短调整；第二次仍不足时不再开放第三次，直接按保守离开结算到 `T2`。

## 共用语法怎样落到五个按键

| 玩家想做什么 | 鼠标／键盘 | 手柄 | 逻辑上发生什么 |
| --- | --- | --- | --- |
| 移动与看向 | `WASD`＋鼠标 | 左／右摇杆 | 走到实体旁，选择观察角度 |
| 观察 | `E`或点高亮轮廓 | `A` | 记录事实、来源和时间 |
| 情境互动 | 点对象动作 | `X` | 交谈、操作、开始或中止试验 |
| 现场手册 | `Tab` | `Y` | 比较证据、建立候选解释、配置试验 |
| 返回 | `Esc`／右键 | `B` | 带着当前不完整结果离开 |

“看缓冲尺”“问停止权”“安装支撑”不是三套新按键，都是同一个情境互动键在不同对象上的合法动作。

## 第一个画面：问题和边界先说清楚

屏幕只显示一个问题：

```text
怎样让三只密封箱安全通过偏航装卸台？
```

旁边直接列出三条边界：

- 装卸台主体只接受预览安全包络内的测试；
- 本地维护员拥有实体停止权；
- 玩家本次可以提出配置和启动请求，不能越过两者强行满载。

这三条不是剧情装饰。配置越界时，开始键就必须说清“谁拒绝、为什么、可改成什么”，而不是用好感数或红色禁止图标糊过去。

## 0:00—4:00：玩家亲眼取得三条事实

场景里只突出三个近看点：

### 1．左侧缓冲尺

玩家走近，按观察。尺上有一段新压缩痕，手册记录：

```text
观察到：左缓冲比右侧多压缩 6 毫米。
来源：现场刻度，刚才的空载回摆后。
能证明：左右受力不对称。
不能证明：支撑损坏，或控制命令本身错误。
```

### 2．控制日志

玩家在控制台按互动，翻到最近一次设置变化：

```text
观察到：偏摆从“控制增益上调”后开始出现。
来源：本地维护日志。
能证明：时间上有关联。
不能证明：增益是唯一原因。
```

### 3．一次空载回摆

玩家请求装卸台做不载箱的慢速回正。主体接受，本地维护员保留停止权。玩家看见平台回正过冲，左缓冲再次压缩。

```text
观察到：无货物时仍向左过冲。
来源：本次实体试验。
能证明：问题不只来自箱体重量。
```

玩家只看其中两项也可以继续，但右侧安全预览会留下更大的未知区间。

## 4:00—6:00：现场手册不是自动答案

玩家打开手册，把证据拖到两个候选解释下：

```text
候选A：左支撑变软，控制系统只是在补偿失败。
候选B：控制增益过高，放大了原有的轻微左右差异。
```

系统不会立刻把一个涂绿。它只说：

- 哪些事实支持这个解释；
- 哪些事实与它冲突；
- 下一次试验能排除什么；
- 仍然不能证明什么。

如果玩家把控制日志连到“支撑已经断裂”，手册提示“这条来源只能证明时间关联，不能证明实体断裂”，但允许保留为待证假说。它不是考作者预设词语的连线题。

证据不只涨一个“调查进度”，而是直接改变配置页能给出什么结论：

| 玩家已取得的东西 | 配置预览发生什么变化 |
| --- | --- |
| 只看控制日志 | 只知道“调高增益后开始失准”；支撑状态未知，三箱正式运输不会被标成已验证安全 |
| 再看左侧缓冲尺 | 能估算便携地面支撑架会缩小多少左右受力差；方案A的预计偏角区间才会收窄 |
| 再做空载回摆 | 确认过冲不只由箱体重量引起；“降增益＋半载”的可控区间才能用本次实体反馈支撑 |

少看一项不会神秘锁掉按钮，但某些结果只能显示为带三角标记和`诊断用途／未验证正式运输`文字的试验，不能直接承诺三箱安全通过。这样取证改变的是可承担的行动和不确定范围，而不是给菜单答案染色。

本案的目标也不是在15分钟内宣布一个唯一根因。玩家要证明的是：“支撑差异和过高增益都是可操作的风险，当前有两种安全缓解法”。精确根因仍进入后续维修工单；调查的价值是让玩家在根因未全定时也能作出负责的安全选择。

## 6:00—9:00：三个配置槽形成真正取舍

配置屏只有三行：

```text
支撑：无 / 安装便携地面支撑架
控制：标准增益 / 降低增益
载荷：三箱一次 / 分成两次半载
```

右侧不是一个模糊的成功率，而是同时显示：

- 预计偏角范围；
- 左缓冲预计压缩；
- 是否处在主体接受的安全包络；
- 世界时间会不会多走一格；
- 便携地面支撑架是否还能带去下一场行动。

在这个纸面种子里，两套合法方案互不完全支配：

| 方案 | 配置 | 得到什么 | 付出什么 |
| --- | --- | --- | --- |
| A．快速承力 | 便携地面支撑架＋标准增益＋三箱一次 | 三箱准时通过；下一场从近入口部署 | 消耗1份安装材料；唯一便携地面支撑架暂留装卸台，等待回收，下一场不可用 |
| B．保留工具 | 无支撑＋降低增益＋两次半载 | 三箱安全通过；材料与便携地面支撑架保留 | 世界时间多走1格；下一场只能从较远入口部署 |

便携地面支撑架是一件唯一、可以回收再用的工具，不是“材料1”的另一种写法，也不会因为方案A被永久消耗。玩家选择方案A后，配置页会多出一张留置确认卡：

```text
便携地面支撑架：暂装在偏航装卸台
合法所有者：不变
现场保管：本地维护员
回收条件：运输结束后，由具名回收工单取回
下一任务：不可携带
```

玩家先与本地维护员互动，看到对方是否接受保管和回收责任，再用主提交键“确认暂留”。默认长按可在全局设置中改为单击或双击。若没有人接受保管、借期不清或回收责任空白，方案A不能提交；方案B仍然合法。确认后，馆内工具清单只显示“留置现场／等待回收”，不能同时再出现一件可出击的复制品。材料1只支付安装耗材，不改变便携地面支撑架本身的所有权。

如果规则让其中一套同时更快、更省、更安全、下场条件也更好，这就不是选择，必须改掉代价或删掉另一套。

## 9:00—11:00：试验靠实体反馈，不靠QTE

玩家按“请求开始”。开始前最后一页显示：

```text
提案者：玩家控制的现场协作者
接受主体：装卸台
停止权：本地维护员
物件授权：方案A另需便携地面支撑架所有者的具名安装与代管回执
测试包络：当前配置的偏角与载荷上限
主动中止：玩家也可随时按住返回键
```

试验开始后，玩家不需要按节拍键。镜头清楚显示平台偏角、回正时间、左右缓冲压缩和三只箱的位置。

- 在安全区内：试验继续，玩家可提前中止，或选择完整／精简演出；
- 接近上限：画面、声音和仪表同时预警；
- 越过上限：本地维护员自动停止，平台回到最后安全状态。

完整演出显示全过程，精简演出只保留开始、越界或完成、停止三次关键反馈，跳过则立即显示结果卡；三者的行动结果必须一样，并且都可展开因果记录，看到“哪个配置→哪个实体变化→为何停止”。

## 试验失败怎样继续

这里区分两种失败：

### 提交前不合法

例如玩家选择“无支撑＋标准增益＋三箱一次”，预览已经越过主体接受包络。开始请求被拒绝：

- 不走世界时间；
- 不扣材料；
- 不改变装卸台；
- 页面指出可以降低增益、减少载荷或安装支撑。

### 已经执行，但结果不够

例如玩家只看了两条证据，选择带三角标记与`诊断用途／未验证正式运输`文字的“无支撑＋低增益＋单箱诊断”。这个配置在紧急停止包络内，所以可以启动；但它没有获得“三箱正式运输”的安全承诺。实体试验若仍出现过大偏摆，本地人员中止，玩家得到：

- `结构偏移仍存在`这一条新事实；
- 三箱尚未全部通过；
- 世界时间从`T0 → T1`，因为第一次实体试验已经占用了本次现场时段；
- 本例没有安装便携地面支撑架，因此它仍在玩家工具清单中；若失败前已经安装，则它仍按留置回执待在现场，不会凭空退回或被写成消耗品；
- 一次修改配置的机会，或选择保守离开。

此时结果卡只给三个清楚选项：

| 玩家下一步 | 长期时间 | 工具与材料 | 写回下一段 |
| --- | --- | --- | --- |
| 修正为方案A：安装支撑后一次通过 | 仍停在`T1` | 材料减1；唯一支撑暂留现场、等待回收 | 近入口；装卸台获得“支撑条件下可通行”结论 |
| 修正为方案B：降低增益并分两次半载 | 运输结束到`T2` | 材料不减；支撑继续随队 | 远入口；装卸台获得“低增益半载可通行”结论 |
| 保守离开 | 本地人工慢运结束到`T2` | 没安装的工具保持原位；已安装的支撑继续留置并等待回收 | 远入口；只写“人工完成运输”，不冒充装卸台已通过验证 |

玩家只能进行这一次修正。若修正后的实体试验仍触及停止线，系统不再开放第三次尝试，自动转入“保守离开”：本地队在`T2`完成慢运，维修工单保留两次试验的事实，故事继续。

这不是“随便失败也算赢”：没有取得的安全结论、路线和工具优势都不会白送。

## 11:00—15:00：结果必须当场被下一段消费

提交结果后，不只出现一行“调查完成”。画面直接切到下一张任务卡预览。

### 若采用方案A

```text
世界时刻：T0 → T1（准时）
抵达：准时
部署：近入口
便携地面支撑架：唯一实物暂留装卸台，等待回收；本次不可出击
材料：2 → 1
装卸台：标准增益仍保留，临时支撑在位
物件回执：所有者不变；本地维护员代管；回收工单待办
```

### 若采用方案B

```text
世界时刻：T0 → T2（比准时晚1格）
抵达：晚1格
部署：远入口
便携地面支撑架：仍在出击工具清单中
材料：2 → 2
装卸台：低增益安全模式；运输分两批完成
物件回执：无转移；持有人与位置不变
```

玩家随后点开出击预览，必须真的看见“近／远入口”和“有／无支撑动作”的差异。若下游只保存一个看不见的完成标记，这段调查应当删成演出。

本例指定的下一场是“吊索井停机”，用一个直接可见的空间差把两种价值落实：

- 方案A从近入口开始，离停机面板只有两个区域，可在第二个战场周期前抢到停机窗口；但便携地面支撑架不在队里，无法打开断裂维修栈桥的可选救援站位。
- 方案B从远入口开始，要多走一个战场周期，敌方先封住一段中路；但玩家可以把便携地面支撑架用在断裂栈桥，开出一条可选的维护员撤离线和一处安全身体支点。

这两项必须在后续任务说明里真实改变抵达时间和可用工具；否则“时间换工具”只是纸面账。

## 这段为什么可能成为好调剂

- 问题只有一个，证据只有三条，配置只有三行；
- 玩家观察的是机器人和设施的身体反馈，不是背设定或猜密码；
- 两种做法分别保存时间或工具；
- 猜错会产生能理解的物理反馈和保守后果；
- 十几分钟后，下一场空间与动作立即不同。

它仍可能不好玩。若玩家只是在把三个`可提交`提示拼起来，或第一次学会后每次都照抄同一配置，这套玩法就没有独立价值。

## 哪些内容现在不随它一起批准

- “知识门控遗迹”仍只有唯一作者答案式纸例，暂不算公共玩法成立；
- 校准、证据编排只是这套调查里的步骤，不另包装成小游戏家族；
- 节奏按键／QTE没有证明能产生新判断，默认留给演出；
- 轻探索仍应保留走路、看地标、问人和主动返回，但不能让每段探索都变成“找两条路线证据后报告”。

## 本页先按什么标准自检

- 证据改变的是可承担的配置与不确定区间，不是隐藏答案的开锁数量；
- 两条完成路线分别保存时间和唯一工具，没有一条路线拿走全部好处；
- 首次失败、一次修正和保守离开都有明确的长期`T`、物件位置和安全结论；
- 下一场直接读取入口与工具状态，调查结果不是一枚看不见的完成标记；
- 同类内容以后可以更换物理问题，但不能只把“左／右”改名后重复同一道题。

当前结论只是一份**可供用户裁决的 Candidate 调查／工程实证核心设计**，不是已经批准的公共系统。

## 与总案的关系

本例只放大[核心玩法总案](00c-core-game-design-master-review.md#不打仗时玩什么城市记忆家与关系)的“事实—解释—实体试验”操作，不增加新的评审问题。若它仍像密码题、两案代价不清或失败力度不合适，请直接批注总案的非战棋部分。
