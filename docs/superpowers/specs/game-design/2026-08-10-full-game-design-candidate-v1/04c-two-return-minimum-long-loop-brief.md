# 两次返馆：长线系统最小闭环到底怎么玩

> 当前状态：`Candidate / retired_parallel_walkthrough / derived_from_00b / non_evidence / zero_build / human_not_run`
>
> 这页曾把编队、成长候选、关系、唯一工具、收藏、世界任务和结算压进两次返馆；现在只保留为旧压缩例与差错追踪。当前完整循环、战果与数值只读 [00b唯一公共循环主稿](00b-full-game-common-gameplay-skeleton.md)，Hub与调查分别读`06c/06d`。本文不再作为用户入口、规则输入或玩法证据。

## 一句话

第一次，玩家为了早到而带着临修出发，救到人却丢了样本；没选择的旧中继任务也被别人做掉一半。第二次返馆时，游戏同时拿出“我失败留下的后果”和“别人处理未选任务留下的后果”。玩家再决定：把有限时间花在修复与反制，还是把一次真实行动训练成新协议并修补协作，然后从两张已经变化的任务卡中承担下一件事。

如果第二次返馆仍显示第一次的原始任务、身体自动恢复、关系刷新、工具瞬移回库，这个长线系统就没有成立。

## 全游戏只需要反复使用六种屏幕壳

```text
1. 返馆变化＋日程
→ 2. 任务比较
→ 3. 出发包＋路线
→ 4. 现场玩法
→ 5. 收尾责任抽屉（有需要才出现）
→ 6. 一张综合摘要
→ 再次返馆
```

它们是六种界面职责，不是六个都要很深的玩法。主战术负责主要复杂度；其它屏幕应快、清楚、让后果持续。

## 测试对象

本例只用五名中性人员、三台身体和三件具名工具：

- 岑安：调度员；负责比较路线和整理承诺，不驾驶前线身体；
- 石稜：工程员；可以维修，也可以随工程机出击，但同一时间不能两边都做；
- 闻野：档案员；负责核验来源和未知，不自动知道物件真相；
- 堰立：护卫机“堤”的合法操作者；负责前线护卫，不会因为石稜留馆或随工程机出击而凭空消失；
- 凌越：游击机的合法操作者；负责机动拦截；
- 护卫机“堤”：左臂承力受限，有独立主体回应；
- 游击机：快速换位，压制弹有限；
- 工程机：开门、测试和现场实证；
- 局部扫描器：一件唯一工具，用来缩小现场未知；
- 折叠支撑架（现场也简称便携支撑）：一件唯一工具，只能在一个地点；
- 绝缘跨接头：一件唯一工具，可随队，也可经授权临时留给地方。

世界图最初有两张任务卡：

- `断桥救援`：早到可以调查侧门；晚到仍可救援，但入口更少；
- `旧中继实证`：完整窗口较长；如果玩家不选，具名档案协作组会按自己的能力处理。

## 第一次返馆

### 屏幕1：变化＋日程

玩家看到：

```text
世界时刻 T0
时间格 3｜工作卡 0/3｜维修设备容量 2
材料 2｜资金 3

左臂受限｜停止建议未回应｜旧芯匣未核验｜断桥窗口正在关闭
```

具体拖卡、并行和冲突规则见 [第一次返馆 Hub 短例](06c-first-return-hub-brief.md)。本轮玩家选择“抢时间”：

```text
第1格：临时支架 + 芯匣核验（不同人和房间，并行）
随后：结束排班，进入任务比较
放弃：停止建议、后两格、第三张卡名额
```

结果：`T0→T1`、材料`2→1`、护卫机只有一次条件承接、芯匣可以比对现场频段、关系事项仍未解决。此时只结束了Hub排班；任务、编队、路线和资金尚未提交。

### 屏幕2：先暂选任务，再谈编队

玩家点开两张任务卡并排比较：

```text
断桥救援
抵达：T2（早窗）
已知：三辆维护车、主桥旧损、侧门状态未知
不选：地方救援队能撤人，但无重型身体保护桥面

旧中继实证
抵达：T2
完整窗口：至T5
不选：档案协作组可先停外发，不能进入内层取日志
```

玩家只是点选`断桥救援`作为当前草案。切任务、返回 Hub、查看路线都不走时间，也不写状态。

### 屏幕3：出发包＋路线

默认页不常驻展示六列合规表，只显示三条职责和异常状态：

```text
前线支撑：堰立 / 护卫机“堤” / 左臂临修，只接受条件承接
机动拦截：凌越 / 游击机 / 压制弹3
现场工程：石稜 / 工程机 / 绝缘跨接头
```

全队任务工具区只有两个槽。本轮从`局部扫描器／绝缘跨接头／折叠支撑架`三件中选择`扫描器＋跨接头`，支撑架继续留馆；查看和替换仍是免费草案，最后承担时才锁定位置。

这里不再凭空假定一名未登记操作者。堰立负责护卫机，凌越负责游击机；石稜仍只能在“随工程机出击”和“留馆维修／支援”之间选一个同时职责。玩家可以：

- 让堰立与护卫机负责前线支撑，石稜随工程机出击；
- 让石稜留馆，改用任务现场工程员，但放弃一部分工程动作；
- 更换当前任务草案。

只有出现借用、权利不足、主体拒绝或临时条件时，玩家才展开详细链：人物、机体、主体回应、产权／操作资格、工具和协议。

玩家随后在两条路线里选一条：

- 公共驳船：资金0，T2从南侧统一到场；
- 侧翼吊运：资金1，仍在T2到场，但游击机先从北侧卸载。

本轮选择公共驳船，所以资金仍为3。最后长按一次`承担任务`。这一次才把任务、路线、到达刻度、出发人员、机体状态、唯一工具、权限／同意和资金原子锁定。任何一项版本或位置不合法，整次提交拒绝，不能先扣钱再发现工具不在馆。

### 屏幕4：现场玩法

本轮只使用一个调查／工程实证现场准备位：玩家走到主桥、侧门和维护员旁取得事实，再用跨接头做空载测试，决定直接工程解决还是进入主战术；不另外叠加一段路线探索。其它任务若主要问题是找路线和问人，可以把这一位换成轻探索。

本例故意得到局部失败：

- 三辆维护车中两辆撤离，人员获救，主要任务成立；
- 主桥保持完整通行；
- 猎手带着样本离开；
- 护卫机的临时支架用尽，开场左臂仍受限，本次锚定腿又变为轻度受限；
- 敌人观察到玩家总是让游击机守同一个救援站位。

这不是“胜利评级B”。五条事实分别保存，后来可以由不同系统消费。

### 屏幕5：只处理尚未决定的收尾责任

事实是只读的。玩家不能把“样本已丢”在结算页改成“样本保住”。本例只有一件尚未决定的实物责任需要打开抽屉：

```text
绝缘跨接头
合法所有者：测试馆
当前持有人：出击队
当前位置：侧门

[随队取回]
[经授权借给地方维护组至T7]
```

玩家把“经授权借给地方维护组至T7”放进待提交责任包。此刻只是准备选择：物件所有权、当前持有人、位置和借期都还没有单独改写。收藏／档案页只读实物记录，不能另写一份“它其实在馆内”。

若还有回程路线或公开范围选择，也必须在各自负责抽屉先选好。结算页不突然发明这些问题。

### 屏幕6：一张综合摘要，只按一次继续

```text
本场事实
两车撤离｜桥完整通行｜样本敌持｜左臂旧伤仍在｜锚定腿新增受限

整次任务
人员救援成立｜跨接头借给地方至T7｜立即返馆

资源
材料 1→2（任务交付）｜资金 3→4

持续问题
样本追踪｜敌方观察到旧站位｜停止建议未处理｜正式维修债
```

玩家只可：

- 展开某一条看因果来源；
- 返回修改仍未提交的收尾责任；
- 长按一次`继续`。系统把已发生事实和负责抽屉里已准备的保管／回程责任在同一事务中提交；按下前任一责任仍可返回修改，按下后一起生效。玩家从不“批准事实”，也不会先把某一项责任偷偷存进去。

已经发生的战术事实不能修改。若后台发现事实记录自相矛盾，那是异常恢复／QA问题，不是让玩家扮演数据审计员的正常玩法。

若玩家此时返回负责抽屉、退出或关游戏，系统只保留一份“只读待结算快照”：事实与来源不会丢，已经准备的合法责任选择仍在，但材料、资金、长期时间和物件转移都尚未正式提交。重载回到同一摘要或未完成的负责页；只有最终一次`继续`成功后才整体生效，同一快照不能重复发补给或推进时间。

## 没选的任务没有冻结

这条时间线的三种尺度必须分开：玩家现实中约用45分钟完成这一轮；长期时钟是`T0`开始、Hub第一格后`T1`、最终承担后出程一格于`T2`到场、现场与标准返程合计再走一格于`T3`返馆；战内的8秒语义周期不推进长期`T`格。玩家在T3返馆时，`旧中继实证`已经由档案协作组处理过：

```text
别人做成：关闭外部发射器
别人没做成：没有重型身体，未进入内层取日志
地点变化：北侧通道坍落关闭
剩余问题：从南侧进入，取回内层日志
```

这不是系统随机惩罚，也不是所有未选任务自动最坏。任务卡在第一次出现时就写明执行者是谁、能力到哪一步、可能产生哪种结果带。

## 第二次返馆：必须同时看见两条后果线

### 来自玩家局部失败

- 样本在敌方手里；
- 敌方已经观察旧救援站位；
- 护卫机左臂旧伤仍在，锚定腿新增轻度受限；
- 停止建议仍未谈。

### 来自未选任务

- 旧中继外发已停；
- 内层日志仍在；
- 北路关闭，南路成为新入口。

系统把这些变化合并成少量事项组，不给每条状态各弹一张红点。

## 第二轮的两个长期方案

### 方案A：恢复与反制

```text
第1格：标准维修第1/2格 + 闻野核验假求援波形
第2格：标准维修第2/2格
随后结束排班，进入任务比较
```

得到：护卫机恢复正常承力；敌方假求援有了可识别特征。

付出：材料用尽；停止建议继续延期；没有训练新协议。

### 方案B：发展与协作

玩家把上次成功的“受限左臂条件承接”打开，看到一张**协议候选**，不是自动升级奖励：

```text
来源：断桥救援中的真实承接记录
已有证据：临时支架承力、动作中止点、主体回应
仍缺：一次短训练和明确停止边界
可能得到：以后在相同条件下使用“受限肢体承接”
```

本轮安排：

```text
第1格：处理停止建议 + 闻野核验假求援（不同人和房间，并行）
第2格：按主体回应做低载训练
随后结束排班，进入任务比较
```

得到：若训练和各方回应都通过，形成条件明确的新承接协议；协作边界更清楚；材料保留。

付出：左臂仍未正式修好；完整承力动作仍关闭。它与方案A都在第2格后结束排班，再经过同一套任务暂选、编队／路线草案和`承担任务`提交；本轮取舍故意不靠“谁更早”，而靠“完整机体与反情报”对“条件协议、关系处理与材料保留”。

这里的成长是“把亲手做过的办法，经证据、训练和主体接受变成可复用协议”。公共 Candidate 已把协议写成`候选→训练中→可用→暂停→复验／修订或退休`，同一触发条件只显示一个当前版本，不设任意技能槽；但现在仍只有这一个连续例子，也没有证明上下文筛选、复验负担和成长感，因此不能称完整成长系统。

## 第二次世界图不是把旧卡重新刷出来

此时只突出两张变化后的任务：

```text
追踪敌持样本
已知：敌人学会旧站位，第一次公开Intent可能是诱导
可选路线：免费全队同行 / 资金1的侧翼先遣

旧中继南路取件
已知：外发已停，北路关闭，内层日志仍在
可选方法：身体承力进入 / 保守断电后分段取回
```

玩家点一张作为任务草案，再配置出发包和路线。另一张继续由具名主体处理，不冻结，也不自动恶化到最坏。

## 编队、库存、关系和收藏在这里分别是什么

### 编队

安排的是职责与真实约束，不是挑战力最高者。人物、机体、主体回应、权利、唯一工具和时间位置必须一致。长期“在馆成员”和本次“出击岗位”分开显示。

### 库存

当前 Candidate 明确不做传统大随机装备仓库：机体固有部件留在身体页，通用材料只记数量，玩家只在有限任务工具槽中装载少量具名唯一工具，也没有随机品质、词条、批量分解与筛选。本例暂用“两个全队任务工具槽、扫描器／跨接头／折叠支撑架三选二”验证取舍；槽数与工具总量仍是纸面种子，不代表全游戏平衡已经完成。

### 关系

保存的是“谁对哪次动作提出了什么边界、是否形成具名协议”，不是好感值。协议不能替未来所有动作永久同意；动作或风险范围变化时仍要重新请求。

### 收藏

档案页可以保存来源、解释是否确认、公开层级和展签。实物损伤、位置、保管和借期只从唯一物件记录读取。芯匣目前只到“频段已核验、来源未知”，不能因为入库就解锁完整背景故事。

## 三级结算不是三次奖励页

- **Encounter事实**：后台保存一张地图发生了什么；若Operation继续，只给短摘要和一次继续。
- **Operation结果**：系统依据已发生事实生成并持久化；任务结束时与最后一场摘要合并显示，玩家只按一次继续，不确认或校验事实。
- **Chapter结算**：只有真正章末才单独出现，封存谁留下、物件长期保管、永久地点、关系债务和下一航向。

结算的目标是清楚、快速、不会重复提交。它本身不需要被宣传成“有趣的玩法”。

## 这个最小闭环真正要证明什么

1. 玩家能区分“任务暂选→编队／路线草案→最终承担”，不会在查看时被偷偷收费或锁定；
2. 第一次任务的局部失败和未选任务的他人结果都能在第二次返馆被玩家认出；
3. 至少两种第二轮安排改变身体、信息、关系、时间或工具，而不是只改奖励数字；
4. 唯一物不会复制、瞬移或被收藏页改写产权；
5. 综合摘要只出现一次，玩家只按一次继续；重载不会重复发材料、修机或生成协议；
6. 陌生玩家愿意带着第一轮后果继续第二轮，而不是觉得系统只是在罚他补作业。

在两次返馆的 UI Build 和真人连续试玩完成以前，只能称它为**可读的长线闭环 Candidate**。

## 现在只需要判断五件事

1. 六种复用屏幕是否足够，还是仍显得菜单过多？
2. 第一次“救到人但丢样本”留下第二次不同问题，这种失败续行是否成立？
3. 未选任务由具名主体部分处理，是否比冻结任务或自动最坏更合理？
4. “证据→训练→条件协议”是否值得继续做成长系统，还是仍不够有成长爽感？
5. “不做传统大随机库存，只用数量化材料＋少量具名工具＋有限工具槽”是否比整理装备仓库更符合这款游戏？

你的回答只用于修改 Candidate，不自动批准原型、章节适配、万机馆设定或 Runtime。
