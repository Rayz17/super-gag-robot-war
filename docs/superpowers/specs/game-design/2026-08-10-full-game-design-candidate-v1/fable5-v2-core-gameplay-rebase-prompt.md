你是一名外部游戏总监、战棋／RPG主策划，也是一名诚实的机器人游戏玩家。你可以通过Cursor读取整个项目工作区。

其中04、05出现了真正值得深化的创意，但尚不能直接成为全游戏总案。

本轮不是继续给05增加更多系统，也不是把04、05机械合并进现有`00c`。你的任务是：

1. 承认并纠正上一轮的分析方法和资料使用错误；
2. 对04、05所有主要机制进行保留／重做／合并／删除／暂缓裁决；
3. 在当前项目设定、已验收故事与玩家幻想上，提出**一个**唯一推荐的V2核心玩法方案；
4. 用当前C01、C02、C03和当前C04边界证明它能够适配真实项目，而不是只适配一个C01高潮；
5. 说明角色、机器人、战棋、探索／调查、万机馆生活、修复、关系、收藏和长期成长怎样构成同一款游戏；
6. 明确哪些漂亮概念必须砍掉，防止再次依靠系统数量制造“完整感”。

你可以采用结构重组，甚至放弃04／05的主要骨架并提出自己的玩法；但最终只能给一个主推荐，不得交给用户几套平级概念让用户代替主策筛选。

在裁决04／05之前，先从当前设定、资产与玩家幻想独立推导一套**不使用04／05术语**的核心乐趣模型，再与04／05比较。不要让本任务书列出的旧机制自动成为答案；最终只提交胜出的一个方案。

## 二、必须承认并处理的上一轮错误

以下不是要求你无条件同意的结论，而是必须逐条回应的审查问题。若你不同意，须引用当前有效项目资料和具体规则反证，不能略过。

### 2.1 01–03过早锁定“小修可救”

01准确发现了：

- 现案把责任、许可、因果和失败都做成了系统，却把燃、爽、笑、宿敌、恋爱和被世界承认主要留给剧情演出；
- 胜利经常“只发债、不发糖”；
- 人物容易从有性格的行动者退化成信息源、权限源和菜单席位。

但01随后把“规则独特、主题正确、能够写出一段好战报、文档已经收口”当成“核心玩法已经成立”的证据，并直接选择局部修订。02又先声明主循环、时制、C2、Hub、轻系统和结算全部继承，03则以“已写了很多文档”为理由之一拒绝结构重组。

这属于方法错误：

- 能写出一段精彩战报，不等于玩家形成方案的过程可反复好玩；
- 机制独特，不等于它不是摩擦；
- 文档沉没成本不能成为保留玩法的理由；
- 没有先设计B／C方案，就不能以“没有证据证明替代更好”为由拒绝替代。

因此01可作为问题账，02只可回收局部种子，03当前不可执行。

### 2.2 04有创意，但只是C01主题垂直切片

04真正有价值的突破包括：

- 机器人主动举手提出符合自身性格的办法，玩家接案、补充信息、反提案或提出高代价请求；
- “清噪”不是普通减益，而是敌人剥夺机器人表达和产生名场面的能力；
- 锚件把收藏、理解一台机器、解封绝活和战场高潮连在一起；
- 具名承诺把抽象审批债务转为人物关系与后续行动；
- 玩家幻想从“检查所有手续”转向“编排一群会争取高光的老机器人”。

但04没有证明这些设计能够形成可重复的战术深度：

- 若完整行动已经由机器人提出并预演，玩家可能只是在选择AI给出的正确答案；
- 若“接案”没有冲突和机会成本，就只是逐个批准；
- 若清噪关闭举手机制，最具特色的玩法反而会在压力最大的区域消失；
- 若每场都变成“拆清噪—攒残响—放绝活”，很快会形成固定模板；
- 绝活默认附带永久重伤或长期缺席，可能把爽点变成囤积焦虑；
- “零新增输入”不等于零复杂度；04实际增加了提案、见证、三色残响、绝活条件、承诺、共振等大量新信息；
- 唯一完整例是高度编排的C01高潮，证明了“能演得很酷”，没有证明普通任务存在两种真正成立的玩法方案。

### 2.3 05扩展过快，以栏目齐全代替规则成立

05的强创意包括：

- 敌人学习玩家高频习惯的“收录律”；
- 纪存、七海、白鸢等人的能力会随错误、关系、创伤和成长改变；
- 残响深潜、策展、修复、舰内生活和“UI就是家”的方向；
- 右臂生涯、收藏成为爱的证据、迟到的回答等玩法—情感连接。

但05同时发生了明显膨胀：

- 在04机制之上又增加收录账、双层指令卡、心债、死亡感受计、生活行动点、策展心情、回航港、三工位等；
- “人类角色不是头像，是牌”容易把人物重新做成第二套法术表；
- 所有非战棋产出都必须落到战棋，会把生活、关系与收藏降为战斗增益工厂；
- 心债、死亡感受计等可能把创伤变成可制造、可清空的资源循环；
- 八项玩家幻想“全覆盖”只是映射表，不是玩家体验已经成立的证据；
- 22章一行机制表是创意索引，不是L4逐章玩法已经完成。

### 2.4 05使用了错误的故事基线

05第12、298行以已经退役为History的`C01-C05连续阅读稿-v3.md`为主要来源，导致所谓C02／C03“完整适配”改写了当前已验收故事。

必须纠正的最低事实包括：

- 当前C01为四话；
- 当前C02为已验收五话，不是05所写的四话；
- 当前C03为已验收四话；
- C02不存在05所写的另一套《救命零件》、四台同模可用机、清仓鲸、六展位四话结构；
- C03四台职业机曾被旧程序短暂锁定而失去响应，随后恢复控制，但工作附件被衡令夺走；它们从未作为敌军单位，之后由驾驶组与机体自主决定参战；
- 社勇王第二锤没有因为敌方“学会第一锤”而停下，而是豪司和社勇王在看见会伤及居民与城市后主动停手，改为承托与拆解；

- 当前C04只有E01、E02为当前单话源，下一合法阶段为E03；旧E03、E04与旧Reader均已失效，不能作为Current；
- C05等待C04用户验收，C06以后冻结。不得借本轮玩法设计推进或续写它们。

05的C02／C03部分必须从Current重新设计，不能靠改标题修补。

## 四、本轮设计必须解决的核心问题

### 4.1 明确玩家身份，不再两头含混

04一面说玩家是导览席，一面让纪存坐在该位置。你必须选定并解释：

- 玩家就是纪存；或
- 玩家控制的是以纪存为主视角的团队决策；或
- 玩家是独立存在的万机馆岗位。

若选择第三种，必须说明它为何不夺走纪存、七海、白鸢等既有角色的位置，也不得自行增加可恋爱主角身份。若项目最稳妥的答案是“玩家控制纪存及其团队关系”，应直接说清。

### 4.2 举手制不能让AI替玩家解战棋题

必须明确：

- 玩家始终直接掌握哪些基础动作；
- 机器人只在什么条件下主动提案；
- 每个战术周期出现几条提案、怎样冲突、何时失效；
- 接受、补充信息、反提案和强行请求各自的真实机会成本；
- 玩家如何凭空间、身体、Intent与目标理解获胜，而不是等待正确提案；
- 清噪、失联或拒绝时，核心玩法怎样仍保持项目身份；
- 熟练玩家具体会在哪些判断上变强。

优先检验一种混合结构：

> 移动、朝向、占位、身体动作、保护、承力和反应由玩家直接编排；举手只作为低频、高价值的人格／临机／名场面层。

这只是当前审查推荐，不是必须答案。若你提出更好的结构，可以替换，但必须解决同一问题。

### 4.3 角色不能只是Buff、审批菜单或法术卡

卡片可以是界面，不得成为角色本体。

完整的专属机制样本只要求覆盖纪存、七海、白鸢，以及C02、C03各一名代表人物。其他人物先归纳进驾驶／工程／调查／支援等参与语法；只有持续制造独特玩家判断的人物才应拥有专属机制。对这些代表人物分别说明：

- 他／她独占的信息或视角；
- 玩家因其存在能执行的独特动词；
- 其主动意愿、错误可能、拒绝或限制；
- 与机器人、其他角色和战场状态怎样组合；
- 关系与成长怎样改变玩法，而不是只减冷却或加数值；
- 战场外会主动做什么；
- 该角色不在场时，玩家失去的究竟是什么。

“精神指令”应是人物习惯、价值观和关系的战斗化，不是第二套技能法术表。

### 4.4 收录律必须符合物理和玩家心理

敌人可以不懂行动背后的“为什么”，但仍能观察动作本身。不要再宣称提案、拒绝或后悔后的行动“永不可收录”。

需要设计：

- 标准动作怎样被快速建模；
- 高语境、多主体、临时协作为什么更难被正确泛化；
- 敌人怎样误读、延迟学习或学到不完整用途；
- 玩家怎样看见学习来源并主动误导、变体或拆除反制；
- 如何避免惩罚玩家喜爱某台机、某个绝活或自己练出的熟练打法；
- 收录律在哪些敌系／阶段生效，不能覆盖每一个普通敌人。

### 4.5 残响、清噪、绝活与承诺必须提纯

逐项判断：

- 残响究竟是资源、场面状态、观众／伙伴的见证，还是别的东西；三色是否真的制造不同决策；
- 如何避免玩家为了刷资源而故意在市民或镜头前表演；
- 清噪是否只是特定敌系和章节的玩法，而非每图固定发电机；
- 绝活如何令人期待而不制造永久伤残式囤积焦虑；
- 锚件是否有多条理解与解封路径，而不是收集清单；
- 承诺怎样通过具体玩家行动兑现、违约或重谈，而不是可爱文案和新账目；
- 哪些机制其实在解决同一个问题，应该合并。

### 4.6 非战棋玩法必须自身值得玩

探索、调查、修复、策展、舰内生活、关系和收藏不能全部发展成平级独立系统，也不能只给战棋送Buff。

你必须选择一个主要RPG／万机馆循环。非战棋最多允许两种真正不同的判断语法，例如“观察—组合—验证”与“选择投入—承担机会成本—关系回应”；它们共享Hub节奏与结果状态，但不能只是换皮。说明其余内容是：

- 该循环中的不同情境；
- 低频高光；或
- 纯内容呈现，不另建资源与规则。

至少一个非战棋完整例必须回答：

```text
玩家第一眼看见什么
→ 具体点／拖／选择什么
→ 两种方案各放弃什么
→ 不做或失败会怎样继续
→ 即时反馈是什么
→ 结果改变人物、万机馆、世界或战棋中的哪一项
```

允许某些结果只改变关系、展厅、世界回应或结局，不强制所有生活内容兑换成战斗强度。

### 4.7 玩家幻想必须诚实排序

不要再把L1八项全部标成“全覆盖”。将幻想分为：

- 第一核心幻想：普通会话反复满足；
- 支撑幻想：持续强化核心；
- 低频高潮幻想：形成长期期待；
- 邻接幻想：有价值但不挤占核心循环；
- 本作明确不服务的幻想。

每项都用以下链条验证：

```text
项目作出什么承诺
→ 玩家亲手执行什么动词
→ 游戏怎样立即证明
→ 人物和世界怎样承认由玩家促成
→ 2–3场后怎样变强或改变关系
→ 中后期怎样形成高潮
→ 哪种设计会产生反幻想
```

重点回答：机器人／战棋玩家、角色RPG玩家、收藏修复玩家分别能得到什么；又有哪些传统“刷级、数值碾压、全歼、无限配装”幻想本作不准备满足，以及用什么替代满足。

## 五、复杂度与内容纪律

本轮默认只允许三层**玩家能够理解的前台心智结构**：

1. 一个基础战术循环；
2. 一个角色／机魂人格与高光层；
3. 一个万机馆／长期RPG循环。

三层不是内部子规则数量的机械上限；验收看同屏信息、输入步骤、记忆项和长期状态的总负担。若需要第四层，必须证明前三层无法承载，并明确删除或合并什么。一次完整替代可以整体删除旧机制族，不要求每个子规则逐项一换一。

每个保留或新增机制都必须登记：

- 它制造的有趣判断；
- 出现频率；
- 玩家新增记忆项、前台信息、输入步骤和长期状态；
- 它取代／删除／合并的旧机制；
- 不加它会失去哪项核心幻想；
- 连续十章后怎样保持变化，而不是每章再加一套菜单。

禁止默认新增：

- 新货币；
- 多色能量；
- 技能树；
- 关系数值；
- 日程表；
- 任务等级；
- 可刷创伤／赎罪循环；
- 每章一个独立小游戏；
- 22章各自一套新机制。

若确实需要其中一项，必须在总复杂度上做等量或更大删减。

## 八、评价标准

你的V2方案必须同时经得起六种检查：

1. **一分钟检查**：不看术语，普通玩家能否说出自己刚才做了什么有趣决定？
2. **十局检查**：第十场是否仍在变化，而不是重复“拆装置—攒槽—放绝活”？
3. **玩家作者性检查**：好结果是否来自玩家理解和组合，而不是系统先给出完整正确方案？
4. **情感因果检查**：感动是否来自玩家曾经做过、放弃过、保存过或答应过的事？
5. **项目专属性检查**：去掉本项目角色、机器人身体和万机馆后，机制是否仍只是通用战棋换皮？
6. **复杂度收支检查**：每个新增概念是否删掉、合并或降频了至少一个旧负担？

不得用以下说法代替设计：

- “以后靠UI解决”；
- “以后靠教程解决”；
- “以后做Build／真人测试才知道”；
- “主题独特所以会好玩”；
- “表格全覆盖所以幻想满足”；
- “故事里角色做过，所以玩家也算做过”；
- “已有大量文档，所以不宜重构”。

本轮可以诚实列出未来才可验证的体验假设，但它们不应阻止你先完成核心策划设计。
