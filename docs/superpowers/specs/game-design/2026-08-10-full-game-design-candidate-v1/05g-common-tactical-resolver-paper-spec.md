## 先用一句话说清楚

这里把“根据规则裁定所有同步动作的系统”简称为 **Resolver（战术裁定器）**。它只接受三样东西：

```text
决策周期开始时的真实战场快照
＋已锁定的我方计划
＋只根据上一份合法观察生成的敌方意图
```

它只能输出：

```text
唯一的战场后态（执行后的真相）
＋独立的目标结果
＋可回放的原因日志
```

关卡作者可以定义地图、单体、动作卡和目标，不能写“第6秒必然救到车”或“这一拳必然把敌人推走”作为结果输入。预览和真实执行必须调用同一个 Resolver；它们的差别只能来自玩家当时不知道的真实状态。

## 玩家眼中的一次完整操作

下面只用 P1-B“短同步整队规划”演示界面。A／C／D 会改变“什么时候锁定哪些单体”，但它们必须把已锁定的命令翻译为下面同样的标准计划。

为让这笔账能够手算，本例临时冻结六项局部假设。它们只对这个例子有效，不等于完整地图规则已经冻结：

| 临时假设 | 本例采用的值 |
| --- | --- |
| 维护车移动 | 每`2秒`正交前进一格；遇到不可通行格就等到下一次移动点 |
| 侧门 | 侧门位于“门前格”与“门后格”之间的一条边，不单独占格；工程机邻接控制台；打开动作`4秒`；同刻完成不能倒改同批次跨边检查 |
| 锚机与桥 | 桥开场应力`1`；敌重机已在本支撑带承载区，所以本窗已有占用来源`+1`；锚机已在具名桥墩支撑格并面向来力；`结构承力（TACT_BRACE）`展开`2秒`；锚机质量与姿态稳定合成身体保持`2`，桥墩另给地形支撑`1` |
| 敌重机 | 等待`1秒`，再移动`2秒`，第`3秒`以推进`3`接触锚机 |
| 截击猎手 | 猎手第`3.5秒`进入公开触发区；截击触发后作用`1秒`，效果是写入临时控制态`本周期不可继续移动`并中止它当前的取样通道；该控制态不是身体功能损伤，在周期末自动清除；不造成HP伤害 |
| 本例同刻分层 | 移动到达候选可触发已预留反应；本批次后态应用完毕后，计划中预写且依赖“已经到位”的后续动作可在同一时间戳的`post_batch_start`阶段开始，但不能倒改刚结束的批次。因此猎手第`3.5秒`到位、触发截击并开始`4秒`取样；若不受阻，它会在第`7.5秒`完成。门与车辆通行都是第`4秒`批次前已排定的候选，仍共同读取批次前态 |

周期开始时，玩家看到：

- 侧门边还关着，工程机在控制面板旁；
- 一辆维护车每`2秒`自动前进一格，将在第`4秒`尝试从门前格跨到门后格；
- 主桥应力为`1`；敌重机已在承载区，所以界面预列本窗占用来源`+1`；锚机站在标有“桥墩支撑`+1`”的支撑格，正对敌重机；敌人意图是“先等`1秒`，再推进`2秒`形成接触”；
- 猎手会在第`3.5秒`进入样本通路，并在该批次应用后的接续开始阶段尝试一段`4秒`取样；
- 游击机可预留“猎手在第`6秒`前进入三格触发区就截击”。

玩家做三个操作：

1. 点工程机，点侧门，选`TACT_INTERACT／打开侧门`，时间线显示`0–4秒`占用操作肢；
2. 点锚机，选`结构承力（TACT_BRACE）`，时间线显示`0–2秒`展开支架、`2–8秒`保持承力；
3. 点游击机，在样本西侧画三格触发区，选`TACT_INTERCEPT`，把最晚触发时刻设为第`6秒`。

提交前，界面必须先回答：

```text
工程机：在本例临时假设下可提交；第4秒门才成为“打开”
锚机：在本例临时假设下可提交；第2秒后得到保持2＋桥墩支撑1
游击机：在本例临时假设下可提交；弹药先预留；动作卡写明“命中后中止当前取样通道”
维护车：第4秒会遇到“门同刻完成”，本次跨门边会等待到下一移动点
```

玩家长按`执行这一周期`后，不再接受补命令。

### 这8秒的纸面预期账

| 时刻 | Resolver 从同一前态看到什么 | 在六项临时假设下的预期结果 | 玩家日志 |
| --- | --- | --- | --- |
| `0秒` | 三条我方计划和敌方意图已锁定 | 预留游击机反应槽与1发弹药；暂不实际扣除 | `计划已锁定：0–8秒` |
| `2秒` | 锚机的结构承力展开完成 | 锚机从普通姿态进入结构承力，保持值`2`；桥墩支撑格另给地形支撑`1`；后续离位或转身就失效 | `锚机在桥墩支撑格完成结构承力` |
| `3秒` | 敌重机的进一格与锚机足迹发生接触 | 推进`3` 对保持`2+桥墩支撑1=3`；不位移，记一条本窗重型接触 | `敌重机推进被支撑住：差值0` |
| `3.5秒` | 猎手的移动到达候选穿入截击区 | 移动候选触发已预留截击，弹药在此刻实际`-1`；移动批次应用后，预写的取样段在`post_batch_start`开始，若不受阻会在第`7.5秒`完成 | `猎手进入触发区；截击已触发；取样开始` |
| `4秒` | 侧门完成打开；维护车也在同刻尝试从门前格跨到门后格 | 门在这一批次的前态仍为关闭，所以车留在门前格；批次后门变为打开 | `门已打开；维护车因同刻前态仍关闭而等待` |
| `4.5秒` | 游击机截击作用完成 | 按本例临时动作卡，猎手获得`本周期不可继续移动`控制态，并中止当前取样通道；它的机动身体功能没有降级 | `截击命中：猎手本周期不可继续移动；取样通道中止` |
| `6秒` | 维护车的下一次自动移动到来，前态中门边已打开 | 维护车合法从门前格进入相邻的门后格，没有跳格 | `维护车越过侧门：ETA已更新` |
| `8秒` | 本周期的占用、重型接触和持续承力记录齐全 | 原始新增来源为占用`+1`、重型接触`+1`；本支撑带优先抵消重型接触`-1`，剩余占用`+1`，所以桥应力`1→2`。三项目标仍为进行中 | `桥应力1→2：占用+1；接触+1被结构承力吸收；车已过门；样本仍在地面` |

这个例子只说明：**若上述六项局部假设获选，说明性纸面账应当这样写。** 目前没有程序自动产生这些事件，完整地图也未冻结，所以它既不是合法路线证明，也不是可复算 oracle 或回放证据。

## 玩家实际看见的六步，不是开发日志

这段仍只演示P1-B短同步界面；A／C／D会改变锁定范围和确认时点，但必须复用同一套结果语言。界面固定区分四种状态，不能只靠颜色：

| 状态 | 固定标记 | 能否提交 | 玩家看到的句式 |
| --- | --- | --- | --- |
| 非法 | `× 非法`＋实线叉号 | 否 | `{对象}的{通道／位置／资源}在{时刻}与{另一计划}冲突；取消其中一项，0时间／0消耗。` |
| 确定 | `＝ 确定`＋实线时间点 | 是 | `按当前已知条件，第{时刻}会{结果}，因为{直接原因}。` |
| 有界未知 | `? 未知`＋斜纹时间带 | 是 | `{结果}仍可能为{最好}—{最差}；未知来自{合法来源}。` |
| 规则缺失 | `■ 暂不能计算`＋灰色停止牌 | 否 | `这不是情报未知；当前缺少{规则名}，不能预览或执行。` |

本8秒说明例的六项临时假设全部公开，所以预览必须诚实写`情报未知：无`，不能为了制造悬念虚构黄色区间。玩家依次经历：

1. **周期总览：** 看到`0—8秒`时间尺、门和车的第4秒同刻、桥应力1、敌重机第3秒接触、猎手第3.5秒进入通路，以及三台机的身体通道和资源；此时只写`未安排`，不提前显示作者结局。
2. **工程机：** 点`侧门→打开`，看见操作肢占用`0—4秒`；计划合法，但明确提示`＝确定冲突：第4秒车辆仍按门关闭等待，第6秒才通过`。确定的坏结果不等于非法。
3. **锚机：** 点`结构承力`，看见`0—2秒展开／2—8秒保持`及`身体保持2＋桥墩1＝3；敌推进3，差值0`。
4. **游击机：** 画三格触发区并设最晚第6秒；看见第3.5秒触发、第4.5秒截击完成、弹药只在触发时消耗，以及“中止取样但不造成HP或身体功能损伤”。若又安排反压制，则直接显示`×非法：0—8秒重叠占用武器／反应通道`。
5. **整队检查：** 三行分别汇总门、接触和截击；桥单列`1＋占用1＋接触1－承力吸收1＝2`；只有`非法：无／规则缺失：无`时才能长按执行。
6. **周期结果：** 先列门打开、车第6秒过门、桥`1→2`、样本仍在地面、实际耗弹1和临时控制已清除，再允许展开下面的白话原因。

执行后的首层日志固定为五条：

1. `第2秒锚机完成承力；第3秒推进3对保持2＋支撑1，差值0，所以没有被推开。`
2. `第3.5秒猎手进入预设区域，截击触发，游击机在这一刻实际消耗1发弹药；猎手的取样也在移动后开始。`
3. `第4.5秒截击完成，猎手本周期不能继续移动，刚开始的取样被中止；这不是身体损伤，周期末自动清除。`
4. `门和车辆都在第4秒变化；同刻读取同一前态，所以车辆先等待，到第6秒下一移动点才通过。`
5. `桥开场1，承载占用＋1，重型接触＋1；承力只吸收该重型接触的1点、不能修旧损，所以周期末为2。`

玩家不需要看到Owner名、Hash或事件ID；但每句都必须能点回对应计划、时刻和数值来源。

## Resolver 必须读取的九种记录

| 记录 | 必须存什么 | 绝对不能存什么 |
| --- | --- | --- |
| `BattleSnapshot` | 地图版本、当前时刻、周期、所有单体的基准格／朝向／功能／资源、所有对象状态、目标状态 | 玩家不知道的内容的界面文字，或作者预写的结局 |
| `ObserverProjection` | 观察者、来源、观察时刻、确定事实、仍可能的未知范围 | 开发未完成的规则；缺规则必须停机，不能伪装成迷雾 |
| `PlanBundle` | 调度器、来源快照哈希、本次锁定范围、所有`UnitPlan`、规则版本 | 任何执行后才能知道的后态 |
| `UnitPlan` | 主体、可选等待、路线与终朝向、一个主动作、一个预留反应、安全中止条件 | 第二个免费主动作，或“失败时自动改打别人” |
| `Segment` | 稳定ID、主体、类型、开始／结束时刻、占用的身体通道、目标、开始／维持／完成条件、失效后态 | 只写“成功”而没有条件与时间的片段 |
| `EnemyIntent` | 敌人观察快照哈希、首个成立优先条款、路线、动作、一个公开受阻分支 | 玩家未提交草案、隐藏体力或本窗临时变更的克制目标 |
| `ReactionReservation` | 反应主体、可观测触发句、区域／弧区、最晚时刻、优先级、占用通道、实际效果、未触发结果 | “看见结果后由玩家再决定是否反应” |
| `ResolutionBatch` | 同一时刻、同一前态哈希、候选事件、触发反应、接触组、各 Owner 待合并变化、唯一后态哈希 | 以动画播放顺序当成规则顺序 |
| `TacticalOutcomeDraft` | 独立目标结果、身体功能、位置与地点、实物保管、资源实际消耗、敌方实际观察、撤离状态、原因链 | 章奖励、Hub价格、关系新事件或作者想要的下一场结论 |

存档不应同时保存“基准格”和可自由修改的“全部占位格”两份真值。整副身体占位必须由`body_profile + anchor_cell + facing`唯一派生；否则会出现“坐标说在A，身体列表却占B”的双重真相。

原因日志也不能由关卡作者直接写最终中文。每个语义事件至少输出：

```text
event_id / batch_id / semantic_time_ms
event_code / outcome_code
subject_ref / action_ref / object_ref
cause_event_ids[] / input_terms[] / state_delta
resource_txn{reserved,consumed,released}
expires_at / certainty
unknown_bounds / unknown_source_ref / visibility_scope
cause_group_id / player_template_id / template_args / display_order
```

本例五个固定模板分别是`CLOG_CONTACT_HELD`、`CLOG_INTERCEPT_TRIGGERED`、`CLOG_INTERCEPT_ABORTED_SAMPLE`、`CLOG_DOOR_SAME_BATCH_WAIT`和`CLOG_BRIDGE_STRESS_MERGE`。`display_order`只控制玩家阅读顺序，不能反过来决定同刻规则结果。

一条标准化单体计划在纸面上至少必须能展开为：

```text
unit_plan_id
actor_id
source_snapshot_version
source_truth_hash
wait_condition_or_none
route_segments[{from,to,start,end}]
rotation_segments[{pivot,from_facing,to_facing,start,end,sweep_cells}]
main_action{profile_id,profile_version,target,start,end,channels,start_predicates,maintain_predicates,complete_effect}
reaction_or_none{profile_id,trigger,area_or_arc,latest_time,priority,channels,effect,untriggered_result}
safe_stop{condition,last_legal_state,cancelled_segments}
resource_reservations[{resource_id,amount,spend_at,release_if_not_started}]
```

任何一项在实现时仍是一句自由文字，都不能进入 Build。它必须引用可求值谓词、动作版本或状态机算子。

## 从点击到事件：不能省略的七道门

### 1. 锁定来源快照

计划必须引用它开始时的`snapshot_version + truth_state_hash + observer_projection_hash`。任一版本改变，计划回到编辑态重算，不带着旧预览强行提交。

### 2. 静态校验整条计划

按下列顺序检查，第一个失败项只用于界面定位，不会隐藏后续已知错误：

1. 主体是否在场、可行动且未被别的同范围计划锁定；
2. 路线、足迹、转身扫掠区、门和地形是否在已知前提下合法；
3. 等待＋移动＋转身＋准备＋作用＋收招是否不超过语义周期；
4. 同一身体通道是否被重叠占用；
5. 目标、朝向、射程、视线、工具、弹药、能量、权限和主体回应是否满足动作卡；
6. 反应条件是否可观测，触发后是否仍有时间和合法身体通道；
7. 所有可执行失效分支是否有具名安全停点。

提交前失败时统一`0时间 / 0消耗 / 0世界写入`。队伍级锁定的调度器中，任一单体计划不合法则整包0执行；单体锁定的调度器只拒绝当前锁定范围。

### 3. 把命令编译成时间段，不编译结果

路线生成每格移动段，转身生成扫掠段，动作卡生成准备／作用／收招段，反应生成一个未开始的条件段。编译器只能写：

```text
“锚机在2–4秒尝试从(3,4)+(4,4)向东移一格”
```

不能写：

```text
“锚机在第4秒成功到达(4,4)+(5,4)”
```

“尝试”与“成功”之间的结果必须由后面的占位、接触和状态机决定。

### 4. 从同一前态建立同刻批次

Resolver 按时间向前找最早端点。下列情况只要时刻相同，就进入同一`ResolutionBatch`：

- 移动到达、相反方向的边交换、转身扫掠结束；
- 动作开始、作用完成、维持条件改变；
- 反应条件成立或超过最晚时刻；
- 门、样本、车辆、桥、撤离边界或其它战场对象转态；
- 本周期环境和目标检查点。

批次中每个候选都读同一份`pre_batch_state`。稳定ID只能用来显示日志，不能让较小ID的门“先打开”、再让较大ID的车穿过。

反应触发有一条窄而明确的输入：它可以观察“某条已冻结移动轨迹在本刻提出穿入触发区”这一候选事件，因此能在同刻开始计时。普通批次完整应用后，计划中预写、且开始条件刚由该后态满足的后续段，可以在同一时间戳的`post_batch_start`阶段开始和消耗资源；它不能倒改刚结束的移动、开门、取得或接触批次，也不能在这里补一个未计划的新动作。接触、功能变化、对象取得等更复杂的同刻依赖仍在下方OPEN表中，未定义时必须停机。

批次内部不再由关卡作者自由排序，而只允许下面这一条有向依赖：

```text
B0 冻结同刻候选与pre_batch_state
→ B1 评估已预留反应
→ B2 冻结前态通行／取得／撤离资格
→ B3 解算占位、移动、接触与位移
→ B4 合并功能损伤、维修、控制态与动作中断
→ B5 运行门、车辆、撤离边界、样本和桥的具名对象合并器
→ B6 全Owner一次原子应用
→ B7 只启动编译期已有、且刚满足条件的post_batch_start段
→ B8 重评剩余时间段
→ B9 仅在周期末关闭桥等环境账，再派生独立目标
```

- B0—B5不按事件ID、阵营或动画顺序运行；事件ID只用于日志。
- 依赖只能向右：门打开不能倒改B2的同刻通行，功能变化不能倒改B3已经完成的接触，目标也不能反写世界。
- B4若发现B3后的操作位置已失效，或必需身体通道在同刻失效，就把到期交互改为`ACTION_INTERRUPTED_CHANNEL_LOST`；动作已经开始的资源不返还。
- B7最早只能生成至少`0.5秒`以后完成的已预写片段，不能在同一时刻形成零时长连锁；`8.0秒`末批次禁止B7新开片段。
- 开发缺项使整个批次回滚到`pre_batch_state_hash`；普通的受阻、争夺或中断是合法玩法结果，不回滚。

### 5. 先准备变化，再由状态归属系统合并一次

这里的“状态归属系统（Owner）”是指：某一份真值只能由一个系统负责最终写入。例如位置只能由占位／接触系统写，实物保管只能由实物状态机写；其它动作只能提出变化请求。

| 真值 Owner | 同刻合并规则 |
| --- | --- |
| 位置／朝向 | 由占位与接触 Resolver 从同一前态产生唯一后态；不允许单体自己改坐标 |
| 身体功能 | 同刻指向同一功能的有效下降步数从同一前态累加；先用步数将`正常→受限→失效`，超过失效所需的每一步再让整体结构安全`稳定→危险→必须撤离`下降一态；维修不能抹掉同刻新伤 |
| 资源 | 提交时只预留；动作真正开始时消耗；开始前失效解除预留；开始后失败不返还 |
| 临时控制态 | 由战术控制状态机写入，必须带`expires_at`；本例`本周期不可继续移动`在周期末环境结算后清除，不改变身体功能账 |
| 侧门／设备 | 本批次所有通行检查读前态；完成开启后才对下一批次可通行；同刻又开又损坏则进`damaged_unsafe` |
| 样本／实物 | 从前态枚举合法取得者；准备后态中只剩一个合法取得者才转移；多个并列则保持原位并记录冲突 |
| 桥与地点结构 | 动作完成可立即改旧损；占用、重型接触和持续承力记为本周期来源，只在周期结束按公开公式合并一次 |
| 目标 | 只从已应用的世界后态派生；主、次目标独立记录，不用总分覆盖 |

### 五个对象合并器的最小合同

| 合并器 | 关键输入 | 唯一结果规则 |
| --- | --- | --- |
| `MERGE-DOOR-EDGE-V1` | 门前态、同刻开／关完成、门损伤、跨门移动候选 | 所有跨边移动只读门前态；同刻开门不会放行同刻过门。开启与不安全损伤同刻时变`damaged_unsafe`；合法开关互斥且无既定规则时报`DEV_DOOR_TRANSITION_CONFLICT`。 |
| `MERGE-VEHICLE-ROUTE-V1` | 车辆前态、唯一下一路线边、移动点、B2通行、B3位置、B4控制态 | 每移动点最多提出一步；目标格在前态被占，即使占用者同刻离开也要等待。维修或开门同刻完成不会补造一段免费移动；只有B3真的到达才推进路线索引。 |
| `MERGE-EXIT-BOUNDARY-V1` | 精确边界、已编译跨界移动、B3整副足迹、同刻接触与功能结果 | 同刻攻击／接触先结算；仍完整越界才撤出，并带着同刻伤损。多格身体必须整副足迹跨界；应用后才从场内占位删除，之后未开始的敌段以`TARGET_EXITED`中止。 |
| `MERGE-UNIQUE-SAMPLE-V1` | 样本前态、取得完成候选、B3交互位置、B4操作肢、撤离结果 | 地面样本只有一个在B3后仍邻接且B4后通道有效的取得者时才转移；多人并列保持原位并记`ACQUIRE_CONTESTED`。已有持有者只能用预写交接；同刻刚取得不能再免费越界。持有肢同刻失效则落在最后场内合法格。 |
| `MERGE-BRIDGE-CYCLE-V1` | 周期开始应力、已完成旧损维修、占用来源、重接触来源、唯一支撑带、来源发生时的承力状态 | 普通批次只登记来源，8秒末统一结算。每支撑带“曾占用”最多`+1`，每条重接触`+1`；有效承力每带最多吸收1项，优先最早重接触、无重接触才吸收占用。维修只减前态旧损。同刻重接触用成员集合Hash成组，不按ID挑选。`0–3`完整、`4–5`降级、`6+`坍塌。 |

对象合并器至少输出前后状态、接受／拒绝的候选ID、原因引用和稳定后态。对应的合法玩法原因码包括`WAIT_DOOR_PRESTATE_BLOCKED`、`VEHICLE_WAIT_OCCUPIED_PRESTATE`、`VEHICLE_STOPPED_BY_CONTROL`、`ACTION_INTERRUPTED_CHANNEL_LOST`、`ACQUIRE_CONTESTED`、`EXIT_NOT_FULLY_CROSSED`、`EXIT_BLOCKED_BY_CONTACT`和`TARGET_EXITED`。它们不会回滚批次。

开发错误则统一停机并回滚：`DEV_OBJECT_MERGER_MISSING`、`DEV_OBJECT_STATE_INVALID`、`DEV_OWNER_DELTA_CONFLICT`、`DEV_BATCH_DEPENDENCY_CYCLE`、`DEV_BATCH_BACKEDGE`、`DEV_POST_BATCH_ZERO_DURATION`、`DEV_DOOR_TRANSITION_CONFLICT`、`DEV_VEHICLE_ROUTE_AMBIGUOUS`、`DEV_SAMPLE_CUSTODY_INVALID`、`DEV_BRIDGE_SOURCE_DUPLICATE`、`DEV_SUPPORT_BAND_OVERLAP`、`DEV_WITHDRAW_BOUNDARY_AMBIGUOUS`或`DEV_OBJECTIVE_PREDICATE_MISSING`。

### 6. 原子应用后态，重评剩余时间段

同刻批次要么生成一份完整`post_batch_state`，要么整批回到前态并报告开发缺项。应用以后，所有尚未完成的段只能：

- 按原计划继续；
- 按预写`ABORT`去具名安全停点；
- 因主体已离场或身体通道失效而取消。

不得因为原目标消失而自动改路、改目标或换成另一个免费动作。

### 7. 周期结束时才派生环境、目标和下一份观察

本纸面版本采用闭合终点：恰好第`8.0秒`完成的既有移动、动作和反应先进入最后一个普通批次并生效；随后结算桥等周期环境和阈值，再派生目标与下一份观察。第`8.0秒`不能新开始另一段动作，新的开始统一属于下一周期。

第一张中性图的桥应力 Candidate 公式分两步，避免同一点应力被重复抵消：

```text
原始新增来源
= 本周期承载区曾被占用1/0
  + 本周期同一支撑带的重型接触次数

结构承力吸收来源数
= min(1, 本支撑带的原始新增来源数)

周期末桥应力
= max(0, 完成旧损修复后的应力
          + 原始新增来源
          - 结构承力吸收来源数)
```

每条原始新增来源必须有唯一`source_event_id`并且只归属一条`support_band_id`；支撑带互相重叠却没有唯一归属时地图直接报`DEV_SUPPORT_BAND_OVERLAP`。同一具名支撑带每周期最多把一条尚未被吸收的来源标记为已消费，优先本窗第一条重型接触；没有重型接触时才抵消承载区占用。原因日志必须写出被抵消的具体来源，同一来源不能被两条支撑重复使用。它不会倒过来免费修复开场旧损。当前数字只是`Neutral Candidate seed`。

地图必须把`车辆／重机的承载区`和`工程支撑／服务位`定义为两种可查询区域。锚机在合法服务支撑位不能自己让“修复要求承载区清空”永远失败；如果地图把两者标成同一类且没有明确例外，必须返回`DEV_LOAD_ZONE_AMBIGUOUS`并拒绝启动地图。

## 占位、移动和转身的唯一语义

第一张中性图的语义精度暂定`0.5秒`，只有正交移动，不允许斜走或对角推移。

- **移动段：** 在这一格的移动时间内，旧足迹仍是唯一稳定占位；同时把`旧足迹＋新足迹＋每个身体格跨越的有向边`登记为平移扫掠预约。已知的同阵营计划若与它重叠、且没有预写协力／交接接触，提交前直接拒绝；对立阵营或自主对象的冻结轨迹重叠，以及已声明的协力接触，不会被预约吞掉，而是在到达刻生成接触候选。到达时刻才从同一前态尝试转入新足迹；执行中才出现的新阻挡会使主体留在旧足迹并进入接触／安全中止。
- **边交换：** 两副身体在同一时刻沿相反方向穿过同一条边，必须进入同一接触组，不能互穿。
- **同终点：** 两副身体同时尝试进入重叠足迹，也进接触组。没有具名推拉或承接动作时，双方默认停在旧足迹，不按阵营先后抢格。
- **转身段：** 旧足迹、新足迹和转身过程扫过的所有格共同组成扫掠区。整段期间旧足迹仍是稳定占位；完成刻只有扫掠区仍合法才转成新朝向。
- **动态阻挡：** 已知计划在提交前标红；执行中才由未知或合法反应产生的阻挡，主体留在最后安全足迹，剩余路线按安全中止处理。

## 第一张图只使用的离散接触解算

为了不把原型变成巨型物理模拟，P1 的接触组先限定为正交网格上的离散身体链：

1. 每条主动推、撞、拖或承接边都给出正交方向和公开推进值；
2. 同方向相加，反方向抵消；一个领动动作最多接受两个已验证协力，每个`+1`；
3. 若东西和南北两轴的绝对值相等，本批次不产生对角位移，接触链保持并把`+1`应力写入连接结构；没有连接结构则写入首要受力身体的整体结构安全；
4. 只有一条主轴时，先算`保持能力 = 目标质量档 + 姿态稳定档 + 地形支撑档`，再用`推进压力 - 保持能力`得到差值；公开表中的“身体保持值”是质量与姿态稳定的合计，不得再重复相加；
5. 差值`≤0`：全链保持；差值`=1`：尝试沿主轴将连续阻挡链整体移动一格，并使首要目标失去站稳；差值`≥2`：在上述结果上再让暴露表指定的功能下降一态；
6. 整体移动只在链尾目标格可用时发生。若被结构、另一副身体、地图边界或非线性分叉占位阻断，全链不位移，剩余推进转为公开的结构／身体应力；
7. 这一 P1 规则不解对角、旋转飞出、双向叉形推挤或自由刚体。若中性图产生这些情况，计划必须在提交前拒绝并返回`DEV_CONTACT_TOPOLOGY_UNSUPPORTED`，不得用ID打破对称。

这条有意把首个灰盒限制在玩家能看懂的推挡与承力。后续若需要更复杂的巨构倒伏，应在 P3 为新接触类型建立另一个受控规则版本，而不是让 P1 拥有一个无穷物理沙盒。

## 敌方意图怎样生成，又怎样被玩家利用

每个周期开始时，每个敌人按同一流程工作：

1. 读取上一周期结束时它合法观察到的`EnemyObservationSnapshot`；
2. 从公开优先表自上而下取第一个成立条款；
3. 在该条款允许的具名路线中，先比较能否完成任务目标，再比较到达时间，仍并列则停在原位并记录并列原因，不用实体ID暗选一条；
4. 产生一条路线、一个动作和最多一个公开条件分支；
5. 在本周期锁定。执行中只能沿已登记分支中止、停在安全格或改用预先公开的次路线；
6. 下一周期才用新观察重新计划。

若多条路线真的对任务和时间完全等价，P1 先统一返回`INTENT_ROUTE_TIE_HOLD`。这比藏一条“总是向左”的ID规则更保守，但玩家能够理解并利用。

## 预览和真实执行必须是同一道题

- 对玩家已知的空间、身体、对象与敌方意图，Forecast 将玩家计划送进同一 Resolver，给出唯一结果。
- 对合法未知参数，Forecast 枚举仍合法的有限值，只显示`最好–最差结果带 + 未知来源`。
- 真实执行只是用 truth snapshot 选定该结果带中的一个分支；不另写一套伤害、碰撞或目标公式。
- 如果缺的是动作持续时间、推力、扫掠区、身体暴露、Owner 合并器或继续态，这不是“情报未知”，而是`DEV_RULE_MISSING`；预览和执行都必须停止。

## 十个纸面参考案例

| 案例 | 输入 | 应得结果 | 若得到别的结果，说明哪条坏了 |
| --- | --- | --- | --- |
| `R01` 关门前路线 | 提交时已知路线穿过关闭侧门 | 提交前拒绝；`0时间/0消耗/0写入` | 静态几何校验失效 |
| `R02` 转身扫车 | `1×2`锚机的新足迹为空，但扫掠区在转身段内被维护车占用 | 提交前拒绝，标出冲突格与时刻 | 程序只检查转身终点 |
| `R03` 边交换 | 两副身体同刻反向穿过同一条边 | 进同一接触组；无具名推拉时都停旧格 | 阵营顺序或实体ID在抢先 |
| `R04` 同刻开门与进门 | 门完成打开与车尝试进入是同一时刻 | 车按前态的关门停下；门在批次后打开；下一移动点再进 | 动画或ID顺序改变通行结果 |
| `R05` 同刻取样 | 双方在同一批次完成对地面样本的合法取得 | 若批次准备后两者都仍合法，样本留在地面并记冲突 | 事件列表第一行抢到实物 |
| `R06` 通道重叠 | 游击机同窗持续反压制又预留截击，两者都占武器／反应通道 | 提交前拒绝 | 只加秒数而没有检查机器人身体接口 |
| `R07` 开始前失效 | 工程机等待站稳，最晚`2秒`仍未成立，修复未开始 | 安全中止，工具解除预留且不消耗 | 提交即扣工具或免费改做开门 |
| `R08` 意图不窥探草案 | 只改玩家未提交路线，敌人观察快照不变 | 敌人意图、路线和优先条款哈希不变 | AI读了草案或后台真值 |
| `R09` 桥应力 | 开场`1`；本窗占用`+1`；重接触`+1`；合法承力吸收`-1` | 周期末`2`，且环境只结算一次 | 承力被当成修旧伤，或A/D每激活一次环境多跳一次 |
| `R10` 撤离边界 | 玩家提交`2秒`撤离，边界内已冻结攻击在`1.5秒`完成 | 先应用该攻击，再撤出；边界后不生新意图 | 撤离被当成免费暂停或逃课 |

这十个案例只是未来 Resolver 必须通过的纸面期望结果，不是已运行的测试，也不能因为作者能口算就叫“已复算 oracle”。

## 冻结第一张图以前仍然 OPEN 的八件事

这些缺项不是给读者出的作业，而是策划不能再用自由文字含混过去的待定项。任一项未关闭，都不能说“中性图已经可实现”。

| 项目 | 当前纸面状态 | 还必须补／验证什么 | 未满足时怎样处理 |
| --- | --- | --- | --- |
| `OPEN-FIXTURE-VERSION` | OPEN | 唯一的地图、规则、动作卡和初态版本 | v0.2与v0.3不得混算 |
| `OPEN-EXACT-GEOMETRY` | OPEN | 样本工作位、支撑位、门、压制走廊、转身袋和撤离边界的精确格 | 不运行路线搜索 |
| `OPEN-MOVE-RULER` | PAPER-SPECIFIED | 05e操作合同2已给三种身体的正常／受限移动和转身尺；仍需精确路线与程序验证 | 规则值可审，不能声称路线可达 |

| `OPEN-PLAYER-COPY` | P1-B PAPER-SPECIFIED | 四种显示语言与六步界面已写；A／C／D原生锁定界面及真人冷读仍未验证 | 只能评审P1-B说明例，不声称最终UI可读 |
| `OPEN-CAUSE-LOG` | PAPER-SPECIFIED | 五条模板和事件字段已写；仍需Resolver实际生成并做Full／Skip回放 | 不能把作者手写句子当运行证据 |

关闭这些项只会让纸案达到“可交给实现”的门口；它仍不会自动证明两条战法可达、没有支配解，或真人觉得有趣。

## 有界搜索未来应怎样攻击这张图

获得实现授权且 Resolver 通过基本确定性后，才允许运行这一步。搜索协议先固定：

- 起点是同一`map + ruleset + snapshot + intent`哈希；
- 只枚举操作卡、路线、朝向、反应和中止条件产生的合法计划，不枚举作者结局；
- 只有完整`post_resolve_state_hash`相同的节点可合并，不用总分或“看起来相似”提前删解；
- 四个周期内主目标至少要有两条可达路线，而且首窗身体职责和主路线必须不同；
- 对每个可达后态保留`车辆/桥/样本/身体功能/工具/弹药/撤离`完整向量，再比较是否严格支配；
- 若存在一条合法路线在所有上述轴都不差且至少一轴更好，立即输出`DOMINANT_PLAN_FOUND`，返回地图或规则重设；
- 机器搜索最多只能证明“候选路线可达／存在或没发现支配解”，不能证明真人看得懂、会发现、觉得公平或愿意重玩。

下列任一情况发生就停止进入 C2：

1. 主目标不可达；
2. 只有一条责任链可达；
3. 出现轻松全赢的支配解；
4. 预览与真实解算使用两套公式；
5. 同一计划因动画、帧率、载入顺序或存读档得到不同后态。

## 程序和真人分别还要证明什么

### 未来规则程序门

- 从`BattleSnapshot + PlanBundle + EnemyIntent`生成全部 Segment 与 Event，不读作者结果表；
- 本文十个案例和 [公共解算十四步](data/tactical-resolution-kernel.tsv) 都能由同一规则核重放；
- Full／Skip、30／60／120fps、实体载入顺序与存读档不改语义后态；
- 预览和执行的所有差异都能指向提交时仍未知的真实状态；
- 事件、Owner 合并、目标派生与原因日志可重放到唯一后态哈希。

### 未来真人玩法门

- 冷启动玩家能说出某台机为什么被挡、某辆车为什么等门、桥应力为什么变化；
- 不靠主持人报解，至少两名不同玩家独立发现两种身体职责与路线都不同的方案；
- 玩家觉得敌人按公开意图执行，失败能回追到自己的路线、朝向、身体或反应决定；
- 锚机、游击机和工程机被体验为三副不同的机器人身体，而不是坦克／DPS／治疗数值皮；
- 学会后愿意换一条方案重玩，而不是只想按快进等结果。

这些证据出现前，我们最多只能说：**基础战术的输入、解算责任和停止门已写成纸面规格。**
