# 一次四十五分钟：这款游戏反复在玩什么

> 当前状态：`Candidate / supporting_public_summary / no_independent_review`
>
> 最终策划范围没有缩减；只是纠正交付顺序，先让公共玩法骨架能被你看懂和裁决。下面是目标体验，不是已经运行的游戏，也不会自动授权制作。

如果整款游戏成立，一次普通游玩大致是这样的。

先分清三只钟：这里的“45分钟”是玩家现实中的目标游玩时长；`T0/T1/T2…`是Hub、航行、现场停留与返程使用的长期时间格；战内暂用8秒作为共同语义解算周期，但不会推动长期`T`格。当前主策推荐在这8秒里逐台编辑，再让全队共同执行；逐台行动保留为低负担备选。本例是`T0`返馆、第一格工作后到`T1`、最终承担后出程一格于`T2`到场、现场加标准返程一格于`T3`返馆。

## 0–4分钟：返馆先看上次留下了什么

玩家回到移动据点。屏幕不弹十几条红点，只合成四件真正需要处理的事：

```text
护卫机左臂受限｜样本仍未确认｜一项停止建议没有回应｜两张任务正在变化
本周期：3个时间格｜最多3张工作卡｜材料2｜维修设备容量2
```

它们都来自之前发生过的具体行动，不是每日随机待办。损伤、关系、物件位置和任务时间不会因为返馆自动刷新。

## 4–10分钟：在 Hub 里做少量高价值取舍

玩家把工作卡拖进三段时间。不同人物和房间可以并行，但同一个人、机体、房间或唯一工具不能同时出现在两处。

例如本轮只能在两种安排中选一边：

- **稳妥整备**：用连续两格完成左臂维修；机体恢复完整承力，但更晚处理关系和调查；
- **带债早走**：第一格只装左臂临时箍架，同时让档案员核验样本频段；较早出发，但左臂仍然受限，正式维修债留下。

这不是“攻击＋5%”与“防御＋5%”。玩家决定的是谁把时间花在哪里、哪种身体功能可用、什么问题继续拖欠。

## 10–14分钟：先暂选任务，再编排完整出发包

世界图同时显示两张会继续变化的任务卡：

```text
裂损桥救援
早到：仍能调查侧门
晚到：入口减少，但救援不会凭空消失
不选择：地方队能撤人，缺少重型身体保护桥面

旧中继实证
需要：工程验证或重型身体
不选择：档案组会先停外发，但无法取得内层日志
```

点任务只是查看草案，不扣时间。随后玩家安排：谁去、哪台机体去、谁操作、主体是否接受、带哪件唯一工具、走哪条路线。只有长按一次“承担任务”，这些内容才一起锁定；任何一项不合法，整包拒绝，不会先扣资源再报错。

## 14–22分钟：用短调查改变现场条件

到达后，玩家不是先看剧情再领固定加成，而是亲手检查三类证据：现场痕迹、仪表测量、本地人员或机器反馈。

例如玩家发现侧门的机械锁完好，真正的问题是远端供能已经断开。玩家用绝缘跨接头在本地控制盒做一次空载试验，确认门可以低风险开启。随后可以：

- 等待压力下降一个长期时间格，把跨接头留给地方队，由他们按保守程序安全绕行；代价是样本随敌方离开、另一项任务窗口继续缩短；
- 带着跨接头立刻进入战术，在战场上开门并争夺样本；代价是机器人身体、桥和车辆真正进入风险。

证据不会自动替玩家选答案。它只把“侧门能否本地开启”从推测变成已验证条件，并把工具、时间和人物回应写入下一段。

## 22–40分钟：机器人战术承担主要深度

进入战场后，玩家先看任务对象、敌方意图、地形和每台机体当前还能使用的身体功能。一次决策通常是：

```text
看敌人准备做什么
→ 给机体画短路线并定朝向
→ 选一个主要身体动作
→ 决定是否预留保护／截击／中止
→ 看确定结果和未知来源
→ 执行本周期，观看这一小段共同发生
```

首个中性题面是：三辆维护车至少撤出两辆，同时决定要不要保住主桥完整度和中央样本。锚机用两格身体承力，游击机换位截击，工程机在修桥、开门和处理样本之间争夺时间。乐趣应来自身体怎样占据并改变空间，而不是刷等级后清光敌人。

上一版只有作者写好的两条结果账，中段决策偏少，已经明确否决。当前纸面修订改为四窗责任阶梯：先分配承力／掩护／压制／截击，再处理停驶车与样本，最后决定是否用持久身体伤损换更好结果。本轮先据此评审“每一轮是否有新判断、两条责任路线是否值得选”，详见[基础主战棋完整例 v0.3](05f-first-neutral-tactics-v0.3-decision-ladder.md)；唯一总案仍是[00c](00c-core-game-design-master-review.md)。

## 40–42分钟：只看一次任务摘要

已经发生的事实不可在结算页重选：

```text
维护车撤出2/3｜主桥保持完整通行｜样本被敌方带走｜开场左臂旧伤仍在｜本次锚定腿新增轻度受限｜敌方记住游击机惯用站位
```

如果还有“把唯一工具带回还是经授权暂借地方”这种尚未决定的责任，先在对应小抽屉处理。随后综合摘要只按一次“继续”。一场地图、整次任务和真正章末分别保存事实，但不做三次重复奖励页。

## 42–45分钟：返馆时世界必须已经不同

再次返馆后，玩家会同时看见：

- 我方失败留下的样本追踪、机体伤损和敌方学习；
- 没有选择的旧中继任务被别人处理到哪一步；
- 一次真实承接动作是否具备“证据＋训练＋主体同意”，可以发展成条件协议；
- 某件物品现在由谁保管、是否能展陈、还有哪些来源未知。

于是下一轮不是重复清单，而是在变化后的任务、身体、关系和物件上继续选择。

## 这套游戏只有三个产品支柱

1. **主战术有深度**：机器人身体、朝向、地形、反应、功能损伤和非歼灭目标本身成立；主角能力以后只改变信息、提案、许可、验证和同意。
2. **长线轻而具体**：返馆只处理少量高价值事项；成长主要增加新动作、协议、岗位、路线和理解，不要求刷级或整理大量随机装备。
3. **故事后果由玩法制造**：成功和失败分别写清，后续人物、地点、敌人和任务真实回应，不用一句台词假装已经消费。

## 十一个公共系统不是十一个每天都要打开的菜单

它们围绕同一批人物、机体、地点和物件工作。本轮没有产生相关变化的系统可以完全不出现。

| 公共系统 | 玩家真正做什么 | 本例中的一次具体犹豫 | 结果必须在哪里再次看见 |
| --- | --- | --- | --- |
| 主战术 | 逐台画短路线、定朝向、选身体动作和预留反应，再执行一个短全队周期 | 锚机继续承力保桥，还是转身保护撤离路线 | 车辆、桥、样本和具名功能伤损 |
| 轻探索 | 走到地标旁观察、询问、记录，然后主动返回行动点 | 先查侧门取得另一入口，还是立刻进战保住时间 | 战场入口、已知信息和本地人物回应 |
| 调查／工程实证 | 比较三类证据、提出候选解释、配置一次安全试验；局部供电、承力或时序题只能作为这套操作的微型变体 | 等一格让地方队用跨接头安全绕行，还是带着它立刻进战开门 | 下一场的部署入口和可用工程动作 |
| Hub | 在三个时间格内最多提交三张高价值工作卡；不冲突的工作可同格并行 | 临修并早走，还是花连续时间彻修并处理关系 | 出发时间、身体功能、未解决分歧和库存 |
| 编队／出发包 | 读取世界图暂选任务，再分配人员、机体、主体回应、权利、工具和路线，最后一次承担 | 带债早走，还是先用两格修完护卫机再晚出发 | 本次能用的职责、到达时点和被延期事项 |
| 成长 | 把真实做过的办法经证据与训练写成身体可行范围；关系页再单独记录主体是否愿意及停止条件 | 彻底修好旧功能，还是保留伤损并验证受限条件下的新承接 | 下一次出现“可提议”的身体用法、适用条件和停止边界；当次仍需回应 |
| 关系 | 回应一个具名分歧，谈清谁能请求、停止或拒绝什么 | 高风险动作等中央二次确认，还是允许现场自主中止 | 具体协作协议、拒绝理由和未来事件，不是好感数 |
| 收藏／图鉴 | 整理来源、已确认解释、公开范围与展签；实物位置只读保管记录 | 公开一条已验证结论，还是保留仍会误导人的候选解释 | 展陈、人物反应、调查入口；不能借收藏页改所有权 |
| 世界图 | 比较少量会变化的任务卡、时窗、路线与未选后果 | 选一项请求时，接受另一项由具名主体部分处理 | 下一轮任务状态、世界时间和具名外部行动结果 |
| 库存与经济 | 管数量化普通材料、运营资金和少量不能复制的具名任务工具；机体固有部件不进仓库 | 两个任务工具槽里带扫描器与跨接头，还是用便携地面支撑架替换其中一件 | 后续可用动作、工具位置／状态、借期和资源账 |
| 三级结算 | 展开地图、任务与真正章末的因果；只在负责页准备尚未决定的责任，最后按一次继续 | 已发生的救援、失物和伤损不能重选；只决定跨接头随队带回，还是获授权后暂借地方维护组 | 机体、地点、任务、关系、唯一物和下一轮入口 |

如果某一行只能写出“进入系统”“获得奖励”，却说不出具体输入、互斥和后续消费者，它仍只是名词，不能进入这套公共玩法骨架。

这里固定采用上表的十一个公共系统。**微型谜题不是第十二个系统，也不是已经成立的小游戏家族**：它只能复用调查／工程实证的观察、连结、配置和试验输入，用一个局部物理问题改变门、供电、危险区或撤离线。若以后需要节奏按键、密码或另一套专用操作，必须作为新的 Candidate 单独说明，不能借“微型谜题”四个字自动进入公共骨架。

这份短稿省略细节，但不省略四条范围承诺：返馆首页最多激活4张后果卡，其余事实进入只读记录；3–5分钟馆内小活动占1张工作卡和1个时间格，不耗材料／资金，跳过也没有惩罚或红点；规划辅助和无障碍只减少解释、记忆、输入与检查点负担，不改事实、权限、主体回应或故事资格；新地点、机器人和界面优先复用地点套件、身体家族和固定顶层页面，章内奇观不自动注册新系统。

## 本轮先审什么，后面再做什么

现在不要求一次批准整套游戏。核心策划的评审顺序是：

1. **先判断产品骨架**：主战术承担深度，返馆、探索和调查负责换节奏，失败留下后果继续。
2. **再判断主战棋**：身体、空间、Intent、反应、非歼灭目标和两种责任路线是否构成足够清楚的核心玩法；主策推荐的短全队协同是否比逐台行动备选更像本作。
3. **再判断轻系统**：Hub、探索、调查、成长、关系、收藏、世界图和结算是否都在改变下一段，而不是多开菜单。
4. **再判断角色协作层**：主角团是否通过信息、提案、核验、许可、同意和工程验证改变战术，而不是变成增伤按钮。
5. **最后看全剧演进**：公共机制怎样逐步加入、组合和被反制；随后才回到跨章共用设定、C01–C03适配和逐章设计。

本轮意见先用于收束或返修 Candidate。以后是否进入灰盒、程序实现和真人测试，另行决定；不能用后续剧情、角色技能或资产规模掩盖当前说不清的玩法。

## 以后进入制作时才验证的体验假设

下面这些问题很重要，但**不阻塞本轮核心策划评审**：

- 第一张战术图是否真的有连续四轮值得思考的选择；
- 是否存在两种合法且互不支配的战法；
- 短全队协同的最终秒数、动作成本、镜头、按键和舒适度是否合适；
- Hub、调查和长线回写在实际操作中是否轻松而不是做表；
- 主角团 C2 层是否增强角色身份，而不是变成多层审批菜单。

它们以后要靠实现与试玩回答，文档和脚本 PASS 都不能代替。本轮只先判断：设计目标是否正确、操作是否说得通、取舍是否值得继续细化。
