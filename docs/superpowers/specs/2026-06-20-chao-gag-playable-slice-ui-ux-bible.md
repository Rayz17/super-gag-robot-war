# 《超GAG机器人大战：万机残响》Playable Slice UI/UX Bible v0.1

## 0. 目的

当前 demo 的主要问题不是“功能不存在”，而是：

- 玩家动线不清楚：不知道自己是谁、在哪、为什么要点、下一步要去哪。
- 界面层级不清楚：地图、目标、角色、指令、反馈互相抢视线。
- 美术资源缺席：程序图形只能证明规则，不能支撑付费游戏第一印象。
- 四种交互割裂：管理、对话、探索、战斗都能跑，但还不像同一个游戏。

本 Bible 的目标是定义一个 15-20 分钟 playable slice 的体验标准。后续所有 demo 改动、美术生成、资源接入和测试验收，都以本文为准。

## 1. 体验定位

### 1.1 参考组合

不是复刻 SRW，也不是网页化战棋。

本作 playable slice 的体验目标是：

- Wargroove 的像素战棋完成度：清晰 tilemap、可爱但有辨识度的单位、紧凑 HUD、剧情与战斗衔接。
- Into the Breach 的信息清晰度：敌意图可见、后果预测明确、目标保护有压力。
- SRW 的角色与机体爽点：驾驶员/机体组合、精神/气力、援护、特殊交战台词、cut-in。
- 《超GAG》的破次元壁梗：法务封印线、民间叫法、模型件、监督/预算梗、万机馆档案。

### 1.2 一句话体验

玩家在一座即将被“法务封存”的机器人博物馆里，整备临时机体、听见角色争执、亲自调查展厅，最后用清晰可预判的战棋行动阻止敌人清除一面留言墙。

### 1.3 第一版画面目标

第一版不要追求精美立绘和复杂动画，先追求：

- 一眼像游戏。
- 一眼知道当前目标。
- 一眼看懂敌人下回合要干什么。
- 一眼看出不同单位的作用。
- 每个确认动作都有反馈。

## 2. 玩家动线

### 2.1 首次进入 30 秒

玩家打开 demo 后，不应该看到说明页，也不应该看到纯剧情文本。首屏必须是“移动格纳库”，并明确给出三个信息：

1. 这里是万机馆的临时出击区。
2. 你手上有一支四人小队。
3. 现在要整备并出击“法务警报”。

首屏默认焦点停在“出击 法务警报”，但“整备 豪司”要视觉上很诱人，让玩家自然按下去看看。

首屏动线：

```text
打开 demo
  -> 移动格纳库
  -> 看到四台机体与资源
  -> 可选：整备豪司
  -> 出击法务警报
  -> 战前对话
```

### 2.2 完整 playable slice 动线

```text
管理：移动格纳库
  -> 玩家整备/查看队伍
  -> 出击确认

对话：法务警报
  -> 七海远程通告
  -> 纪存坚持先救人
  -> 兜灯指出火警与封存系统冲突
  -> 豪司给出热血反应
  -> 系统给探索目标

探索：万机馆前厅
  -> 玩家移动角色
  -> 调查留言墙：建立情感目标
  -> 调查0号侧廊：建立世界谜团
  -> 调查馆守Z胸牌：建立机魂伏笔
  -> 调查法务封存线：触发战斗

战斗：留言墙防卫
  -> 玩家看到敌意图
  -> 选豪司移动
  -> 攻击前看到预测
  -> 确认攻击
  -> cut-in
  -> 敌意图解除

结算：闭馆记录
  -> 回到管理
  -> 显示本次保住了什么
  -> 解锁机魂档案001
```

### 2.3 每个模式的玩家问题

每个界面都必须回答玩家脑内的四个问题：

| 模式 | 我是谁 | 我在哪 | 我要做什么 | 做了有什么后果 |
| --- | --- | --- | --- | --- |
| 管理 | 万机馆临时指挥者 | 移动格纳库 | 整备队伍并出击 | 改变单位状态、进入任务 |
| 对话 | 旁观/推进剧情的玩家 | 万机馆通信/前厅 | 理解冲突和任务 | 解锁探索目标 |
| 探索 | 操控纪存 | 万机馆前厅 | 调查关键物件 | 解锁档案/触发战斗 |
| 战斗 | 指挥小队 | 战棋地图 | 阻止敌意图 | 保护留言墙/解锁闭馆记录 |

## 3. 全局交互原则

### 3.1 永远有焦点

键盘/手柄式游戏必须永远有明确焦点：

- 管理：当前菜单项有高亮边框和左侧焦点条。
- 对话：当前台词框是焦点。
- 探索：玩家角色所在格是焦点。
- 战斗：战棋光标所在格是焦点。
- 预测：确认按钮/返回提示是焦点。

鼠标可以存在，但不能成为唯一交互方式。

### 3.2 永远有目标

屏幕顶部或右侧必须有一句短目标，不超过 18 个汉字：

- 管理：整备出击队伍。
- 对话：听取法务警报。
- 探索：调查前厅物件。
- 战斗：阻止封存线清除留言墙。
- 预测：确认是否解除敌意图。

不要在主界面放长说明。长说明进入 tooltip、档案或对象调查文本。

### 3.3 预览、承诺、反馈

所有关键动作都必须遵守：

```text
预览 -> 承诺 -> 反馈
```

例子：

- 管理装备零件：预览效果 -> 确认装备 -> 资源变化/单位卡变绿。
- 探索调查物件：站到物件格 -> 按确认 -> 台词/档案解锁/目标变化。
- 战斗攻击：目标 hover -> forecast -> cut-in/地图结果。

### 3.4 不把说明写成 UI

UI 不应该像说明文档。能用图形表达的不用文字：

- 敌意图用箭头和目标高亮，不只写“敌方意图”。
- 移动范围用格子色，不只写“绿色格可移动”。
- 单位状态用 HP/EN 条，不只写数值。
- 当前模式用色彩和布局变化，不只写模式名。

## 4. 四态界面企划

## 4.1 管理：移动格纳库

### 目标

让玩家在任务前认识主角团和机体定位，并完成一个有意义的小整备。

### 布局

```text
┌──────────────────────────────────────────────┐
│ 标题 / 当前模式 / 短目标                      │
├──────────────────────┬───────────────────────┤
│ 队伍区                │ 指令区                 │
│ 纪存  兜灯            │ > 出击 法务警报         │
│ 豪司  唐胶            │   整备 豪司             │
│ 每张卡：头像/机体/定位 │   查看档案             │
├──────────────────────┴───────────────────────┤
│ 资源条：制作费 / 修理材 / 机魂样本             │
│ 底部提示                                      │
└──────────────────────────────────────────────┘
```

### 必须改进

- 四张单位卡要有角色头像/SD机体小图，而不是相同机器人图标。
- “整备 豪司”必须显示装备前后变化：民间叫法扩音器、制作费 -1、封印抗性 +1。
- 如果玩家直接出击，也可以进入剧情，但战斗中“封印”预测会提醒装备不足。

### 美术需求

- 格纳库背景：暗色机库、维修灯、货架、半透明屏幕。
- 单位小卡：每人头像 96x96、机体 SD 64x64。
- UI skin：金属边框、黄/青高亮、焦点条。

## 4.2 对话：法务警报

### 目标

用短而有角色味的台词交代冲突，不把设定解释成旁白。

### 布局

```text
┌──────────────────────────────────────────────┐
│ 模式：对话 / 目标：听取法务警报               │
├──────────────┬───────────────────────────────┤
│ 角色头像/半身 │ 背景：万机馆前厅/通信屏         │
│              │ 角色名牌 / 身份                 │
├──────────────┴───────────────────────────────┤
│ 台词框：两行以内，支持确认推进                 │
└──────────────────────────────────────────────┘
```

### 台词原则

- 七海：礼貌、冰冷、法务措辞里带威胁。
- 纪存：克制、具体，先关心人和物。
- 兜灯：技术视角，话短但能指出真实危险。
- 豪司：热血但不要傻，像把复杂事简化成行动的人。

### 必须改进

- 对话背景必须有场景图，不能是抽象矩形。
- 角色头像要有明显差异。
- 每段对话最多 2 行，避免文字墙。
- 对话结束时出现探索目标弹层：调查留言墙 / 0号侧廊 / 馆守Z胸牌。

### 美术需求

- 前厅背景 1280x720。
- 通信屏 overlay。
- 角色头像或半身：纪存、兜灯、豪司、七海。

## 4.3 探索：万机馆前厅

### 目标

让玩家在小地图里主动建立空间关系和情感目标。

### 布局

```text
┌──────────────────────────────────────────────┐
│ 模式：探索 / 目标：调查前厅物件               │
├────────────────────────┬─────────────────────┤
│ 可移动小地图            │ 调查面板             │
│ 玩家角色                │ 当前物件名           │
│ 留言墙/0号/胸牌/档案/封存│ 调查文本/档案解锁     │
├────────────────────────┴─────────────────────┤
│ 底部提示                                      │
└──────────────────────────────────────────────┘
```

### 探索对象

| 对象 | 作用 | 反馈 |
| --- | --- | --- |
| 留言墙 | 情感目标 | 解锁档案，说明为什么要保护 |
| 0号侧廊 | 世界谜团 | 提示门后有“不该移动的东西” |
| 馆守Z胸牌 | 机魂伏笔 | 提示机器在“假装没听见” |
| 档案柜 | 设定奖励 | 解锁旧导览册/设计图 |
| 法务封存线 | 战斗触发 | 白线爬向留言墙，进入战斗 |

### 必须改进

- 探索地图不能只是战斗地图缩小版，要有博物馆前厅视觉。
- 调查对象要有 icon/小物件图。
- 触发战斗前要有 1-2 秒危险反馈：封存线闪烁、目标格变红、音效。

### 美术需求

- 前厅 tile set：地砖、展柜、灯、留言墙、侧廊门、档案柜、封存线。
- 玩家探索角色 sprite：纪存 32x32/48x48。
- 物件 icon：留言、0号、胸牌、档案、封存。

## 4.4 战斗：留言墙防卫

### 目标

用一场小战斗展示本作核心：看懂敌意图，使用机体能力解除风险。

### 布局

```text
┌──────────────────────────────────────────────┐
│ 模式：战斗 / 目标：阻止封存线清除留言墙       │
├────────────────────────┬─────────────────────┤
│ 战棋地图                │ 战术 HUD             │
│ 单位/地形/敌意图箭头     │ 目标/当前格/单位状态  │
│ 移动范围/攻击范围        │ 指令菜单/武器信息     │
├────────────────────────┴─────────────────────┤
│ 底部短提示 / 当前动作反馈                     │
└──────────────────────────────────────────────┘
```

### 战斗目标

- 胜利：击破法务无人机A，解除封存意图。
- 失败：留言墙被拆除。
- 隐藏目标：豪司装备民间叫法扩音器并击破无人机，解锁机魂档案001。

### 敌意图

敌意图必须在地图上可见：

- 法务无人机A：封印豪司武器。
- 封存框体：拆除留言墙。
- 法务无人机B：扫描最近我方单位。

表现：

- 箭头从敌人指向目标。
- 箭头标签显示动词：封印 / 拆除 / 扫描。
- 目标格高亮。
- forecast 中说明“击破此敌人会解除 X 意图”。

### 单位定位

| 单位 | 定位 | 必须有的可读性 |
| --- | --- | --- |
| 纪存 / 策展指挥机 | 指挥/解封 | 中性色，带指挥天线 |
| 兜灯 / 工具支援机 | 支援/维修 | 绿色，工具臂 |
| 豪司 / 勇拳试作机 | 超级系近战 | 橙/红，拳头大 |
| 唐胶 / 拼装陷阱机 | 地形控制 | 蓝，背包/胶带 |
| 法务无人机 | 封印/扫描 | 红白，单眼扫描器 |
| 封存框体 | 目标破坏 | 箱形/夹臂 |

### 战斗预测

预测窗口必须回答：

- 我方用什么武器。
- 预计造成多少伤害。
- 命中率。
- 敌方是否反击。
- 目标 HP 变化。
- 此行动是否解除敌意图。

最重要的信息顺序：

```text
1. 会不会解除当前威胁
2. 目标会不会被击破
3. 我方会不会吃反击
4. 消耗是什么
```

## 5. Cut-in 企划

### 目标

低成本但有“确认攻击后爆发”的仪式感。

### 普通攻击 cut-in

用于本轮 demo：

```text
地图暗下
  -> 攻击者大 pose 滑入
  -> 敌方剪影/无人机滑入
  -> 武器名大字
  -> 速度线/闪白
  -> DAMAGE
  -> 回地图/闭馆记录
```

### 美术需求

- 豪司大 pose：正面偏 3/4，拳头前伸。
- 法务无人机受击图。
- 速度线背景。
- 武器名字体/牌匾。

## 6. 视觉风格

### 6.1 画面关键词

- 像素战棋。
- 博物馆夜间闭馆。
- 维修灯、扫描线、封存白线。
- 机器人玩具与真实机甲之间的暧昧比例。
- 不要赛博霓虹过度，不要网页后台感。

### 6.2 色彩

主色：

- 深蓝黑：背景和 UI 底。
- 暖黄：焦点、档案、重要提示。
- 青蓝：系统、科技、可调查。
- 绿色：我方/支援。
- 红橙：敌方/危险。
- 紫：0号侧廊/异常。

比例：

- 深色背景 60%。
- 地图与单位 25%。
- 高亮色 10%。
- 危险/特殊 5%。

### 6.3 字体

当前可先用系统黑体，但字号必须分层：

- 大标题：28-34px。
- 模式/面板标题：20-24px。
- 正文：15-18px。
- tooltip/底部提示：13-14px。

不要把卡片内文字做成 hero 字号。

### 6.4 UI 皮肤

第一批 UI 资源需要：

- 面板 9-slice：深底、细亮边。
- 焦点框：黄/青两套。
- 按钮焦点条。
- HP/EN 条。
- 敌意图箭头：封印/拆除/扫描三套。
- 目标格高亮。
- 预测窗口边框。

## 8. 生成图像提示词标准

### 8.1 总原则

生成图像要服务游戏，不要生成插画海报。

要求：

- 清晰轮廓。
- 可缩小阅读。
- 统一视角。
- 避免复杂背景噪声。
- 避免真实 IP 特征。
- 不要出现文字，文字由游戏 UI 绘制。

### 8.2 头像提示词模板

```text
pixel art inspired anime game portrait, original character, [角色描述],
clean silhouette, expressive face, dark museum emergency lighting,
limited color palette, 512x512, transparent or simple dark background,
no text, no logo, no copyrighted character resemblance
```

### 8.3 SD 单位提示词模板

```text
small pixel art tactical RPG mecha unit sprite, original robot design,
super deformed proportions, readable at 64x64, [机体特征],
front three-quarter view, strong silhouette, limited palette,
transparent background, no text, no logo, no copyrighted mecha resemblance
```

### 8.4 场景提示词模板

```text
pixel art tactical RPG museum hangar interior, night emergency lighting,
robot exhibition hall, display cases, maintenance lamps, taped warning lines,
top-down/isometric readable game background, tileable elements,
dark blue black palette with warm yellow highlights,
no text, no logo, no copyrighted robots
```

## 9. Phaser 接入标准

### 9.1 资源结构

```text
demo/chapter1/assets/
  backgrounds/
  portraits/
  units/
  tiles/
  ui/
  fx/
  manifest.json
```

### 9.2 渲染原则

- Phaser 负责所有游戏 UI，不再靠 HTML。
- 资源通过 manifest 加载，不在代码里散落路径。
- 程序绘制只保留 debug/占位，不作为最终视觉。
- 每个资源都要能缺省回退到程序占位，保证 demo 不空白。

### 9.3 验证

每次接资源后必须检查：

- 首屏是否非空。
- 角色头像是否加载。
- tilemap 是否没有拉伸模糊。
- 单位是否能在 64x64 下识别。
- 敌意图是否盖住但不遮挡单位。
- forecast 是否在小屏下不溢出。

## 11. 验收清单

### 体验

- 玩家 30 秒内知道“我要出击法务警报”。
- 玩家能自发完成：整备 -> 出击 -> 对话 -> 探索 -> 战斗。
- 玩家进入战斗后能看懂至少一个敌意图。
- 玩家攻击前知道这一击会解除什么风险。

### 视觉

- 首屏不像网页后台。
- 战斗画面像像素战棋。
- 单位不是色块。
- 地图不是纯网格。
- 对话有角色头像和场景。

### 技术

- `npm test` 通过。
- 浏览器控制台无 error/warning。
- 无 HTML 操作说明条。
- Canvas 首屏非空。

## 12. 当前 demo 与目标差距

当前已有：

- 四态流程。
- 战斗预测。
- 地图敌意图。
- 程序生成的 tile/sprite 占位。

当前缺失：

- 真正美术资产。
- 明确首屏叙事引导。
- 管理界面角色差异。
- 对话情绪画面。
- 探索触发战斗前的危险演出。
- 战斗 HUD 仍文字过多。
- cut-in 仍像占位动画。

下一步必须先补资产，再调界面。继续只用程序图形微调，收益会很低。
