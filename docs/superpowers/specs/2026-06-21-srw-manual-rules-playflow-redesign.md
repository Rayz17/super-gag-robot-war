# 《超GAG机器人大战》SRW手册规则与玩法流程修订 v0.1

> 资料源：
> - 官方《超级机器人大战30》Steam版在线手册：`https://srw30-thirty.suparobo.jp/manual/steam/`，重点阅读第5、12-20页。
> - 官方《超级机器人大战Y》SYSTEM页：`https://34.suparobo.jp/system/`。
> - 本项目本地影像研究：`docs/superpowers/specs/2026-06-21-srw-y-opening-episode01-video-comparison.md`。

## 1. 这次必须修正的误区

当前 demo 的问题不是“缺少更多数值”，而是基础交互语法没有站稳：

- 单位行动没有被正确锁定，移动后还能重复移动。
- “结束阶段”混在单位命令里，导致单位命令和全体菜单混淆。
- 菜单直接遮住战术地图，玩家看不清地形、单位和意图线。
- 只有战斗地图对白，没有清楚区分 ADV 剧情、探索对白、地图态剧情、战斗事件对白。
- 玩法企划仍像流程页面，而不是一话 SRPG 的可操作体验。

这份修订的目的，是先把 SRW 的底层语法翻译成《超GAG》的可执行规则。

## 2. 官方资料提炼出的SRW核心规则

### 2.1 大循环

官方《SRW30》手册第5页和《SRW Y》SYSTEM页都把流程拆成：

```text
战略/整备阶段
  -> 会话/ADV剧情
  -> 战术地图
  -> 胜利/失败判定
  -> 战果与战略阶段
```

《SRW Y》官方SYSTEM页还明确说：玩家先在 Adventure Part 阅读战斗前故事，再进入 Simulation Part；地图上逐台操作机器人；战斗分为我方阶段和敌方阶段；先由玩家移动与战斗，然后敌方行动；清图后回到战略部分强化机器人和驾驶员。

对《超GAG》的结论：

- 第一章 demo 不能只有“章节切换”和“战斗场景”。
- 至少要落下：战前ADV、探索小场景、地图态剧情、战术战斗、战后记录。

### 2.2 地图光标与菜单层级

《SRW30》手册第13、18页说明：

- 光标在我方单位上确认：打开单位命令。
- 光标在空格上确认：打开全体菜单。
- 光标在敌方单位上确认：查看敌方移动/状态等信息。
- 全体菜单包含阶段结束、检索、部队表、作战目的、战况报告、系统、途中保存等。

对《超GAG》的结论：

- “结束阶段”不应常驻在单位命令里。
- 单位命令只处理当前单位：移动、攻击、资料、待机等。
- 阶段命令是全局命令。当前 demo 先采用“全员行动后开放阶段结束”；未来如加入提前结束，必须放在全体菜单，并做二次确认。

### 2.3 单位行动与移动后命令

《SRW30》手册第15页是最关键规则：

- 可用单位命令会随单位种类和状态变化。
- 待机、攻击等部分命令使用后，单位会变为行动结束。
- 选择“移动”后显示移动范围，确认目的地后，移动本身还不是完整行动结束。
- 之后选择“待机”，移动目的地确定，单位行动结束。
- 如果单位拥有移动后可用武器，移动后仍可选择攻击。

对《超GAG》的结论：

```text
READY
  -> Move 进入 MOVED_READY
  -> Attack/Wait 进入 DONE

MOVED_READY
  -> 不能再 Move
  -> 可以 Attack/Wait/资料
  -> Attack/Wait 后进入 DONE

DONE
  -> 不能 Move/Attack/Wait
  -> 下回合重新 READY
```

当前 demo 暂时把所有我方武器视为“移动后可用”，后续应给武器增加 `post_move` 字段，形成武器差异。

### 2.4 攻击、预测和反击

《SRW30》手册第19、20页说明：

- 有可用武器且敌人在射程内时，单位命令中才追加/可用“攻击”。
- 攻击先进入武器选择与攻击范围，再选择目标。
- 确认后进入战斗数据窗口，显示敌我信息、命中、伤害、武器、HP/EN等。
- 战斗开始后，攻击方先攻，防御方可反击。
- 敌方阶段被攻击时，玩家可选择反击、防御、回避等反应。
- 攻击结束后，攻击单位行动结束；无特殊技能时，攻击后不能再移动。

对《超GAG》的结论：

- 攻击范围内没有敌人时，不能进入“卡死式目标选择”；应直接提示“当前射程内没有敌人”，并回到单位命令。
- 战斗预测不是装饰，而是承诺前的理解层：伤害、命中、敌剩余HP、敌意图是否解除、是否反击。
- 短 cut-in 只在确认后出现，不能代替预测层。

### 2.5 战术外支援层

《SRW Y》SYSTEM页的新系统“Assist Link”说明：不直接参战、不搭乘机体的角色，可以从后方通过 Assist Command 支援战术地图；消耗全队共享资源；使用和任务结算会提升支援角色等级，并触发 Assist Talk。

对《超GAG》的结论：

- 真实世界监督、模型厂、动画公司、作者梗，不一定要上战场当单位。
- 它们更适合做“幕后支援/吐槽/法务规避/演出许可/情绪增幅”层。
- 支援角色的成长要通过剧情和战斗行为共同推进，而不是单纯数值堆叠。

## 3. 《超GAG》的四种主要交互

### 3.1 ADV剧情

用途：建立情境、人物关系、世界尺度。

表现：

- 背景图/事件图/角色立绘/底部台词框。
- 有 backlog、人物/术语词典入口。
- 文本只服务角色当下处境，不在主界面堆系统说明。

示例：

```text
闭馆前厅背景。
纪存在游客出口边上收拾展签。
七海的封存流程从馆内广播插入。
旧守护者的灯在展柜玻璃里第一次亮起。
```

### 3.2 探索小场景

用途：让玩家用“身体感”认识地点、目标和人物，而不是读说明。

规则：

- 不是把整张战斗地图当探索地图。
- 每个房间/展区是一个小场景，例如：前厅、留言墙、0号侧廊、整备间、纪念品店。
- 玩家控制角色在小场景内走动，接触 NPC、展品、异常光点。
- 探索产出不是资源表，而是：目标理解、人物关系、可选台词、战斗前布置、支援角色解锁。

示例：

```text
前厅小场景：
  - 跟小观众对话，知道留言墙为什么重要。
  - 看“社勇拳”展柜，豪司会吐槽命名被改。
  - 调查0号侧廊门，听到不属于馆内广播的合唱声。
  - 返回七海处，触发封存线落下，切入地图态剧情。
```

### 3.3 地图态剧情

用途：在战术地图上讲剧情，让玩家在对白中理解空间、敌我位置和任务目标。

规则：

- 玩家暂时不能操作单位，但地图、单位、目标、敌意图已经显示。
- 台词推进时相机/光标聚焦到对应单位、目标物、封存线。
- 重要目标必须在地图上可见：留言墙、观众、0号侧廊、敌方意图。

示例：

```text
封存无人机在留言墙前落下红线。
七海说“请把观众从流程路径中移除。”
纪存说“人不是附件。”
旧守护者的展柜亮起，玩家第一次看到可操作单位。
```

### 3.4 战术战斗

用途：让玩家用选择来承担剧情，而不是旁观剧情。

当前 demo 的目标规则：

- 右侧是信息/命令坞，不遮挡棋盘主体。
- 单位行动采用 READY -> MOVED_READY -> DONE。
- 单位命令：移动、攻击、资料、待机、返回地图。
- 全体/阶段菜单：阶段结束、作战目的、战况报告、系统等。
- 阶段结束暂时要求全员行动完毕；后续如要提前结束，必须二次确认。
- 攻击前必须进入预测层。
- 敌方意图必须可见，并能被玩家行动打断。

## 4. 对第一章demo的最低可玩标准

下一轮第一章 demo 不应只做“能切到1-3”，而应满足：

- 玩家能在战前ADV知道：万机馆是什么、今晚为什么闭馆、谁在封存、谁在保护。
- 玩家能在探索小场景里亲自看见：留言墙、0号侧廊、展柜、观众、七海。
- 地图态剧情要把探索里认识的目标转换成战术目标。
- 战斗中每台我方单位每回合只能完成一次行动链。
- 攻击范围无目标时不进入卡死状态。
- 右侧菜单不遮挡棋盘主体。
- 战斗结束后回到“闭馆记录”，说明保住/失去的东西和角色关系变化。

## 5. 后续系统扩展位置

- `post_move` 武器属性：区分可移动后攻击和不可移动后攻击。
- `reaction` 敌方阶段反应：反击/防御/回避。
- `assist_command` 支援层：导演、模型厂、公司梗、非驾驶角色介入。
- `map_event_dialogue` 战斗事件对白：HP阈值、击坠、靠近目标、回合开始。
- `explore_flags` 探索旗标：影响战前布置、支援台词、战后记录。
- `relationship_delta` 关系变化：来自探索选择、援护、战斗保护对象、战后对话。
