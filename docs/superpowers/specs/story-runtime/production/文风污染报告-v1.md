# Story Runtime 文风污染报告 v1

> 日期：2026-07-29  
> 结论：问题确实来自输入装配，不只是“写作Agent发挥不好”。

## 一、主要污染源

### 1. 坏句被写进作家提示

退役内核v1直接列出边界对偶、账本词和技术词，虽然语义是“禁止使用”，模型仍会在生成时受到这些词形和节奏的提示。

自动扫描在v1内核找到：

- 边界对偶模板候选：3处；
- 否定式解释候选：2处；
- 账本与技术词候选：12处。

旧作家上下文又重复出现3处边界模板和50处账本/技术词候选。

### 2. 合同语言穿透正文

旧上下文把以下字段直接排给作家：

- `禁止提前消费`
- `硬合同`
- `必须主动`
- `不得写成`
- `离场`
- `债务`

这些字段适合程序与审稿，连续堆叠后会让人物说话像验收表，也让场面围绕授权、登记、边界和责任结算展开。

### 3. 候选素材在创意形成前抢占注意力

旧编译器会对11份素材表进行BM25检索，并把前若干条摘要直接塞进作家上下文。模型尚未确定人物欲望和核心场面，就开始平均满足IP、关系、文化、现实案例和生态字段，结果容易成为“都提到了”的拼装稿。

### 4. 旧Reader被误当声线

C01-C05当前Reader扫描得到：

| 风险候选 | 命中 |
| --- | ---: |
| 否定式解释 | 557 |
| 账本与技术词 | 533 |
| 灯光/亮灯替代动作 | 151 |
| 半格、几秒、一回合等微量级表达 | 80 |

这些命中不是逐条定罪，很多句子在语境中成立；但密度足以证明整批Reader不能作为无条件文风语料。Reader今后只用于事实与接缝连续性。

### 5. 前章状态包也是污染入口

旧Runtime虽隔离了原始Reader，却把规则式前章总结整段塞给作家，其中仍有大量“不能、不得、不是”和作者防误读说明。本轮把继承改成6至12条正向状态增量，详细禁区留给合同和审稿器。

## 二、已经完成的修复

1. 默认内核切换为Creative First v2，体积从`6,183`字节降到`3,184`字节。
2. 默认创作素材检索改为`explicit_only`，作家素材默认为`none`。
3. BM25广域素材模式保留为`legacy_bm25`，只能显式启用。
4. 候选素材即使被后台检索，也要再通过`writer_material_seed_ids`才能进入作家上下文。
5. 前章状态改为正向短增量，不再整份装入。
6. 人物的`cannot_reduce_to`、坏句和审稿意见从作家上下文移除。
7. Current事实语料缩减约48%，并标注事实、连续性、空间和后台四种可见级别。
8. 正向声线与负面回归案例分库存放。
9. 新增机器门禁，检查默认内核、素材泄漏、History来源、坏句泄漏和上下文预算。

## 三、烟测结果

| 指标 | 旧C02 v2 | Creative First隔离烟测 |
| --- | ---: | ---: |
| 作家上下文 | 32,262字节 | 9,406字节 |
| Candidate素材 | 自动BM25与显式种子 | 0 |

| 前章状态 | 整份规则式总结 | 6条正向增量 |
| 用户认可声线 | 无独立正向语料 | 4条 |

编译、哈希检查和生产隔离检查均通过。

## 四、尚未被本轮自动修复的内容

- C01-C05现有Reader里的否定式解释、技术cookbook、微动作和亮灯习惯仍然存在。
- L3与部分生命周期表仍可能包含陈旧或过度工程化的创意字段。
- Creative First内核能减少污染，不能代替主笔判断和真正的成文测试。
- 写后语义审查仍需判断人物是否像人、战斗是否能看懂、场面是否有趣；正则零命中不代表好看。

因此，下一次有效测试应在清退后的输入上创作一个短而完整的场面，再与无Runtime直写版本做盲读比较。此测试与本轮清退分开记录。
