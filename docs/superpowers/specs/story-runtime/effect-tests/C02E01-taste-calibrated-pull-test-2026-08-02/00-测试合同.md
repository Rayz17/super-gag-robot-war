## 测试问题

当前 Pull Runtime 方法能否在不向主笔推送完整 Canon、旧 Reader、审稿报告和三万字阶段包的前提下，把一整话写到以下水平：

- 普通读者能从正文直接理解时间、地点、人物、物理行动和场尾变化；
- 战斗不是运输说明，而是一场能复述争夺目标、玩家行动和胜法的机器人大战；
- 唐胶、纪存、兜灯、玛拉和七海的行动由各自欲望与关系推动，不只是执行设计职能；
- 母亲与维修页的情绪来自具体行动和人与人的反应，不由作者说明意义；
- 唐胶与物主的共同选择直接发动 E02，而不是另贴一个功能钩子。

## 用户判断点

本轮只设置一个正文前人工判断点：

1. 主笔完成 S2、S3。
2. 主笔为 S4 提供两种入口与出口相同、过程真正不同的短演绎方案。
3. 用户选择其中一种，或同时否决两种。
4. 未获选择前，不扩写 S4，不写 S5。

## 成本与熔断

- 品味校准独立于 S2 之后的 7 至 9 次模型调用预算。
- S2、S3、S4选中稿、S5均由同一主笔顺序创作。
- 场级简报只含上一场出口、当场欲望、空间与控制边界、开放问题及少量正面声线。
- 同一根因第二次出现即熔断；不增加审稿席，不临时创造新技术机制补洞。
- LLM盲比只提供分维度证据，不能替代用户审美裁决。

## 禁止事项

- 不迁移 Canon，不修改正式 Story Writer Skill、Runtime 或 Pipeline。
- 不写 E02 以后正文。
- 不把内部审稿通过写成用户认可。
- 不把当前 S1 标成正面金标准；它仍是 `user_unrated_candidate`。
- 不把 V3 当成质量目标；它只是带有已知优点和已知硬伤的回归基线。
