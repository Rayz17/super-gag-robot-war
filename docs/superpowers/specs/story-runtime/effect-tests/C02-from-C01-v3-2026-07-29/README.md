# C02 从 C01 v3 接续的 Runtime 效果测试

## 测试问题

Story Runtime v2.1 能否在不把旧 C02 Reader 喂给主笔的前提下，只继承
`C01-C05连续阅读稿-v3.md` 中 C01 已发生的事实，连续写出可读、连贯、有机体
拥有感、人物关系和明确玩法的 C02E01、C02E02，并把上下文和返工成本控制在可接受
范围内。

## 输入边界

- 唯一前序正文：`C01-C05连续阅读稿-v3.md` 的 C01 部分。
- 上游创作依据：当前 C02 第四层章引擎、演出规划和 C02 Runtime v2 合同。
- 主笔禁止读取：任何旧 C02 Reader、旧 C02 候选正文和旧 C02 场面解法。
- 旧 C02 只在 E01、E02 全部写完并封存以后揭盲，用于历史对照。
- 本测试不迁移 Canon，不提升 C02 用户验收门，不覆盖正式 Reader。

## 执行纪律

1. 由同一主笔按 `E01-F01` 至 `E02-F06` 顺序写作。
2. 每次模型交互只写一个完整场面或战斗阶段，并填写出口状态回执。
3. 每场通过窄上下文审查后才能提交；失败只返修当前最早问题场。
4. E01 封存后的期末状态是 E02 的唯一故事差量，不把 E01 全文再次塞入 E02。
5. 记录输入字符、输出字符、返修次数、耗时和缓存键；字符量是成本代理值，
   不冒充服务端精确 token 账单。
6. 两话完成后进行整话盲读、两话连续阅读、机器人文化与玩法审查，再与旧稿对照。

## 目录

- `E01/`、`E02/`：导演板、运行卡、事务计划和编译运行目录。
- `reader/`：机械合成后通过审查的候选 Reader。
- `reviews/`：整话与跨话审查、揭盲对照。
- `cost/interaction-cost-ledger.tsv`：每次模型交互的成本代理记录。
- `C02E01-E02-Runtime效果与成本评估.md`：综合结论、根因归属和 Runtime v2.2
  必要改法。

## 测试结论

- 新稿相对旧稿：中度改善。
- C01 至 C02E02 连续盲读：`CONDITIONAL`。
- 机战与玩法盲审：`CONDITIONAL`。
- Runtime v2.1 已证明能改善因果、连续状态、机体角色性和局部逻辑，但当前
  交互成本、解释密度及上游导演板反证能力尚不足以直接全剧推广。
- 本测试没有修改正式 Reader，也没有迁移 Canon。
