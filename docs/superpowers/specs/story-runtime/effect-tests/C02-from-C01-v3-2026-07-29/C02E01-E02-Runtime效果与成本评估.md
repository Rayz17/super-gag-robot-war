# C02E01-E02 Runtime 效果与成本评估

## 一句话结论

Story Runtime v2.1 **有效，但当前版本不够划算，也不能直接全剧推广**。

它把旧稿中大量“作者知道、读者只能猜”的关系，改造成了能被场面、机体动作和
玩家目标验证的因果；新稿因此不是无效扩写。但三份独立连续审查的综合结论仍是：

- 相对旧稿：**中度改善**，不是显著全面改善。
- 连续故事审查：**CONDITIONAL**。
- 机战与玩法审查：**CONDITIONAL**。

当前最准确的判断是：**Runtime 已证明自己能稳定生产更扎实的场面，却还不能自动
判断上游章引擎是否值得这样写，也没有控制住解释密度、单话体量和生产成本。**

## 测试边界

- 只把 `C01-C05连续阅读稿-v3.md` 的 C01 正文作为前序故事。
- 主笔可以读取当前 C02 第四层章引擎、演出规划、Canon 检索结果及 Runtime 合同。
- 主笔在 E01、E02 全部封存前不能读取旧 C02 Reader。
- 同一主笔连续写十二个场面；每次模型交互只生成一个场面。
- 每个场面通过局部语义审查后才能提交；每话完成后另做全话盲审。
- 两话封存后，才进行 C01 至 E02 连读和旧稿揭盲对照。
- 本测试不替换正式 Reader，不迁移 Canon。

## 效果判断

### 确实解决了什么

1. **章际状态能够真正继承。**

   C01 留下的万机馆离城、馆守 Z 缺臂、黄色巡展臂、七海停权、舰体损伤和木桶街
   坐标，都在 C02 直接造成行动后果，没有在新章自动归零。

2. **模型、手艺与实机工程的关系终于可见。**

   模型只保存缺失版本、维修方向和观察方法；六米实物的整圈测量、失败试制、
   全尺寸材料与低速复验才决定能否安装。玩家不再需要在正文外接受“玩具能修
   巨机”的作者解释。

3. **机体成为角色，而不是任务工具。**

   馆守 Z 主动以残缺身体面对观众；货柜领袖以道路和承载表达价值观；喷气叛星、
   死锁、镜星、雷翎从充电姿态、声音、战法、选择和持续战损上彼此不同。

4. **战斗、人物和主题出现了真正合流。**

   无牌一号夺转辙台、四机轮流实体充电、归一星反用上一阶段收招、三机放弃击破
   机会救回镜星，都既是可玩目标，也是人物选择。

5. **关系线不再只是设定说明。**

   唐胶与兜灯通过专业否决、身体承重和战后维修靠近；纪存与七海沿“不要再让我
   从警报里猜”推进旧关系；纪存与白鸢从停用侵权稿开始建立新的冲突与吸引。

6. **局部审查不是走形式。**

   十二个场面中有五个被要求重写。它实际挡住了靠港受力链不成立、没有排除常规
   处置、转子诊断无来源、平台权利与控制来源矛盾，以及充电节点变成隔空群体
   回血等问题。返工均限制在当前场面，没有推倒整话。

### 仍然没有解决什么

1. **上游导演板的错误会被忠实放大。**

   “平台切索制造巨环险情”以及“玩家直接切换并决定自主机体动作”已经写在导演板
   与场面事务计划里。主笔不是临场写坏，而是把有问题的设计写得非常完整。

2. **玩家操作权与机体主体性相撞。**

   无牌一号有明确挑战席和操纵关系；四台有自觉人格的飞行机却同时被写成会拒绝的
   主体和由无名玩家逐台操作的棋子。故事主语、战术建议、玩家输入、机体否决和
   最终执行没有分开。

3. **反派升级缺少责任主体和常识重力。**

   平台前半是有真实投入、所有权和维护作用的复杂制度，后半却在有人街区切索，
   释放二十吨级巨环。正文没有说明这是算法误判、合同漏洞、远端恶意操作，还是
   白框或具体执行者劫持，因此高潮仍带有“为了奇观先制造事故”的痕迹。

4. **高显著度人物承诺没有被兑现。**

   C01 用“唐胶认识来电者，而且不想见”发动木桶街；Runtime 确实检索到了这项
   信息，却只让私人频道闪过，没有在计划层要求碰面、拒绝或明确延期。知识在包里，
   不等于剧情会使用它。

5. **队伍扩大了，玩家编制没有同步扩大。**

   货柜领袖只是护送，无牌一号是临时挑战机，四台飞行机留守木桶街并可拒绝支援。
   这尊重机体主体性，却让玩家经历两话后仍缺少稳定的第二台常规可部署主力。

6. **信息正确，但连续阅读仍然过载。**

   技术验证、所有权、召回、作者权利、服务节点和控制边界经常先由动作证明，再由
   人物解释，最后由叙述总结。同一条规则没有遵守“一次失败、一次选择、一次反馈”
   的上限。

7. **场面和资产承诺膨胀。**

   两话同时承诺外港、内街、高架、飞行仓、夜市、六米巨环、货柜变形、无牌一号、
   四台共享骨架机、归一星、平台敌群和多套持续战损。若逐句做成专属高规格演出，
   制作量不可控。

## 与旧稿的真实差异

新稿前两话约为旧稿对应部分的 **2.3 至 2.4 倍**。增加的篇幅并非全是水：

- 靠港、诊断、公共转子不能直接拆、产权转移和有限安装都获得了完整因果。
- 模型线从“能解释”升级为“可反驳、可失败、可复验”。
- 四机差分进入充电、移动、战斗和战损，而不只存在于角色卡。
- 七海、白鸢及唐胶/兜灯的关系获得连续动作。

但质量提升没有达到 2.3 至 2.4 倍：

- 新稿的连续可读性、目标规模、人物关系只是中度改善。
- 因果常识、模型/实机边界和玩法可执行性属于显著改善。
- 概念密度反而退步。
- 未来可扩展性与旧稿相比没有实质改善。
- 旧稿更快、更轻，有更均匀的街区生活和更宽的职业人物网络。

因此，新稿适合作为更可靠的创作底稿，不适合以当前长度直接成为最终 Reader。

## 成本账

### Runtime 核心生产

| 项目 | 数量 |
|---|---:|
| 最终场面 | 12 |
| 主笔生成调用 | 17 |
| 局部语义审查调用 | 17 |
| 全话盲审调用 | 2 |
| 核心模型交互合计 | 36 |
| 被局部审查退回的场面 | 5 / 12 |
| 最终正文 | 36,092 字符 |
| 核心输入字符代理值 | 772,745 |
| 核心输出字符代理值 | 72,435 |
| 从建测试目录到两话生产账完成 | 约 3 小时 27 分 |

核心输入代理约为最终正文的 **21.4 倍**。这还没有计算主对话自身的分析、工具
调用、持续子 Agent 对话历史，以及服务端实际 token 化方式。

### 最终评估附加成本

- C01 至两话连续盲审：2 次。
- 新旧稿揭盲对照：1 次。
- 一次重复启动的 E02 盲审被中止：1 次编排损耗。
- 包含评估后，账本共记录 40 次交互，输入字符代理上限为 979,806，输出为 95,332。
- 全部测试与评估的墙钟时间约 3 小时 38 分。

字符量只是可复核的成本代理，不是服务端 token 账单。由于主笔和局部审稿人使用
持续对话，模型还会携带此前交互历史；当前数字更接近可见输入的下限，而不是总成本。

### 协议成本

本轮还发生两次结构化回执漂移：

- F05 主笔把既定状态回执字段和实体 ID 改成自己的版本。
- E02 全话审稿人把 `assembled_draft_sha256` 改成了另一套字段。

两次都被确定性脚本拦住并机械修复，没有污染正文。这证明门禁有效，也证明不应再让
模型自由生成回执外壳。

## 根因归属

| 问题 | 主要归属 | 判断 |
|---|---|---|
| 模型到实机逻辑 | Runtime 检索与场面事务计划 | 已明显改善 |
| 前后位置、损伤、控制权 | 出口状态与单场审查 | 已明显改善 |
| 平台切索缺少动机 | 上游章引擎/导演板 | Runtime 忠实放大了错误 |
| 玩家与自主机体抢主语 | 玩法合同/导演板 | 写作前就应解决 |
| 唐胶旧人钩子失踪 | 高显著度承诺调度 | 检索到了，但未变成必须支付项 |
| 稳定主力不足 | 全剧机体生命周期合同 | 测试合同只要求登场，没有要求玩家永久收益 |
| 解释复述、对举句过多 | 主笔提示与篇幅预算 | 局部审稿没有把节奏列为阻塞项 |
| 平台部门被压成单一恶意 | 阵营模型与连续审查 | 单场上下文不足以发现 |
| 资产量过高 | 导演板制作预算门 | 写作前没有先降规格 |
| 回执字段漂移 | Runtime 协议实现 | 应改成脚本预填，模型只写内容值 |

## Runtime v2.2 的必要改法

### 1. 在写第一场以前增加“导演板反证门”

这一门不检查“元素有没有”，只攻击章引擎：

- 对手为何此刻升级，谁承担责任，是否有更简单、更专业的做法。
- 玩家、驾驶员、纪存、机体 AI 和自主机魂分别拥有哪一层决定权与否决权。
- 上一话所有高显著度钩子在本话是兑现、推进还是明确延期。
- 本话结束后玩家得到哪项稳定、可成长、可预期调用的编制收益。
- 哪个是唯一主高潮，哪个只是阶段变化；哪些动作是关卡自由，哪些是固定演出。
- 资产是否能用一张地图、共享骨架和有限英雄演出实现。

反证门不通过，不编译场面上下文，也不消耗主笔调用。

### 2. 把故事行动权与玩法操作权拆成两列

每个战斗动作都要记录：

- `diegetic_decider`：故事里谁作出决定。
- `player_operation`：玩家实际选择什么。
- `veto_owner`：谁可以拒绝。
- `execution_actor`：最终由谁执行。
- `reader_wording`：Reader 中不得用“玩家切换到某自主机体”替代人物行动。

### 3. 把“检索到的钩子”升级为带权承诺

前序钩子不只作为普通事实进入 RAG。按显著度编译成：

- `must_pay_now`
- `must_advance`
- `explicitly_defer_with_cost`
- `background_only`

高权重承诺若在场面事务计划中没有落点，计划直接失败。

### 4. 先编译稳定前缀，再只发送场面差量

当前主笔每场都收到约三万至四万字符的完整包，同时持续对话又保留旧包。生产模式应改为：

1. 每话只发送一次稳定世界、人物、章引擎和语言合同。
2. 后续每场只发送场面事务卡、最新出口状态、前文尾部和新增检索结果。
3. 每话结束即重置主笔会话，避免跨话历史无限增长。
4. 对所有包保存稳定前缀哈希和差量大小，才能真正利用缓存。

### 5. 局部审查按风险分级，不撤掉

本轮五次返工都挡住了真实问题，不能把局部审查全部删除。应改为：

- 高风险场：新机制、复杂物理、阵营升级、Boss、分支、永久战损，必须独立语义审查。
- 中风险场：新人物首登、关系转折、重要解释，可用较短上下文审查。
- 低风险场：生活余波、既有角色短场，确定性门禁后交给全话盲审。

目标不是减少判断，而是让昂贵判断集中到会污染后文的地方。

### 6. 结构化回执由脚本拥有

- 脚本预填 schema、实体 ID、fragment ID、context key 和允许字段。
- 模型只返回事实句、状态值、开放问题和下一场触发。
- 未知实体必须走准入申请，不能在回执里现场发明 ID。

### 7. 控制最终篇幅和高潮数量

- 同一规则只允许一次可见失败、一次人物选择、一次结果反馈。
- 已被动作证明的主题句不再总结。
- 每话保留一个主高潮、一个主尾钩。
- 章级 Reader 目标应先压到本轮的约 60% 至 70%，再决定哪些证明材料进入可选档案、
  关卡提示或制作说明。

## 是否继续按当前模式写 E03

**不建议。**

当前模式已经证明“能写得更稳”，继续原样运行只会以同样高成本把导演板里的问题写得
更完整。更合理的下一步是：

1. 保留本轮 E01、E02 作为完整开发底稿，不立即重写。
2. 把上述反证门、行动权合同、承诺调度、稳定编制收益和风险分级审查写入 Runtime。
3. 用同一份 E01、E02 做一次不扩写的规划层复核，确认新门能够提前抓出三项连续硬伤。
4. 只有预写门能稳定拦截这些问题后，再以轻量生产模式进入 E03。

这轮测试的价值不只是得到一份更好的 C02，而是找到了 Runtime 当前的能力边界：
**它已经会记住、会组装、会局部纠错；下一步必须学会在写作前判断“这场戏值不值得
这样发生”。**
