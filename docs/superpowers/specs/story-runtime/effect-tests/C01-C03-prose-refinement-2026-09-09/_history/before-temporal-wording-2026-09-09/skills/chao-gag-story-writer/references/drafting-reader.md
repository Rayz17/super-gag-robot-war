# 纯剧情 Episode Reader 写作

## 主笔立场

把本话写成一段可以脱离策划案独立阅读的故事。读者只需要经历人物、机器人、冲突、战斗和余波，不需要同时阅读关卡说明书。

Episode Reader 在这一阶段是纯剧情文本。游戏流程解构、UI、变量、触发条件、制作资产和公开情报由后续独立工序承担。

## 开写以前

先用普通语言复述本话：

```text
谁现在想得到什么
-> 谁或什么不让他得到
-> 为什么不能等到以后
-> 他采取什么办法
-> 对手怎样反击
-> 谁作出不可替代的选择
-> 结局改变了什么
```

复述里若必须使用新造术语、地图变量或多层技术说明，先退回因果门。不要把尚未想清楚的设计写成漂亮段落。

## 允许写什么

- 人物行动、对白、关系与情绪；
- 足够形成空间感的环境和大画面；
- 战斗为何发生、双方争夺什么；
- 关键机体动作、转折、必杀与胜负；
- 战后余波、所得、失去和下一话悬念。

## 不允许写什么

- `玩家`、`UI`、菜单、界面、可操作名单、地图格、回合、冷却和变量名；
- 胜利条件、失败条件、隐藏条件、教学步骤和结算字段；
- 资产需求、镜头预算、触发器与制作说明；
- 为证明设计合理而逐项解释接口、权限、承重、位置和小机构；
- 话末百科、公开情报卡或作者后台答案。

角色可以看屏幕，但屏幕必须是世界中的具体证据，而不是策划案借人物之眼朗读规则。

## 场面

推动情节的场面通常可以这样理解；生活片段不必机械满足每项：

```text
某人或某台机体带着欲望进入
-> 使用一种具体办法
-> 对方或现实作出反应
-> 场面转向
-> 离开时至少一项事实、关系或计划已经改变
```

场面长短由戏剧承重决定，不平均分字。转场由人物的新目标、迫近危险、被打断的行动或已经发生的后果发动。

空间只交代当前动作需要的三件事：人在何处、危险从何处来、去哪里能改变局面。城市和巨机的结构可以用一幅大画面建立，不逐一游览零件。

## 人物与对白

- 先理解人物此刻想从眼前的人那里得到什么，再写回应。目的可以是闲聊、掩饰紧张或希望被理解，不必每句都是高效率谈判。
- 开口前读取本场活跃人物的小传、当前欲望、知识、关系和声线；不要只读取身份标签。
- 人物可以先说废话、打断、改口、误会、装没听懂，也可以在真正危险时突然直白。
- 群像不平均发言。谁能改变当前场面，谁进入前景。
- 一个角色换成另一个人仍能说同样的话、做同样的事，重写。
- 技术角色先说人话；只有当听众此刻必须知道时才使用专业词。
- 不让所有人都带着“我早已看穿”的口气。人物可以不知道、问错、说得笨、解释一半或选择不说。
- 避免反复使用“你可以……但别……”“我不替你……”“今天先……但……”“没有把……说成……”等作者判词式句法。

先让对方的回应改变下一句；不要把一段预定结论分给几个人念。动作可改变交流，也可建立现场的松弛与熟悉感，不为每个小动作附加意义解释。

## 信息与常识

只解释当前行动必须理解的一步。能由常识、画面或一句自然问答说明的，不另造概念。

开写前检查：

- 新登场人物是否自然交代了与前章的关系；
- 谁亲眼见过什么，谁只听说过；
- 谁知道机体在哪里、是否上船、是否受伤；
- 证件、权限、故障和身份能否真的被当场看见；
- 建筑、交通和巨构变化是否符合所需时间；
- 为什么不能用更简单的办法。

如果读者需要先读话末资料才明白人物为什么行动，正文失败。

## 战斗

剧情 Reader 中的战斗是一场戏，不是一份关卡表。

战前让读者清楚争夺对象。按场面需要选择展开，不把以下各项当作每场配额：

- 一个可辨认的大局面；
- 对手一次有效反击；
- 我方一次由前文能力或关系带来的转折；
- 一个值得动画化的机器人动作；
- 胜负后真正改变的状态。

不逐回合复述，不写单位说明和支援菜单。关卡阶段、触发器、失败条件和玩法教学留给后续游戏解构。

高潮优先写重量、速度、距离、声音、剪影和人物决断。小关节与接口只在它们决定大动作成败时出现。

## 机器人文化与 IP

吸收原作的欲望、关系、姿态、舞台、节奏和共同记忆，不把引用当点名。名台词只有在当前人物真的走到相同情境时才进入。

模型、玩具、修理和收藏可以表现爱好、玩梗与生活，不必都成为证物。涉及实机时要遵守模型与实机的区别，不凭空变大，也不自动赋予物理权限。

## 完稿冷读

交稿前只读正文，回答：

- 我能否不用项目术语复述本话？
- 开场后为什么要继续读？
- 谁主动制造了局势，谁作出了不可替代的决定？
- 机器人是否做了只有机器人能做的事？
- 人物是否像在和眼前的人说话？
- 去掉所有设计说明，因果是否仍成立？
- 结尾留下的是人物愿望与危险，还是一个陌生名词？

任一根问题失败，停止交稿，返回上游。不要用更多文字掩盖。

## 后续工序

纯剧情 Reader 暂定通过后，另启 `game-adaptation`：把故事拆为 ADV、探索、SRPG、战中事件、关系事件和结算。随后按需生成公开情报。三者不得重新合并进同一正文。
