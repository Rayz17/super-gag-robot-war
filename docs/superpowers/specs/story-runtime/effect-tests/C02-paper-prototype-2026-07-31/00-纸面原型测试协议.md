# C02 知识辅助创作纸面原型测试

> Status: `isolated_method_test / no_story_authority`
>
> 本测试不修改 Canon、V35 六层生产状态、C02 当前 Reader 或任何用户验收状态。

## 一、测试问题

验证以下假设：

1. 完整知识底座可以作为按需查询的资源，而不必被编译成正文必做合同。
2. 编剧在只掌握少量硬事实时，能先提出清楚、有吸引力、真正不同的故事发动机。
3. 针对方案的二次检索可以增加人物、机体、IP与世界联系，而不会把方案重新压成资料汇报。
4. 白话落地、空间预演和短样熔断能够在生成完整一话前发现“局部漂亮、整体看不懂”的文本。
5. 不看设计答案的冷读者，能够比原流程更早识别理解障碍和无趣场面。

## 二、严格隔离

创意编剧和场面主笔不得读取：

- `C01-C05连续阅读稿-v3.md`中的C02至C05；
- 现有C02完整总纲、导演板、战斗预案、逐话结构表和Episode Reader；
- `C02-runtime-pilot`、`C02-runtime-v2`；
- 2026-07-30两组Creative First与Story Writer失败实验；
- 旧C02、旧A2或任何已经写出的具体高潮解法。

允许读取的创作输入只有本目录中的阶段文件。Runtime资料由实验主持人按编剧明确提出的查询需求定点摘取，不提供原始语料堆。

V3及失败稿只允许在全部新产出封存后，由最终比较者作为盲测基准读取。

## 三、实验阶段

### P0：查询前故事提案

输入：

- `01-最小事实与章节职责包.md`

输出三个结构真正不同的C02故事提案。每案只需包含：

- 一句话发动机；
- 五至八句白话剧情复述；
- 主角与对手各自想要什么；
- 玩家主要做什么；
- 一场值得做成PV的机器人场面；
- 一次人物关系转折；
- 章末不可逆变化；
- 为完善本案希望向Runtime查询的资料。

不写正文，不替每个角色平均安排戏份，不使用尚未检索的具体机体和素材名称。

### P1：针对性二次检索

实验主持人只围绕三案真实提出的问题，从Current Canon与创作素材库摘取小型资料卡。每条资料标注：

- `must_obey`：当前事实；
- `optional_palette`：可用可不用；
- `future_reserved`：不可提前消费；
- 来源与权威层。

### P2：查询后修订

原编剧读取P0提案与P1资料卡，可保留、改写或废弃任一方案。必须说明资料使方案：

- 更清楚；
- 更丰富；
- 或更沉重、应当舍弃。

不得为了证明Runtime有用而强行使用素材。

### P3：盲读选案

普通读者/编剧只读取：

- C01结尾的极短前情；
- 三个查询后提案。

先对白话复述，再判断：

- 是否看懂；
- 是否想继续；
- 是否具备机器人大战吸引力；
- 是否有人物欲望和转折；
- 是否依赖作者解释；
- 哪一案值得进入场面设计，或三案全部退回。

机器人文化/游戏读者另行判断机体是否是故事主体、玩家行为是否成立、IP与文化素材是否只剩点名。

### P4：场面链与短样

仅为胜出方案制作：

- 全章场面链；
- E01场面链；
- E01开头和第一场主要冲突短样。

先建立人物、机体、地点和可见行动，不写完整一话，不设字数下限。

### P5：冷读与归因

冷读者只读取C01极短前情和短样，回答：

- 现在在哪里；
- 谁在场；
- 发生了什么；
- 冲突为什么开始；
- 每个人为什么行动；
- 机器人为何不可替代；
- 哪一句或哪一段开始看不懂；
- 是否愿意继续。

随后才运行Canon、机战和常识审查。任何失败必须归因到：

- 上层职责；
- Runtime检索；
- 故事架构；
- 场面规划；
- 正文写作；
- 冷读审查；
- 或模型创作能力。

## 四、成功标准

本测试不以字段齐全、零冲突或审稿Agent给出`PASS`为成功。

至少满足：

1. 三案能够被普通人准确复述，且不是同一套动作换皮。
2. Runtime查询后至少一案明显增益，没有因资料进入而失去主因果。
3. 冷读者在不知道作者意图时仍能理解胜出方案。
4. E01短样的空间、人物行动和冲突不需要后台说明才能成立。
5. 用户认为新方向至少具有超过V3的潜力；否则不得把方法固化进正式Skill与Pipeline。
