# C02E01 创意编剧 Skill 效果测试协议

> Status: `user_rejected_method_not_validated`
>
> 日期：2026-07-30

## 测试问题

验证新建的 `chao-gag-story-writer` 是否能在不灌入旧 C02 Reader、旧审稿结论和既定高潮动作链的情况下，依据 C01 结尾与当前少量事实，写出一话：

- 连续、好懂、有推进欲；
- 人物主动而非执行流程；
- 机器人是戏剧主体，不是搬运工具；
- 战斗因人物与机体欲望必然发生；
- 模型、手艺与全尺寸工程关系清楚；
- 对白自然，有听众、有生活气；
- 既能作为游戏经历，也能作为故事阅读。

## 非目标

- 不替换 Current Reader。
- 不迁移 Canon。
- 不解锁 C02 或 C06 的正式生产门。
- 不用字段齐全、脚本通过或“比旧稿好”宣布文学成功。

## 隔离原则

1. 创意提案 Agent 不读取旧 C02 Reader、导演板、战斗预案和审稿。
2. 因果 Agent 只读取被选方案与相关事实，不参与润色。
3. 正文只有一名主笔；不把多个 Agent 的正文片段拼接。
4. 两名审稿 Agent 分别从普通读者/编剧与机战玩家/游戏制作角度做绝对评价。
5. 主笔最多重写一次；若发动机失败，回到提案，不继续贴补丁。

## 原预计调用

1. 创意提案：1 次。
2. 因果预演：1 次。
3. 主笔初稿：1 次。
4. 普通读者/编剧审稿：1 次。
5. 机战玩家/游戏制作审稿：1 次。
6. 必要时主笔重写：1 次。

总计 5 至 6 次模型调用。主流程负责选案、压缩上下文、合并根因和确定是否重写。

该估算在Run A后被证明不完整：因果根因在正文重写后仍可能迁移给另一角色，因此升级后的流程增加“因果修复门”和“重写后独立根因回归”。稳定流程的实际调用上限应改为：

- 无需返修：5次；
- 仅语言或局部场面返修：7次；
- 涉及因果修复：8次。

## 成功门槛

只有两名独立审稿者都认为文本已经具备独立吸引力，且用户首读后认可，方法才算成功。内部允许的阶段结论为：

- `PASS_FOR_USER_READ`
- `REWRITE_ONCE`
- `RESTART_FROM_IDEATION`

## 成本记录

完整研发测试实际使用14次Agent调用：

- Run A：提案、因果预演、初稿、两席审稿、一次重写、根因回归，共7次；因“战斗诱因迁移给另一名角色”失败。
- 方法升级后Run B：起草前因果修复、初稿、两席审稿、单轮因果修复、原主笔重写、独立根因回归，共7次；内部判定`PASS_FOR_USER_READ`。
- 最终候选Reader为10,191字符（`wc -m`口径）。
- 本次14次是开发和修理方法的总成本，不应伪装成以后每话的稳定成本。
- 稳定方法取消旧Runtime的全量Canon灌入、21次机械门禁和多Agent拼正文；保留单主笔、两席绝对审稿及最多一次返修。
- 用户仍需判断故事是否真的好看、工业物流题材是否适合作为C02E01、篇幅与机器人文化快感是否合口味。
