# C02选案前Story Runtime v3底座验收

> 日期：2026-08-01  
> 结论：`FOUNDATION_READY_FOR_IDEATION_TEST`  
> 边界：只证明知识底座与阶段接口可用，不证明C02故事已经好看。

## 一、这次到底改了什么

旧Runtime把大量设定压成一次性剧情合同，再让主笔润色已经被决定的场面。v3改为：同一知识底座在不同决策点反复查询，主笔先选择戏剧方向，再按需取得素材、人物模型、机制事实和迁移参照。

已经建立并接通：

- L1/L2/L3/H0/L4/L4.5/L5/L6的阶段使用政策；
- 20名重要角色的稳定人物模型Registry与可重建投影；
- 逐场实体存在方式表，区分肉身、远程、作品痕迹、机魂联系和禁止提前登场；
- 30项逐章节层源登记，明确L4、L4.5和L5何时可见；
- `ideation / research / entity_model / scene_plan / draft / review / writeback`阶段编译；
- `cold_reader / design / benchmark`三种彼此隔离的审查视野；
- Vault重建后自动恢复人物模型，消除派生层被静默清空的问题；
- Story Writer与Writing Pipeline实际Skill同步。

## 二、L1-L6现在怎样用

| 层 | C02选案时 | 选案以后 | 禁止事项 |
|---|---|---|---|
| L1 | 读取作品体验和玩家幻想 | 设计审查再读 | 不生成局部桥段配额 |
| L2 | 读取总发动机和长期冲突 | 设计审查再读 | 不要求C02解释全宇宙 |
| L3 | 读取C01-C03章位、生命周期和未来保留 | 场面规划核对 | 不把候选未来写成已发生 |
| H0 | 选案只看机制目录 | 研究、建模和因果阶段定向读取 | 不把百科塞进正文 |
| L4 | 不读取旧C02答案 | 只显示迁移参照索引，点名后读取 | 不让旧章纲预写新方案 |
| L4.5 | 不读取 | 场面规划时按ID准入 | 不用演出表代替故事 |
| L5 | 只读取C01确认出口 | 新C02完成冷读后才揭盲旧稿 | 旧C02 Reader不得进入重构输入 |
| L6 | 无输入 | 等L5通过后另行生产 | 不反向假定镜头、关卡或资产已存在 |

## 三、C02人物与出场口径

本次选案包共给出7名合法人物，不再临场重造人设：

| 人物 | C02存在方式 | 当前边界 |
|---|---|---|
| 纪存 | E01-E04肉身在场 | 主动使用万机响应天赋，但真相仍未揭示 |
| 唐胶 | E01-E04肉身在场 | 承担手作、维修史和模型文化，不与陆衡抢工程职能 |
| 兜灯 | E01-E04肉身在场 | 馆守Z整备、安全判断和维修间关系持续存在 |
| 七海 | E01-E04实时远程 | 仍在本地调查链，不得无交通过程突然随舰 |
| 白鸢 | E01-E02仅作品痕迹；E03-E04本人到场 | 分镜要经过预演、行动图、现实执行者与现场修改，不能画笔改现实 |
| 豪司 | E03条件到场，E04可延续 | 必须先演明从勇气株式会社来的原因与过程；不自动带来社勇王控制权 |

## 四、C02机体与IP创意入口

选案包共有21个实体，其中人物7名、机体/敌人/关键概念14项。关键机体没有因上下文压缩而消失：

- 火种货柜领袖：全尺寸变形生命与领袖/车队文化；
- 玩家模型机“无牌一号”：全尺寸模块竞赛底盘，缩尺模型只提供同构数据；
- 喷气叛星、死锁、镜星、雷翎：同骨架重涂但不同主体，分别保留Starscream军团、死锁/漂移、镜像世界等投射入口；
- 旧拳王机、影子陪练机：机器人拳击与影子模式；
- 未发售变形工程样机：取消企划与未发售商品生命；
- 馆守Z：延续C01单臂和巡展臂装状态；
- 商品回收王牌“归一星”、全装冠军“百刃”：分别承载统一商品身份和过度武装/尖刺配件的对手功能；
- 万机馆主循环磁流散热转子：以全尺寸工业总成替代小密封环；
- 旧机复产开放日：仍只是可迁移的事件概念，不是强制高潮。

选案视图只给机体的戏剧功能、生命周期和短投射锚点。详细名场面、名台词、模玩生态与What-if必须等某案成立后进入`research`，避免“完全不知道IP”和“素材整库压死创意”两个极端。

## 六、门禁已经能抓到什么

本轮实际抓出并修复了三类问题：

1. 无牌一号在完整实体表存在，却因主笔视图按ID截尾而消失；现改为人物去重、所有本章机体完整保留。
2. 豪司E03存在行引用了不存在的旧路径；Canon authority拒绝通过，现指向当前合法继承包。
3. Vault重建会清空人物模型；现将人物模型生成并入Vault重建和`--check`。

阶段可见性回归还验证：

- `ideation`看不到旧C02 L4；
- `entity_model`只看到可查询层源索引；
- 只有显式准入的L4来源才出现内容；
- `cold_reader`看不到L4/L4.5和旧C02 Reader；
- `design`可读取迁移/制作参照；
- `benchmark`只读取旧Reader基准。

## 七、还没有被证明的事

当前不能宣称Runtime已经会写好故事。以下仍需用下一次创作测试验证：

- 三案是否真的结构不同，而非同一故事换三个措辞；
- 人物模型是否让兜灯、唐胶、纪存、七海、白鸢都产生主动行为，而非字段齐全；
- 机体/IP锚点是否进入戏剧发动机，而非事后贴皮；
- 一次主笔调用能否写出白话成立、具备机器人奇观与关系转折的C02章级方案；
- 新流程的实际调用次数、上下文和返工成本是否低于旧Runtime。

## 八、下一次最小有效测试

下一步只运行一次`story-architect / ideation`，根据当前`06-writer-view.md`提出三种完整C02章级方案，不写Reader正文。每案必须先用白话回答：谁想要什么、谁阻止、为何现在必须打、玩家主要做什么、赢后永久得到什么；再给一场机器人奇观、一次人物关系转折和所需Working迁移。

先由用户判断三案本身有没有意思。若三案仍然糊涂、行政化或只是换皮，问题就集中在创意Skill/主笔能力，不继续消耗research和正文成本；若选案成立，再进入一次定向素材检索和实体建模。
