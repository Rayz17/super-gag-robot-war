# C03E01 根因诊断与迁移说明

## 结论

C03E01 的主要问题不是对白润色不足，而是旧生产格式把“剧情小说、游戏流程、关卡规则、演出说明、变量结算、公开情报”压进同一份 Reader。这个格式会稳定地产生三类副作用：

1. 主笔为了解释玩法，不断创造设施、接口、阶段和小动作；
2. 人物被迫替策划说明规则，对白失去欲望、听众和生活语气；
3. 审稿人能从后台板补足意义，普通读者却只能看到不合常识的跳转。

因此只做“对白去装腔”不能解决根因。

## 用户问题与根因

### 1. 陆衡无交代出场

根因是实体状态写在后台 Canon/在场表里，却没有转化为读者可见的再介绍。C02只建立了陆衡的远程协诊，C03必须明确这是实体首登。

处理：新稿用“木桶街屏幕里的工程师，如今本人站在重载坞”完成自然回收。

### 2. Reader什么都混在一起

根因是旧 `drafting-reader.md` 明文把Reader定义为“不是纯小说”，现行Pipeline又要求先写演出承载计划，再把关键场面“转换成演出”后写Reader。

处理：改为三份独立产物，生产顺序为纯剧情Reader、游戏流程解构、可公开情报。

### 3. 纪存与七海抱文件坐车

根因是为了证明七海如何到场、如何携带原件而写出过程账，关系戏只剩物件交接。

处理：删除文件箱过程。七海到场只保留真正改变剧情的原因：停职后仍有人调用她的签名；她以事故证人身份进入工务城。

### 4. 结构、位置与小动作解释过多

根因是Reader承担了物理板和战斗预案的证明责任。

处理：剧情只保留一幅空间大画面、一个冲突机制和一个高潮动作。地图层数、单位、阶段、条件和变量全部移入游戏流程解构。

### 5. “低比例试载”等新概念难懂

根因是设计术语先于人物目标出现。

处理：正文改用常识表达：万机馆替交通桥承重二十分钟，换取主转子校正和以后能回来的泊位。技术名词不再进入剧情。

### 6. 城市、证件与货柜领袖的常识错误

根因是后台作者知道正确答案，正文却没有维护人物知识与物理时间。

处理：

- 城区换位改为提前三天准备、持续数小时的工程；
- 白鸢不再凭外观看出公务卡失效；
- 纪存明确知道货柜领袖走陆路，并惊讶它更早抵达，而非询问为何没上船；
- 工务城先封路、疏散和铺临时线路，再移动城梁。

### 7. 白鸢的作图道具与能力暗示断裂

根因是原稿只想表达“白鸢把作者权交给现场人”，却没有先确定她在户外如何作图。同一个动作链中先后出现地面粉笔线、白鸢的笔和来历不明的“图”，不仅造成物件跳转，也浪费了白鸢首次在真实现场显示L1预演天赋的机会。

处理：本话候选稿统一使用白鸢的“折叠分镜板”。该道具只负责实景叠加、画线和多人修改；白鸢本人则在路口尚未被告知时，画出一条停在对应墙面前的半线。现场人员补全只有本地人知道的坡道和危险点，白鸢再原样同步。这只暗示异常的预演直觉，不在C03提前确认未来视，也不让画稿改变现实。

## 新的层级边界

| 产物 | 判断问题 | 禁止承担 |
|---|---|---|
| 纯剧情Reader | 好不好看、清不清楚、人物像不像人 | 关卡说明、变量、UI、百科 |
| 游戏流程解构 | 怎么玩、怎么演、怎么制作 | 给剧情补动机与前情 |
| 可公开情报 | 哪些已见事实值得进一步解释 | 推进剧情、修补因果 |
