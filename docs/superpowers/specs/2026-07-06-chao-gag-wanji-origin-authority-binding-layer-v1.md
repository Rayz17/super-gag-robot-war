# 万机馆来历、权限边界与馆藏绑定入口设定 v1

日期：2026-07-06

## 为什么要补这条设定

如果万机馆只是一个普通私人博物馆，它不可能同时拥有这些能力：

- 保存大量机体、模型、黑匣子、维修关系、旧名和观众记忆。
- 让纪存的档案终端看到馆内地图、谱系、支援、泊位和异常。
- 在代哥远程清算时仍保留一部分离线原名、实物锚件和低功率响应。
- 在第一章末尾展舰化，并逐步变成“会开馆的方舟”。

所以万机馆必须被定义为灾后特殊机构，而不是普通展馆。

## 核心决定

万机馆的根身份是：

**G.A.G.事件后的机器人文化与机魂灾害中立保全馆。**

它同时有四层身份：

1. **灾变证据保全点。**  
   保存旧G.A.G.事件后的机体残骸、黑匣子副本、封存流程、维修记录和事故模板。

2. **机器人文化公共托管馆。**  
   接收企业、军方、作者、模型街、玩家社群和旧展会交来的展品、样件、模型、说明书、口令、错版记录和观众留言。它不是这些IP或机体的商业所有者，而是保管者。

3. **机魂低功率观测站。**  
   用馆内离线系统观察展品、模型、实机、黑匣子和残响之间是否发生G.A.G.活化。它能记录和隔离，不能随意创造或命令机魂。

4. **旧式展舰封存体。**  
   万机馆建筑底层保留移动底盘、维修脊柱、外部锁泊和残响接口层。早期它被伪装成固定博物馆；第一章末尾才暴露“会开馆的方舟”能力。

这能解释：万机馆有很多信息，但不是全知；有一些权限，但不是万能；能保存原名和锚件，但不能无视代哥、军方、平台和索引。

## 万机馆的信息从哪里来

万机馆的信息不是凭空生成，来自六类来源：

| 来源 | 内容 | 限制 |
| --- | --- | --- |
| 实物入藏 | 机体残骸、模型、玩具、说明书、旧票根、维修件、黑匣子 | 只覆盖入馆或托管过的对象 |
| 灾后托管副本 | 企业、军方、公共机构交来的事故副本、封存记录、维修接口 | 多数是副本，不等于商业授权 |
| 工坊维修链 | 兜灯、唐胶、原型工房、模型街留下的维修、补件、改造和接口记录 | 会有缺页、错记、手工口径 |
| 观众记忆层 | 留言、昵称、导览记录、孩子的叫法、玩家社群误记 | 只能形成弱别名或共鸣，不自动成为正式名 |
| G.A.G.残响 | 机魂反应、旧灾变噪声、版本层漂移、低功率响应 | 只能被观察、隔离、调律，不能直接编辑 |
| 旧展舰系统 | 馆体地图、泊位、外部锁、消防、底盘、机库脊柱和残响接口 | 多数被封存，第一章不能全开 |

## 馆藏绑定入口

为了让“名字被改后为什么会影响响应”不显得像玄学，新增一个系统层概念：

**馆藏绑定入口**。

它不是展签文字，也不是机魂本体，而是一条跨层绑定记录。它把一个馆藏对象和以下内容连在一起：

- 实物锚点：模型、实机、黑匣子、维修件、驾驶舱、展柜、泊位。
- 名字层：原名、旧名、别名、观众昵称、错版名、风险编号。
- 展示层：展签、导览、终端条目、公开/预展/封存状态。
- 维修层：兜灯和工坊能否找到接口、备件、调试口、低功率启动方式。
- 安全层：消防、门禁、封存闸、儿童滞留、巡检路径。
- 战斗/支援层：支援按钮、低功率响应、战场识别、合体/援护条件。
- G.A.G.共鸣键：哪些名字、物件、口令、残响能让它醒一点。
- 权限签名：馆长旧钥、纪存档案权、兜灯维修权、代哥现代合规层、后期索引建议。
- 变更日志：谁改了什么，影响了哪条路线，是否留下追责记录。

一句话：**名字本身不让机器人动；名字连着入口、路线、权限、记忆和低功率唤醒方式。**

## 谁能改馆藏绑定入口

| 行为者 | 能改什么 | 不能改什么 |
| --- | --- | --- |
| 普通观众 | 弱昵称、留言、导览反馈、观众记忆层 | 不能改正式名、权限、维修路线 |
| 纪存 | 馆内档案、展区显示、临时路线、预展/托管状态、部分低功率唤醒指令 | 不能改外部商业授权、代哥公共登记、G.A.G.核心 |
| 兜灯 | 维修接口、安全锁、机体状态、消防/封存的馆内实操层 | 不能决定公开口径或商业权限 |
| 馆长/旧馆钥 | 深层托管关系、旧灾变保全状态、展舰底层部分封印 | 不能无限覆盖现代合规层 |
| 代哥 | 现代品牌资产合规层、公共登记、风险编号、封存流程、供应链、物流、保险、外部维修授权 | 不能直接擦除馆内实物、观众记忆、G.A.G.残响和旧馆离线原名 |
| 索引 | 后期可提出清噪、合并、最优模板建议，污染显示和检索 | 不能在早期直接等同G.A.G.本体，也不能凭空替代实物 |
| G.A.G. | 触发活化、误译、暴走、机魂响应、债务和残响 | 不是可被管理员随意编辑的数据库 |

## 代哥到底改了什么

代哥在第一章不应该被写成“把墙上的名字改了，所以机器人失忆”。它改的是：

**现代合规层对馆藏绑定入口的外部覆盖。**

它具体会做这些事：

- 把万机馆从公共地图、票务、维修、物流、保险和安全平台里下架。
- 将馆藏对象的原名和别名标为风险别名，外部查询只返回风险编号。
- 冻结维修件订购、支援调用、外部授权和活动许可。
- 把消防/封存系统套进旧灾变风险模板，导致门禁、封存闸和无人机接管。
- 将“馆内有人”误判为“风险展品活动”，让救援和巡检路线失效。
- 给半醒机体的低功率唤醒指令加过滤：原来的叫法被当成风险词，支援按钮灰掉。

代哥没有做到：

- 抹掉机体真实记忆。
- 让所有机器人都忘记自己。
- 直接控制G.A.G.核心。
- 直接拥有万机馆所有藏品。
- 改写观众曾经怎么叫它们。

这就能解释冲突的合理性：代哥改不了“灵魂”，但能改掉通往灵魂的公共入口、维修路线、支援条件和安全系统。对玩家来说，后果不是抽象“夺名”，而是门锁上了、车进不来、支援灰了、孩子还在馆里、馆守Z的低功率响应被误路由。

## 万机馆的权限边界

万机馆能做：

- 保存入馆对象的旧名、别名、维修关系、观众记忆和G.A.G.残响。
- 在馆内离线系统中维持馆藏绑定入口。
- 对馆内或托管对象进行低功率唤醒、维修、隔离和紧急收容。
- 在灾害/清算/流亡状态下临时开馆、预展、托管和保护观众。
- 让模型、玩具、残响道具和实机接口形成“缩尺锚件转换”的改装关系。
- 把战斗、深潜、修复和开馆结果写入馆内状态，供后续剧情/玩法读取。

万机馆不能做：

- 宣称拥有所有机器人IP或商业版权。
- 强制命令所有机体参战。
- 无条件复活、巨大化或实体化模型。
- 无视代哥、军方、平台、城市安全系统和公众信任。
- 随意公开私人记忆、真实案例或未授权内容。
- 把G.A.G.当成万能能源或万能数据库。

## 第一章应用口径

第一话到第一章末尾应先让玩家看到现实后果，再听到设定名词。

推荐表现：

- 纪存档案终端仍显示旧名，但外部大屏只显示“移动风险源候选”。
- 儿童滞留路线被消防系统误判成“展品异常移动”，闭馆门开始落锁。
- 维修件订单从“馆守Z肩轴临时件”变成“风险展品零部件，禁止配送”。
- 某些支援按钮不是因为机体忘了自己，而是因为原唤醒名被风险层过滤。
- 七海应说清她能改的是合规层，不是墙上的字，也不是机体心里记得的东西。
- 0号侧廊只短暂提示“旧馆钥还在”，不解释万机馆全部来历。

读者层可以说：

> 代哥把万机馆从现实系统里删掉了。

系统层再结算：

> 现代合规层覆盖馆藏绑定入口，生成移动风险源编号。

这样既保留“夺名/开馆权战争”的设定意义，又不让玩家觉得角色在为一张标签大惊小怪。

## 后续剧情用途

- **C01：** 万机馆证明自己不是普通展馆，而是有旧托管权和展舰底层的灾后保全馆。
- **C02-C03：** 模型街、原型工房和真实案例能进入馆藏绑定入口，但必须区分弱昵称、证据、托管和公开。
- **C11：** 七海主场可把代哥现代合规层拆成安全封存、限定流通、数字运营、商品化谱系和改革派内部权限。
- **C12：** 索引可利用绑定入口做清噪，但它是从名字、别名、版本、支援和观众记忆中推模板，不是直接“黑进灵魂”。
- **C15：** 终局不是统一所有名字，而是让不同绑定入口保留各自声部、公开责任和拒绝统一模板的权利。

## 写作禁区

- 不要写成“代哥改了展签，所以机体不会动”。
- 不要写成“万机馆拥有所有机器人文化的最高权限”。
- 不要让纪存档案终端成为全知神谕。
- 不要把馆藏绑定入口当成普通数据库字段；它必须连着实物、维修、路线、记忆和机魂反应。
- 不要让“夺名”“改名”“证词”“开馆权”等词抢在现实后果之前出现。
- 不要让万机馆的旧权限免除公共责任。它越有保全权，越要解释为什么公开、谁会受伤、谁来承担。

## 一句话给后续创作

万机馆能保存很多东西，是因为它是灾后中立保全馆；代哥能让它寸步难行，是因为现代世界的入口在代哥手里；机器人会被“改名”影响，不是因为灵魂被改掉，而是因为名字、路线、维修、支援、观众记忆和G.A.G.低功率响应被绑在同一个馆藏入口上。
