## 1. 先说结论

当前第一章不是“完全没有内容”，而是容量分布明显前轻后重；四话的结构容量合同现已全部接入，但真人容量仍未验收：

1. E01 已完成第一轮容量迁移：`standard -> compact`，并从“六房间、四必做”改成“六站、八个因果物件、八项必做责任”。静态模型由 `9.7-22.9分钟`上升到 `11.7-27.2分钟`，已经覆盖 Compact 目标的部分区间，但真人首玩回执和战术净时长仍未验证。
2. E02-E04 已补齐 `experience_contract`、稳定物件跨模式绑定、玩家承诺、四槽消费账本与容量档：依次为 `compact / standard / standard`。
3. E03、E04 已具备中长话骨架；当前主要风险不是再加节点，而是操作呈现、思考空间、场景转场与角色反应没有把已有结构兑现成体验时长。
4. 真人容量仍为 `pending_external`。脚本估时只能发现明显过薄或声明缺失，不能证明玩家实际花时、理解或喜欢。

## 2.1 E01容量迁移记录

本次迁移直接修改已接入Runtime的Story-First来源，替代审计时的旧口径：

1. `capacity_band` 从 `standard` 改为 `compact`；`capacity_evidence.status` 继续保持 `pending_external`。
2. 开场ADV不再替玩家远程处理模型病院锁扣；该事件回到模型病院现场，由玩家选择先清散件或先托模型。
3. 六站分别绑定人数、胸灯、锁扣、跌跌、机器犬、空白回信和闭馆箱；现实机器区含两个不同机体责任，0号门是六站后的第八项异常确认。
4. 模型病院安全罩映射到R3导光挡板；远星副柜与闭馆箱分别写明不得武器化和不得把普通生活物转成证据。
5. 0号员工支廊只有在前七项责任完成后才开放；跨层远景和馆外工务屏仍为可选内容，不要求点光全部热点。
6. 三回合、29人四Token、19条撤离边、失败到R3才结算、RT013S原子快照均未改变。

迁移已由内容编译、Spatial自动玩家、整话Episode集成和E01 Runtime/Graybox检查共同验证；这证明流程成立，不证明22-30分钟真人容量成立。

## 3. 模型怎样估算

### 3.1 Narrative

- 只统计当前 Bundle 内实际显示的 `lines[].text`。
- 阅读速度按每分钟180-300个可见字符。
- 每拍另加0.7-1.5秒构图、头像切换或停顿。

### 3.2 Spatial

- 统计房间、必做 Offer、首轮多拍对话和最短房间边。
- 每次调查另加8-25秒靠近、确认和状态反馈。
- 每次必要场景移动另加6-18秒。
- E02-E04 的 `5-8 / 4-6 / 5-7` 分钟只保留为作者目标，不拿它反向灌入估时。

### 3.3 Desk

- 当前 E04 三卡、两槽、三种合法组合按1.5-4分钟规划信号计算。

### 3.4 Tactical

- 从 `round_requirements`、`round_layers` 或 `stage_requirements` 推导最少必做动作。
- 每个动作按12-35秒覆盖选择、走位、目标、预测、确认和短演出。
- 每回合/阶段另加25-75秒意图阅读、结算和人物反应。
- 自动移动、反复试错、可选动作会延长实际时长，因此输出宽范围。

所有行固定写入 `STATIC_AUTHORING_MODEL_NOT_HUMAN_RECEIPT`，不得改名成“容量验收通过”。

## 4. 容量档建议

### E01：改为 Compact，并把首玩做实到22-30分钟

不建议为了保住错误的 `standard` 标签，把三回合小型救援硬灌成35-60分钟。E01的戏剧功能是让玩家爱上万机馆、认识纪存的照看能力、第一次控制跌跌与机器犬，并在四令落下时产生“刚救下它就要失去它”的推力。它适合 `compact`，但当前连 Compact 下限都不稳定。

建议在不改变三回合结局与 RT013S 的前提下补足：

1. 六站每站至少有一次不可混同的具身事件，不要求点光所有热点，也不能只是读说明牌。
2. 合体台/模型病院补“错误合体件仍被保留”的操作场；旧影像厅/档案室补七海旧杯、爆音旧片与闭馆箱的连续人物场。
3. 站间移动加入同行者位置变化、远景机体动作和短触发对话，使路线本身有节奏，不靠空走路拖时。
4. 三回合仍只三回合，但每回合都要形成“看见威胁 -> 选择位置/对象 -> 预览后果 -> 确认 -> 角色与机器回应”的完整战术句。
5. 现有四个合同动作保留；增加的是有效目标选择、移动和后果读取，不增加无意义点击。

### E02：Compact 22-35分钟

五回合、三证调查和双R2分支适合高压短章。当前上限接近 Compact，但快手路线仍过短。优先补足火线转场、七海公务判断的可见依据、消防架桥的三段施工反馈，以及R5关系/权限事件后的喘息，不再增加第四件调查物。

### E03：Standard 35-60分钟

八阶段、战中人尺度探索、断臂成桥和三类回滚已经有标准主线话骨架。下一轮主要补战场意图可读性、巨物动作演出、阶段间角色位置与身体状态变化、豪司与勇拳的参与感。不要再把一个阶段拆成更多字段。

### E04：Standard 上沿，保留 Major 候选

E04 是 `1.5` 生产等价和三阶段长话，当前静态上限已接近60分钟。近期先按 `standard / 45-60分钟`打磨；只有真人试玩表明起立、城市走廊与受损巡航三幕都需要完整独立高潮，才迁移为 `major / 60-90分钟`。不能仅因“章末”两个字自动变成长达九十分钟。

## 5. 第一章合理总容量

按以上建议，第一章首次游玩目标为：

| Episode | 建议目标 |
|---|---:|
| E01 | 22-30分钟 |
| E02 | 22-35分钟 |
| E03 | 35-55分钟 |
| E04 | 45-60分钟 |
| **C01合计** | **124-180分钟** |

这会形成约2-3小时的完整独立游戏开章。容量来自四种玩法各自承担不同戏剧任务，不来自把同一句设定解释三次。

## 8. 边界

- 本审计不判定剧情是否感人、对白是否像活人、画面是否达到商业品质。
- 生产等价 `1.0/1.2/1.5` 是资产与制作复杂度信号，不等于分钟倍率。
- 逻辑 Parity 完成不等于内容容量完成；二者必须并列保留。
- 正式修改容量档前仍需走 Canon/Experience Contract 迁移，不在本审计中静默改 Manifest。
