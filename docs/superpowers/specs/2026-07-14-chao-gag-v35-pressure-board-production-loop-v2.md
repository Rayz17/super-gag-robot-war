# V35 Pressure Board创作重校准生产循环 v2

> 状态：`active_for_c01_c12_recalibration_and_c13_plus`
>
> 适用范围：V35.9的C01-C18 Pressure Board、章审、前缀回归与V35.10解冻门禁。
>
> 核心变化：V1证明故事状态不丢；V2进一步证明故事值得继续看。机器闭包、文本完整和观众吸引力不再共享一个`pass`。

## 一、四种通过状态

每块板与每章分别记录四个互不代偿的状态：

1. `contract_status`：ID、路线、逐机/逐人生命周期、资产和下游适配闭合。
2. `story_status`：因果、欲望、对手行动、反转、代价和人物变化成立。
3. `audience_status`：去工程字段盲读后可懂、可记、愿意继续，且没有被重复发动机明显消耗。
4. `production_status`：地图、时长、演出、分支与资产能够被Episode层实现。

合法状态为`pass / warn / fail / not_reviewed`。`contract_status=pass`不能覆盖其他三项；任何文档写`accepted`时必须说明接受的是哪一层。Pressure Board进入下一章至少需要`contract_status=pass`、`story_status=pass`、`audience_status!=fail`和可追踪的production风险。全剧解冻V35.10前四项均需完成全量审计。

## 二、创作证据与工程证据分离

### 2.1 工程证据

机器表、fixture、选择器、外键、基数、生命周期与Canon检查只证明`contract_status`。不得用路径数量、字段数量、字符数量或checker绿灯证明人物有魅力、分支有感、IP有本味或剧情精彩。

### 2.2 创作证据

创作通过至少需要：

- 一份去ID、变量、合同和审稿术语的连续阅读稿；
- 一张逐槽戏剧指纹表；
- 本章独立编剧、机器人文化、游戏制作、关系/情绪四席回执；
- 章级能量波形、对手主动链、谜团揭示、债务退休和可见分支审计；
- C01至当前章的盲读前缀审，不读取历史PASS结论后再下判断。

无效或空白审稿回执不计入轮次。工具失败、额度耗尽、上下文中断和审稿者只复述字段，都只能记为`review_invalid`，不能消耗同根因三轮上限。

## 三、单板创作预检：戏剧指纹

起草正文前先写伴随行，不要求把旧板改成新格式。字段至少包括：

- `primary_pov`：观众主要跟谁经历，而非角色名单；
- `concrete_desire`：这个人此刻想得到什么；
- `active_opposition`：哪个人或人格主动阻止，环境压力不能替代全部对手；
- `common_sense_stakes`：不用项目术语说明输了会失去谁、什么身体、关系、家、钱、机体或未来；
- `reversal_shape`与`resolution_shape`：反转和解决动作；
- `native_ip_pleasure`：所吸收谱系在本话提供的独占气质；
- `energy_level`：quiet / medium / high / climax；
- `moral_answer_mode`：open / tragic / route_contested / fixed；
- `visible_branch_delta`：玩家当场能看见的差异；
- `debt_action`：seed / escalate / transform / pay / close，禁止只累计不处理；
- `estimated_adv_minutes`、`estimated_srpg_maps`、`estimated_total_minutes`和`asset_pressure`。

### 3.1 同构报警

将本槽与此前三槽、同章其他槽及同一IP旧用法比较。若`active_opposition + reversal_shape + resolution_shape + moral_answer_mode`高度相同，必须由独立编剧席说明为何是有意回环，或更换发动机。仅换机体、地点和术语不算不同。

下列模式只能作为可疑信号，不能机械禁用：完美方案先成功后越界、临时授权变永久统治、统一声音压掉差异、以拒绝/撤回/空位/不同步收尾。审稿重点是本话是否仍有新的欲望、伤害、快感和答案。

### 3.2 常识复述

每槽必须能用三句普通话复述：谁想要什么；谁在阻止；输了具体失去什么。三句中若只能使用“主体、接口、撤回、信托、证词、授权、索引、声部”等项目词才能成立，`story_status`不得直接PASS。

### 3.3 正向人格与胜利欲

“拒绝、停机、错拍、留空、拆开、撤回”只能证明角色拥有边界，不能反复代替角色全部人格。每个章节还要检查：

- 至少一台核心机体主动想赢、想保护某个人、想完成一次合体、想和宿敌分出高下，或为自身机械骄傲承担风险；
- 至少一个高潮允许完整形态、必杀、承诺或协同堂堂正正解决问题，不要求所有力量先为自己的强大谢罪；
- 若本章最终动作再次是停止、解体或去中心，必须说明为什么只有该谱系会这样做，以及它与前三章同类动作有何不同；
- “我愿意做到”与“我有权不做”在全章必须都有戏剧重量。

缺失正向欲望不一定让合同失败，但`story_status`和机器人文化`audience_status`不能无条件PASS。

### 3.4 战场主语与状态聚光

每个Episode只允许三至五项旧状态进入主舞台；其他历史差异必须压入可读的宏观状态包、短回声或结算记录。起草前必须写清：

- 本段观众首先看哪台我方机、哪台敌机、哪一个人物欲望；
- 敌方在地图上主动想得到什么，而不只是代表一个错误系统；
- 哪一处装甲、武器、步态、旧伤或战术习惯让观众认出它继承了此前哪次交手；
- 本段结束后哪三项差异需要玩家立刻看见，禁止用十几项术语同时争夺注意力。

## 四、单板循环v2

```text
前序状态与已用发动机审计
→ 写戏剧指纹和常识三句
→ 读取V35.8装载但允许提出上游迁移
→ 起草一槽一板
→ contract机器校验
→ 至少一个有效创作镜头审稿
→ 重型板追加盲读观众镜头
→ 定点修订
→ 分别提交四种状态
→ 更新发动机、对手、分支可见性、债务生命周期与生产质量账本
```

`upstream_migration_request`是合法结果。V35.8属于Candidate Canon：若装载、槽位、机体或既定发动机妨碍更好的剧情，可提出迁移影响面并重跑合同；锁定用于防止静默漂移，不用于保护不够好的旧决定。

## 五、章级门禁

### 5.1 读者装配

章末先生成只含剧情、战斗/玩法、人物、机体与结局的连续稿。创作审稿者默认不得先看fixture数量、历史PASS、问题关闭记录和下游适配规模。

### 5.2 四个独立创作席

1. **专业编剧：**欲望、因果、反转、高潮层级、人物弧线和连续追读感。
2. **机器人文化观众：**机体人格、IP本味、名场面辨识、爽感和谱系是否被统一主题压平。
3. **游戏制作人：**玩家实际做什么、选择是否只是伦理考试、分支是否肉眼可见、关卡与剧情是否互相驱动。
4. **关系与情绪顾问：**吸引、误会、照料、欲望、笑与痛是否进入场面；配角关系是否退化为资源端点。

四席必须是不同上下文或不同审稿实例。写稿者不能同时充当唯一观众PASS签署人。四席之后，连续性/制作席读取工程附录并负责合同与资产，不反向覆盖创作失败。

### 5.3 必交章审面

- 最记得的五个场面与最容易遗忘的三个槽；
- 本章和此前三章的戏剧发动机重复图；
- 高/中/低能量波形，确认高潮前后有空间；
- 主角和配角的欲望变化，而非只列权限变化；
- 具名对手的主动行动链；
- 对手机体的身体继承链：旧伤、武器、步态、惯用封锁角、战术记忆和宿敌对象；
- IP独占气质与已被压平的用法；
- 正向胜利欲与拒绝/解体动作的比例；
- 已揭示真相、仅新增线索和仍未回答问题；
- 玩家可见分支差异与后台状态差异；
- 债务的种下、升级、转化、偿付和关闭；
- Episode实现估算，明确一槽对应一话、上下篇或多地图长话。

章审输出`LOCK / PATCH / REBUILD`。`LOCK`锁的是场面与因果，不代表文字永不修改；`PATCH`保留主发动机定点增强；`REBUILD`允许更换发动机、槽位装载或章节波形。

## 六、前缀回归v2

连读C01至当前章时，审稿者必须先读Reader Assembly，再读状态附录。前缀审必须回答：

1. 玩家会在哪一章开始疲劳或弃坑；
2. 哪条人物、机体、对手或谜团线最想继续追；
3. 哪些故事只是在更换名词后重复；
4. 最早根因章在哪里；
5. 修改根因后哪些后章需要重验，哪些只需保持；
6. 当前规模升级是更大，还是换了新的戏剧维度；
7. 三章批次是否至少兑现一个重大答案，而非只开新谜团。

前缀审不得只写“连续性成立”。`passed_with_production_watchlist`若没有四席回执、读者稿、重复诊断和最早根因判断，只能降为`contract_prefix_pass`。

## 七、分支、玩家意志与可见性

组合状态再多，也必须压成玩家能理解的少数可见后果：机体是否在场、谁离队、哪座城市/设施仍可用、谁记得什么、哪段关系破裂、哪个Boss或地图规则不同。`player_visible_branch_ledger`只记录肉眼和玩法可感知差异，不用路径数代替。

每个选择声明`moral_answer_mode`。固定伦理答案可以存在，但不能成为全剧默认。开放、悲剧与路线争议选择应允许不同价值观有尊严地通过；硬失败优先用于身体矛盾、状态不可能或明确灾难，不把所有作者不赞同的选择都写成失败。

## 八、债务退休与谜团揭示

进入下一章的债务必须声明本章动作。连续三章只标`escalate/defer`而无`transform/pay/close`者触发债务淤积审查。谜团表区分`clue / partial_answer / hard_reveal / false_answer / payoff`；三章批次至少应有一项观众能够复述的`partial_answer`或`hard_reveal`，不能只证明谜团彼此尚未合并。

## 九、生产质量与容量

字符数仅作异常信号。容量判断改用预计游玩时长、地图数、高潮数、关系大场数、独立资产组和分支演出差异：

- 一槽含两个独立不可逆高潮、两张完整SRPG地图或超过一个章级关系爆点时，必须声明Episode映射；
- 连续三槽均为`high/climax`触发高潮通胀审查；
- 拆成制作段可以保持一个作者槽，但必须提前登记对应一话、上下篇或长关，不能把所有拆分都推迟到V35.10；
- 动态候选域不得冒充同周目资产量，制作估算按实际最大同场与必要变体计算。

分支制作采用“宏观路线包 + 少数具名机体永久伤痕”原则。未选路线必须保有尊严和后果，但不默认拥有与亲历路线等量的独立地图、过场、语音和跨章变体。每章必须提交Episode容量图，标出单周目段数、全量生产等价、复用边界、状态聚光项和结算回放。

## 十、持续对手与谜团阶段

前期系统压力、G.A.G.活化和后期连续人格不得混称为同一个已经成熟的反派。每个持续对手均需登记：

1. 当前是否具有连续自我、主观欲望和责任能力；
2. 本章主动计划、取得的东西、失败后保留下来的身体或数据；
3. 与主角/机体建立的是恐惧、信任、依赖、宿敌还是误解；
4. 下一章观众凭什么认出“还是它”，而不是只认出相似论题；
5. 哪一项谜团在本章获得可复述答案，哪一项仍只是线索。

以索引为例，C11以前必须区分无主体的检索/推荐层、被G.A.G.放大的跨事件残响，以及C11后能说“我”、记得上一秒遗漏并承担后果的连续人格。后期反派若要让观众痛，必须先在场面中真实救过某个主角没救到的人，并因此赢得至少一方自愿信任。

## 十一、C01-C12重校准与C13放行

1. 冻结现有61槽合同基线，不静默改动机器状态。
2. 生成C01-C12连续阅读稿与逐槽创作指纹。
3. 完成四席独立盲审和章级合并诊断。
4. 将C01-C12标为`LOCK / PATCH / REBUILD`，找到最早根因。
5. 优先改可读故事与章级发动机；触及机体、槽位、分支或生命周期时发起上游迁移并重跑合同。
6. 从最早根因章依次重验到C12，记录哪些状态未受影响。
7. C13只有在重校准门禁不再存在创作Blocker后放行。

同根因三轮上限只计算有效审稿与实际修订。三轮后仍有问题，取证据最好的版本、保留`warn`并写明用户决策；不得伪造成四状态全PASS。
