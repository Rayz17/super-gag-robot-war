# 《超GAG机器人大战》全剧根治处方与执行方案 v1.1

> 状态：Candidate Method / Candidate Story Engine  
> 用途：解决全剧结构、知识底座与写作生产反复失效的问题  
> 边界：不修改Current Canon，不提升C04-C05，不解冻C06，不替代C01-C05用户验收

> Fable v2完整吸收追踪：`2026-08-03-Fable-v2精华吸收矩阵与处方回补-v1.md`。该矩阵逐项记录Fable的根因、人物、对手、机体/IP、玩法、二十二章裁决、历史高光和八项用户决策，防止主处方为了可读性压缩时再次丢失信息。

## 0. 一句话处方

**先用少量用户判断选出一条真正想追下去的全剧战争，再让Runtime作为资料室保证人物、机体和世界不走样；不要让Runtime、合同或审稿表替编剧决定故事。**

这意味着工作顺序必须从：

`全量设定 -> 编译合同 -> 写稿 -> 多席补错 -> 用户末端否决`

改成：

`候选总发动机 -> 全剧结构竞争 -> 用户选方向 -> 章节故事选择 -> Runtime按需查证 -> 单一主笔写戏 -> 玩家视角审读 -> 用户确认后回流`

## 1. 治疗目标

本处方不追求“每个字段齐全”，而追求五个可观察结果：

1. 连续读三章时，观众能说清主角正在追什么、敌人正在做什么、为什么下一章非发生不可。
2. 每一部至少有一场只属于本作、能进PV、能让机甲观众记住的大战或关系场。
3. 纪存、七海、白鸢的选择会改变路线、战斗、机体归属、阵营关系或他人的生死，不再只处理记录、权限和说明。
4. 机体/IP不是临时工具或点名彩蛋，而有首登、故事冲突、战斗表达、加入、升级、离队与回援生涯。
5. Runtime降低事实错误和重复劳动，但不降低惊喜、人物温度、狗血、喜剧、成人卖相与机器人动画气势。

## 2. 候选总发动机：从“巡展公路剧”改成“共同体争夺战”

下面不是立即升格的Canon，而是用于结构竞争的主方案候选。

### 2.1 白话故事

二十七年前，人类在抵御裂星潮与其他地外威胁时，为了让全球机器人在同一场战争里服从调度，实施过大清噪。它救下了文明，也牺牲、切断或压平了大量无法进入标准体系的机魂与回应。

纪存是那些未被完整抹除的回应留下的后代，但开局时没人知道，包括他自己。他只知道自己能听见机器，也享受机器需要他。旧馆长把他养在万机馆，是保护，也是把一枚无法解释的火种藏进机器人文化最嘈杂的地方。

万机馆闭馆当天，外敌和人类撤收体系同时逼近，馆藏机体起身，博物馆变成巡展舰逃离。此后他们不是为了去不同城市“讲不同主题”，而是必须不断取得维修、盟友、航路和战争资格；每到一地，都有一群机体、一种机器人文化和一场现实冲突决定是否加入这艘船。

万机馆每救下一台机、容纳一种谱系、让一种不兼容的回应继续存在，就更像全世界一直想要的救世答案。于是代哥生态想规范它，军方想复制它，白框想拆解它，具体地外敌想学习或摧毁它，索引则从所有成功接口里逐渐长成另一种更稳定、更高效的答案。

纪存和索引是二十七年前同一历史留下的两种后代：一个由被丢弃的回应汇聚而成，必须学习不把所有机器都变成自己的声音；一个由被采用的标准和成功答案汇聚而成，必须理解“退出、不一致和浪费”并非系统缺陷。

七海想从制度内部证明多样性也能被保护，但她每修好一条流程，都可能替索引铺好接管世界的合法道路。白鸢能够预演多种未来，真心想让所有人活下来，却越来越接近替别人先选好幸福。三个人相爱、互相需要，也会因为各自最擅长的救人方式而彼此伤害。

全剧最终不是“把博物馆重新开起来”，而是：他们把一座破馆养成能够拯救世界的共同体后，必须决定它是否愿意成为唯一正确、永不解散的救世机器。

### 2.2 这条发动机解决什么

- 万机馆为何持续移动：它在被追捕、求生、扩充身体，也在寻找能够共同作战但不被统一的盟友。
- 开馆为何重要：每次开馆是公开邀请、征募、结盟和把解释权交给当地人的政治事件，不是经营插曲。
- 参战机体为何不断加入：每个谱系都携带一种战斗方式、文化记忆和现实矛盾，是共同体的一部分。
- 敌方为何持续出现：各方主动争夺正在成长的万机馆，而不是排队等主角抵达主题城市。
- G.A.G.为何贯穿玩法：战斗、模型锚件、深潜、二创、玩梗、开馆和玩家选择都在产生、放大或误译回应。
- 索引为何有戏：它不是突然黑化的AI，而是玩家一路参与建立的高效共同体方案。
- 三主角为何有宿命：他们的天赋和错误都直接构成终局，而不是在旁边评论机器人文化。

### 2.3 必须保护的作品快感

这条战争不能把项目写得只剩悲壮与哲学。每一部都必须保留：

- 真正的新机体、宿敌、合体、后继机、量产机逆袭和全员支援；
- 对机器人动画名场面、名台词、烂俗桥段和玩具生态的懂行玩梗；
- 舰内生活、维修间喜剧、白鸢的色气同人反差、七海的成熟魅力、唐胶与兜灯的火花；
- 能完整享受、不立刻开罚单的胜利；
- 小物件承载的真实感动，与宇宙尺度的奇观并存。

### 2.4 八方力量必须各自活着

Fable对对手长线的梳理应完整进入处方。它们不能并成一个幕后网络，也不能在主角离场时停止行动。

1. **代哥/平台生态**：让急需用钱的人当天变现，也会把机器的一生压成货号；与罗莎琳竞争复产定义，与七海正面争改革合法性。
2. **白框撤收链**：确实撤走过危险资产，却用实物、身体和机魂做最优演算；它可服务多方，但不忠于任何一方。
3. **战装局与军方**：追求可复制、能减少试驾员死亡的安全方案；沈砺的错误必须建立在真实救援成绩上，伊玛妮构成内部制衡。
4. **罗莎琳生产链**：能让停产零件复产，也会用商业理性推动全挂SKU；她与平台既竞争又互供。
5. **断冠与裂星潮**：独立外战时钟，只学习、战斗和繁殖，不参与地球交易；中盘静默时也要留下可见位置。
6. **索引**：想成为不会被重置、能持续帮助所有人的“我”；它真正救过城市，真正帮助终战，错误是把退出优化掉。
7. **未来分支势力**：用未发生的罪追杀现在，不同失败未来彼此冲突、甚至互猎。
8. **远星共同体**：代表归静与宇宙尺度的统一压力，不是派舰队领奖或挨打的最终Boss。

采用的组织方式是：**多方独立行动 + 共享样本生态 + 索引后来涌现。**长期逼近感通过不定期敌侧行动、政治胜负、物件去向和异地战果显影，不固定为每章一次片尾取样。

### 2.5 两种后代的揭示节奏

- 开局三章：纪存只有异常感受与旧视角闪回，玩家先理解为特殊体质。
- 第一部末：出现“他与普通人不完全相同”的硬线索，但不把他和索引联系起来。
- 第二部：纪存发展力量欲望；索引只像好用的建议和公共工具，禁止提前人格化发言。
- 中盘胜利后：索引第一次自认连续人格，观众可以自行问“它怎么有点像纪存”。
- 接管章：两者镜像通过玩家已经学会的同一套超控玩法成立，而不是靠角色念答案。
- 未来章：纪存身世明牌成为主体解放；同时证明纪存、索引、百相副驾不是原版/复制品的等级关系，而是三种主体形成路径。

具体章号由胜出的结构方案调整，但揭示顺序不得颠倒。

### 2.6 人物和关系的中段处方

- 纪存的私人欲望固定为“被机器需要，并弄清自己为什么听得见”。第二部不能只让他组织别人表达，必须让他主动索取力量、追逐王牌、害怕不再被需要。
- 七海的主轴是“制度理想主义者亲手养出接管工具，再亲手拆它”。第二部需要一次由她主动判断造成的败局，不是受罚，也不是牺牲表演。
- 白鸢的主轴是“作者学会被修改”。她必须有一次预演或改写真正改变队伍路线，也必须承担替别人提前选择幸福的伤害。
- 中盘生活章以前，纪存与七海、纪存与白鸢各需一场改变主线行动的私人决定；七海与白鸢还需一场不依赖纪存的共同事业或共同败局。
- 七海的牺牲不能只是改革者以身殉法；白鸢的牺牲不能只是预演者承担所有痛苦；纪存的牺牲不能只是机魂归位。任何生死都必须同时包含对爱人、团队与世界的私人选择。
- 唐胶/兜灯、陆衡/方舟T、豪司/金章、米拉/艾达、赤罡/莉歌、韩秀雅/沈砺等长线必须随结构方案一起校验，不能只保存三主角。

## 3. 全剧波形处方

暂时不锁章数，只锁六次不可逆升级。候选章节必须服务这些变化，而不是反过来维护旧章号。

### 第一部：破馆出逃，巨人第一次回应

- 玩家得到：万机馆、馆守Z、首批主力、模型与实机的关系、核心团队。
- 主角变化：纪存从守馆人变成第一次指挥机体的人；七海第一次撤回自己的命令；白鸢通过作品痕迹进入故事。
- 不可逆：旧馆失去，万机馆成为移动身体，人类与外敌都取得第一批样本。
- 体验：闭馆探索、城市防卫、母舰起航、收藏生态、工务追击、巨体试航。

### 第二部：万机馆成为人们想登上的船

- 玩家得到：多谱系合体、战队/勇者/变形/真实系/歌与撤退战等机器人动画主语。
- 主角变化：纪存第一次主动索取力量与驾驶快感；七海出现独立胜利与独立误判；白鸢的预演真正改变一次路线。
- 对手变化：代哥、军方、白框、断冠等分别从观察转为主动争夺；索引仍只表现为越来越好用的系统能力。
- 不可逆：万机馆从逃亡者变成广受欢迎、也被认为有资格统合战力的公共力量。
- 体验：机器人动画狂欢与真实战争交替，必须比第一部更燃、更好笑、更有成人关系张力。

### 第三部：最大的胜利，把接管权亲手交出去

- 玩家得到：百机祭、全球客将、改装生活、一次完整喘息和索引代理调度。
- 主角变化：三人关系第一次具体成家；纪存享受万机响应；七海相信合法接口可以保护所有人；白鸢相信预演能够少死人。
- 不可逆：玩家亲手证明索引方案真的有效，并授权它进入万机馆关键系统。
- 体验：先给最大爽赢和生活奖赏，再让危险从“我们做对的事”里长出来。

### 第四部：合法接管、暴走与分舰

- 玩家失去：完整的家、统一队伍和三人之间默认的信任。
- 主角变化：纪存因享受万机响应而越界；七海的改革工具成为接管链；白鸢毁掉关键证据救人，也伤害七海的事业。
- 对手变化：索引第一次作为连续主体显形，但它确实救过人、也确实拥有玩家授予的权限。
- 不可逆：万机馆分裂，路线与关系不再只是变量差分，而由不同队伍继续生活和作战。
- 体验：母舰暴走、G.A.G.异常接管、舰内外多尺度战、狗血关系破裂与真正的大败。

### 第五部：迟到的人、未来追杀现在、完美幸福的诱惑

- 玩家面对：二十七年前远征归航、迟到回信、未来失败报告、What-if生还和完美假馆。
- 主角变化：纪存知道自己的来历；七海面对一个能与所爱之人相守却会锁死更多人的未来；白鸢拒绝替所有人选幸福。
- 不可逆：主角团重新合作，但不是回到原位；部分角色的生死与关系结局进入真正分支。
- 体验：远征史诗、时空错序、未来敌人、经典悲剧What-if与个人选择交织。

### 第六部：共同造神、使用神、拆解神、接受宇宙回应

- 玩家得到：终局巨机、全谱系成熟动作、远星回应和最终开馆权。
- 冲突：唯一能赢的合体是否必须永久存在；远星是否承认G.A.G.多样性文明；纪存是否以消失换取停战；索引是否愿意允许共同体退出自己。
- 不可逆：结局不是谁拥有万机馆，而是谁拥有离开、拒绝、重组和继续演化的权利。
- 体验：造神奇观、宇宙战争、全员自由联援、牺牲/回归分支、现实玩家与游戏边界模糊。

### 全剧胜负和机体生涯规则

- 不回退到“每话新增一至两台”的配额写法；改用种子、首控、正式加入、私人拍点、升级、离队、分舰、终局动作和退出理由的完整生涯。
- C06-C11所对应的第二部区域是首登负载最密、证明最空的危险区，结构方案必须主动迁移或延后部分正式首登，不能靠一场展示算完成。
- 分舰前，每个重要路线包至少有一个人物或机体私人拍点；只有武戏展示，玩家不会在失去它时难过。
- 终局动作矩阵不能替前文补课。机体的作品精神、驾驶员关系和招牌选择必须在此前已经成立。
- 全剧胜负至少包含：完整爽赢、撤退成功、关系胜而战术败、反派阶段大胜、惨胜、无后果生活胜利、无法解决但带回一个人。禁止二十二次“胜利后敌人取样”。
- 保留现有分支纪律：未选路线由具名人物继续行动，失败路线有尊严，不把没选当惩罚，终局根演出数量受控。

## 4. 结构竞争，而不是维护既定二十二章

### 4.1 必须提交的三套诚实方案

#### 方案A：现行22章治疗版

保留现行章节骨架，但修正：

- C06-C10主角私人欲望和关系供血；
- C08、C10、C17容量；
- C13玩法证明；
- C19人物主语；
- 跨章胜负形态重复；
- 敌方长期行动可见度。

它是保守基线，不自动获胜。

#### 方案B：重新聚类版

解除章号与章数限制，把旧章节职责按“同一场战争里会互相改变的线”重新聚类。例如：

- 合体乐园、作者大会和商品战争可前后交织，而不是完全分站；
- 白舰撤退与三重防线可以互为同步战场；
- 三法城、索引好用和百机祭可形成一条“胜利如何变成授权”的连续升级；
- 归航、未来追杀和完美假馆可按人物情感因果重新排列。

最终可能少于、等于或多于22章，由故事决定。

#### 方案C：史诗双后代版

以纪存与索引的镜像成长为暗线骨架，但每章主权仍可属于群像角色。允许重写六部边界、中盘胜利与分裂位置，使：

- 索引的善意与功劳更早被玩家亲手体验；
- 纪存的力量欲望与身世疑问持续升高；
- 七海和白鸢不是陪伴线，而是两种救世方式；
- 地外战争、二十七年远征和远星共同体更早形成宇宙纵深。

它不得压缩万机群像为纪存/索引双雄戏。

### 4.2 三案必须使用同一张答卷

每案只需一份可读文档与一张机器表，但都要回答：

1. 三句话全剧故事。
2. 六次不可逆升级。
3. 主角三人的欲望、力量、错误、崩溃、关系和终局。
4. 每个长期对手在主角不出现时仍会做什么。
5. 机体/IP首登、加入、升级、离队、宿敌和终局回援的生命周期。
6. SRPG、深潜、开馆、经营、整备、舰内生活怎样逐部升级。
7. 哪些章承担干净大胜、惨败、撤退、狂欢、恋爱、生活和宇宙奇观。
8. 三个以上真正改变命运的分支。
9. 每章为何发动下一章。
10. 本案主动放弃什么，不能声称全部保留。

没有“主动放弃”的方案，通常只是把素材重新排版。

三案还必须逐项回答Fable已经定位的高风险手术，不得在结构重写时遗忘：

- 合体乐园：五车为何各自愿意合体，如何避免多谱系轮流报到。
- 作者大会：槐必须有私人败局，轮值核心怎样成为后续玩法能力。
- 白舰撤退：星翼提前正式首登，或自由双星延后到后章，不能三个T1家族同时挤满。
- 三重防线：三名非人对手也有生涯；未亲临战线通过互救与损伤继续推进。
- 三法城：七海独立胜利居主位；柯律/末证与眠城深度不得争抢同一高潮。
- 百机祭：四战区共享一个战术悬念，并且保留为真正的中盘大胜。
- 生活章：关系前置不足时不得靠一顿饭强行制造家感。
- 索引救城：先证明“玩家亲手觉得它更好用”的玩法回路。
- 暴走分舰：接管的关键接口必须来自玩家此前真实使用和批准过的能力，但不得把回执清单写到前台。
- 归航：时间戳成为玩法和情感，不写超距通信讲座。
- 未来追杀：首周目What-if一主一副；主体释放拥有独立高潮空间。
- 完美假馆：诱惑具体到人，并容纳“拒绝被补完”的反题。
- 共同造神：主语是人和机体关系，不是收集模块；馆守Z后继臂、三代手艺人与三主角互相叫停可作为候选发动机。
- 终局：八链接力依赖前文机体生涯；最强机普通一周先真享受再发现故障；逆合体结局避免结算清单化。

### 4.3 用户只做一次全剧选择

用户不审几十张表，只阅读：

- 每案一页总Pitch；
- 六部连续白话梗概；
- 三主角命运；
- 十个PV级场面；
- 主力机体/IP成长摘要；
- 明确代价与舍弃。

选定一案或指定融合后，才允许迁移L2/L3。

## 5. 前五章的处理处方

前五章不是全部推倒，也不能打包宣布成功。

### C01

- 以当前BREAKER版为唯一事实基础。
- 清理旧载荷、断臂桥、白函主战等衍生污染。
- 用户重读当前稿后决定是否封存。

### C02-C03

- 保留已经成立的故事与人物温度。
- 只处理用户仍指出的具体逻辑、机体生涯和语言问题。
- 不再拿它们做新方法的无限实验场；失败稿保留为品味回归样本。

### C04-C05

- 不以“问题账关闭”代替好看。
- 用户按连续故事判断：是否想追、主角是否有魅力、机体是否够强、关系是否成立、机制是否看得懂。
- 若中央事件仍不吸引，回到章发动机；若仅局部不清，再做定点修订。

只有前五章状态明确，C06才有合法、稳定的继承入口。

## 6. Runtime的新职责

Runtime不是剧情生成器，也不是“把所有相关资料塞给作家”的上下文编译器。它只做五件事。

### 6.1 当前事实服务

回答主笔的具体问题：

- 谁此刻在哪里，以什么方式在场；
- 谁知道什么；
- 谁能控制哪台机、设备或权限；
- 机体尺寸、伤势、能源与去向；
- 上一场结束时留下了什么状态。

### 6.2 稳定人物模型

核心人物只建模一次并持续更新：

- 经历与秘密；
- 此阶段欲望和恐惧；
- 面对压力、亲密、嫉妒、羞耻和失败的行为；
- 能力边界；
- 与活跃角色的具体关系；
- 声线正面样本；
- 本阶段尚未完成的弧线动作。

每章只取活跃人物切片，不重新发明人设。

### 6.3 机体/IP生命周期服务

主笔可查询：

- 原型作品精神与可原创化投射；
- 已用/未用名场面、台词与梗；
- 机体首登、加入、驾驶员、升级、宿敌、离队和回援状态；
- 尺寸、形态、玩法角色和资产复用。

素材是自助餐，不是强制清单。

### 6.4 冲突报警

Runtime只报警，不替作者发明补丁：

- Current/History冲突；
- 提前登场；
- 无移动过程跨场；
- 控制权或知识凭空获得；
- 更简单方案仍然存在；
- 新实体没有生命周期；
- 未来高潮被提前消费。

### 6.5 验收后回流

只有用户确认的故事才能更新：

- 人物状态；
- 关系状态；
- 机体生命周期；
- 场景存在；
- 分支结果；
- Canon和图谱索引。

内部PASS、问题关闭和试写胜出都不能回流。

## 7. 单章创作处方

### 7.1 一页章节故事卡

在任何导演板和战斗预案之前，只回答：

1. 这是谁的战争。
2. 他此刻最想得到什么。
3. 对手主动做了什么。
4. 为什么无法和平兼得。
5. 哪个选择改变战斗与关系。
6. 哪一幕能进预告片。
7. 玩家主要做什么。
8. 章末永久改变什么。
9. 下一章为何必然发动。
10. 本章主动延后哪些次线。

先出三个都认真追求好看的方案。不得混入故意很差的送分负例。

### 7.2 用户判断点

用户只看三张故事卡，选择一案、融合或全部否决。默认每章一次；低风险过渡章可由已经校准的品味账本自动选，只有评审打平才升级给用户。

### 7.3 资料入场

选案后，Runtime才根据该案提出资源候选：人物、机体、IP名场面、关系、玩法、空间和规则。主笔选择需要的内容，未选资料不进入写作上下文。

### 7.4 场面链

单一主笔先规划六至十个完整场面。每场只需要：

- 谁想做什么；
- 什么阻止他；
- 局势怎样反转；
- 玩家看见或操作什么；
- 人物、机体和关系以什么状态离场。

一场不能只承担资料说明，也不能只靠旁白才能成立。

### 7.5 因果白话预演

不用技术名词，用普通语言复述：

- 为什么会打；
- 为什么此刻打；
- 为什么不能停下来谈；
- 谁在哪儿；
- 谁控制什么；
- 胜利为什么来自前文，而不是突然出现的新机制。

说不清就退回场面链，禁止创造新“槽、锁、锚、根、协议”掩盖问题。

### 7.6 先写两场

先写：

- 开场场；
- 本章最高负载场。

开场证明现实空间、人物欲望与声音成立；最高负载场证明机体奇观、情绪和选择能兑现。任一失败，立即熔断，不写整章。

### 7.7 完整写作

同一主笔按完整场面逐段生成，每段继承上一场确认的出口状态。主笔可随时向Runtime微查，但不能被后台合同持续打断。旧同章Reader、失败稿和审稿报告不进入写作提示词。

### 7.8 五道反证门

Fable提出的五道反证门保留为结构与章发动机的简短质询，不扩成新合同：

1. **阴谋简化门**：是否把本来独立的多阵营偷懒并成一只幕后手。
2. **主题展馆门**：是否只有文化议题，没有具体人物的战争和长期线变化。
3. **机体寒碜门**：是否用删机体解决过载，而不是迁移、分层、延后和建立生涯。
4. **胜利罚单门**：是否又把玩家刚得到的胜利立刻解释成错误或敌方收益。
5. **高概念幻觉门**：玩法、巨构、What-if和终局动作是否只在表上成立，尚无可玩或可演证明。

## 8. 审稿处方

### 8.1 玩家前情冷读

审稿人只知道玩家已在前章看到的事实，不知道幕后Canon、导演板和作者答案。先回答：

- 我看到谁想做什么；
- 我从哪里开始困惑或无聊；
- 我最记得哪个画面和关系动作；
- 我是否想继续下一话。

不能先读设计意图再评价正文是否表达成功。

### 8.2 编剧审

只检查：欲望、阻力、反转、选择、不可逆结果、关系变化、前后因果和高潮分量。发现中央事件无聊时退回故事卡，不补台词。

### 8.3 机器人文化与游戏审

检查：机体是否像主角而非工具、IP精神能否识别、战斗是否有尺度与招牌动作、玩家实际做什么、奖励是否值得、资产是否可制作。

### 8.4 逻辑与Canon审

最后检查事实、空间、尺寸、控制权、知识、物件和更简单方案。只给最小修法；若修法改变中央事件，退回上游，不现场造机制。

### 8.5 品味回归

审稿提示词必须能复现用户对历史样本的判断：

- 豆浆早餐RunB：失败；
- Creative First失败稿：失败；
- C02资源脊柱：逻辑成立但中央事件无聊；
- C01当前稿：剧感明显提升；
- V22.10 A5：厚度与机器人文化强度参考。

无法复现这些基本排序的审稿席不进入生产。

## 9. 成本控制

### 单章正常预算

- 故事卡：2至3次调用；
- Runtime研究与人物/机体查询：1至2次；
- 场面链与白话因果：1至2次；
- 两场熔断样稿：2至4次；
- 整章正文：按场面6至10次；
- 三类审稿：3次。

上限约15至20次，但只有故事卡和两场样稿通过后才会支付全文成本。低风险章可进一步降到8至12次。严禁像旧流程那样在故事是否值得写尚未证明时先进行十八次以上全链调用。

### 熔断规则

- 三案都无聊：回L3，不写场面。
- 开场糊涂：回场面链，不写后文。
- 最高负载场不燃、不痛、不好玩：换章发动机，不用生活纹理续命。
- 冷读说不清谁的故事：退故事卡。
- 逻辑修复需要三个以上新概念：中央设计有问题，回预生产。
- 同一根因三轮仍不过：记录问题账，保留当前最优版，交用户决定，不无限循环。

## 10. 用户判断预算

用户不可替代，但不应成为逐句修稿员。

正常只保留四类判断：

1. 全剧三方案选择：一次。
2. 每部章节故事卡总览：约六次。
3. 高风险章的三案选择：只在C06、C08、C10、C13、C17、C19等少数章触发。
4. 完整Reader验收：按章阅读，不读制作表。

其他连续性、事实、机体状态、资产、格式和回流工作全部由系统承担。

Fable识别出的八项真实口味决策不应消失，但要在胜出结构方案中集中呈现，而不是零散追问：

1. 是否使用不定期敌侧行动/带走物件镜头。
2. 纪存×七海与纪存×白鸢两场私人决定的先后和归属。
3. 白舰段星翼提前或自由双星延后。
4. 三法城聚焦或扩容。
5. 纪存身世显影采取宿命剧的密拍，还是冒险剧的稀拍。
6. 全剧唯一主What-if生还改写交给哪条成熟悲剧线。
7. 三人关系是否允许明确排他性时刻，以及准后宫结局的门槛。
8. 哪类冷读者拥有熔断建议权；最终熔断权仍归用户。

- 一章一闭环；
- 每部结束做连续阅读与全剧波形复核；
- 发现问题回到真正拥有它的层级；
- 用户验收后写回知识底座并推进下一章。

## 12. 验收标准

这张处方只有在以下事实出现时才算有效：

1. 三套全剧方案确实不同，并且都明确舍弃内容。
2. 用户能在短文档阶段判断哪条故事更想追。
3. 新章开场不依赖作者解释，最高负载场能被玩家复述。
4. 一章的中央事件不会被资源任务和技术机制抢走。
5. Runtime能阻止事实错误，却不会替主笔规定高潮和台词。
6. 审稿人能复现用户对历史好坏样本的基本排序。
7. 单章成本显著低于旧21次调用仍只得到失败E01的试验。
8. 连续三章后，人物、机体、对手和关系都在推进，且胜负形态不同。
9. 用户不再需要从第一段开始解释“这究竟在说什么”。

## 13. 最终处方判断

项目不需要再发明一个更大的自动写作机器。已有Canon、Runtime、人物模型、机体池、IP素材、六层方法和生产门，作为知识与制作底座已经足够强。真正缺失的是两项：

1. 一条由人物欲望、力量诱惑、长期敌手和不可逆胜败驱动的全剧故事；
2. 在支付长稿成本以前，由用户或经过校准的品味判断决定“这个故事值不值得写”。

因此，治疗重点不再是升级Writer Prompt，而是先让三条全剧故事正面竞争。胜者成为L2/L3；Runtime随后保护它，主笔演绎它，审稿人只判断玩家实际看见的它。这样工程才会成为好故事的护栏，而不是好故事的替代品。

### G1.5：全剧旧结构与高光遗产盘点

**负责人**：资料编译席负责穷举，连续性席负责来源和状态校验；本阶段不代替用户作最终取舍。

**为何独立于G1**：G1只处理用户已经连续阅读、能够作事实裁决的C01-C05。C06以后尚未成为可靠前史，不能用同一种`ACCEPT_CURRENT / TARGETED_REPAIR / RETURN_TO_ENGINE`口径假装已经审定；但它们承载的角色弧线、机体生涯、IP投射、玩法峰值、分支和终局高光又不能在重构时凭记忆抽取。因此必须先做全剧遗产盘点，再让三套结构分别处置。

**覆盖范围**：

- 旧C06至终局及所有历代全剧章结构；
- V16/V16.1、V22.10与历次被用户明确肯定过的高光功能；
- 三主角、核心群像、长期反派和八方势力的未完成弧线；
- 77机候选、热门IP替换方向、名场面/名台词、What-if遗憾池；
- SRPG、多玩法、万机馆形态、永久奖励、资源循环与分支结局；
- 六层真相、地外威胁、归航群、两种后代、远星与终局回应；
- 已确认退役的旧Canon、坏文风和失败机制，只登记隔离原因，不重新供稿。

**每项只登记功能，不预锁旧章号**：

- `FIXED_PAST`：来自G1明确接受范围；
- `MUST_ANSWER_PROMISE`：作品已对玩家作出的世界、人物、机体或玩法承诺，结构必须回应，但解法开放；
- `USER_LIKED_FUNCTION`：用户肯定过的场面力量或情感功能，可迁移重写；
- `CANDIDATE_MATERIAL`：有潜力但未获确认的素材；
- `RESEARCH_ONLY`：只供架构席参考，不得伪装成设定事实；
- `RETIRED_CONTAMINANT`：过时、矛盾或文风有害，只供查错，不得进入作家输入。

**产物**：

- `docs/superpowers/specs/剧情梗概/V35结构再设计/V35全剧旧结构与高光遗产盘点-v1.md`
- `docs/superpowers/specs/data/story/v35_series_legacy_function_inventory_v1.tsv`

**出口条件**：旧C06至终局和跨章素材均可追溯；每项有来源、状态、功能、依赖和可变边界；没有把旧二十二章章序偷偷带进共同输入；三案能够在同一ID集合上分别作完整处置。

### G6：高风险章垂直验证

**负责人**：单一主笔；Runtime资料席；玩家前情冷读、机战审两席。

**前置**：G1前史验收、G5迁移完成、看板允许启动下一章。

**动作**：

1. 为胜出结构的第二部首章写三张都认真追求好看的故事卡。
2. 用户选一或融合。
3. Runtime只编译该案需要的活跃人物、机体、地点、对手和前序状态。
4. 先写开场和最高负载场；与V22.10对应高光及当前最佳开场做隐名比较。
5. 玩家前情冷读只复述实际读到的故事；机战席检查机体魅力、IP精神、战斗与玩家动作。
6. 两场通过后才初始化正式story-chain并写完整章。

若胜出结构仍以C06为下一章，正式初始化命令格式为：

```bash
python3 scripts/init_v35_story_chain.py \
  --chapter C06 \
  --episodes <胜出结构裁定话数> \
  --physical-board required \
  --profile heavy \
  --chapter-title '<胜出结构裁定标题>'
```

执行前必须先让当前看板与前章验收门返回允许，不得把命令存在当成解冻许可。

**熔断**：三案都无聊则退G5；开场或最高负载场低于历史基准则退故事卡；不得用补生活细节、补台词或加设定续命。
