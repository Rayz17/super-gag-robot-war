# 超GAG写作方法再诊断与最小验证方案

日期：2026-09-05

状态：Candidate / 方法诊断与实验设计，不是故事验收或生产迁移

范围：复核旧Fable综合任务，形成模型无关、能被验证和淘汰的写作改进方案。

本轮不修改：Current Canon、L1-L4、已验收Reader、Story Chain、Skill、Runtime、Demo、Godot或美术。

## 0. 结论先行

可以继续使用设定知识底座来创造好故事。当前没有证据证明Runtime必然损害创作，也没有证据证明换一个更强模型就能解决问题。

这轮最重要的判断是：**我们把尚需创作的答案提前变成了必须解释的事实。** 人物、机体和世界规则本来应当帮助作者选择故事，实际生产却经常先规定各人承担什么、各机怎样接力、各场怎样交接，再让主笔把这些安排写得动人。正文于是只能增加解释、微动作和修辞。精细程度上升，人物真正改变故事的余地反而减少。

这还不是唯一原因：有效来源与过时设计混杂、Skill相互矛盾、上下文按长度截取、作品体验被逐项打勾、审稿替文本补答案，都会放大问题。部分是已确认的工程缺陷，部分是有文本证据支持、仍需实验检验的创作归因。

建议不是再建一个大型写作系统，而是改三件事：

1. 知识底座保住事实，未来方案保持可选择；重要事实不能依赖截断后的摘要。
2. 编剧先决定值得讲的事件，游戏设计同时提出可玩的选择空间；正文只进行一次主要创作，不把详细章纲再扩写成另一份详细章纲。
3. 用“最简直接主笔”作成本与质量基准。新增方法必须证明自己带来净收益，不再把V3当作唯一对手。

## 2. 对此前Fable结论和我写的提示词作修正

### 2.1 保留的精华

- 创意取舍必须发生在昂贵扩写之前，主笔需要真实否决权。
- 同一项目需要跨章检查空间、戏剧结构和玩法是否重复，不能只做单章合规。
- 首读审稿不能预先知道作者的解释与内部PASS；反例能用于校准审稿，但不能混入作家声线样本。
- 方法需要真实作品、失败记录和成本证明；“写出移植包”不等于移植成功。

### 2.2 不能原样接受的结论

| 旧说法或要求 | 本轮裁决 |
| --- | --- |
| G6-G7未执行，因此创作改革从未用过 | 正式G6-G7未运行有记录；但G5R3-R5已经发生C02三案、用户融合D与重建。只能说完整新路径未证明，不能说创意选案从未被采用 |
| C02选过案、C04未选案，因此选案是唯一决定质量的变量 | 不成立。章节题材、人物、上下文、反馈和返修量同时变化，不能作单变量实验；选案有价值，但不是充分条件 |
| T0事实已经解决 | 当前知识底座仍FAIL，且L1-L3有未清理旧口径；事实与文学问题都还存在 |
| 每场一个变化、设一位不说金句的人即可改善 | 可作诊断提醒，不应变成逐场配方。否则只是在旧配方上叠新配方 |
| C02E05能作未见过的迁移留出测试 | 已反复参与诊断、提示词和案例选择，不是干净留出；可作回归题，不能证明新任务泛化 |
| 用两次失败确定模型创作上限 | 样本不足，也无法排除题目、上下文和提示词原因；只能淘汰这次方案，不能宣布能力边界 |

### 2.3 我此前提示词中的具体错误

S1仍要求研究C14“通过玩家批准接口接管”的路线；S4正式迁移已经将C14改为物理危机、主动救援选择与分舰，不再是索引八步接管。这个旧要求是我提供错误任务的实例，不能交给更强模型继续优化。

S1对后盘What-if的配置也不能直接替代现行迁移的章节位置与三个实际区域。要比较新结构可以，但必须明确是候选结构手术，而不是“修复既定事实”。

此外，要求全剧重审、整章重写、游戏解构、两类移植实验和七份交付同时完成，容易把创造力再次消耗在任务管理上。任务耦合应由同一主笔协调，不等于所有任务必须同时扩写到最细。

## 3. 真正需要处理的五组问题

### 3.1 规则说让作者自由，生产顺序却先把故事写完了

S5的创作Skill已经禁止预写高潮完整动作。生产Skill前部也这样说，但约198-220行又要求先完成并封存导演板、战斗预案、物理板、拓扑，再写完整总纲，之后再经过演出规划写Reader。

这些板如果只表达尺度、能力与成本边界没有问题；实际C04板和总纲已经规定大量动作顺序、具体站位、反应与状态答案。Reader能重新决定的东西越来越少。其“创作”常变成把设计会议写成对话，把动作表写成连续小说。

更直接的冲突：生产Skill约448行仍要求每话至少一个真正的参战包级首登，449行要求每话刻意落账燃、泪、Gag。这与前文“不能以配额生成故事”相冲突。人物不能自然休息，机体不能靠持续使用形成感情，因为每话还要履行新的展示义务。

**已证实的是指令冲突；它对具体段落的影响是有证据的归因假说，不是假装完成了因果实验。**

### 3.2 人物有小传，但没有争取具体东西的空间

C04E02里，七号的等待、韩秀雅的承诺、独臂百相与一副普通身体之间的取舍，都是好材料。但相当一部分文字用于证明交接安全、说明模型不含人格、讨论谁可保证导航负荷。角色发言的主要任务变成“把正确规则讲全”。

这样即使读取小传，生成的也是不同人轮流确认方案。声线修订只能换词，救不了对话本身没有可争取之物的问题。

应先问：这个人此刻想从眼前的人那里得到什么？他怎样开口？对方的回应使他改变了什么做法？不是每场都必须争吵；逗乐、试探、逃避难堪、希望被认真对待，也是真实的行动。

同样，“所有生活、喜剧和IP投射都必须改变同一条主因果”过强。它会让每次亲近都必须换来权限、每个玩笑都必须产生功能。生活戏可以只增加熟悉感、暴露品味、留下共同记忆；应在一段连续阅读中判断作用，不是要求每句对白改变世界状态。

### 3.3 丰富资产被压缩成主题说明，巨机戏被写成工序

三旗舰的屏障、毕业照、旧爱等材料具有潜力，但标签和损伤属性不能替代人物经历。三个IP伤口各露一句，不等于三条有情绪分量的投射剧情。

多机接力也不是原罪。问题在于只有“甲完成一步、乙补一处、丙打开通道”，没有谁想赢、谁被逼改变、哪一下让人意外。不断强调错位、停住、支撑、归还控制，容易把机器人大战写成精密协作说明。

主笔应确定一两个承受主要情绪的角色，其余角色保留自己的气质与战斗存在感；不要每话平均结清所有人。关键战斗只在剧情中保留局势变化、决定和可记住的大动作，技术执行展开留给游戏设计。

### 3.4 旧来源仍会在正确Canon旁边复活

S7母盘仍有C03“共同监督”、C04四身体路线与已移往C05的角色/机体首登。L2当前声明的Working范围里仍可见索引锁定唯一完美结构的旧终局表达，与S4新迁移不符。Canon实体查询正确，不能自动清除这些段落的影响。

因此不需要“把所有History删除”，需要明确哪个来源有资格回答哪个问题。C03已发生事实由正式验收Reader回答，C04未来职责由有效迁移回答，旧章名或候选母盘不能越权回答人物位置、能力和未来必然事件。

S6还存在按字符截取的压缩：实体implementation_policy约58字符，人物模型单项截取后再整体截取，场面链和交接分别按长度截取。截断可能恰好丢失限制条件或后排人物。这个风险需要专门测试；本轮没有证明每次生成包都已发生同样遗漏。

### 3.5 剧情和游戏分文件是对的，但不该在思考上完全串行

S10的方向是玩家亲手创造名场面，同伴改变战术问题而非替玩家解题。若先把战斗每一步动作写死，再“游戏解构”，得到的通常只是让玩家触发既定程序。

早期就要共同回答：敌人造成什么局面？玩家能主动改变什么？什么结果属于故事？什么方法留给玩家？然后分别写纯剧情与游戏设计。不能让UI和规则倒灌小说，也不能让小说提前吃掉所有玩法选择。

## 4. C01有效之处，以及不能机械照搬的部分

C01开场先让读者遇见一个具体损失：馆藏要被拆散，孩子问它们以后还能否合体。纪存让最后一次参观继续。后来机器人起身保护这座馆，战斗接续的是读者已经在意的东西。

它先给文化乐趣和亲近感，再让读者理解机制。退休重盾先作为展品被看见，再在战斗中有用。豪司希望测试的项目真的包含“拳”，笑点来自角色想做的事。七海那顿未完成的约会让工作与私交互相打断，不是两个人轮流展示聪明。

这不等于以后每章都要闭馆、吃饭、救援、旧物复活或多人接力。可迁移的是：

- 先建立一个值得期待或不愿失去的具体对象。
- 角色为了它采取行动，而不是先讨论正确立场。
- 机器人让这个愿望以只有机器人作品才有的规模实现或受挫。
- 笑点、感情和背景来自同一个活着的现场，不必每样都承担剧情任务。

这是一组选择标准，不是一套固定开场结构。

## 5. 新方法如何真正工作

### 5.1 先区分四种输入，不再把它们都叫“合同”

| 输入类型 | 举例 | 主笔权限 |
| --- | --- | --- |
| 已发生事实与世界硬限制 | C03结束谁上舰；机魂需要载体；馆守Z右臂状态 | 不可静默修改；冲突时查询或提迁移 |
| 未来章节职责 | 本阶段取得身体、推进导航、为C05留试航入口 | 保留目的，可提出更好的实现；改变重大结果需用户裁决 |
| 创作资源 | 机战精神、IP遗憾、角色嗜好、历史样稿的某个好场面 | 可选择、变形或不用，不是逐项交作业 |
| 呈现与制作方案 | 环状布局、接力顺序、镜头、模块化演出 | 在未正式批准前可重构；已封存方案需依治理回退，不能假称已改 |

Runtime回答必须带“事实/计划/候选/历史”、来源和适用时点；无法裁决就返回冲突，不得替主笔从最新日期中随便选一个答案。

### 5.2 写作与游戏采用两条相互校准的线

```text
已验收前情 + 有效未来职责 + 人物/机体资料
                  |
          故事提案与取舍
                  |
        章级故事梗概 <----> 玩法概念草案
                  |
       难点场面试写与必要修正
                  |
           纯剧情Reader
                  |
   事实/因果检查 + 不知设计答案的体验首读
                  |
  详细游戏解构 / 演出承载 / 按需公开情报
                  |
       一致性核验与用户验收
                  |
       确认事实和状态回流知识底座
```

这是候选创作流程，不是本轮擅自改写现有Story Chain顺序。正式采用前需明确迁移哪些阶段。内部保存草稿可以早做，昂贵的正式封存应服务成熟结果，不能把探索草稿伪装成不可变剧情。

### 5.3 各种文档到底写到哪一层

**章级总纲：** 写连续故事、人物决定、情势变化、高潮、章末去向与下一章原因。机械常识要讲通，但不写逐次关节动作、完整对白和地图操作。可以试写关键场面检验声音，然后回收为短梗概，不能为了满足字数把总纲写成第一遍Reader。

**纯剧情Reader：** 正式承担当下体验，写人物、场面和必要战斗转折。场面长度由戏的需要决定，不能因一次调用还剩容量就增加解释。不会按每个小场面都切换新作者、重复装配全套上下文。

**游戏解构：** 写玩家目标、选择、敌方规则、关卡拓扑、失败与重试、资源差分和演出触发。大动作既可以是玩家通过条件做出的普通战术成果，也可以是剧情情境动作，不能一律强制播放或一律技能菜单化。

**公开情报：** 补充已见证的背景和机制，不负责替剧情补动机、交代人物忽然出现、解释为何忽然开战。

### 5.4 单一主笔怎样查Runtime

主笔起稿前只读有效前情、相关人物模型、必要世界限制与本章职责。需要的资料不以统一1500字或固定一页硬截断，而以可理解和不丢关键限制为准。

提案时查询文化素材和未来保留；规划场面时查询人物关系、能力、位置和控制权；写到具体疑点时微查；写后核对新增事实。查询可以来回发生，不要求只用一次，也不让查询自动替作者排剧情。

人物模型保存相对稳定的欲望、恐惧、关系、知识、行为习惯和正面声线例子。当前情绪及临场策略由故事决定。不能每次重造小传，也不能把模型写成“遇到X必说Y”。

缓存的对象是版本化资料与检索结果；失效应随相关来源变化，不必全量清缓存。模型端缓存命中、实际输入和输出成本另行记录，本地有缓存不等于推理免费。资料缺失或预算不足要显式说明，不能靠截掉硬限制解决。

## 6. 必须落实的改动，而不是新增一批口号

| 落点 | 具体改动 | 完成证据 |
| --- | --- | --- |
| 活跃来源 | 依据正式迁移清理当前L2/L3与章节入口的冲突；先处理会进入C04及C05查询的段落 | 同一个身份/位置/能力问题只有一个有效答案，冲突不被摘要掩盖 |
| Canon Skill | 移除硬编码的瞬时NEXT状态，改为读取live状态；保留权威层级 | 文档导航不再比manifest陈旧 |
| 写作Pipeline | 删除逐话首登、燃泪Gag等配额要求；将阶段前的板限定为暂定边界，不提前固定完整动作答案 | 新提示词中没有换名残留的强制配额；明确探索与正式封存的区别 |
| 创作Skill | 不再要求每段日常都改变主因果；让人物目标与互动先决定台词；允许重构无戏的场面 | 不是只新增“自然一点”的文风禁令 |
| Runtime编译器 | 硬事实完整返回；软素材按相关性选择；报告省略项；人物模型不得被聚合尾截断静默挤掉 | 对短实现政策、否定条件、后排角色、未来禁用项有保留测试 |
| 游戏接口 | 提前建立“固定结果/可选方法/需裁决分支”；详细规则后派生 | 代表战斗至少有一种非照稿操作的有效玩法，且不改变未授权人物选择 |
| 体验审查 | 首读只给必要前情与正文；事实席另读证据。分别报告无聊、看不懂、不可信，不用合规分数平均抵消 | 审稿不能用“设计上想表达”替正文辩护 |
| 生产回写 | 用户确认的发生事实与作者提案分表管理；体验通过和机器通过分开记录 | 未选桥段不会成为下一次的已确认高光 |

这些是后续最小实施清单。本轮只给方案，不声称已经完成代码或Skill升级。

## 7. 全剧与C04具体怎么处理

L1的机器人文化情书、Gag、强烈情感、群像与多样性，不需要因局部写坏而推翻。首先去掉执行层把这些体验量化为每话义务的做法。

L2/L3则不能免审：先纠正已被正式迁移替代的旧事实，再判断“这一章为什么值得玩和看”。近期只展开当前章、前一章和后一章的连续性，宏观另保留主要角色与反派、IP生命周期、胜败与情绪波形。不能为写一章每次重读全部全剧，也不能完全不看全剧。

环状结构重复是症状，不是把天空铸环改成山谷就治好。若人物仍然抵达设施、获得临时资格、完成接力、敌人采样、留下维修债，换几何形状还是同一个故事。跨章比较应检查“谁的欲望发动、冲突怎样升级、玩家做何种决定、胜利得到什么”，不能仅统计某个字。

Fable融合D值得保留对七号和韩秀雅的聚焦、普通身体的期待感。但山村替代地点、断冠学习制造身体、伪造命令推动授体等，不是自动正确的答案，分别可能触及C03接口、敌方能力和行政叙事回潮。它是候选提案，不是现成解药。

对C04，最值得先验证的不是再写E03，而是：**韩秀雅与七号的承诺，能否成为读者真实期待的事件，并推动机战，而不是被工房流程解释完。** 全章可以讨论两种焦点：兑现承诺为主、外敌威胁为压力；或共同迎敌为主、给予身体是改变战局的人物选择。两者不能只改标题，必须展示不同的行动因果。若改变已锁定主要选择或结局，应先提候选迁移。

## 8. 最小验证：新方法必须打败最简方法

### 8.1 先验证什么

第一轮不是全C01-C05重写，也不是立即全面改工具。用同一组已清理的事实、同一个模型和相近生成预算，比较两种输入方式：

| 组别 | 输入与做法 |
| --- | --- |
| 基准组：直接主笔 | 有效事实、人物资料、作品体验要求；请作者直接选择并讲出一个C04故事，不给旧详细总纲与失败稿 |
| 候选组：轻量方案 | 相同事实与资料；先决定人物争取什么及故事取舍，补一小段玩法选择空间，再写作；不预排完整高潮动作 |

两组共用一份有来源、无冲突的实验事实包。现行Pipeline的逐话配额、完整动作表和旧章纲不进入两组作者上下文；实验主持者保留治理责任。该隔离必须在Candidate实验入口明确登记，不能一边宣称测试新方法、一边偷偷加载旧生产义务。冷读者不见组别与方法名称。

先各交一份简短、能白话复述的故事提案。用户只判断哪个故事更想看，或两者都不值得写。比较候选故事时不能把新发生的重大改动默认为已授权。

选定方向后，让两个隔离上下文以相同故事决定写同一个最难场面，而不是各写一个不相干开头。建议约1800-2500字，足以看见人物来意、互动、情势改变和场面结束。一次开头短样不足以验证整话，低于它也不应开始昂贵整章。

这分开检验了“会不会选故事”与“会不会把相同故事写好”。样本少，只给方向性证据，不作统计显著或模型能力上限结论。

### 8.2 体验怎么判

冷读者先复述事件、指出想继续看的问题，再解释喜好。至少回答：

1. 我知道谁想要什么、为什么现在非做不可吗？
2. 人物的反应改变了场面，还是只在解释规则？
3. 哪一处让我期待、紧张、好笑或在意？没有就明确说没有。
4. 机器人是否创造了独特体验，而非把普通事务放大执行？
5. 哪段可以删掉而毫无损失？有没有在替文章补事实？

另由事实审查检查身份、时间、尺度、能力和跨章边界。普通读者不负责背Canon；事实审查也不能以逻辑正确判故事精彩。最终报告允许“合乎设定但无聊”，不合成一张掩盖问题的总分表。

### 8.3 成本与停止条件

第一轮预计4次创作调用：两份提案、同一选定方向的两份场面；再用1次体验首读、1次事实审查。只是预算提案，不是本轮实际发生的调用。提案都不行就在两次后停，不为了凑齐六次继续。

记录实际输入、输出、可获得的缓存与推理用量、耗时、人工阅读量及返修范围；未知项记未知。没有可比计费数据时，不宣称节约百分比。

候选组若不比直接主笔清楚、动人或省返修，就不升级成默认流程。不能因为它“更符合我们设计的方法”而获胜。允许直接主笔胜出，那意味着应删除无收益的中间步骤。

### 8.4 何时才算可以继续生产

短场面胜出后，完成一个完整Episode与对应游戏解构，验证开头到结尾的满足感、普通战斗可玩性和状态交接。再选一个未参与当前提示词调试、戏剧类型不同的新任务进行迁移验证；C02E05仅作回归题。

至少跨过“困难场面成立、整话成立、游戏解构不只是照稿点击、不同任务仍成立”四项，才有理由把方法作为生产默认。仍然不等于以后每章自动精彩。跨章体验与重大选择保留用户少量判断，普通纠错由作者承担。

## 10. 本轮停止点

本轮交付的是有证据的再诊断、具体实施清单与可否定的实验方案，不是写作质量已经提高的证明。

当前最该停止的是继续把未获用户认可的C04正文往后扩写；最该开始的是一次小而公平的作者能力检验。先证明故事选择和人物场面真的变好，再据此改Skill与流程，而不是先宣布又一次架构升级成功。
