# 《超GAG机器人大战》Reader表演编译模板 v1

> Status: `working_method_candidate`
>
> 日期：2026-07-23
>
> 验证样本：C05E02《是谁签了我的名字》
>
> 用途：把已经成立的章引擎、预制包、导演板和玩法预案编译成玩家能够顺畅经历的Reader。它不替代上游设定，也不提前写逐句台本。

## 一、为什么需要这一层

章引擎回答“为什么发生”，预制包回答“本章有什么、谁能做什么”，Reader还必须回答：

- 玩家按什么顺序看见事实；
- 谁在对谁说话，为什么此刻要说；
- 关系怎样通过阻拦、误判、受伤、救场和选择改变；
- 机器人怎样用不可替换的身体动作完成关卡；
- 机制怎样通过画面和操作成立，而不是靠作者解释；
- 固定演出、可操作玩法和后台设定怎样保持边界。

如果跳过表演编译，即使所有设定分别正确，正文仍可能出现同声台词、技术说明会、错误控制权、临场新装置和“作者说它成立所以成立”。

## 二、固定生产顺序

```text
全剧结构母盘
→ 章引擎
→ 章级实体、空间与行动预制包
→ 章节导演板
→ 物理因果与人物站位板
→ 战斗与玩法预案
→ 完整剧情总纲
→ 章级演出承载规划
→ 单话表演与对白简报
→ 单话Episode Reader
→ 三席独立语义审查
→ 定点回写上游或重编场面
→ 确定性lint
→ 章节连续阅读
```

不得用后一步的旁白替前一步补洞。发现控制权、空间、能力或玩法不成立时，先回写最早出错层，再重编Reader。

## 三、单话最小输入包

每次只编译一话，输入不得是一整部Canon原文。上下文编译器只提供：

1. 本章引擎与本话开始、结束状态；
2. 上一话直接造成的伤势、位置、关系、机体和敌方动作；
3. 本话涉及的人物有限认知卡；
4. 本话关键机体控制权、尺寸、能力与限制；
5. 本话地图、玩法目标、固定事件和资产预算；
6. 本话必须回收与不得提前消费的未来内容；
7. 相关Canon条目和必要IP素材，不加载无关历史方案；
8. 本话禁用句式、禁用捷径和用户已指出的同类错误。

输入包无法回答“谁控制、谁知道、东西在哪里、为何不用更简单办法”时，不得开始写Reader。

## 四、写前五张小卡

### 1. 一句话玩家任务

必须能由普通玩家复述，不得使用项目术语。

错误：

> 撤销旧根授权并阻止四路分流迁移。

可用：

> 在军方把四副仍连着纪存的测试体运走前，把船留在地面。

### 2. 前台对象卡

同一话通常只要求玩家主动区分三至五个关键对象。后台可以更复杂，前台不能让外形、图标、称呼和作用相同。

每个对象写清：

- 固定位置；
- 可见外形；
- 谁控制；
- 玩家当前应当理解的唯一差别；
- 本话结束状态。

### 3. 角色表演卡

每名关键人物只写本话状态：

- 想立刻得到什么；
- 知道什么、不知道什么；
- 最不愿接受什么；
- 会主动做什么；
- 对具体听众采用什么声音；
- 身体会先于语言泄漏什么。

角色不能因为作者需要而完整说明自己。允许听岔、抢话、回避、说错、改口和不回答。

### 4. 机体不可替换动作卡

每台关键机体至少有一个只有它能完成的动作。动作应同时使用其：

- 身体轮廓或损伤；
- 驾驶员、AI或机魂关系；
- IP精神或机器人类型；
- 当前地图规则。

若换成任意单位仍成立，该机体只是功能棋子。

### 5. 场面可见因果卡

每个关键变化写成：

```text
可见起因
→ 物理或人物动作
→ 立即结果
→ 谁因此改变选择
```

同一场通常只要求玩家理解一个决定性变化。控制权、签名、远程操作、机魂请求和运输许可不能在一轮对白里一次解释完。

## 五、Reader正文编译规则

### 1. 按玩家实际经历写

使用 `舰内自由活动 / ADV / 探索 / SRPG / 战中通讯 / 固定地图事件 / 短动画 / 结算` 标出承载形式。

如果删掉作者旁白，画面、操作和人物仍应足以让玩家知道：

- 当前要做什么；
- 谁正在阻止；
- 为什么出现转折；
- 通关后有什么永久变化。

### 2. 先表演，后解释

优先顺序：

1. 人物或机体动作；
2. 环境和UI状态变化；
3. 有明确听众的短对话；
4. 必要的一句背景；
5. 作者解释只允许出现在生产附录，不进入Reader。

禁用Reader叙述者替作品答辩：

- “这不是……而是……”
- “她没有把……说成……”
- “这是某人第一次明白……”
- “它们并非自己醒来……”
- “这证明了……”

### 3. 对白必须有听众和企图

一句对白至少应满足两项：

- 让对方停止、交出、承认、靠近、离开或作选择；
- 隐瞒某件事；
- 伤害或安抚具体的人；
- 争夺现场控制；
- 暴露说话者不知道的事；
- 因身体、时间或情绪而没有说完整。

不允许把人物写成轮流发表正确立场的编剧。

### 4. 技术词只用于技术对象

“接口、权限、路线、控制、程序”可以描述机器和系统，不得代替私人感受。人物害怕、嫉妒、心疼、愤怒时，应当碰人、抢东西、走开、说难听话或沉默，而不是谈“关系接口”“情绪债务”“选择语法”。

### 5. 大机体做大动作

高潮优先使用：

- 整体转身；
- 托举、冲撞、变形、合体、截舰、破墙；
- 用身体伤势改变战法；
- 改变整张地图的地形或射线。

厘米级卡扣、关节余量和微小挪动只能支持可信度，不能承担PV主镜头。

### 6. 固定演出不能冒充玩法

固定发生的救援、坠落或转身：

- 必须登记资产状态；
- 必须标为地图事件或短动画；
- 不得同时列为玩家可失败目标；
- 不得让关卡胜负依赖玩家无法操作的动作。

## 六、三席独立语义审查

三席只找证据、根因和最早故障层，不直接向正文追加修补。

### A. 人物表演与人类声线

执行七项测试：

1. **隐名：**遮住名字，能否听出是谁；
2. **互换：**两人的台词交换后是否明显错误；
3. **听众：**每句话是否真的对场内某人说；
4. **知识：**人物有没有提前知道作者答案；
5. **动作：**关系变化是否由行动造成；
6. **关声：**关闭对白，关键因果是否仍可见；
7. **朗读：**是否有呼吸、打断、长度差异和不完整表达。

### B. 游戏制作与物理因果

检查：

- 控制权是否前后一致；
- 人物与机体是否可能同时出现在当前位置；
- 尺寸和移动路径是否成立；
- 玩家目标、失败条件和阶段触发是否互相因果；
- 固定演出是否诚实登记；
- 资产是否为了只用一次的说明而膨胀；
- 是否存在更简单、角色理应采用的办法。

### C. 机器人文化与机体人格

检查：

- 机体是否只是占点工具；
- 每台机的动作是否使用其伤口、驾驶关系和类型精神；
- IP投射是剧情与情绪变奏，还是只有外形和台词点名；
- 战斗是否有一眼可懂的机器人奇观；
- 本话结尾是否用机器的动作发动下一话，而非只用状态UI。

## 七、故障路由

| 发现的问题 | 回到哪一层 |
| --- | --- |
| 机魂载体、能力输入输出、控制权不清 | 世界机制或章级预制包 |
| 人物不可能抵达、巨机尺寸不成立 | 物理因果与站位板 |
| 失败条件由固定演出自动解决 | 战斗与玩法预案 |
| 场面要靠三个终端依次解释 | 演出承载规划 |
| 人物同声、对白像立场报告 | 表演简报与Reader整场 |
| 机体可被任意单位替换 | 机体动作卡与战斗编排 |
| 只剩作者总结句不自然 | Reader句级清理 |

同一根因最多回滚三轮。仍未解决则保留当前最优稿，记入问题账，不无限循环。

## 八、C05E02回归样本

首轮试点暴露四类典型捷径：

1. 纪存与测试体镜像抬臂，让玩家误以为他直接驾驶四副身体；
2. 夺取起飞锁凭空获得撤销权限；
3. 四副身体已经入舱，U盾却因不存在的吊装负载过热；
4. 固定检修台既没有资产预算，又被列为玩家失败条件；
5. 社勇王与旧拳王只执行通用占点动作；
6. 公开对质与U盾争执像两名编剧轮流陈述立场。

通过回写上游后，Reader改为：

- 远程操作员先失去路线，测试体撞架，冲击随后传回纪存；
- 七海从战斗开始便执行撤销，三处起飞锁只争取时间；
- 四台运输滑架在负载中逐台抱死，转接盒和U盾过热获得可见原因；
- 检修台登记四个固定状态，并移出失败条件；
- 馆守Z用空肩坐死地锁，社勇王以黄金工具作巨楔，旧拳王用擂台步把对手打出控制圈；
- 装运进度、机体动作和未回答的问题打断观点辩论。

这个样本说明：确定性lint为零不等于人物自然；表演语义审查也不能替代控制权和玩法审查。

## 九、通过条件

一话只有同时满足以下条件，才能并入章节Reader：

- 三席语义审查均为`PASS`，或只有不阻断的明确观察项；
- 确定性人类声线lint无Block；
- 玩家不读附录能复述目标、转折和结果；
- 前台对象、控制权、站位、资产与上游一致；
- 至少一个人物选择改变战场或任务；
- 每台承担主镜头的机体都有不可替换动作；
- 关系通过场面发生，叙述者不替人物宣布结论；
- 话末状态能够直接发动下一话。

章节合并后还要重新连续阅读。单话通过不代表章内没有重复结构、能量衰减或关系孤岛。
