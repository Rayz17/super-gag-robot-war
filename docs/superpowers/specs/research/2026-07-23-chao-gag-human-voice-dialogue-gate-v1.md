# 《超GAG机器人大战》人类声线与去AI味生产门 v1

> Status: `project_working_method / non_canon / skill_migration_pending`
>
> Date: `2026-07-23`
>
> 用途：解决台词、梗概叙述和动作括注长期出现的同声、工整、抽象、解释腔与“像编剧替所有人说话”的问题。它不是给文本撒语气词，也不允许用文风润色掩盖设定、因果和人物动机错误。

## 一、上一轮为什么低估了它

外部项目确实普遍设置了去AI味或真实性环节：

- `Chinese-WebNovel-Skill`把它放在动机、人物、转场和对白之后，避免用文风修改掩盖上游错误；
- `chinese-novelist-skill`用角色有限认知和反抗大纲，减少人物替作者发言；
- `oh-story-claudecode`检查元文本、重复、退化和AI句式；
- `vibe-noveling`使用多项AI味清单和语言密度校准；
- `Novel Control Station`强调真实性、分析腔和术语清理。

先前方案因为这些项目的自动检查大多只是关键词、比例或浅层规则，便把去AI味降成末尾lint。这混淆了两件事：

1. 自动工具不能可靠判断人物是否像人；
2. 人物同声和生成腔因此不重要。

第一点成立，第二点不成立。本项目已经反复出现同一类失败，因此必须把**语义声线审查**升为正式生产动作；机器检查只是旁证。

## 二、本项目的AI味不是一个问题，而是十二种问题

1. **同一个深沉编剧**：纪存、七海、白鸢、唐胶、韩秀雅都使用相同的短句、对偶和价值判断。
2. **责任结算腔**：`算我的`、`我替你背`、`你可以X但别替我Y`、`今天先X但别Y`。
3. **否定式作者辩护**：`没有把X说成Y`、`不是为了X`、`没有让X替Y`，叙述者替读者预先解释“正确理解”。
4. **技术Cookbook入侵感情**：`锁、槽、锚、语法、权限、路由、接口、亮灯`被所有人当作隐喻。
5. **人人都是金句王**：每句话都短、完整、可截屏，没有口误、绕弯、重复、无效试探或普通话。
6. **抽象名词替代欲望**：角色谈主体、边界、选择、责任、证词和可能性，却不说眼前的人、东西与害怕失去的事。
7. **没有具体听众**：一句话换给任何角色、任何场景仍然成立。
8. **全知式理解**：角色迅速理解机制、对方动机和主题，没有误听、猜错、嘴硬或只懂一半。
9. **括注替演员表演**：`若有所思、意味深长、眼神复杂`直接宣布潜台词；动作不改变距离、物件或决定。
10. **语言节奏平均**：人人两三句一组，长短、停顿、抢话和信息量相似。
11. **情绪过分正确**：人物总能体面地表达受伤、边界和歉意，没有迁怒、回避、嫉妒、羞耻、笨拙和事后后悔。
12. **场尾自动总结主题**：每场都用一句漂亮结论收口，缺少被打断、悬着、说错或只做不说的余味。

## 三、它在生产线里的位置

```text
章级总纲与场面合同
-> 关键场表演与对白简报
-> 相关角色有限认知私稿
-> 单一主笔完成场面初稿
-> 因果与信息来源复核
-> 角色声线分离
-> 人类声线/去AI味语义审查
-> 确定性lint
-> 朗读与换名测试
-> 单一主笔定稿
```

不能颠倒顺序：

- 设定说不通，退回设定或预生产模型；
- 人物没有欲望，退回角色沙盘；
- 场面没有压力，退回场面合同；
- 只有这些都成立，才处理台词和文风。

## 四、写前的表演与对白简报

关键ADV、关系场、喜剧场和高风险战中通讯只写一页以内：

```text
场面正在发生什么：
谁在逼谁回应：
甲此刻要从乙身上得到什么：
乙此刻要躲开什么：
双方知道、误以为和不知道什么：
公开议题 / 真正压力：
两人手上各自在做什么：
身体距离如何变化：
哪句话不能说出口：
这个角色本场允许使用的词和句长：
这个角色绝不会使用的作者词：
必须由动作而非对白完成的事：
离场时谁得到行动权，谁还误会着：
```

简报不预写金句。它只给台词制造听众、压力和不完整性。

### 4.1 章内新增角色的微型声线卡

重要说话角色若尚未进入全局声音Bible，不得直接靠国籍、职业或人设形容词临场写台词。先建立一张章内微型声线卡：

```text
她最先注意什么：
普通状态的句长与礼貌：
压力下会变快、变短、变绕还是沉默：
幽默来自哪里：
对本场听众使用什么称呼：
手上不会停下的动作：
会说的具体词：
绝不会使用的作者词：
一句隐名后仍能认出她的测试句：
```

微型卡只在本章生效；角色后续持续登场时再迁入全局声音Bible。仅写“成熟、冷静、热血、毒舌”不算声线。

## 五、角色有限认知私稿

只让每名相关角色看到自己知道的事实，并各自回答：

1. 我以为现场正在发生什么；
2. 我现在最想让对方做什么；
3. 我最怕对方问哪件事；
4. 我会先说正题、岔开、装懂、装不在乎还是先动手；
5. 我可能把哪件事理解错；
6. 我真正想说却说不出口的半句话；
7. 我说话时手上不会停下的动作。

私稿只提供行为压力，不能直接拼成正文，也不能让角色发明世界规则。

## 六、两次不同的改写

### 6.1 声线分离

逐角色处理，不一次润色全场：

- 读取该角色声音卡、文化、职业、年龄、关系和当下体力；
- 保留她会注意的具体东西，删除她不会使用的作者术语；
- 让不同角色拥有不同的句长、转折、礼貌、攻击方式、笑法和沉默；
- 允许某人把重点说错，让另一个人不得不回应；
- 保留机器角色的数字、条件和逻辑异感，但不让所有人机器化。

### 6.2 人类声线

整场处理，重点不是“更口语”，而是：

- 把结论退回欲望：这句话想逼谁做什么；
- 把一半信息交给动作、物件、停顿或对方误解；
- 把抽象名词换成现场的人、机体、伤口、饭、衣服、工具和称呼；
- 打破过分整齐的句式与轮流发言；
- 删除作者替读者作出的正确解释；
- 允许无效试探、听错、嘴硬、改口和不及时的道歉；
- 让场尾留下行动、距离或误会，不自动留下格言。

## 七、五个验收测试

### 7.1 隐名测试

遮掉角色名，只看台词和动作，核心角色是否仍能被辨认。不能辨认便回到声线分离。

### 7.2 互换测试

把两人的台词互换。若场面仍然成立，说明台词只在传递作者信息，没有属于角色的欲望和表达方式。

### 7.3 听众测试

每句话能否指出具体听众，以及说完后希望听众做什么、误会什么或感受到什么。没有听众的主题句优先删除。

### 7.4 关声测试

关掉语音和字幕，玩家仍应看懂发生了什么；重新打开台词后，玩家才更懂人物为什么这么做。若台词承担物理机制，退回上游。

### 7.5 朗读测试

真实读出整场。检查：

- 是否每个人都在同样位置停顿；
- 是否一句话长得无法自然换气；
- 是否连续多句都像标题；
- 是否角色明明激动却完整说出三层逻辑；
- 是否括注只是在解释语气。

## 八、机器能做什么，不能做什么

机器可以报警：

- 已知责任结算模板；
- 高频`不是X而是Y`与`没有把X说成Y`；
- 同章跨角色复用同一句型；
- `锁、槽、锚、语法、权限、接口、亮灯`等词异常集中；
- 连续短句长度过于整齐；
- 人物台词中的制作层字段和元文本；
- 重复标题、占位符、截断和退化。

机器不能宣布：

- 台词自然；
- 人物有魅力；
- 潜台词成立；
- 方言、语气词或虚词达到某个比例便像人；
- 没有命中正则便已经去AI味。

机器输出始终是`pass / advisory / block`中的工程证据，不是文学评分。

## 九、隔离上下文的声线医生

台本初稿后，由一个不参与正文起草的声线审稿上下文只读取：

- 当前场面合同；
- 出场角色声音卡；
- 角色有限认知私稿；
- 当前场面正文；
- 本项目真实坏句回归表。

它只返回：

```text
行号 / 说话人：
症状：
为什么不像这个人：
它是否其实是上游因果问题：
应恢复的欲望、听众或动作：
一至三种局部方向：
```

它不重写整场，不新增设定，不替角色统一成另一种“更文学”的AI声线。单一主笔根据证据修订。

## 十、回归基线

配套[人类声线真实回归表](../data/research/dialogue_human_voice_regression_cases_v1.tsv)同时保存：

- 用户明确否定过的坏句与坏机制；
- 用户认可的自然改写方向；
- 无法由正则判断、必须语义审查的同声案例；
- 可以被机器稳定拦截的模板案例。

新流程必须让坏例失败、自然正例通过。只在旧句外面加`啊、呢、吧`、省略号、方言、口误或括注，不算修复。

## 十一、迁移裁决

本门立即进入项目级第四层之后、Episode Reader与台本之前的生产方法，并进入C04/C05后续演出与对白验证。

正式`chao-gag-writing-pipeline`与Episode Loop仍按既定门槛：C04阻断关闭、C05回放能够抓错且不误杀后，再统一迁移。这样既不忽略长期台词故障，也不把未经验证的新流程直接扩散到全剧。

C04语义回放另见[《C04人类声线语义回放》](./2026-07-23-chao-gag-c04-human-voice-semantic-pilot-v1.md)。它证明确定性扫描只能找到两条表面警告，而人工声线审查还能发现新角色缺少声音卡、关系场由叙述者代演、作者预先辩护和对称机锋等更关键问题。
