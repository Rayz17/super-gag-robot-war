## 一、先修正测试前提

C01-C03不是金标准。它们只是已经取得较好读感、且用户曾确认可以继续使用的Creative Working稿。

“确认过”只改变修订方式：

- 发现问题仍要如实记录；
- 只有控制权、空间、因果、连续性等根因才立即改；
- 表演、对白、IP辨识和资产警告进入下一层；
- 修改必须说明保住了什么、损失了什么；
- 不得因为用户曾接受而自动判优，也不得为了证明流程有效而整章推倒。

这次统一回放证明该前提必要。C01真抓出路线时间不足、G.A.G.求救缺实体载体和陆衡临场出现；C02-C03也各自存在权限表现、场面过载、动作量级和语义AI味问题。

## 二、总裁决

新生产线可以进入正式Writing Pipeline与Episode Loop，但只能以：

> `PASS_WITH_MIGRATION_CONDITIONS`

迁移，而不是宣布“C01-C05全部过关”。

它已经证明能做三件旧流程做不到的事：

1. 在扩写前锁定主体、控制权、空间、尺寸、现实执行者与玩家可见证据；
2. 对用户确认稿仍独立找错，对Candidate也不靠追加术语补洞；
3. 在C04关闭U盾分身与假路线无执行者，在C05前向发现授权链复活、遥控与外运混写、百相未装舰便离场等真实问题。

它尚未稳定解决两件事：

1. 高密度设定怎样压缩为玩家一次能懂的表演；
2. 人物怎样说人话、产生欲望冲突和关系吸引，而不是提交责任报告。

所以预生产校验通过不等于Reader通过。C01-C05的结构可继续使用，五章Reader都仍需接受语义人类声线门；C04-C05尤其不得直接由当前第四层总纲自动扩写。

## 四、五章共同暴露的根因

### 1. 反派发动机重复

平台、衡令、战装局和后续白框很容易都被写成“把复杂个体压成统一标准”。立场可以相通，戏剧动作不能相同。

后续每个长期对手必须拥有不同的欲望、受益者、可取之处和胜利方式：

- 平台靠价格、注意力和玩家共谋；
- 衡令靠城市确实需要稳定运转；
- 战装局靠战争时间压力与公共防卫；
- 白框才使用真正牺牲机魂的平行演算；
- 索引追求全宇宙尺度的可压缩解释。

### 2. 胜利总被立刻开账单

五章都倾向在高潮刚结束时马上说明代价，削弱玩家拥有胜利的时间。代价仍需存在，但要区分：

- 当场享受的完整胜利；
- 章末才显影的后果；
- 数章以后被对手利用的长期反噬。

并非每次胜利都要证明主角刚才做错了。

### 3. 人物常在设计正确流程，而不是追求想要的人和事

纪存、七海、白鸢、陆衡和唐胶经常表现为聪明的制度设计者。成立，但不足以支撑长篇魅力。

每章导演板必须新增一条真正的人物发动：

- 他现在最想抓住谁或什么；
- 他愿意为此冒什么不理性的险；
- 哪个选择会伤到最在意的人；
- 即使章级议题不存在，他仍会不会这么做。

### 4. 机体很精彩，拥有感不稳定

不少机体完成一场漂亮功能便离场，玩家难以形成“这是我的主力”的情感。后续结构要区分：

- 永久入队；
- 路线协力；
- 敌我往返；
- 章节客将；
- 只作名场面投射。

首登时就应让玩家知道自己可能怎样再次拥有它，而不是到结算才宣布。

### 5. 后台正确性被直接写进前台

作者越怕误解，越会让旁白和人物把机制、责任与主题重复解释。结果是逻辑变清楚，戏却变硬。

正式流程必须执行：

> 后台知道十件事，前台一场只要求玩家理解一个控制变化。

其他事实通过位置、重复出现的物件、动作后果和下一场回收建立，不在同一场讲完。

### 6. 去AI味不能由正则承担

本轮确定性扫描对C05给出零问题，独立语义审稿却把C05判为Reader层Block。这不是工具失败，而是边界证明：

- lint适合抓固定句式、技术密度和重复词；
- 语义审查才判断作者辩护、同声编剧、责任报告腔、假文艺、人物是否有听众；
- 最终必须经过隐名、互换、关声、朗读和有限认知测试；
- 用户确认、字段齐全和脚本PASS都不能替代文学判断。

## 五、对正式生产线的迁移要求

### 必须新增

1. **接受稿不等于金标准**：Working只提高改写阈值，不关闭审查。
2. **最小上下文编译**：每章只读取必要事实、上章出站与未来保留项。
3. **章级实体、空间与行动预制包**：人物、机体、敌人、能力、空间、动作和资产先灰盒。
4. **前台信息预算**：每场只锁一个必须理解的因果变化。
5. **故障路由**：控制权回预制层，空间回灰盒，欲望回章引擎，台词回表演层，不准用新术语补洞。
6. **角色有限认知沙盘**：人物可以误解、拒绝和打断作者安排。
7. **表演稿先于对白稿**：先写谁看谁、谁靠近、谁躲、谁打断、谁不回答，再写台词。
8. **语义人类声线门**：独立于lint，由角色审稿职责检查。
9. **单一主笔**：审稿职责只提证据和根因，不分别向正文塞规则。
10. **C01-C05回归集**：把本轮真实故障作为Pipeline测试，不使用理想化样例。

### 不应新增

- 每章另造四五份重复说明文；
- 为每个警告立即重写正文；
- 让十几个审稿职责分别改稿；
- 用百分数、评分或全绿表格宣布文学质量；
- 把所有轻量关系章也强制制作完整机体预演。

常规章的上限仍是：

> 一份可读预制模型 + 一张机器表 + 一份审查结果。

轻量章允许把预制直接并入导演板；只有多尺寸巨体、新能力首用、变形、三方混战或复杂空间章才强制做灰盒和关键帧。

## 六、迁移结果与下一步

独立物理与制作复核已经确认C05四项修复全部`PASS`：半拔接驳、吊台提前入镜、三状态并列和百相完整装舰均不再有开放的物理或控制权矛盾。

上述迁移与工程闭包已经完成：

1. 十项要求已迁移进正式`chao-gag-writing-pipeline`与Episode Loop v2.4；
2. C01-C05已登记为语义、因果和控制权回归案例，而不是内容范本；
3. 生产状态、研究索引和Design Graph已同步；
4. C04预制与Creative Compiler、C05预制、对白fixture与五章扫描、Canon authority和Canon smoke均已复跑；
5. C04为`37 approved / 6 warn / 0 block`，C05为`32 approved / 7 warn / 0 block`；两章都只获得第四层有条件通过，不获得Reader许可。

当前唯一合理的下一次试验，是先用C05完成一小段“章级演出承载 -> 场面表演编译 -> 单话Reader -> 语义人类声线审查”。它要证明新流程不仅能抓错，还能把复杂设定写成自然、好看、可制作的戏；通过以后再决定是否进入C06。

这次测试的价值不是证明五章都写对了，而是证明新方法能区分：

> 哪些问题应该在写故事以前消失，哪些问题必须由真正的写作来解决。
