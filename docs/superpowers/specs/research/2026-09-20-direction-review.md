# 超改方向诊断：为什么投入没有转化为作品，以及哪些东西值得留下

2026-09-20。研究与讨论材料，Candidate。依据本轮项目原文、代码、公开案例实际操作、实况与作品视频的有序画面分析。没有改写剧情、修改玩法、切换引擎或启动新制作。

**9 月 21 日补充及后续纠正：** 此后形成的[具体制作建议](/Users/rayz/Documents/超gag机器人大战/docs/superpowers/specs/research/2026-09-21-concrete-production-proposal.md)已被用户否定其产品定位与缩减方向，不能作为当前制作依据。用户重申玩梗、熟悉 IP 故事与名场面变奏、跨作品互动、模玩与机甲文化讽刺是核心价值；缩成平凡的机战模仿作品不构成可接受的方案。该提案中的战斗数、机体数、时长及地球阶段上限已撤回。新增的 B 站 3D 视频和同名开源游戏仓库核查仍保留为研究事实。未实施剧情或游戏修改。

**先回答最重要的问题：你拿朋友一晚做出的坦克游戏作比较，是合理的。它检验的是投入有没有及时变成能感受到的游戏体验。三个月后仍无法稳定提供这种体验，不能用“我们目标更大”来解释过去。具体方案、参考研究和取舍由我承担，我此前没有做好这些工作。**

现有证据指向的是制作判断和工作顺序出了问题；它不足以证明你没有策划能力、没有想象力，也不足以证明这个题材不能成立。与此同时，“已经投入三个月”本身不构成继续投入的理由。

**这份报告能支持什么。** 坦克、NEON CITADEL 和 Paper Route 有本轮实际输入与画面结果；商业游戏有下文标明区间的实况观察；故事研究结合事件全貌、具体场景和完整故事段落。视频采用本地有序抽帧、关键处加密和画面字幕核读，没有听辨原声，不能冒称实时影音观看或亲手体验商业游戏。《超越视觉》仍有未看视频的篇目，《剑风传奇》后续只有文字背景；《法芙娜》已补完系列主线解说，但没有逐集研究全部正片。下文给出有依据的诊断与优先方案，**不把它包装成已经验证的“最佳组合”**。

**一、三个月主要消耗在哪里**

| 问题 | 本项目可核对的证据 | 我的判断 |
| --- | --- | --- |
| 把“组织得完整”当成创作成功 | 当前梗概把人物、阵营、旧案、主体权利和跨地区行动组织在一起；不少段落紧跟着说明人物不是什么、事件不能意味着什么 | 文本优先回答审查者可能提出的反驳，读者的好奇、偏爱和惊讶被挤到后面。把解释补齐，不会自动增加人物吸引力 |
| 从设定推出过多必备机制 | Fable 早期方案强调身体限制与协作；后来的 v3.4 已允许正面会战、强力组合和战斗高光，但大量具体操作仍围绕朝向、抓握、站稳、牵引与承重 | 规则能表达机器人有身体，不等于这些规则适合成为玩家反复执行的主体。机甲指挥的快感没有稳定决定机制去留 |
| 评审失灵后继续加制作程序 | 8 月根审已记下多次“内部 PASS → 用户否决”，还记录过在章级方向确认前完成 1130 行演出规划 | 问题早已暴露。继续细化生产、回执和修复，容易让一个不值得展开的方案得到更昂贵的执行 |
| 参考研究受既有答案限制 | OG 综合结论明确写着不学 HIT%、防御姿态、气力门槛，以及不学动画 ON 的全屏舞台 | 当时的适配有既有设计边界，但这些边界本身需要重审。恰好把你重视的机战回报排除掉，研究就难以纠正原方案 |
| 美术成本花在高要求、低回报的地方 | 公式台反复修姿态、手点、脚点、遮挡和接触；9 月 19 日记录仍认定战斗体验未通过，新增章节验证包完成数为 0 | 为承重、搬运等动作支付连续身体表现的成本，却还没有证明这些动作值得成为日常玩法。技术难点和娱乐价值出现了错配 |

这里也要纠正两种过度归因。第一，不能说过去完全没有实机研究：9 月 18–19 日已经留下具体视频区间、返回操作和画面核查；问题是这些研究尚未有效改变核心取舍。第二，不能说所有工作都毫无价值：已有获验收的 Reader、规则内核和一些可复用实现。9 月的 C04 主笔稿也有[审读回执](/Users/rayz/Documents/超gag机器人大战/docs/superpowers/specs/story-runtime/effect-tests/C04-author-first-2026-09-05/reader-build/04-审读回执与C05交接.md)。但局部成果不能用来抵消你对整部作品和实际游戏的不满。

旧根审本身也不是定论。它把 C02 与 C04 的差异称为“唯一自变量是用户是否参与章级选择”，这不是有效的对照实验：章节、素材和具体处理都不同。因此不能把失败又推回“你应该更早、更细地选案”。我需要对具体创作和设计判断负责。

**二、坦克和你给的案例，究竟说明了什么**

我在[坦克对局](https://tapeouttank.vercel.app/fly/frozen.html?lang=zh-CN)实际进行了两次射击并输掉该局。操作本身也有下拉选项：移动、角度、力度。但选择指向一个清楚的问题——这发炮弹能否越过障碍击中对方；随后弹道、命中和生命变化把答案显示出来。我的两次射击都落空，对手两次命中结束对局。“一晚、没有计算机基础”是你提供的制作背景，我没有独立验证作者工时，也没有必要靠否定这个背景来回避比较。

![坦克实际对局结束画面](/Users/rayz/Documents/超gag机器人大战/output/playwright/direction-20260920/tank-shot2-result.png)

它直接说明：**菜单选择并不天然无聊；关键是玩家是否知道自己在争取什么，选择是否改变结果，结果是否值得看，以及失败后有没有一个想尝试的调整。** 我们的公式台让你看到的更多是安排与解释，机体能力的兑现不足。这比“有没有操作按钮”更接近问题本身。

NEON CITADEL 的本轮实际操作包括移动、建造 Pulse 和 Flak 两座塔、释放技能、观察敌群减少和暂停。只覆盖开局，未完成整波或整局，不据此评价长期平衡。文件代码使用原生 WebGL 2、Canvas 兼容绘制、程序化几何和 Web Audio，没有 Three.js 或 Blender 运行依赖。这里的效果来自统一的形体、色彩、光照、镜头、范围提示与战斗反馈。代码能确认当前实现，不能反推作者完整制作过程。[原始 HTML](</Users/rayz/Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files/RayzYang_d5b6/temp/RWTemp/2026-09/ac15e713d3fcfc1cf47fe6874d2c12a3/NEON_CITADEL_3_1.html>)

![NEON CITADEL 实际建造后的场景](/Users/rayz/Documents/超gag机器人大战/output/playwright/direction-20260920/neon-flak.png)

[Paper Route](https://www.paperroute.lol/play/)也实际操作了短段骑行、投递和暂停，完成两次投递，未完成一天或整周。它把方向控制、投递时机和可见命中放在前面。作者的[开发日志](https://www.paperroute.lol/devlog/)记录了 Blender 脚本道具、生成角色，以及对碰撞、镜头和控制的持续修改；页面本轮显示的投入统计还明确区分了人工与代理时间。因此可以借鉴它如何围绕实际体验迭代，不能把宣传中的“一句话”当作完整成本模型，更不能拿它的成本反过来替我们辩护。

四个微信链接本轮均核到了公开预览文字，**没有成功观看视频正片**。第一条 Godogen、第四条 Paper Route 已另找原项目；第二条开源游戏列表的具体仓库、第三条 3D 制作视频的完整原片仍未核实。没有把这两条算作已完成研究。

Godogen 的[源码与变更记录](https://github.com/htdt/godogen/blob/05cebffc8b10c5817e8a3db495b82e7b6004ab84/CHANGELOG.md)显示，它在 7 月删掉了多阶段规划、拆解、架构、场景等技能管线，改为较薄的运行说明，强调从运行中的游戏判断结果。这是一个相关反例：更复杂的代理流程不是更好游戏的必要条件。它的演示视频本轮未看，也没有安装、运行或证明它能替我们完成游戏。

开罗这些样本并没有靠“操作复杂”建立乐趣。它们将题材转换成玩家愿意扮演的角色：经理、教练、制作人；把大量现实工序压缩为少数有辨识度的决定。队伍、产品、比赛和收入又使决定可见。我们反复强调机体怎样站、抓、撑，却没有持续交代玩家作为机甲队指挥者怎样形成优势、怎样打出令人期待的表现。

OG 的 09:18 预测确认之后，画面进入该武器的完整动作，约 09:42 出伤害；11:08 又能看到玩家选动画 OFF，加速普通交火。**长演出可以成为玩家主动选择的奖励，快结算也有用途。不能将二者预先压成一种节奏。** 本轮看到了精神指令菜单，但没有充分证明某项精神的完整使用链，不据此编写数值平衡方案。

**四、剧情逐项诊断，和具体参考场面**

| 你的问题 | 原文核对后能说什么 | 需要改变的创作判断 |
| --- | --- | --- |
| 元素很多，像大杂烩 | 当前梗概确实承担大量人物、世界历史与阵营串联；局部也有生动生活段落，不能一概说没有戏 | 每一段先确定读者在追谁、等什么、怕什么；出场资格不应由设定覆盖率决定 |

**五、玩法、交互、画面应怎样组成一个方向**

我的当前优先建议是：**一支有个性、能打出独特效果的机甲队，参加直接而有取舍的战斗，再回到能看见同伴与战果变化的万机馆。** 这是待讨论的整体方向，不是本轮已批准实施的新规则。

| 可选方向 | 与你表达的期待的吻合 | 主要代价 | 当前判断 |
| --- | --- | --- | --- |
| 继续以承重、朝向、搬运和共同提交解题为主体 | 能突出身体协作；你已多次反馈重复负担、战斗感弱 | 规则、关卡和连续接触表现都昂贵 | 不宜继续按现有规模扩展；有趣的个别解法可以留下 |
| 改成以收集与万机馆经营为主体 | 能承接玩具文化、收藏与同伴生活 | 会改变你对亲自指挥机战的期待，经营内容也要另做 | 可作为另一款游戏的清楚方向；本项目现阶段不优先 |
| 改成直接操纵单机的动作游戏 | 力量反馈直接，容易理解短演示亮点 | 操作、镜头、碰撞、敌人行为与动画要求高，多机关系难自然进入 | 现有证据不支持为追赶网络演示而迁往这里 |
| 以直接机甲战术为主体，协作巧解与轻返馆生活作补充 | 同时回应机体魅力、战术控制、伙伴关系和收藏归属 | 要主动撤回一部分原有强制规则和内容负担 | **最值得保留并讨论的组合** |

这一组合中的各层有明确分工：

- **战斗决定什么：** 移到哪里、用哪种武器、集中火力还是保留资源、谁援护谁、何时使用一次强力能力。先让普通攻击和击破值得期待，再容纳特殊协同。
- **机体差异从哪里来：** 射程、机动、武器形状、范围打击、变形或合体、独特援护，以及角色自己的表达。身体特征应带来可利用的优势，也可以形成有限弱点；不要求每次出手先通过抓握与站稳检查。
- **环境解法放哪里：** 让聪明的推撞、掩体破坏、临时支撑成为少数局面的加分玩法。它需要产生明显的局势变化，不能只是任务要求再搬三次东西。
- **共同提交怎么处理：** 现有规则并非已经被证明不好，但全队安排完才能看见回报，会增加理解与等待。顺序执行和共同提交的取舍仍需具体局面比较，不能以现有内核已经实现来结束讨论。
- **返馆做什么：** 看见新伙伴、新位置、新展品和关系变化，完成少量有意义的整备与安排。让战斗和生活互相提供期待，不把返馆扩成七种日常清单。
- **故事怎样进入：** 人物的欲望影响出战、选择与关系；战后的人和物发生变化。人物需要普通相处和快乐，也需要矛盾。不能每场战斗都变成一道道德考题。

交互上的建议也应落到玩家眼前：选中机体即看到可达位置；选武器才显示相应范围；指向目标时把成本、效果和主要反击放在邻近区域；取消退回刚才那一步。提交后，移动、起手、命中、受创和结果在同一战局中能够对应。普通行动允许快速看完，第一次招式、强力攻击和关键合击有更充分的表演。日志负责补充，不承担主要打击反馈。具体 UI 仍要比较实际方案，本轮没有给出虚构的“统一最佳秒数”。

这会触及 [00c](/Users/rayz/Documents/超gag机器人大战/docs/superpowers/specs/game-design/2026-08-10-full-game-design-candidate-v1/00c-core-game-design-master-review.md) 中共同提交、卡牌和成长边界，必须作为方向问题明确讨论。不能一面说重新考虑玩法，一面继续把这些约束全视为不可动，再假称得到了新设计。

**六、美术与技术：目前不支持先换引擎，支持先减少表达上的互相为难**

你提到的立体码头演示来自 [dock_contact_space_probe.gd](/Users/rayz/Documents/超gag机器人大战/game-godot/tests/formula_lab/dock_contact_space_probe.gd:99)，使用 Godot 的 3D 相机、网格体和动作插值；基于已有一段执行结果作临时空间演示。它不是 Blender 渲染片，也不是 Three.js 页面，更不是已经完成的战斗系统。[既有演示与审核](/Users/rayz/Documents/超gag机器人大战/artifacts/formulas/production-lab-v1/qa/dock-field-20260919/root-review-v2.md)

![项目已有立体接触试验](/Users/rayz/Documents/超gag机器人大战/artifacts/formulas/production-lab-v1/qa/dock-field-20260919/space-probe-v2/0043_contact.png)

| 表现路线 | 适合什么 | 在本项目的风险 |
| --- | --- | --- |
| 二维图像、有限姿态与特效 | 肖像、少数有力的招式构图、固定视角下的简化单位 | 若同时追求多朝向、精确抓握和连续接触，就会持续增加分件、补画与遮挡修补 |
| 简化 3D 机体与场景、受控镜头，加二维肖像和招式插画 | 统一空间、可复用关节动作、战场移动与少量近景；保留角色美术辨识度 | 模型仍需分件、比例和动作检查；现有体块的成功不等于正式机体已可用 |
| 全自由镜头、高细节模型与大量电影式演出 | 近距离鉴赏和复杂动作 | 资产、镜头、表情、动画与性能的成本全面提高，当前没有采用依据 |

**我的倾向是第二条，并继续把 Godot 作为首选候选承载。** 原因是本地已能呈现统一体积和接触，已有规则和界面实现可复用；目前没有证据把主要失败归因于引擎能力。[Godot 官方 3D 导入文档](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/index.html)也支持从建模工具导入场景的常规路径。尚未做正式机体的动作、质量与总工时对照，因此这不是全 3D 迁移决定。

Three.js 可以构建场景、相机与渲染，但这些基础能力不会替代本作的交互、内容和表现设计。[官方入门](https://threejs.org/manual/pages/creating-a-scene.html)。Blender 更适合作为几何、分件、动作和导出的制作工具；它与 Godot、Three.js 不是同一层的替代选项。

AI 出图、图生模型或脚本建模可以减少起步成本。最终成本仍取决于同一角色换角度和动作是否一致、是否易修、能否进入实际镜头，以及以后新增一台机体要重做多少工作。这里应优先统一轮廓、比例、材质复杂度、光照与镜头距离。NEON 的启发是简单形体也能形成完整美感；这不等于把超改全部换成它的霓虹风格。

**七、该保留什么，哪些承诺现在不值得继续背着**

| 保留的理由 | 值得保留的内容 |
| --- | --- |
| 能形成题材辨识度 | 有历史、脾气和身体的机器人同伴；修复、收藏与共同生活的万机馆；机体之间尺度与能力的反差 |
| 能形成实际游玩期待 | 指挥不同机体打出不同效果；援护、合体、强力武器与少数环境巧解；战斗后能看见的成长和生活变化 |
| 已有具体作品基础 | 已获验收的故事段落、少数生动人物动作和关系；经核实仍有用的规则、状态保存、界面与空间试验 |

不值得因为沉没成本继续坚持的，是全设定必须入戏、每条梗概都要扩成一话、所有身体细节都要变成玩家操作、全部公式与长线系统在基础体验之前一起完成，以及内部评审通过即可持续放大制作。这些是取舍建议，本轮没有删除相应文件或改变既有验收状态。

我不建议此时再开一轮梗概改写，也不建议把公式台继续润色成更多包。当前讨论需要先解决：战斗中玩家究竟在追求哪种快乐，哪些规则应当让路，人物由哪些具体关系承担阅读兴趣，以及所选美术路线能否用真实机体达到期待。研究资料、候选设计和已经好玩的游戏是不同成果。

**项目是否值得继续：现行推进方式不值得原样延续；题材和少数具体核心仍有保留价值。** 是否继续生产，应建立在这些核心已经形成可信、具体的体验依据上。现在没有商业成功的证据，也没有足够证据宣判整个创意失败。你不需要为此前投入负责到必须把它做完，我也不能再把希望建立在下一轮更多 token 会自动带来突破上。
