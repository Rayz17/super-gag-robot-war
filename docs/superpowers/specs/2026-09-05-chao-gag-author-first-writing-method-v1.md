# 超GAG主笔创作与分层交付方法

状态：现行工作方法。用户授权：2026-09-05“按这个把写作方法改对，并制定一个写作计划”。

方法生效不等于新稿有效，不提升任何Candidate故事或替换用户验收。

## 一、创作与治理分开

先在独立Candidate区找到值得讲、能讲通的故事，再依法回填正式生产链。现有Story Chain保存正式证据和依赖，但不再要求作者先用完整生产板从零创造故事。

本轮可进行方法、工具与计划修订；不继续写C04E03、不覆盖C01-C03、不改C04已封产物、不修改游戏实现或美术。当前机器NEXT必须现场查询；用户对C04内容的否决仍是创作阻断，不能被READY覆盖。

## 二、资产怎样用

| 输入 | 内容 | 必须保留的边界 |
| --- | --- | --- |
| fact | 已验收前情、有效身份/能力、世界规律 | 事实与否定条件完整，不静默改动 |
| future_obligation | 章职责、未来高潮保留、下章接口 | 实现不是既成事实；重大结果调整先裁决 |
| creative_material | IP精神与情境、名场面、角色爱好、生活与梗 | 自助选用，不要求点名或逐项消化 |
| presentation_option | 候选空间、编排、载体 | 可以提出更好办法；已封存事实仍须迁移 |

每条输入指向原文和来源SHA。来源权威先由Canon入口核对；SHA只证明原文字节，不证明来源资格或语义分类正确。不能把文件名、更新时间、Working文档中的未来段落当作已发生事实。

L1提供作品体验，L2提供长期发动机，L3提供当前章与邻章职责。它们不要求逐话展示每个维度。H0和人物/机体资料在需要时查询；L4/L4.5的旧答案默认不进入新提案。旧稿只有在指定恢复高光或冷读后比较时读取。

有效来源不一致时，先裁清本次需要的部分，记录哪条有效、哪条待迁移。不能让主笔根据摘要自行猜答案。History保留，不参与默认当前事实检索。

## 三、一次实际创作

1. 看必要前情与当前职责，主笔决定谁想要什么、对手会做什么、故事为什么值得看。没有真正分歧就不机械凑三案。
2. 写简洁、连贯的章纲；同时考虑玩家能改变什么、固定结局与可选方法。先核对会推翻故事的常识、尺度与控制关系，不逐件造设备。
3. 新方法或高风险内容先试写最难的完整场面，未必是开头。普通已知段落不重复建立一套试验。
4. 同一主笔按授权范围完成纯剧情，不让多人拼接正文。长话按完整场面续写，继承局部状态与必要前文；不按模型还能输出多少字决定篇幅。
5. 冷读只看前情与正文，先复述再判断想不想继续。事实席另查资料，不用“设计上是这样”替正文解释。
6. 普通缺陷局部修；发动机或人物选择失效回提案。一次结构性返修仍失败就停，不进入无限补强。
7. 故事暂定成立后详细派生游戏解构与可选公开情报，再检验三层一致性、提交用户验收。

上述是职责，不是强制七次Agent。主笔可在同一上下文往返查询、规划、写作；只有声称独立冷读时才必须有真实隔离上下文与实际回执。

## 四、章纲、Reader和游戏的分工

章纲写人物选择、局势发展、主要战斗转折、高潮和去向。不要提前写全对白、逐个机械动作与镜头再扩写第二遍。关键场面可以先试写验证，选定后直接成为候选正文资产，不重复从头生成来耗费质量。

Reader写人在场面中如何行动与反应。机体战保留战斗目的、关键反击、大动作和结果；细节只在读者需要它理解戏时展开。机甲文化既包含世界规律，也包含驾驶、合体、必杀、精神、机体脾气、模玩圈笑话与共同记忆，不能只变成制度议题。

对白先看人物正在向谁争取什么、回应怎样改变下一句话。可以犹豫、闲聊、解释、直接答应；不让全员用一句酷话结束交流。人物模型提供倾向，不提供现场答案。

称谓与时间指代在写作时说准，完稿后复读一次。区分年代、损伤、停用、版本和既往关系，不把资料中的“旧XX”标签搬进正文；用途已清楚便用名字或简称，删去无作用的修饰。不为替换词语新编历史，不将“旧”改成另一套重复形容词。正式名称、必要的新旧对照与“旧件”等领域用语保留。执行细则在story-writer的`references/drafting-reader.md`，只占现有主笔复读环节，不新增文档配额或多Agent循环。

生活与玩梗可以增加熟悉感、亲近和趣味，不需要每次换得权限、救援或一笔关系债。不得取消本作成人关系、热血与Gag精神，也不要求每话每项齐全。

游戏早期共同构思，详细交付后派生。普通战斗要有玩家自己的有效办法，不只按指定顺序点几台机体。情境剧情动作可锁定戏剧结果，但不能把全部战斗都变成剧情动作。

正式解构保留跨话Operation、Encounter、Phase、Checkpoint和IncidentState；Episode不天然等于关卡。谁拥有动作决定、玩家可以改变哪一层、Full/Skip/Retry/Resume如何守住状态，属于后台接口，不写进小说。

公开资料只补玩家已见证的背景与机制，不负责拯救无法理解的剧情。

## 五、Runtime已经落地的接口

入口仍为`compile_story_runtime_stage_context.py`，新默认策略`author_first_v1`；旧自动宽装载只能显式指定`legacy_inspection`，其manifest永远`writer_ready=false`。

新请求用`source_cards`选择四类来源，必填`id/kind/authority/source/sha256/quote`。引文必须完整存在于绑定文件；重复ID、缺项、哈希漂移、历史冒充事实均阻断。权限/事实分类仍需人工语义核对，编译器不认证作者声明的权威。

明确选中的实体从当前Canon查，人物复用现有模型的戏剧核心和正面声线，不自动带入模型中的未来弧线或旧状态账。人物私有历史、当前关系、知识和场景在场性中会影响本次写作的事实，必须另以fact卡交代，不能用模型的Candidate关系边补答案。

硬事实、未来职责、选中实体与人物模型不截断。超过预算，主笔视图变为BLOCKED；先缩小查询、减少非必要人物或把写作拆到自然场面，而不是删限制。素材和呈现候选只允许整条省略，manifest与视图都显示省略ID。

冷读`review_scope=cold_reader`只允许`audience=known_prefix`和`reader_text`，不得装作者卡、实体模型、旧自动handoff或设计板；没有正文也阻断。首读事实来源由调用者核实为玩家已知，不把后台真相换个标签混进去。

`play_concept`是早期玩法概念阶段，不是详细gameflow。详细解构仍独立生成。

## 六、缓存与成本

上下文manifest绑定实际源、请求配置和编译器哈希；人物正面声线与小传源发生变化时，模型未重建则阻断。没有命中相关输入变更，不需要重建全项目所有包。

本次没有批量生成缓存，不清理他人的缓存或生产证据。历史包继续可追溯，但新请求不默认复用旧语义。只删除本轮临时测试目录；Reader、回执和历史样本不当缓存删除。

记录真实输入/输出、可获得的缓存/推理用量、耗时、返修和人工阅读。未知记UNKNOWN，不用字符估算伪装账单。流程增加一步必须有可观察收益。

## 七、正式Story Chain桥接

探索成果与正式稿件分化是有意的。计划必须标出唯一当前探索入口，旧正式链只提供已核实边界，不会因新样稿出现自动失效或更新。

用户选定方向后：列出与封存文件的差异和最早owner；重大方向/角色/机体/结果/跨章接口先裁决；再执行正规的invalidation，按既有依赖重建上游板与正式L4，逐话对接Reader和派生物。不得只刷新哈希、手改机械合章或重用旧用户验收。

这不是绕过正式门，而是把它从创意生成器恢复为生产整合与验证机制。本轮不修改机器阶段枚举与旧manifest，因此不存在虚报“整条链已经迁移”的结论。

## 八、方法验收

工具正确：来源、预算、隔离、指纹与失败行为有回归测试。

创作有效：同事实、同模型、相近预算下，比较直接主笔与候选方法；短场面只是第一关，随后需整话与游戏解构、不同任务再验证。若最简直接主笔更好，保留有效知识接口、删除无收益流程。

用户批准方法不等于批准C04提案或正文。机器PASS不等于故事精彩。
