# 《超GAG机器人大战》单话制作分层拆分规则 v1

## 目的

后续梗概、台本和关卡拆分不能再把剧情、战斗、探索、舰内日常和结算混成一段话。混写有利于第一遍找故事感觉，但不利于后续制作：美术不知道要画哪些场景，关卡不知道棋盘目标和触发器，台本不知道哪些对白发生在战斗内，程序不知道哪些变量在什么时候改变。

本规则要求每一话同时保留两层产物：

1. **可读层**：连续的剧情梗概或 Reader Synopsis，用来判断故事是否好看、人物是否动人、章节是否连贯。
2. **制作层**：把同一话拆成 ADV 剧情、探索/副玩法、SRPG 战斗、战斗内演出、舰内日常/关系事件、结算与状态变化六个制作段落。

核心原则是：**先写能读的故事，再拆制作层，不要用制作字段代替戏剧。**

## 六段制作层

### A. ADV 剧情段

用于非棋盘、非操作或弱操作的主线叙事：开场、压力到来、角色争执、出击准备、敌方宣告、场景切换、战前选择。

必须说明：

- 地点和背景资产。
- 出场角色、立绘/表情/动作需求。
- 本段冲突是什么，谁提出问题，谁被迫回答。
- 进入下一段的触发：选择、来电、警报、地图开启、敌方动作或物件变化。

常见错误：把 ADV 写成设定说明会；把角色对白写成任务简报；没有明确转入玩法的触发。

### B. 探索 / 副玩法段

用于残响深潜、馆内探索、修理、改装、开馆经营、听证、潜入、追逐、认证小游戏、展签编辑、观众引导等非 SRPG 主棋盘玩法。

必须说明：

- 玩法类型和操作目标。
- 可交互对象、道具、线索、失败或遗漏状态。
- 该段如何改变剧情、战斗条件、机体状态、关系、敌方样本或分支变量。
- 如果本话没有副玩法，写明 skip reason，不要空着。

常见错误：把“调查了一下”“深潜看到资料”当玩法；副玩法只给文本信息，不改变后续战斗或状态。

### C. SRPG 战斗段

用于主战棋部分。不是每话都必须大规模战斗，但凡有 SRPG 段就必须像关卡设计一样清楚。

必须说明：

- 地图：地点、尺寸感、主要地形、可破坏物、特殊区域、视野或高低差。
- 单位：我方、敌方、中立、NPC、支援、Boss、场景巨机。
- 胜利条件、失败条件、可选目标、隐藏条件。
- 关键规则：护送、撤退、非致命、说得、同步、合体、暴走、索引清噪、G.A.G.债务、远星错序等。
- 回合或阶段变化：第几回合、HP阈值、位置触发、选择触发、击坠/不击坠触发。

常见错误：只写“发生战斗”“保护展品”；没有地图目标、失败压力、敌方学习或中段变化。

### D. 战斗内剧情演出段

用于 SRPG 中穿插的剧情：回合开始对话、HP 阈值 Cut-in、援护台词、支援灰显、机体觉醒、Boss 变相、G.A.G.暴走、索引改写、远星误译、关系支援变化。

必须说明：

- 触发条件。
- 演出形式：Cut-in、通讯窗、地图动画、UI 噪声、BGM 切换、镜头、机体动作。
- 谁说话，谁听见，谁不知道。
- 演出后战斗规则或关系/变量如何改变。

常见错误：把战斗内事件写成战后总结；把关键情感台词放在不清楚触发条件的位置。

### E. 舰内日常 / 关系事件段

用于战后处理、舰内生活、维修间、饭桌、值夜、误会、成人关系积累、低俗机战日常、支援状态恢复、关系支线入口。

必须说明：

- 这是必触发、可选、条件触发还是路线事件。
- 关联的生活温度 hook 或 skip reason。
- 人物关系或性格感受有什么变化。
- 是否改变支援、权限、疲劳、维修、探索、开馆、分支或后续债务。
- 是否保留一个不立刻系统化的普通物件。

常见错误：用闲聊注水；把日常戏全部转成证词、债务或世界钥匙；让成人向内容接触儿童/少年线。

### F. 结算与状态变化段

用于把本话真正改变的东西写清楚，作为下一话的输入。

必须说明：

- 新入队、临时支援、隐藏条件、机体状态、装备、改装、损伤。
- 角色关系、支援状态、权限、内审/追责、舰内设施、万机馆空间变化。
- 敌方获得的样本、误读、封存、清噪模板、宣传材料。
- 分支变量、失败尊严、未回收物件、下一话必须回答的问题。
- 制作资产增量：新场景、新机体、新 UI、新 Cut-in、新音效/BGM、新地图机制。

常见错误：只写“留下债务”；没有下一话可读取的具体状态。

## 单话推荐结构

```markdown
## CxxExx 标题

### 本话功能
### 可读剧情梗概 / Reader Synopsis
### 制作拆分

#### A. ADV剧情段
#### B. 探索/副玩法段
#### C. SRPG战斗段
#### D. 战斗内剧情演出段
#### E. 舰内日常/关系事件段
#### F. 结算与状态变化段

### 机体出场
### 燃点 / 爽点 / 梗点
### 情绪与关系
### 分支与债务
### Clear State
```

如果一话是纯日常、纯听证或纯探索，也仍然需要保留六段结构；不用的段落写 `not_applicable` 和原因。这样后续制作才能判断它是刻意不用，而不是漏写。

## 已成稿修订方式

修 V31 或其他已成稿时，不建议先整章重写。优先做“制作层补拆”：

1. 保留原有可读剧情，不急着改故事。
2. 在每话后补 `### 制作拆分`。
3. 把混在剧情段落里的战斗、触发、日常、结算信息搬进六段。
4. 若发现某段为空且没有合理 skip reason，才回到剧情本身补场面。
5. 若 SRPG 段、战斗内演出段或舰内日常段补不出来，说明原话不是“没拆”，而是设计确实缺玩法或角色场。

这套规则的重点不是把文档写长，而是让每一话都能同时回答三个问题：

- 玩家读起来发生了什么。
- 玩家玩起来具体做什么。
- 制作团队需要准备什么。
