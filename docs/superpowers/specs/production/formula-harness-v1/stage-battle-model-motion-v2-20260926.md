## 当前可试玩的改动

- 纪存、白鸢的地图角色改为实时三维骨架模型。衣物、手、脚、持书及腕端设备跟随同一骨架；移动方向直接转动模型。各自导出 Idle、Walk、Stop、Turn、Observe 五个动作片段。对白继续用已有正常比例立绘。
- 检修铺改为 Blender 建筑资产：墙体、门洞、窗框、瓦楞屋顶、钢架、排水、柜台、工具、桌椅、推车、油桶与盆栽。人高约 1.86 米，门口净高 2.1 米；巨型馆守仍按 18 米呈现。人物实际通过门洞进入，进入后收起屋顶，退出后恢复。
- 前场可点地移动、方向键移动、左拖转镜、右拖平移、滚轮缩放；拖动不会顺便发出走路命令。相机、人物与场景同处真实三维空间。
- 馆守沿用 V10X 候选造型，补做并导出待机、步行、左拳推进、架护与受击动作。明确保留缺失的原右前臂；`Knuckle_R` 是旧模型断口处的兼容挂点，不是右拳。
- 馆守动作消费已有战斗结算时序，保留接触修正与支撑脚校正；没有另起命中判定，没有修改 V6 规则或冻结的 V8 对照源码。
- P 仍是可操作前場 → 实际战斗 → 真实战后回应的连续包。选择突围或破阵会进入对应任务，预演不写战果，重试会清理上一局的特殊招式、接力记录。

## 资产与制作证据

可修改源文件：`artifacts/formulas/production-lab-v1/source/stage-battle-v2/`，含两名人物、检修铺、馆守动作的 `.blend`、构建脚本及动作报告。运行资源：`game-godot/assets/formula_lab/stage_battle_v2/`。具体来源与 SHA 见该目录的 `provenance.json`。

本轮用了 Blender 4.4.3 和 Godot 4.7。Meshy 登录页能读取，但模型选项的控制没有成功；**没有用 Meshy 生成、下载模型或消耗额度**。本轮模型在本机 Blender 制作，不能把网页访问写成 Meshy 生产成果。人物设计图由图像生成工具提供比例参考，实际网格、骨架与动作另外制作。

导出检查发现并修复两类实际错误：曲线转换误应用相邻网格的蒙皮修改器，导致手部和脚跟未随骨架；GLB 默认优化删除刚性节点的恒定动画轨，使架护姿态缺少关节数据。现在限定转换选择，并保留完整刚性动画轨。

实机证据在 `artifacts/formulas/production-lab-v1/qa/stage-battle-20260926/asset-v2/`。`runtime-check.mp4` 是 Godot 自动检查的连续录制，覆盖四向移动、入屋、屋顶遮挡和馆守姿态；录制使用固定时间步，不代表真实帧率或用户体验通过。`input.log` 是经真实宿主窗口与子视口注入键鼠事件的检查；不是人工试玩。
