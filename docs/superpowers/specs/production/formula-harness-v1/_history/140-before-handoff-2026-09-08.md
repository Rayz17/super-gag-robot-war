## 1. 完成后应得到什么

**得到基于现有 Godot 工程的超 GAG 专用游戏框架与内容生产系统：金标级的七种可组合公式、可用的配置/资产工具，以及从输入诊断到可玩内容包的生产闭环。实验室是检验这些能力的工作台，不是最终只交七个样片。**

每个公式都要同时提供：

1. 一段可走完的代表性体验，含开始、玩家判断、行为反馈、结果与退出。
2. 至少两份有实际行为或空间差异的 JSON 配置；不能只是换名字、背景色和数值。
3. 配套场景、角色/机体、台词、UI、声音与演出；临时资产也须有清楚身份、空间关系和状态区分。
4. 可替换资产与可复现构建源；坐井台能解释并调整图放在哪里、脚落在哪里、遮挡谁。
5. 同版本真实操作轨迹、关键帧、状态结果与未通过项。离线图、程序测试、制作者自评和用户验收分别记录。

### 1.1 轨 A/B 的共同终态与边界

- **轨 A 做可复用能力与金标样例**：七公式各自的玩法、交互、UI、美术、台词、角色演出与声音要形成完整体验；配置应表达目标、空间、参与者、触发、状态后果等实质差异，不能把固定样片改名就叫复用。
- **轨 B 做输入诊断、适配与生产**：接收 Reader、已有玩法结构/解读及资产目录，识别所需公式与组合、来源冲突、缺失设计信息、资产规格和引擎能力。只有 Reader 时也应能列出缺少的玩法解读并提出有来源的候选适配，不冒充已有完整设计。
- **系统承担生产转换工作**：对已明确的设计生成可编辑的公式配置、场景/流程编排、状态连接和资产绑定；布局、镜头、对白时机等制作细化可以提出候选并预览，不要求用户预先手填所有坐标、镜头、字段，也不能只校验路径后把制作工作全部退还用户。新的故事结果、核心玩法或身份裁决仍交用户。
- **补充后能够真正生产**：缺口报告逐项说明缺什么、源自哪个场景/玩法需要、用途与最低规格、由谁补、是否阻断及合法回退。补齐后重新诊断，按已验证公式构建可玩、可编辑、可重建的内容包；报告不能替代实际产出。
- **范围不绑定章节**：C01/C04 或任何 Reader 只是一次调用的输入，不是公式台的状态、开发前提或验收终点。可先用非正式 Lab 素材验证管线，不因此启动第一章。七公式的组合与配置产生不同玩法结构，但未实现的新机制必须显式回到轨 A 补能力，不能声称支持任意玩法。

这条闭环的完成标准是：**读入素材 → 可解释的公式/流程适配 → 可行动的缺口清单 → 补充或裁决 → 配置与资产编排 → 可玩包及修改后重建**。这恢复并落实 137 已有的两轨责任，不新增通用编辑器或全自动故事创作平台。沿用既有四件套和验收边界；可在隔离 Candidate 中验证尚未冻结的接口，但不得冒充正式量产或绕过冻结门。本目标不修改 Reader/Canon，不自动升正式 Runtime，也不承诺已经完成全游戏。

## 5. Blender 在管线里具体做什么

本轮用户授权范围：**全新 Formula Lab Candidate 环境与空间资产**。用 Blender 建立道路/建筑/房间、相机、照明、投影与地面材质；输出供 Godot 消费的 2D 绘景、遮挡层、接地点与相机数据。暂不迁移 Godot 为 3D 引擎，不制作新馆守 Z 三维机体，不复活失败资产。

独立可复现源：`artifacts/formulas/visual-targets-v1/blender/`；离线渲染：`artifacts/formulas/visual-targets-v1/renders/`。只有明确登记的导出 PNG/配置进入实验室资源目录。这是记录新授权，不是规避或全局放宽旧 C01 失败来源检查。

统一场景流程：

1. 由游戏配置确定世界尺寸、可行走区、阻挡、格位/脚点、画幅和镜头；先注册空间，再生成精细环境。
2. 同一场景建立规划与接触机位，导出分层景、相机矩阵、可见地面/遮挡数据。远景不承担碰撞；建筑占地不得与可走格冲突。
3. 人物/机体仍以独立透明图、姿势与动作资源呈现；保持一套身份/比例表，不靠不同生成帧互相猜测。常态地图 token 与正比例 cut-in 不混用尺度。
4. Godot 根据同一玩法状态画路径、威胁、机体和 UI；这些不能烘死在底图。短视频/LibTV 只作为可替换峰值段，必须有同结果静态回退。
5. 在实际游戏画面验接地、遮挡和可读性；离线景渲得好不等于接入成功。

第一刀采用低机位钢青湿沥青 `tile-chrome` 接 `execute_pad`，不是把等距地图砖拉伸成近景。后续完整街区必须接入明确的世界到屏幕变换，不能把两个漂亮机位随意贴到旧棋盘后面。

本轮首个注册样本是 **TAC_T3 城市擂台**：保持原 7×7、49 格开放、`ring_out=true`、terrain 与胜负条件。周边街区只提供尺度和空间环境，不能称为已新增可玩道路、户外滚动地图或修改了擂台规则。其它战术档与更大地图按各自配置另行适配。

### 6.1 金标与复用双主线（2026-09-07 用户再次校准）

**不是“先无限打磨一个样片，将来再考虑引擎”，也不是“先堆通用设施，以后再补好玩好看”。** 每个完整增量同时交代金标体验、可复用能力、输入诊断/生产闭环三方面的贡献；可以分步实现，但不能只证明其中一面便关闭该公式。原地复用已有效的内核、资产、工具和验证，不推倒重做、不降低七公式完整范围。**复用不等于保留错误的 Candidate UI 或场面设计**：不改变已定事实、身份和核心规则的表达替换，由制作人主动判断并实施，不能只沿着旧结构做微修。

派发前由制作人先确定完整玩家流程、空间/镜头组织、表现分层及必要资产，再拆实现任务。每个任务必须指出它关闭哪个体验或复用缺口，如何在完整段落中验看；局部测试通过只关闭对应工程问题，不能把最终设计判断交给实现者自行补齐。

1. **先定位能力缺口，再选代表案例。** 在既有第4/6节矩阵及当前入口中简明列出七公式的金标体验、第二输入换料、轨 B 可诊断/可生产状态与最大缺口；不重建合同体系。以影响整套框架的实际瓶颈排序，而非把最近的 T3 美术问题永久当作整个项目的下一步。

## 7. 质量门：什么情况下才值得给用户玩

现有质量门按两个时点执行，不新增文书关卡：**精修前先审场面/交互方案是否成立，交付前再审整段实玩与工程正确性是否同时成立。** 构图、画面精度和工程正确都不能抵消错误的场面组织。纯调试包可以用于诊断，但须明确未达到体验评审资格；不得将技术通过或局部精修累计成金标通过。

- **玩法**：玩家能知道目标、合法操作、公开风险与结果；设计上允许取舍的档不能退化为顺着提示按唯一按钮。WR_T0 固定目的地只查看并承担已定任务，不为达标伪造自由选项，路线比较由 WR_T1/T2 证明。摘要不锁世界，执行不可偷偷改计划。
- **空间**：建筑占地/可达格/道路同源；机体脚点与阴影落地；跨机位身份、相对位置、受力方向和尺寸关系一致。
- **美术**：轮廓与脸清楚，机体身份稳定；准备/受力/余波至少姿态或重心显著不同，不能仅改颜色；无草图、抠图黑边、浮空贴纸和占位标签混入体验画面。
- **交互**：默认画面保留地图；信息按需展开；鼠标与现有键盘路径一致，焦点、取消、长按、不可操作状态都有清楚反馈；1280×720 与 1920×1080 检查遮挡、缩放与文字溢出。
- **演出与声音**：起手、接触、停顿、余波、回盘能辨认；声音对应发生的动作；可同结果跳过，缺媒体可静态回退，不拿震屏/白闪掩盖没动作。草案与界面可以返回，但提交后的回盘不撤销世界结算，不提供免费倒带。用户未另行授权前不花付费额度批量生成。
- **证据**：测试 PASS 只证明被测内容；RGB 计数只做回归。截图必须来自记录的真实状态，不能用离线图替代运行帧。用户视觉验收始终由用户给出。
- **复用与生产**：每公式至少两份实质不同的配置；至少两份多公式输入包能在已支持能力内不改公式代码完成生产。缺项能准确诊断并在补齐后重新构建；包可编辑、可重建且跨段后果真实传递。不能只换皮、改硬编码脚本或只生成报告；七个样片通过也不代表轨 B 自动完成。

制作者连续两轮修正仍未解决同一体验问题时，回到空间/玩法/构图假设检讨，给出可比较方案；不无限微调色值并宣布越来越好。
