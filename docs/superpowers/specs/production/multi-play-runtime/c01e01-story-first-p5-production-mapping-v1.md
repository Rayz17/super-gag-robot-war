## 1. 生产裁决

C01E01 是第一话中首个满足 P5 条件的 Episode：故事、受众、制作与 Canon 均已通过独立验收；三回合玩法、唯一物理期末快照和 8x10 棋盘常量也已机器化。

现有 Godot `manifest.m1.json`、`manifest.m4.json` 与 `c01_e01_v3510_candidate_3t.json` 只保留为历史运行时验证。它们使用“三小时前、留言墙保护、封存无人机 HP、战后 Desk”等旧结构，与当前事实源冲突，不得成为正式 C01E01 的母版。

新运行包必须另建，不覆盖历史验证包；通过完整试玩、容量回执和平台验收前维持 `candidate`，不得标记 `production`。

## 2. 本话的 Episode Knot

```text
戏剧对象：最后一条闭馆路线，以及被它连接的人、机器与消防回线
浅层问题：怎样让二十九名观众在九点前越过闭馆线？
纪存主张：不把人和机器交给“标准姿态”分类，闭馆仍要像一次真正的照看
兜灯/唐胶主张：专业停止权和材料否决不能被英雄冲动覆盖
机器主张：跌跌用主动侧倒完成巡检；机器犬自行认定维修员需要救援；馆守Z收暗一瓣灯给人让出阴影
玩家承诺：用小机身体、有限消防回线和低热支援救人，不开启完整搬运脊道
不可逆代价：外部网络捕获消防路由地址与纪存声纹，四令取得物理介入口
后续责任：二十九人只到前厅；门锁、胸灯、数字钥匙和泵站被分别切走，E02成为真实火场
```

### 3.1 为什么本话不进入 Desk

Desk 是多玩法语法库，不是每话强制打卡。本话结尾的物理危机在数秒内发生；插入责任比较界面会破坏因果速度，也与已验收文本冲突。

本话采用：

- `commitment_model=enacted`：玩家通过开侧门承受贴片机、确认主动侧倒、选择安全胸灯角来承担承诺。
- `settlement_model=narrative_consequence`：消防回线被捕获、四令切走设施，后果在 Narrative 中具身发生。
- `DESK` 跳过理由：二十九人仍未离楼，责任尚不能归档；E02 火场先消费。

需要比较多项未来责任、允许玩家选择先后顺序的 Episode，继续使用 `choice + desk_choice`。

## 4. Spatial 合同

玩家只在 L1 行走；十九区总图负责显示规模，不把十九区都做成房间。

```text
前厅总图
-> 馆守Z基座
-> 合体台 / 模型病院
-> 现实机器舞台
-> 旧影像厅
-> 档案室
-> 员工支廊 / 0号门（路线完成后）
```

L2、L3、B1、B2只通过跨层视点、终端灰显和远景建立容量。Portal 必须保留精确返回点；纪存不能每次回房间都出现在默认出生点。

## 5. Tactical 合同

### 5.1 规则边界

- 固定 `8x10` 斜45度棋盘；坐标由 `C01E01-graybox-constants-v1.tsv` 唯一决定。
- 真正可控单位只有跌跌与机器犬；馆守Z是一次场景支援，不占普通可控机格。
- 四枚 Token 固定代表29人，`C3` 不可拆；不得生成第五个人员 Token。
- 路径框和两台贴片机是功能模块，无 HP、无普通攻击、无说得。
- 每回合顺序：`player_units -> evac_auto -> environment -> local_receipt`。
- 玩家可以提前结束己方阶段；漏做关键动作会令 Token 停滞，并在 R3 结束后触发失败重试。
- 失败、危险胸灯角和取消操作均不得提交 Episode 状态。

### 5.2 三回合动作

1. R1：机器犬开侧门并接受一台贴片机进入；跌跌复位主闸。环境阶段路径框学会标准路线并重新合拢。
2. R2：玩家确认跌跌主动侧倒，占据传感格一个自动移动阶段；九点钟响，机器犬叼走晚饭袋。
3. R3：玩家在三个挡板位中预览胸灯角。左右两格被兜灯在确认前阻断且不耗行动；中格安全。馆守Z收暗靠近机器犬的一瓣灯，四Token最终到黄线。

### 5.3 状态提交

`29/29` 与 `4/4` 只产生本地 Battle Clear。战后 Narrative 读取它来演出跌跌站起和闭馆熄灯，但 E02 唯一可读输入必须等到 `c01e01_four_orders_tag`，由一个 transaction 提交 `RT013S`。

## 6. 表现与资产分档

### A档地图识别

- 跌跌：0.7m双足小机，重心偏斜与左膝故障必须可读。
- 机器犬：现实尺度四足牵引机，不能做成战斗兽机。
- 四组撤离Token：不同人数/照看职责角标，不画成四个等价人形兵。
- 路径框：折叠边界机械，动作是开合和读路线。
- 贴片机：贴膜工具，不使用枪炮轮廓。
- 馆守Z：地图北缘巨型地形与胸灯，不缩成和小机同体量的普通棋子。

### 关键演出

- 跌跌主动侧倒：至少一张 B 档地图动作图或独立程序骨架变形。
- 机器犬开侧门、挂接D5、叼湿晚饭袋：短动作与战后复用。
- 馆守Z胸灯：安全角预览、兜灯 Cut-in、外圈点亮、极小偏头收灯、旧导览语音。
- 贴片膜卷曲：程序 FX；不需要击坠爆炸。

现有馆守Z半跪与兜灯运行资产可作为候选输入，但必须按 E01 的“胸灯外圈/极小偏头”重新编排，不能复用旧掌部防卫语义。

## 7. 构建与验收门禁

1. 新包不得引用旧 `c01_e01_v3510_candidate_3t.json`。
2. 编译器必须验证 `commitment_model=enacted` 的动作锚点和 `settlement_model=narrative_consequence` 的 Narrative 后果节点。
3. 三回合每个回执必须与 `GB017-GB020` 完全一致。
4. 失败重试前后，`world_facts`、`battle_outcomes` 和 `RT013S` 均不得增加。
5. 成功但未走完尾声时，E02快照仍不存在。
6. 尾声完成后只存在一个 `C01_PHYSICAL_SNAPSHOT=RT013S_ATOMIC_PAYLOAD`。
7. 图像验证必须证明8x10棋盘、巨神尺度、四Token角标、传感格、黄线和三挡板位不被侧栏遮挡。
8. 真人必须能用普通语言说明：为什么跌跌要故意摔倒、机器犬为什么自己去找维修员、馆守Z为何只亮胸灯、二十九人为何仍不安全、七海何时从私人频道转为公务频道。
