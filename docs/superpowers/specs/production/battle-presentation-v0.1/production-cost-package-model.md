> 本模型用于方案比较，不是外包报价或全游戏排期承诺。

美术 Session 没有逐工序计时日志，因此地图 Sprite、Cut-in 和 Pose 不能伪报成“实测工时”。下表是下一轮必须采集的工单字段和当前规划区间。

## 2. 单次演出工时模型

| 工序 | A 级规划区间 | B 级规划区间 | C 级规划区间 |
|---|---:|---:|---:|
| 地图 Sprite / 状态 | 2–4 h | 1–2 h | 0–0.5 h（复用为主） |
| Cut-in | 1–3 h | 0–1.5 h | 0 h |
| 机甲 Pose | 3–6 h | 1–3 h | 0 h |
| AI 视频候选与筛选 | 0 或 2–6 h | 通常 0 h | 0 h |
| 程序装配 | 2–4 h | 1–2 h | 0.25–0.75 h |
| QA / Canon / 多模式 | 1.5–3 h | 0.75–1.5 h | 0.25–0.5 h |
| 合计（无视频） | 9.5–20 h | 3.75–10 h | 0.5–1.75 h |

馆守 Z 首件包含内核、测试、导入和切片总装，不能把不足一小时的自动化装配墙钟误当成后续完整人类生产成本。首件应单列“平台建设”，复用件才能按 B/C 区间估算。

## 3. 费用公式

```text
单次费用 = 美术小时 × 美术时薪
         + 程序小时 × 程序时薪
         + QA小时 × QA时薪
         + 视频平台实际费用
         + 外包返修准备金
```

用于敏感性分析的占位时薪可设：美术 250–450 元/h、程序 300–550 元/h、QA/编辑 180–350 元/h。它们不是市场报价，只是让方案在同一假设下可比较。

按无视频中位工时和上述区间粗算：

| 等级 | 规划费用区间 |
|---|---:|
| A | 约 3,000–9,000 元/次 |
| B | 约 1,000–4,000 元/次 |
| C | 约 150–900 元/次 |

## 4. 单话参数模型

不在此决定每话 A/B/C 数量。制作人可以把拟定数量代入：

```text
H_episode = A_count × H_A + B_count × H_B + C_count × H_C
Cost_episode = A_count × Cost_A + B_count × Cost_B + C_count × Cost_C
```

仅用于量级演示的假设样例：某话 `1A + 3B + 8C`，无视频时约 25–64 小时、7,200–28,200 元。这个组合不是项目推荐，也不能据此冻结全游戏比例。

## 5. 全游戏参数模型

```text
H_game = Σ H_episode + H_shared_kernel + H_tools + H_platform_QA
Cost_game = Σ Cost_episode + shared_cost + contingency
```

全游戏还应单列：共享战棋内核、模式场景框架、内容工具、存档迁移、平台适配、无障碍、性能档位和 15%–30% 返修准备金。不能简单用“单话 × 话数”替代这些固定成本。

## 6. 包体模型

本次 17 张批准 PNG 在 Windows PCK 中增加 8.431 MiB，平均约 0.496 MiB/项，但 Pose、Cut-in、地图 Sprite 差异很大，不能按张数线性外推。

建议预算：

```text
Package_episode = unique_runtime_textures
                + unique_audio
                + optional_video
                - cross_episode_shared_assets
```

- A 级无视频：当前首件约 8.4 MiB，但通过 Pose 降采样和跨模式复用可进一步下降。
- B 级：应优先复用地图母体、Cut-in 和 FX，目标新增约 1–4 MiB。
- C 级：目标新增接近 0–1 MiB，主要由共用图集承担。
- 视频：当前实测为 0；未来必须按最终 OGV/平台编码文件实测，不能用 MP4 母版大小替代。

## 7. 下一轮必须记录

每张资产记录：提示词准备、候选数量、生成时长、人工修图、Canon 返修、导入、运行时校准、采用/淘汰原因、最终源文件和导出增量。

每次演出记录：脚本装配、FX 调整、音频、三模式、跳过测试、20 次循环、平台性能和第二次复用节省比例。只有完成第二台机体后，才有资格把这些区间收窄为项目标准。
