# C01E02｜联合吸引力 Demo 质量重置裁决

> 日期：2026-08-18  
> 状态：`active producer correction / Candidate only`  
> 影响范围：C01E02 Candidate Demo 的美术、演出、UI、交互与游戏感生产线  
> 不影响：C01 已验收 Reader、Canon、默认 M2、正式 Runtime 与 C04 剧情生产

## 1. 制作人结论

用户对当前 Demo 的判断成立：现在得到的是一个共同回合工程验证器和一组资产接口证明，不是能验证商业吸引力的试玩。

- `M3-J1 G1` 的纯 resolver、草案零写入、公开意图、路线／朝向／预备反应、摘要与确定性证据可以保留。
- `M1a` 只证明夹具能被 Godot 消费；它的 `REAL ART: 0` 画面不可再进入用户视觉判断。
- A4 只保留拓扑、画布、遮挡与滚动映射；当前几何街区不是成片地图。
- A5 只保留小体身份、四朝向 idle 与脚点；它没有扑击、被挡、踉跄或幸存逃散表演。
- A6 的人物单张身份可以继续作为来源，但近似三态不能作为角色表演完成。
- A8 B1.1 是用程序图形重建的动作／pivot 示意，无法通过继续加线条和修轮廓升级为成片美术。

根因是制作目标错了：此前把“规格一致、可校验、可加载”当成了“好看、好玩、让人想继续”。从本裁决起，前者只作后台工程门；用户可见门改为完整段落的联合观感。

## 3. 新的产品目标

建立一条约 4 分 15 秒至 4 分 30 秒的成片质量 Candidate 垂直切片：

```text
同体谜团
→ 人物承担
→ 玩家规划
→ 第一次共同结算与巨体受力
→ 取盾挡击
→ 玩家亲手制造盾拍高潮
→ BREAKER 再起与勇拳钩子
```

它必须在同一可玩构建中联合验证：

- 新共同回合是否好理解、能预判、有两种真实代价；
- 最新人物与机体设计是否在实机中成立；
- 对白、构图、镜头、声音和角色职责是否令人记住；
- 地图单位动作与正比例 Cut-in 是否互相衔接；
- 巨体接触、赤红挡击与盾拍是否有重量和回报；
- 玩家是否愿意重玩另一条解法并继续看 E03。

## 5. 用户决定与制作人责任

本轮无需用户再决定是否继续修 B1.1，也无需在美术 Session 往返确认技术条目。制作人负责统一收件、对照、派发和将真正需要判断的画面带回本任务。

第一次用户门只看一组 `Gold Frame`：

- 规划态一帧；
- 巨体接触执行态一帧。

用户判断的是“这是不是我要继续投入的游戏画面”，而不是 SHA、pivot 或文件是否齐全。

只有两件事在开工前仍需另行得到用户明确授权：

1. 付费批量 LibTV／其他付费模型生成；
2. 临时 AI 配音的声线与商用路线。

静态 Gold Frame、内部 Godot 架构、玩法内核和无付费素材的前置制作可以立即开始。

## 6. 硬质量门

- 用户可见链路：`sketch=0 / fixture=0 / old_asset=0 / identity_critical_fallback=0`。
- 去掉标签后，馆守 Z、BREAKER、小体和关键动作可在 3 秒内辨认。
- 人物状态必须改变视线、肩颈、动作轮廓或镜头关系，不能只换灯色、嘴角或文案。
- 玩家在 30 秒内能说清保护对象、最危险意图和自己要决定的内容。
- 两种第一轮方案必须改变第二轮的空间、损伤、热量或容错；不能只改战报文字。
- 一次重击必须具备蓄势、接触、停顿、反冲、环境后果和分层声音。
- 盾拍后立刻回到同一棋盘位置与破坏状态，Cut-in 不能与战术因果脱节。
- 机器 PASS、文件齐全、哈希一致、截图好看均不能单独代替实际试玩吸引力门。

## 7. 禁止项

- 禁止把 B1.1、A1/B1方向样张、旧 portrait／unit、`story_first/**` 或 fixture 回流为正式画面。
- 禁止主程序自行搜索、挑选或猜测美术版本。
- 禁止美术在没有共享镜头表和实机用途时批量扩 Atlas。
- 禁止用 Python/Pillow/ImageDraw 直接绘制用户可见的角色、机体或地图成片；脚本只可用于装配、切图、遮罩、导出和校验。
- 禁止为了“爽”提前改变 Reader 顺序、把七海写成现场指挥、把纪存写成驾驶员、让小体听从 BREAKER，或把 P1 写成 Mission Clear。
- 禁止在 Gold Frame 未通过前批量花费 LibTV 额度。
