# C01E02｜“起身、取盾、盾拍”Golden Slice 联合母合同

> 生命周期：`Candidate / non-default / save-isolated / no Canon promotion`  
> 产品用途：验证玩法、美术、演出、台词、角色表现和打击感结合后是否有吸引力  
> 首次游玩：约 `4:15–4:30`；熟练重玩：约 `2:40`  
> 母故事：当前已验收 C01 Reader，不重写、不反向污染

## 1. 固定故事边界

顺序必须保持：

1. 轮式导览终端被压，同一句声音从馆守 Z 胸前继续；旧守护者与馆守 Z 是同一主体。
2. 兜灯开放导览席；纪存只提供路线、人员和城市判断，不控制四肢。
3. 七海只撤回本人停机令，不获得城市炮火、车辆或战场指挥权。
4. 馆守 Z 起身出馆，先让应急车通过，再挡开扑向东门的小体，站到撤离线与 BREAKER 之间。
5. 首次巨体接触后，馆守 Z 被推出、冲角被偏开，城市炮击中侧甲，BREAKER 开始聚集红光。
6. 这之后才看见并取得重盾。
7. 重盾挡下赤红冲击，形成第四道新焦痕；随后最后车辆通过、东门关闭。
8. 馆守 Z 利用 BREAKER 重心未收回的机会顶盾侧压，再完成盾拍。
9. BREAKER 首次倒地但未毁；小体仍有幸存且继续 scattered；这里只到 P1 阶段检查点，不是 Mission Clear。

可直接使用的 Reader 台词：

- “它管身体，你管路。别抢方向，也别让它一脚踩进楼里。”
- “停机令撤了。”
- “先把它带出展厅。别第一步就把馆踩了。”
- “人都在后面。把它引到南边去。”
- “想拿那面盾？”
- “兜灯，放开展架。”
- “东门清了！”
- “馆守Z，把它推回去！”

旧表现合同中的“欢迎回来／导览尚未结束”等非当前 Reader 高潮句不得回流。

## 3. 两种真实第一轮方案

两路都必须完成“让车—挡小体—站到撤离线前—第一次接触”，且都不得提前取盾。

### A｜卡位迎撞

- 2×2 身体优先占住冲线／撤离线关键格；主动作留给迎接巨体接触。
- 馆守 Z 后退和热量较少，第二轮取盾时序较宽。
- 另一只小体获得更长行动窗，非关键警戒设施或路面损伤更大。

### B｜护线预备

- 走较宽路线，设置“小体进入东门保护线／扑向车辆时，以腿或身体侧推；否则守住出口”的预备。
- 车辆和设施保护更好，小体落位更可控。
- 与 BREAKER 接触更迟，馆守 Z 多退一格或热量更高；第二轮回取盾时序更紧。

第一轮差异必须实际写入并被第二轮读取：`guardian_position / guardian_heat / breaker_depth / road_damage / warning_facility_state / swarm_positions / remaining_timing_margin`。不得仅改变评价文本。

## 4. 玩家一轮流程

```text
看公开意图与保护对象
→ 在棋盘上画短路线／增删 waypoint
→ 在终点直接选择朝向
→ 选择主动作或预备反应与备用方案
→ 打开仍可返回的提交摘要
→ 约0.7秒长按“执行本轮”
→ 同一 resolver 按冻结前态共同结算
→ 观看结果与环境后果
→ 基于真实新状态进入下一轮
```

“下一步”只能作为关闭状态的可选帮助；默认不得给唯一标准路径或替玩家决定朝向。

## 5. UI／交互基线

- 1280×720：正文至少16–18px，辅助信息至少14px；不显示坐标、hash、Stable ID、Candidate或英文调试字段。
- 地图是主要画面。规划期顶部只留一个当前目标和最多三个最高威胁；右侧命令抽屉在移动光标时可收起。
- 意图箭头、目标、时点和作用范围就地挂在单位／地格上；详细解释按需展开。
- 默认不铺满网格；编辑路线时才显示步点、2×2幽灵占位、朝向扇面、保护区、冲撞走廊与争格脉冲。
- 底部时间线只显示车辆、小体、巨体接触、城市炮、赤红光五类图标和当前时点。
- 摘要保持完整地图，只回答：保护了谁、何时接触、预备何时触发、备用方案是什么、仍暴露什么风险。
- 摄像机中央约60%为安全区；光标越过阈值后才平滑滚动，不永久锁在中心。建筑、街区、展墙与东门都属于棋盘内容。
- 教程逐步开放：看意图→画路线→定朝向→选动作／预备→摘要→执行；不一次堆满控件。
- 人物提示只指出风险与责任，不直接报标准格。

## 6. 演出与打击感基线

一般关键接触的目标节奏：

```text
蓄势 250–400ms
→ 接触点 hit-stop 67–100ms
→ 定向震屏 120–180ms
→ 单帧高光／接触闪
→ 机体反冲 250–400ms
→ 道路开裂、碎屑与姿态恢复 500–800ms
```

- 首次巨体接触优先在战棋地图内完成，保留战术因果；不滥用 Cut-in。
- 赤红挡击与盾拍是本切片两个高规格峰值；Cut-in 首帧接地图朝向，末帧回到实际结算姿态。
- 每个重击至少叠加伺服／脚步、低频体重、金属压缩、道路碎裂／碎屑三至四层声音；接触时环境与 BGM 短暂让位 5–7dB。
- 盾拍落点前短暂抽掉音乐与环境声；不能只靠红滤镜、白闪或一次震屏冒充重量。
- Full／Skip 只改变播放，不改变结果、随机种、破坏状态或检查点。

## 7. 视觉语法

- 常态：`KINETIC_CEL`；机魂、同体揭示、盾拍峰值可在其基础上叠加有限 `ARCHIVE_OFFSET`。
- 地图单位：正式约4头身 Q/SD、清晰轮廓、两级硬阴影、材质磨损与方向光；不得使用现在的扁平矢量图标。
- 人物：采用美术资产 Session 最新身份设计；状态差异必须进入视线、肩颈、手势、动作轮廓和镜头构图。
- 旧守护者三种演出不是“同一胸像换灯”：`guide`是稳定导览中景，`contact`是承力近景，`shield_gaze`是明确侧转看向墙盾。
- 地图 A4 只作拓扑。正式画面必须有雨夜湿地反光、建筑身份、会展馆幕墙、东门疏散设施、烟尘、碎屑、炮击与道路战损。
- Q版、正比例 Pose、Cut-in、视频必须共享头冠、胸门、肩环、主色、盾痕、雨夜光向和动作开始／结束姿态。

## 8. 分阶段停止点

### GF｜Gold Frame 双帧

1. `GF-PLAN`：正式地图局部＋最终Q/SD单位＋人物通讯＋正式UI＋路线／朝向／威胁。
2. `GF-CONTACT`：同一场景第一次巨体接触＋正式FX＋执行态UI退场。

用户明确认为两帧已达到“值得继续做”的画面后，才扩真资产与完整 UI。

### GT｜45–75秒 Golden Turn

从第一轮局势揭示开始，到巨体接触、城市炮命中和 BREAKER 聚红光结束；必须是真实可操作、真实资产、真实声音的共同回合，不是视频或点击播放。

### GS｜完整 Golden Slice

在 GT 通过后扩到取盾、挡击、盾拍和 P1钩子；形成本文约4.5分钟的完整标杆段。

## 9. 用户验收问题

盲玩后只问：

1. 不看帮助，是否说得清唯一直接操作对象，以及纪存、旧守护者、兜灯、七海各自负责什么？
2. 提交前，是否能预判五类事件的大致顺序和方案代价？
3. 接触后，是否能复述谁把谁推向哪里、地图发生了什么变化？
4. 去掉标签，是否能分清导览、承压、望盾三种旧守护者表演？
5. 是否记住至少两名角色和一句台词？
6. 盾拍是否像是玩家此前规划和身体条件亲手搭出来的，并让人想继续看 BREAKER 再起与勇拳加入？

任一基础问题失败，回到最早责任层修正；不以增加说明文字、更多状态卡或更长动画掩盖。
