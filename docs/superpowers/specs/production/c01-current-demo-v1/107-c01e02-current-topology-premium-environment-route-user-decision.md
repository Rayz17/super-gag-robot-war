## 1. 为什么现在需要裁决

ENV-E0已经证明：32×18拓扑、40×20投影、四镜头、控制点和分层几何都成立，但仅用Call02的六块安全裁片机械铺满2400×1350画布，无法达到精品视觉。103号回执已将其E1／E2可见像素判为`VISUAL_FAIL / NOT_CONSUMABLE`。

P99／106同时证明，真实透明Sprite的Atlas、pivot、脚点、占地、z、socket与简化局部屋顶淡化消费者已经具备。现在缺的不是新的渲染系统，而是一张能统一地图材质、光色、建筑尺度和玩法第一读法的精品静态环境母体。

环境应先于BREAK​ER与馆守Z地图母版冻结，因为两机的明度块、边光、接地对比和缩小可读性都要在同一地图背景上验收。

## 2. 制作人推荐：路线A

批准**一次环境专用、无角色的ImageGen试作**，与剩余两次单机母版Call03／Call04分开计数：

- 只生成actor-free current-topology静态环境；
- 输入只包括已校正的exact拓扑／相机导向和隔离后的环境风格板；
- 不生成馆守Z、BREAKER、小体、车辆、盾、东门状态、警戒设施状态、炮、路线、UI、文字、ghost或T3／T4／T5演出；
- 只允许一次调用，不自动reroll；失败即停，不追加第二张；
- 通过50%／100%视觉门后，才做简单确定性拆层：静态地面＋后景建筑、少量roof／foreground遮挡片、低成本雨／湿地FX；光影以预烘2D为主；
- 不建设SubViewport、逐像素mask、动态光照、法线、通用遮挡或第二套投影系统；
- stateful对象继续由程序按Current anchor单独摆放，不烘进环境图。

这一路最快，也最符合“精品Demo但不把棋盘做成渲染技术项目”的目标。风险是ImageGen仍可能漂移建筑拓扑；因此exact注册、选择口袋、五格承力大道、东侧生命线和四镜头共同crop任一失败，都必须拒收原图，不能靠挪玩法对象补救。

## 3. 备选：路线B

改用外部人工2D场景绘制／清稿，直接按保留的2400×1350拓扑mask和相机合同施工。

优点是空间、建筑和分层最可控；代价是外部工期与费用更高，也需要另行确定执行人和预算。本路线同样只做静态环境与少量局部遮挡片，不扩大实时渲染复杂度。
