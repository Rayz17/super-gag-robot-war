## 1. 制作人纠偏

此前把“零真实资产壳”放在用户可见链路上是错误编排。主程序不负责自行寻找、判断或挑选美术版本；美术任务也不能只交方向板而不交程序可消费文件。制作人必须先建立唯一资产真值表，再分别派发互锁任务，最后签发精确 handoff。

当前结构性矛盾是：46 号要求馆守 Z、BREAKER、墙挂盾等身份关键槽在 U2 全部真实加载，但 45 号没有授权美术制作馆守 Z／BREAKER 地图 Atlas。旧链因此无法到达有效联合试玩。本计划替代 38 号看板中“先做零资产视觉试玩，再决定是否修玩法”的顺序，但不改 43 号对现有 R0 证据缺口的判断。

## 2. 冻结产品边界

- 仍是 `Candidate`、非默认入口、禁正式存档、禁 Canon／Reader／正式 Runtime 晋升。
- 保留 C01E02 已验收故事顺序与结果；当前代表轮只到 BREAKER 开始聚集红光，重盾仍墙挂、撤离线仍 active，不提前取得重盾、挡赤红冲击、盾拍或到达 P1。
- 完整 E02 后续目标仍为：首次身体责任与接触 → 取得重盾 → 挡赤红冲击 → 最后一辆车通过 → 盾拍 → BREAKER 首次倒地但未毁 → 小体仍有幸存 → P1。
- 玩家只直接操作馆守 Z；纪存负责路线、人员和城市判断，不控制机体四肢；七海只显示远程撤令状态；旧守护者是馆守 Z 本体。

## 5. 用户只承担三个产品裁决

1. **U1 人物／机体资产门**：在美术任务逐项确认 A6 人物、地图单位、重盾与代表 Cut-in。技术路径、哈希重绑和 loader 不交给用户判断。
2. **U2 联合试玩门**：判断角色在场感、机体身份、共同结算重量、信息可读性和操作乐趣。
3. **完整 E02 门**：判断两条打法是否真的不同，是否继续投入完整取盾—挡击—盾拍演出。

## 6. 制作人验收责任

- 只接受具体文件、Stable ID、路径、SHA、尺寸、帧序、pivot、alpha、来源与用户裁决齐全的 handoff。
- 任一身份关键槽缺失或 fallback，联合构建自动标为 `U2 blocked`，不得拿给用户判断视觉效果。
- A4 的固定映射为 `pixel=(880+(x-y)*40, 170+(x+y)*20)`，世界画布原点必须为 `(-880,-170)`；不得照抄旧 M2 的 `(-800,-180)`。
- Preview 与执行必须共用同一个纯 resolver；Full／Skip 只能改变播放方式，不能改变结果。
- 重大身份改造、新剧情、新玩法资源系统、正式 Runtime／Canon 晋升、付费批量生成必须停下交用户确认。
