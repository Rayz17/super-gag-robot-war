# C01E02 G2-A.1｜地图内演出与消费者准备返工目标

## 1. 保留结论

保留G2-A已经证明的部分：三轮共享状态、两条第一轮策略、草案零写入、冻结意图、同一resolver预览／执行、摘要返回、0.7秒提交、确定性与失败重试。

不得继续宣称：正式UI已完成、表现cue已有真实消费者、多层声音已发生、语义槽可直接插资产、A／B七项差异均已形成玩家可感的第二轮难题。

## 2. 坐标与地图迁移

- 在`m3_golden_slice`非默认车道内将世界投影统一为`tile_half=(40,20)`，与A4批准映射一致；不得修改默认M2、A4源资产或Reader。
- 保持32×18、馆守Z2×2、BREAKER3×3、小体1×1、地图滚动和边界钳制。
- `edge_threshold`必须真正参与相机判断；光标越过阈值才滚动，不能只保存参数。

## 3. T1–T5真实地图结算

首轮执行必须在同一地图节点按事件逐项发生，不得等待总计时后瞬间跳最终世界：

1. T1应急车沿公开轨迹通过落脚区；
2. T2小体沿轨迹进入保护线，预备满足时馆守Z完成侧顶／挡开，小体仍完整存活；
3. T3馆守Z占线，BREAKER沿冻结冲线接触；馆守Z后滑、冲角偏开；
4. T4城市炮从独立方向命中暴露侧甲；
5. T5路面保留战损，BREAKER头部红缝开始聚光。

表现director必须实际驱动单位节点、Camera、zoom/pan、anticipation、hit-stop、定向shake、recoil、flash、碎屑和aftermath；焦点必须来自事件接触点，不得使用提交时光标冒充。

Full／Skip／缺媒体三路结束后必须回到完全相同的世界状态、相机上下文与下一轮入口。

## 4. 玩家可见的规划语言

- 世界Overlay真实绘制保护区、冲撞走廊、争格、2×2终点幽灵、终点朝向扇面、T时点与对象锚定意图；receipt字段不能替代画面。
- 第一轮车辆、小体、BREAKER、炮击条件和路面后果都必须在地图或时间轴可追溯。
- 第二、三轮的意图必须补齐可画的轨迹／区域／目标锚，不得只存在JSON文字。
- 摘要保持地图可见，并把保护对象、接触时点、预备触发、备用方案和暴露风险投影回地图。
- 非法操作显示中文产品文案，不得暴露`waypoint_unreachable`等内部token。
- 鼠标、键盘、手柄都必须具备：进入规划、编辑waypoint、改朝向、选动作／预备、打开摘要、返回、可见长按进度、取消和提交；建立真实焦点导航。

## 5. A／B差异必须成为第二轮问题

保持既有两路事实，但至少让以下两项成为第二轮真实、可见、可操作的不同约束，而非战报字段：

- 从不同馆守Z落点到展墙／挡击位形成不同合法路径与时序余量；
- 道路破坏、警戒设施或小体落位改变一处可见风险区／路线代价／保护对象压力。

热量若继续保留，必须在至少一路合法边界上形成真实约束或明确降为战报评价；不得维持“永远碰不到阈值”的伪系统。

不得改变两路最终Reader事实，也不得制造永久剧情分支。

## 6. 真实消费者准备

用明确标注`fixture_validation_only`的内部资源证明接口，但不得产生用户截图：

- 将语义槽绑定到确定的地图图层、世界坐标、z层、单位Stable ID、状态、朝向、动画名、pivot和屏幕UI区域；
- 主场景必须实际调用消费者，而不是只创建未挂接的裸`Sprite2D/TextureRect`；
- 单槽坏资源只回退该槽；身份关键槽回退时`integrated_visual_playtest_ready=false`；
- 不扫描美术目录，不读取A9、A8、旧portrait／unit、story_first或旧receipt。

G2-A.1只冻结消费者契约形状；最终尺寸、帧数和SHA等待A9.1-A用户母版门与制作人exact handoff。
