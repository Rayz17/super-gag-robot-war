## 1. 试验目的

当前主程序与 Phase A Keyframe 各自完成了原目标，但无法直接总装：

- 主程序证明了 X/Y、碰撞、Y-sort、热点、三步战术和 preview outcome，视觉上却读成正上方俯视的可滚动管理地图。
- `KF_C01_RM_2P5D_STYLE_V01` 证明了人物、场景和馆守 Z 可以共享一套电影化视觉语言，但它是已压平的满屏概念图，人物屏占比过大，也不是运行时资产。

本试验只验证：能否以“电影化斜侧视舞台 + X/Y 浅纵深 + 分区相机”统一两边，同时保留现有剧情因果、玩家动词和三步战术。

## 2. 保留、返修与冻结

### 必须保留

- 已完成的剧情状态、对白数据、R1/R2/R3 因果、跳过幂等、preview transaction 和测试基线。
- X/Y 浅纵深移动、前景遮挡、热点距离判断和同房间轻战术。
- 纪存、兜灯、唐胶、七海与馆守 Z 的现行 Canon 锁。
- 馆守 Z 半跪、低热、一次输出、命中后硬停机。

### 必须返修

- 场景的视觉投影、地平线、地面带、人物屏占比和相机行为。
- Phase A Keyframe 的运行时构图适配和资产拆分计划。
- 战术覆盖层在斜侧视地面上的可读方式。

### 本轮冻结

- 不生产整套 Phase B 角色四方向与动画。
- 不把当前满屏 Keyframe 导入运行时或反向硬切成伪分层资产。
- 不改变剧情动作、结局、热点事实、R1/R2/R3 规则或正式 SRPG 内核。
- 不升级为全项目正式 2.5D 模板，不解冻 V35.10，不计正式 Episode 进度。

## 3. 共同画面合同

以下数值均以 1280×720 视口为验收基准。

| 项目 | 联合试验值 |
|---|---|
| 运行时场景底图 | 目标 1920×900，允许有限横移；试验阶段可用几何占位 |
| 摄影机读法 | 35mm 感斜侧视/人尺度中景；必须看见墙面或远景结构，不能只剩大面积俯视地板 |
| 地面转折/远景下缘 | 建议落在屏幕 `Y=330–410`，由美术 v03 定稿 |
| 可行走地面带 | 主要落在屏幕 `Y=430–650`；必须形成可绕行的浅纵深，不是三条轨道 |
| 成年人物屏幕高度 | 中景约 180–200 px；远侧不低于 165 px；近侧不高于 220 px |
| 小机器人屏幕高度 | 60–100 px，仍能读出方向和动作 |
| 纵深缩放 | 仅允许稳定的约 `0.90–1.08` 分段/缓变；不得随每像素抖动 |
| 脚点 | 所有角色以脚底中心作为位置、排序、碰撞和缩放基准 |
| 摄影机纵向 | 普通探索基本锁定，容许不超过约 12 px 的导演式微调；不跟随人物前后走动 |
| 摄影机横向 | 三个构图区，目标中心可先按 `X=640 / 960 / 1280` 试验 |
| 构图区切换 | 0.45–0.70 秒缓动；同一区内人物走动时相机保持稳定 |
| UI 安全区 | 顶部 56 px、底部 118 px、左右各 32 px 不放关键脚点和交互物 |

三个构图区：

1. `ZONE_A_ENTRY`：入口、兜灯停机端、唐胶工作位。
2. `ZONE_B_REAL_MACHINE`：跌跌、机器犬、充电位与白框主要行动区。
3. `ZONE_C_OLD_DOOR_LOW_HEAT`：成年观众、旧门、低热扇区与馆守 Z 受限高潮。

导演演出可短时覆盖上述相机位置，但演出结束后必须回到当前构图区，不得把自由探索重新变成贴身跟随。

## 4. 美术层级与运行时职责

当前 `KF_C01_RM_2P5D_STYLE_V01` 只可作为风格、材质、光影和斜侧视气氛参考。Phase A.5 必须先证明下列资产能够独立存在：

| 层级 | 内容 | 运行时要求 |
|---|---|---|
| `FAR` | 馆墙、上层廊道、深层结构、馆守 Z 半跪主体 | 不含人物和可移动小机；胸灯另有 MASK |
| `MID_CLEAN` | 无人的地面、墙面和固定结构 | 不烘焙可开关门、白框、人物和小机 |
| `PROP` | 旧门、充电桩、工作台、导光板、互动设备 | 需要状态变化的部件必须独立 |
| `FG` | 栏杆、展台边、吊臂、近景遮挡 | 透明 PNG；与脚点/Y-sort 关系明确 |
| `MASK` | 房间灯、低热区、馆守 Z 胸灯和熄灯余辉 | 可由程序独立调亮、熄灭或着色 |
| `SPRITE` | 人物、跌跌、机器犬、贴片机 | 透明、统一脚点、方向和尺度合同 |

AI 满屏图不能通过裁切恢复被人物遮住的背景。Phase A.5 应基于 Keyframe 重新生成/修补 clean plate 和分层母版，不得把缺失区域用模糊涂抹冒充完成。

## 5. 交互与战术合同

- 玩家仍可使用 X/Y 前后绕行；本试验不是纯横版。
- Y 方向移动只改变脚点、遮挡、轻微尺度与可接近热点，不推动相机上下追踪。
- R1/R2/R3 仍发生在同一房间。行动点、照射区和意图线必须贴合地面透视，不能继续使用看似正上方棋盘的矩形覆盖。
- 允许用椭圆、梯形、地面贴花或沿透视线的局部高亮表达行动范围；不得因此发明新的战斗数值或练级机制。
- 普通对白仍以场内字幕为主；人物变大后要重新校验字幕不遮脸、不遮脚点、不遮热点。

## 6. 联合门禁

只有以下项目全部通过，才允许讨论 Phase B：

1. 首屏静止 3 秒内，至少能被读成斜侧视场景而不是俯视管理地图。
2. 纪存中景高度落在 180–200 px，表情/发型剪影可读，同时仍有可探索空间。
3. 玩家能完成一次前后绕行和一次前景遮挡；相机不随 Y 移动漂移。
4. 玩家在同一构图区内连续移动时，背景基本稳定；跨区时才发生可感知但不过度的横向运镜。
5. 旧门、两台小机、成年观众和低热区在三个构图区内均可被指出。
6. 主程序三张构图区截图能与美术 `v03` 的地平线、脚点、人物尺度和 UI 安全区对齐。
7. R2 倒地点与 R3 照射区在斜侧视地面上可读，不需要切回俯视棋盘。
8. 未导入任何 `runtime_allowed=false` 的 Keyframe，也未产生 Phase B 批量动画。

若联合门禁失败，应保留旧可运行基线并报告失败原因，不得用继续堆素材掩盖视角问题。

## 7. 重大决策停门

遇到以下任一情况，两个 Session 都必须停止并向用户/制作人提交 Decision Request：

- 需要改成纯横版、正上方俯视、等距俯视或八方向大地图。
- 需要取消 X/Y 探索，或把本场景改成纯 ADV/纯战棋。
- 需要把人物高度移出 165–220 px，或改变三个构图区数量。
- 需要减少/增加角色方向数、重画 Canon 锁定造型或改变馆守 Z 姿态。
- 斜侧视下 R2/R3 无法成立，必须改变玩法因果或切换独立棋盘。
- 需要采用新的付费插件、长期引擎架构或覆盖既有 `approved_for_runtime` 资产。
- 要把本试验升级为正式模板、正式 Episode 或全项目美术方向。

## 8. 跨 Session 同步

1. 两边开工前必须读本合同、对方最新状态页和旧验收报告。
2. 美术先交运行时构图 `v03` 与相机/脚点标注；主程序可先搭壳层，但不能在看见 `v03` 前宣布完成。
3. 主程序只读取美术 manifest，不修改美术批准状态；美术不直接修改 Godot。
4. 两边均在各自状态页记录：使用的合同版本、偏差、截图/资产路径和待确认事项。
5. 联合验收由用户/制作人完成；任一 Session 不得单方面宣布 Phase B 开门。
