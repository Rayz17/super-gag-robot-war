# 美术资产 Session 目标：C01 2.5D 低热救援统一美术包

> 当前状态：Phase A 已交付并停在用户/制作人确认门。当前仅获准进入 `art-phase-a5-perspective-trial-goal-v1.md` 所定义的运行时构图桥接试验，Phase B 仍未开门。

## Objective

为 `SCN_C01_RM_RESCUE_2P5D_V01` 制作一套统一风格的 2.5D 场景与角色资产，解决上一轮“程序矢量小人＋旧头像＋复用背景＋高精机体”之间的风格拼贴问题。

开工前必须完整读取：

- `producer-brief-and-shotbook-v1.md`
- `character_mecha_art_locks.tsv` 中 `CML001/002/003/004/008`
- 当前 `battle-presentation-v0.1/art-status.md`
- 主程序 Session 最新场景尺寸、轴点和遮挡/镜头需求

## Phase A：风格 Keyframe，必须先停门

先只制作一张 1280×720 最终感 Keyframe：

- 现实机器区 2.5D 三层空间。
- 纪存在中景，跌跌和机器犬在近景，兜灯/唐胶在工作位。
- 馆守 Z 半跪轮廓从远景上方压入，但不抢走人尺度阅读。
- 一处前景栏杆遮挡、一个充电桩、旧服务门、低热扇区和白框 UI 样例。
- 夜间闭馆色脚本：深海军蓝/青色结构线、少量警示金；低热胸光为琥珀色。
- 角色走图、背景、对白 UI 必须像同一个游戏；高精 Cut-in 可以更细，但色温和轮廓设计必须同源。

Keyframe 完成后必须暂停，等待用户/制作人确认。不得在风格未确认时批量生成走路帧。

## AI 生产约束

- 先锁定角色正侧背方向 Key，再派生动画；禁止每一帧独立 Prompt 后直接拼接。
- 优先使用分层母图、局部重绘、骨骼/形变和人工清理保持一致性。
- 走路循环的脚底轴点漂移不超过 2 像素；身体高度和头身比不得随帧跳动。
- 四方向的发型、终端手臂、衣扣、工具数量、支具方向必须一致。
- 透明边缘、色边、残影和多余肢体必须在交付前清理。
- 背景不可把所有展项画成同密度噪声；互动门、充电区、低热扇区必须一眼可找。

## Manifest 与交付

- 使用共享 Stable ID；路径、尺寸、轴点、方向、帧序、FPS、安全区、Alpha、来源母版和批准状态全部进入 manifest。
- 新资产状态由美术 Session 自己维护；主程序 Session 不代写。
- 提供：全资产 contact sheet、25%/50% 尺度检查、角色方向对比、走路循环预览、场景合成 Keyframe、透明边缘检查。
- 源文件、生产母版、运行时副本分目录；不得把生成中间图直接标为 runtime approved。

## Acceptance

- 纪存四方向一眼仍是同一人；无眼镜、青年不幼、左臂终端始终正确。
- 兜灯、唐胶、七海的性别/年龄/职业剪影符合 Canon 锁。
- 2.5D 地面透视与人物脚底一致；人物前后移动时不显得贴在墙上。
- 玩家在 Keyframe 中不看说明也能指出旧门、两台小机、观众、低热扇区和馆守 Z。
- 场景走图与普通对白不依赖旧头像；新半身只承担关键情绪。
- 馆守 Z 低热效果明确区别于全功率攻击：窄、低温、短时、照明/脱胶用途。
- 所有运行时文件通过尺寸、Alpha、轴点、hash 与 manifest 验证。

## Stop and ask

- 风格 Keyframe 需要选择像素、厚涂、赛璐璐或其他长期方向。
- 四方向资产无法从当前锁图稳定派生，需要改角色造型或减少方向。
- 主程序要求改变视角、地平线、人物尺寸或房间纵深。
- 需要重画馆守 Z、改变机体姿态，或追加 AI 视频。
- 新资产会覆盖已有 `approved_for_runtime` ID，而不是使用本轮新 ID。
- 发现 Canon 参考彼此冲突或唐胶/七海/纪存出现旧版漂移。
