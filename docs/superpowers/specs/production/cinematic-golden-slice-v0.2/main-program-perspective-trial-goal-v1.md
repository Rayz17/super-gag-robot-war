# 主程序 Session 目标：C01 电影化斜侧视壳层返修试验

> Goal ID：`GOAL_C01_RM_MAIN_PERSPECTIVE_TRIAL_V1`
>
> 性质：已完成主程序之上的可回退视觉壳层试验
>
> 禁止解释为：推翻旧技术验收、重写剧情流程、升级正式探索架构

## Objective

在保留 `SCN_C01_RM_RESCUE_2P5D_V01` 现有剧情、状态、R1/R2/R3、跳过/重播和测试基线的前提下，把当前“俯视管理地图 + 小人物 + 连续跟随相机”返修成“电影化斜侧视舞台 + X/Y 浅纵深 + 三个构图区相机”的可玩验证壳层。

本轮不等待 Phase B 正式资产，也不得把 Phase A 满屏 Keyframe 直接加载进运行时。先用高质量几何/色块占位证明镜头语言和交互成立。

## 开工前必读

1. `perspective-integration-trial-contract-v1.md`
2. `producer-brief-and-shotbook-v1.md`
3. `main-program-joint-acceptance-report-v1.md`
4. `art-status.md`
5. 美术 Session 最新 Phase A.5 状态、构图图和 manifest

读取后先在自己的状态页写清：旧基线入口、试验入口/开关、合同版本和可回退方式。

## Must deliver

### 1. 保留旧基线

- 不删除或覆盖当前能完整跑通的场景与测试证据。
- 新壳层可以使用独立场景、可回退适配器或显式开发开关；不得让旧基线无法启动。
- 剧情数据、状态 ID、preview outcome 和 Stable ID 保持不变。

### 2. 斜侧视舞台

- 重做房间占位绘制，使首屏拥有明确墙面/远景结构、地面转折和浅纵深地面带。
- 1280×720 下，地面主要落在屏幕 `Y=430–650`，不得再用大面积俯视地板占据主体。
- 运行时世界按 1920×900 目标组织；正式美术未到时用与层级合同一致的 `FAR / MID / PROP / FG / MASK` 占位节点。
- walkable polygon 适配斜侧视地面梯形；仍允许真正 X/Y 绕行，不退化成单线或三条轨道。

### 3. 人物屏占比与脚点

- 成人中景高度目标 180–200 px，容许远侧最低 165 px、近侧最高 220 px。
- 小机器人高度 60–100 px。
- 位置、碰撞、Y-sort 和纵深缩放统一使用脚底中心；禁止用角色图片中心当世界坐标。
- 纵深尺度只在约 `0.90–1.08` 内稳定变化，必须设置阈值/平滑，避免每像素抖动。
- 几何人物也要用接近最终比例的轮廓占位，不能继续用约 100 px 的小图标判断构图。

### 4. 三个构图区相机

- 实现 `ZONE_A_ENTRY / ZONE_B_REAL_MACHINE / ZONE_C_OLD_DOOR_LOW_HEAT`。
- 普通探索时摄影机 Y 基本锁定；玩家前后移动不驱动相机上下跟随。
- 同一区内相机保持稳定；只有跨区时才在 0.45–0.70 秒内平滑横移。
- 可先使用 `X=640 / 960 / 1280` 作为 1920×900 世界的试验中心，再根据美术 v03 做普通尺寸微调。
- CinematicDirector 可短时接管 position/zoom，但结束后必须可靠回到当前区，不产生跳变或脏 offset。

### 5. 斜侧视战术覆盖层

- R1/R2/R3 数据与因果不变。
- R2 两个倒地点改成贴合地面的椭圆/梯形/贴花，不使用看似俯视棋盘的方格框。
- R3 低热照射区必须沿地面透视可读；人物/小机处于扇区内时仍能精确触发兜灯具名拒绝。
- 鼠标点击、键盘选择、预览撤回和安全检查全部继续可用。

### 6. 对白与 HUD 适配

- 人物放大后重新定位 `scene_caption`，避免遮脸、遮脚点和遮交互提示。
- 顶部 56 px、底部 118 px、左右各 32 px 作为关键画面安全区。
- `halfbody_focus` 与 `cinematic_cutin` 不得让场景完全消失；普通对白仍至少 70% 不依赖头像框。
- 禁止重新引入旧美术头像作为“临时最终效果”。

### 7. 联合截图与短录屏

必须自动或可重复地产出：

1. `01-zone-a-entry.png`：入口构图与人物比例。
2. `02-zone-b-depth-occlusion.png`：纪存完成前后绕行并被前景遮挡。
3. `03-zone-c-old-door.png`：成年观众、旧门、低热区同框。
4. `04-r2-perspective-targets.png`：两个斜侧视倒地点。
5. `05-r3-low-heat-sector.png`：照射区与具名安全拒绝。
6. 一段 45–75 秒录屏：同区移动稳定、跨区运镜、Y 向绕行和一次战术选择。

截图必须使用新壳层，不得复用旧验收图。

## Suggested implementation boundary

- 优先新增独立的 Stage/Camera Zone/Depth Scale 适配层，不重写 RescueState、CinematicDirector、preview ledger 或剧情 JSON。
- 把旧 `rail_camera_target(actor_position)` 的持续追随改成“由所在构图区返回固定构图中心”。
- 把占位房间绘制拆成与未来 manifest 对应的节点，方便 Phase B 逐项替换。
- 把所有画面数字集中到一个可读配置或资源中，避免散落在剧情脚本。
- 允许普通碰撞和构图微调；不得借机推广为全项目相机框架。

## Acceptance

- 首屏静止 3 秒，视觉读法不是正上方俯视地图。
- 纪存中景高度 180–200 px，人物身份轮廓可读，仍能看到相邻两个热点。
- 玩家可在 20 秒内完成一次 X/Y 绕行和前景遮挡，证明不是纯横版。
- 在同一构图区内连续移动 5 秒，摄影机位置保持稳定；Y 移动不造成地图上下漂移。
- 跨越相机区时只发生一次平滑横移，不反复卡边抖动。
- R2/R3 在斜侧视地面上无需切回俯视棋盘即可理解和操作。
- 完整/全跳过 outcome 与旧基线一致；重播/跨区/演出接管无脏相机状态。
- 旧 smoke、Canon strict、Canon smoke 全绿；新增测试覆盖构图区、相机回位、脚点缩放和扇区命中。
- 所有占位明确标注，不加载 `runtime_allowed=false` 资产。

## Stop and ask

- 斜侧视下无法保留 X/Y，只能改纯横版或俯视。
- 需要改变三个构图区数量、人物 165–220 px 范围或正式资产方向数。
- 需要改变 R1/R2/R3 因果、热点顺序、对白结论或馆守 Z 动作。
- 需要另建独立战棋棋盘、引入新战斗数值或替换现有 SRPG。
- 需要覆盖旧基线、重构全项目相机/地图架构或引入新插件。
- 美术 v03 与共享合同冲突，无法通过普通尺寸微调对齐。
