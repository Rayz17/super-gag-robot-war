# 陷阵之志完整攻略与界面研究：工务城诊断

2026-10-05 · 对照当前「逐机回合与联动」版本

## 结论

工务城的主要缺口，是玩家不能方便地把**眼前的威胁、机体能够施加的改变、改变后的后果**联系起来。现有三战场、不同占地、寻路、持续作业、增援和地形结算，可以继续作为基础。下一版应围绕具体的两难局面组织这些能力，同时重做信息层级；只增加技能数量、地形数量或界面装饰，解决不了这个问题。

本轮读完游侠集合的 12 篇独立文章、64 页正文，以及 Steam 进阶攻略的全部正文；查看驾驶员、成就图表和钢铁柔道三个战例的图组，并补看官方商店的 8 张截图。另对当前代码做了检查和独立规则探测，只读观察了正在运行的第 2 回合窗口。**没有改动游戏规则，也没有把这次研究算成新的完整人工试玩。** Grok 的操作经历由用户提供，下文会与本轮确认的证据分开。

## 1. 这次研究真正带来的设计判断

进阶攻略最有用的视角，是以“消除威胁”衡量一手的价值，而非只比较伤害；留下的敌人可能成为挡路、堵出口或引发友伤的工具；移动和装备的价值要放回当前局面判断。这些是攻略作者的战术分析，不是官方公开的 AI 合约。[Steam 进阶攻略](https://steamcommunity.com/sharedfiles/filedetails/?id=2255572363)

钢铁柔道的战例进一步给出了可观察的操作过程：腾出受限制机体的行动，再利用投掷、牵引和炮击改变几处危险；列车战例同时处理眼前车道与后续出场位置。值得迁移的是这种**一手改变多个关系**的关卡组织。[钢铁柔道战例](https://gl.ali213.net/html/2018-3/221917.html)、[列车战例](https://gl.ali213.net/html/2018-3/221917_7.html)

由此，对我们游戏的判断是：丰富性应该来自少量通用效果在不同对象上的组合。单位、货物、设施和地形，都能参与可预测的因果链；机体的装备决定它能够介入哪段链，而不是靠剧情临时赋予所有人同一种“操作”能力。

### 1.1 一手的价值，要能在棋盘上验算

我们可以在设计关卡时使用下面的检查式，帮助发现无聊动作；它不应变成玩家必须学习的隐藏分数：

**一手的价值 = 消除的当前威胁 + 创造的后续位置/任务机会 − 造成的附带损失 − 占用的未来行动。**

例如，打掉敌人 2 点耐久，但它仍会拆桥，这一手可能没有解决眼前问题；将它移离拆锁位置，虽然不扣耐久，却可能保住桥、释放维修时间。反过来，击毁敌人也应始终是有效路线，不能把所有战斗都设计成“只能推”。

落到工务城，应把战斗和工程放在同一套选择里：

| 玩家选择 | 当下获得什么 | 需要承担什么 |
| --- | --- | --- |
| 击毁阻挠工机 | 解除占位、锁车或拆锁威胁 | 损失可保全设备，消耗输出行动 |
| 推离、牵引或吊移 | 改变位置，保留设备 | 需要合适的落点，后续仍可能受阻 |
| 护盾保护设施 | 用一次行动抵消部分损伤 | 威胁源仍在，护盾会被消耗 |
| 持续托举 | 迅速形成通路 | 支撑机后续不能自由行动 |
| 两回合抢修 | 获得永久通路 | 需要供电、备件和保护窗口 |
| 核验旧令 | 保全市政机并解除旧命令 | 要先取得记录，等待回执 |

这些路线中的多项已经有实现。问题在于，界面还没有并排说明它们的收益和代价，开局也没有把它们编排成容易理解的选择。

### 1.2 地图丰富性，取决于位置关系

当前三个工作面是 10×8、10×9、12×8，共 266 格。数据探测得到非普通地坪的已定义地形为 A 17 格、B 22 格、C 21 格；这不含设施和单位，不能直接当作完整地图密度。

因此，“完全没有地形”已经不符合当前实现，但“地形没有充分参与决策”仍成立。许多油地、电弧、断口和输送轨，没有同时与敌人承诺、玩家出手位置和任务通道建立有价值的关系。

下一版保留较大的地图，重点调整接触区：让断口在有机会推落的方向上，让可移动隔板位于能挡炮或堵路的位置，让燃料带连接敌群但同时接近需要保护的设施。大块普通地坪也应承担通道、射界、绕行或大型机转身空间的作用。

### 1.3 增援应该制造选择，避免只增加执行次数

当前已有裂口预告、封口、占位堵口、延期和单面敌军上限。下一版要公开这几个状态的差别：**即将入场、被堵而延期、达到上限而延期、已经封闭**。显示待出场数量时，注明工作面和发生回合。

调节难度，应同时看“本回合真正危及目标的承诺数”“玩家可用主行动数”“被托举/抢修/蓄力占用的行动数”。敌军总数本身不能解释玩家压力。有的存活敌人当前并不构成威胁，有的一个敌人会改变整条撤离通道。

保留用户提出的两类解法：顶住入侵直到撤退后完成工程，或提前清除敌人和阻挠设备。敌情清除后，如果后续只剩没有选择的重复维修，可以快速结算剩余工程；涉及通路取舍、设备保全和奖励的部分仍让玩家决策。

## 2. 当前机制中已经成立的部分，以及尚未形成的玩法

| 先前研究提出的方向 | 当前实现 | 当前缺口 |
| --- | --- | --- |
| 小决策立即反馈 | 移动与主行动分开，确认后执行；允许撤回 | 结果主要说明“发生什么”，没有说明“取消了哪条危险” |
| 公开敌人承诺 | 有顺序、路线、攻击方向、本轮/下轮；普通攻击受位移影响 | 路线被挡后实际出手位置的变化不容易看懂；预览标记需要跟精确模拟一致 |
| 通用位移 | 推、拉、吊移、质量限制、碰撞、失去支撑 | 缺少围绕这些效果设计的接触区和明确组合机会 |
| 地图参与战斗 | 水、断口、碎裂地坪、电弧、燃料、输送轨、可爆电容 | 材质、几何与规则状态没有充分对应；有些效果只靠文字区分 |
| 多机合作 | 位移制造失衡，同伴追加 1；护盾与支持作业 | 组合价值过于集中在追加伤害；没有充分体现聚敌、改线、保护中立物、铺路等不同协同 |
| 多战场联动 | A 供电影响 B 作业/C 行车；C 馈电影响 A 炮/B 安全；核验保全工机 | 常驻界面缺少“本手影响另外哪面”的变化提示 |
| 不同尺寸 | 王者 2×2，完整占地寻路和落点检查 | 大型机的空间代价有了，但额外战术收益需要更有说服力 |

底层效果应继续共用，机体招式则应形成不同的作用形状与动作理由：

- 无牌：快速正蹬、改变近邻位置与方向，以低伤害交换好位置。
- 旧拳王：重心、撞击和反击，强调接近目标后的贴身选择。
- 馆守 Z：左臂牵引、支撑和守护，以站位承担持续代价；不能恢复右臂完整功能。
- 完全版王者：2×2 占地、冗余装备、强推钻具与蓄力炮。多格占地应换来相应的覆盖、承重或抗位移收益。
- 工程、警备、航空机：维修/吊移、实体屏障、越过危险地形等能力，应由装备和行动方式解释。

这是下一版的设计建议。不能把“家族名称不同”当成已经具备不同玩法，也不能为了拼出一条关卡解法，让所有机体突然获得修桥能力。

## 3. Grok 反馈核查：哪些是故障，哪些是表达错误

### 3.1 本轮规则探测得到的确定结果

**桥座 −1 与 −3：目前不能据此认定预告和结算不一致。** 在均衡和工程两个初始编队下，不安排玩家动作直接结算，第一回合桥座实际减 1；进入第二回合，再计算下一次敌方阶段，预计减 3。同一输入重复计算结果一致。第 2 回合运行窗口也显示“若现在结束回合：桥座 −3”。这符合“下一回合的预告”，但界面没有明确把本次实绩和下一次预告分开。不能排除 Grok 的其他操作产生另一条问题，尚未完整复现其全过程。

**第一回合可以复位母线。** 工程编队白色样机移动预算为 5，最短有效工位是 (4,1)，花费 4 格移动，随后操作控制柜合法且成功。玩家先走到 (0,4) 并非目标方向；下一版要显示控制柜、可用工位、推荐路线及距离，而不是只教“点青色地格”。

**接通供电不等于车能马上走。** 同一探测中，母线复位后，撤离车仍因工机锁车停在 0 格。再让吊装机从 (2,6) 移到 (2,4)，把锁车工机吊至 (1,1)，预测车能前进 2 格，随后被 (4,3) 的货柜阻挡。这是当前已有而没有讲清楚的真实因果链：**供电已满足 → 锁车仍未解除 → 解锁后车道仍有障碍。**

**共享招式定义与逐机规则有残留分歧。** 旧导弹定义写中心伤害、四邻推位和两拍飞行；当前逐机结算是中心及四邻各 2 伤害，无推位，立即发生。探测也验证 2×2 单位被十字范围覆盖多个占格时，只受到一次 2 点伤害。当前右栏主要显示简略数值提示，并未确认旧长说明直接展示给玩家；问题是尚未有完整一致的新描述，复用旧演出也存在误导风险。

探测脚本和输出存于本文同目录的 `研究证据-20261005/`，不读取或覆盖正常试玩存档。它们验证具体规则，不代表玩家理解和乐趣已经通过。

### 3.2 操作、HUD 和体验逐项处理

| Grok 观察 | 本轮核查 | 下一版处理 |
| --- | --- | --- |
| 教学固定写无牌，实际编队不同 | 代码确认开局文案写死 | 按本场单位、可用装备和当前目标生成第一步提示 |
| Enter 经常无响应 | 尚未复现；基础按钮已经关闭焦点，不能直接归因按钮抢焦点；忙碌/模态状态会拦截输入 | 专门复测普通确认、预演、模态弹窗、动画期间；明确哪些状态可以确认，按钮和键盘调用同一入口 |
| 控制柜太远或点标签后原因消失 | 规则层有超距、非控制器等原因；浮动标签不等于可点击对象，右栏会回到通用提示 | 标签、模型、占格映射同一对象；非法原因留在目标附近和行动卡，给可用工位 |
| Beam 点歪有明确原因 | 代码有同行/列限制 | 沿用这种短句；同时让有效目标高亮符合限制 |
| 左键选择和旋转易误触 | 累计移动 6 像素即可转镜头 | 分离点选和镜头拖动，容差按屏幕尺度；不让细小抖动变成旋转 |
| 顶部 0/2 意义不明 | 实际是已用主行动/在场己方机数；只移动仍是 0/2，新回合重置 | 写“主行动已用 0/2”或“待行动 2 台”；任务进度另列 |
| 撤离 0/20 格，不知车卡在哪里 | 是撤离路径进度，共 20 个节点 | 展示“已走 0/20 路段”，并显示当前阻塞物、工作面和剩余条件 |
| 多处都标立即，持续托举像一次性动作 | 代码确认非蓄力招统一标立即 | 区分“立即生效”“持续占用”“两回合准备/作业”；写取消和移位代价 |
| 控制柜/转台塞一个按钮 | 当前通用操作标题确实合并 | 按附近对象列“复位母线”“断开馈电”“转台旋转”，仍共用底层操作机制 |
| 下方名单只看当前面 | 代码确认 | 全城六机保留简略可用状态；当前面展开，其他面显示危险及剩余主行动 |
| 预告、任务、权限和提示条太多 | 当前窗口观察确认视觉权重接近 | 主目标、眼前危险、当前行动分层；权限取得证据后再强调 |
| 敌人编号和装饰编号混淆 | 当前窗口可见，同样是短文本标签 | 顺序用统一的编号徽章；装饰编号降低对比，顺序可临时展开 |
| 增援突然变 6，不知已出现还是将出现 | 计算的是本回合末三面各 2 台待出场数量；无遮挡探测实际也是 6 | 写“第 2 回合末：A×2、B×2、C×2”；延期、封口、已入场分别表达 |
| 看不到取消了哪条损伤 | 当前后果面板偏向事件描述，地图预览主要标直接伤害 | 行动前后并列计算同一敌方阶段；划去被取消的危险，显示仍然存在的阻塞 |
| 三区玩成三个关轮流刷 | 有联动规则和全城说明，但局部界面提示弱 | 操作完成时提示远端变化及最紧急下一面；切换由玩家决定 |
| 联合预演默认关，入口像高级功能 | 代码确认默认关闭 | 单手预览始终提供；有可组成的接力时出现明确入口，不要求开模式才能看后果 |
| 悬停与 I 不容易发现 | 已有随光标检查窗，当前窗口可见；教学缺少示范 | 首次点目标就展示检查卡，提示可展开；光标经过单位、地形、设施都要有回应 |
| 白机与金属高光融在一起 | Grok 的视觉反馈；本轮只读观察也可见白机接近浅地面 | 调整接触阴影、背景局部明度、轮廓与材质层级，保留机体自身涂装 |
| 标题好看，战斗像功能沙盘 | 属于用户提供的完整体验判断 | 用正常战棋距离检查整张画面，场景、机体、标记和 HUD 一起制作、一起验收 |

代码还显示一个需要优先处理的细节：选招时用曼哈顿距离绘制范围，但光束实际上要求同行/列，操作实际上要求控制器。因此“范围内”目前不等于“可以作用”。下一版要区分射程/作用距离提示和真正合法目标，避免教玩家点一个亮格后又判无效。

## 4. UI、HUD 和视觉：应该学习什么

### 4.1 参考画面的观察

官方截图中，任务和剩余回合、队伍、武器和对象检查各有稳定位置；地形形状、血量格、局部箭头和高亮承担棋盘信息。攻击顺序可以展开。地图可在绿地、水渠、冰雪、工业区之间变换，同时保留一致的阅读方式。**对象信息并非全部跟随光标，固定卡片也能清楚，关键在内容随当前关注对象变化。** [官方商店截图](https://store.steampowered.com/app/590380/Into_the_Breach/)

结合当前运行窗口，我的判断是：工务城过多采用同底色、同边框、同大小文字的面板，任务、权限、招式和预测争夺注意力；蓝灰 HUD 与工业场景也互相贴近。多个区域各有配色，但同类小屋、地面分格和设施标签仍容易呈现重复感。

这不是由 3D 决定的。三维场景同样可以用轮廓、接触阴影、材质粗糙度、断面高度和局部明度组织画面；代价是这些部分必须共同设计。当前需要把精度用于战棋机位下看得见的结构，避免地面变成一张图、建筑细节却异常密集。

### 4.2 工务城界面重新分工

| 信息层 | 展示内容 | 应避免的现状 |
| --- | --- | --- |
| 常驻战役栏 | 救援目标、当前回合、三面的关键状态、待行动机体 | 用无解释的数字代替任务状态 |
| 棋盘 | 真实占地、合法移动、目标/落点、方向、范围、预计伤害、取消的威胁 | 所有格子长期发光；把方向和结果全搬到边栏 |
| 当前行动卡 | 移动/主行动成本、弹药备件、时机、执行/取消、关键后果 | 所有能力统一“立即”，大段原理混在按钮里 |
| 对象检查卡 | 单位特性、地形效果、设施用途、无法作用原因 | 需要翻固定操作大全才能知道当前对象 |
| 联动通知 | 来源面、改变的条件、受影响面、下一步阻塞 | 用泛泛的剧情对白代替明确状态变化 |
| 结算展示 | 本回合实际发生的事件、变化数值、落点与远端影响 | 与下一回合的预告混在同一个位置 |

建议主界面让棋盘成为最大的连续区域。选机展开一行移动/主行动资源和少量技能图标，详细描述按需展开。七海取得证据前以通讯状态出现，取得证据后才成为明确可用行动。单手预览默认成立；白鸢的联合预演进一步展示一段接力。

这里有一项我们需要额外做好：

**选择前：桥座本回合预计损伤 3。**

**选择后：移离架设位，取消跨区炮；桥座预计损伤 3 → 1。**

**仍有风险：近战啮线体造成的 1 尚未处理。**

这是一条建议的显示格式，并非上述固定开局动作的实测结果。数值应来自同一个精确模拟，而不是单独编写提示文案。

### 4.3 视觉规则与美术制作

- **环境与信息色分开。** 场景保留中等明度、有色阴影和不同区域主色；单位保留自己的 IP 涂装。移动、选中、危险、增援只用少量局部语义色，并配合形状和纹理，避免全屏铺青、黄、红、紫。
- **地形的体积说明用途。** 断口有下层与断面，水面低于桥板，输送轨有方向明确的滚筒/轨槽，导电地带有电缆与故障脉冲。装饰能帮助理解，却不能被误当成可操作物。
- **细节密度按阅读尺度统一。** 机体、建筑、地面都要在普通机位下成立。缩小时保留轮廓与大材质块，细螺丝和污损退后；控制柜与普通小屋应有不同的轮廓。
- **状态比名字更像图标。** 护盾、蓄力、抢修、托举、断电、失衡应有短图标和进度，点开再读规则。普通视图优先显示与决策相关的状态。
- **动态标记围绕变化。** 路线箭头朝落点流动，取消威胁的线收束或划去；联动发生时从来源区走向受影响区；结算短停顿对准关键变化，而非每个无后果小动作都同样慢。
- **机体表现统一制作标准。** 棋盘上的单位继续使用三维角色；头像统一取头胸部，技能图标表现作用形状。统一的是建模、贴图、骨骼、机位与反馈的完成度，机体轮廓和招式仍须各有特点。

每张工作面要独立检查普通视图、移动选择、技能选择、对象检查、结算五种状态。关闭 HUD 后看材质和空间；打开 HUD 后看目标与后果。两种检查都成立，才能说明完成度有实质提升。

## 5. 下一版的具体推进顺序

### 第一阶段：规则与表达一致，修复操作断点

把逐机版本的招式作用形状、持续时间、护盾消耗、反击条件和变形限制整理成同一份定义，由判定、预览、说明与演出读取。旧四拍字段继续服务旧版本，但不能让新版本含义含混。导弹的推位型/伤害型需要明确选择；如果保留两种，应成为不同武器。

同时处理动态教学、Enter 的实际输入复测、标签命中、非法原因、点击/拖镜头分离、合法目标高亮、0/2 的含义、持续作业时长，以及本回合实绩和下一回合预告的区分。

### 第二阶段：做出第一回合可见的因果闭环

当前工程编队已经能做出下列可验证过程：

1. A 白色样机走到母线工位并复位，电弧带解除，B 获得抢修供电；C 行车条件中“缺电”消失。
2. C 吊装机吊离锁车工机，撤离车预测由 0 变成前进 2；货柜成为清楚可见的下一处阻塞。
3. B 根据玩家选择托举、修桥或应急桥，改变撤离车到达渠口后的通行条件。

前两步已用规则探测验证；第三步列的是已有机制的不同路线，未在本轮连成新的完整试玩。下一版围绕这条链做教学与镜头交接，同时让其他编队按自身能力获得可行建议。不要要求所有玩家照做同一条脚本。

白鸢预演应逐层展示：一手改变什么；再加一手是否形成接力；结束回合后会发生什么。纪存的重点是标出多面紧急程度、支援位置与抵达时间。七海提供的是本地旧令核验与设备保全的另一条解法。三者能力各有边界。

### 第三阶段：增加值得取舍的局面与协同

在保留地图尺寸的基础上，重排交战区、掩体、危险地形、增援口和路线。每面先做少量明确组合：推离作业、挡炮、护盾保护中立设施、诱导友伤、燃料连片、运输带搬运。每种效果至少验证己方、敌方、设施和多格单位中的相关对象，不能只对某一台指定角色有效。

大型机除空间代价之外，需要能体现重量、承重与覆盖的优势。市政机、外敌和居民设施带来的损失，应明确影响保全、资源或额外目标；当前居民建筑受损缺少足够明确的后果。奖励差异要公开，避免等到结算才发现选择有代价。

敌人路线的表达也需要一次明确设计选择：建议优先尝试“敌人先就位，再公布当前攻击”的小范围候选对照，让玩家直接处理眼前射线；跨回合蓄力、任务持续和三面联动保留。若继续保留敌人结算时移动，则路线、受阻后的实际落点和攻击线必须由同一模拟给出。两种方式不应混在同一套模糊预告里。

## 6. 玩家验收标准

1. 开局不读长文，能指出要救谁、当前阻塞是什么，以及哪台机体能够介入。
2. 自选合法编队仍有与实际单位匹配的引导；能力覆盖不足在部署时明确提示。
3. 点一个合法地格能安排实际可行路线；点错目标能立即知道原因与可用工位。
4. 一手确认前能说清移动/主行动成本、作用对象、时机，以及改变了哪条危险或任务条件。
5. 能区分本回合实际损失、下一次预计损失、待入场增援和已入场敌人；确认与结算一致。
6. 在第一回合看见至少一次跨面后果，且知道继续停在本面或切面有什么取舍。
7. 同一局面至少有两种代价不同的合法处理方式，能够通过通用效果组合，而非只点击指定剧情按钮。
8. 正常战棋距离下能辨认机体、危险地形、可操作设施和方向；HUD 不遮住主要决策区域。

自动检查负责规则和输入可靠性。上述玩家理解与乐趣仍需要实际操作验证，不能由截图或探测脚本代替。
