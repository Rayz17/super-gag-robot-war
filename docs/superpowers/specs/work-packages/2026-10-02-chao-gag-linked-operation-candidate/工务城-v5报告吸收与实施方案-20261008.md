# 把一手棋做得看得懂、值得下、打得响

工务城 v5 报告吸收与实施方案 · 2026-10-08

**这次应该改的是“玩家如何认识并利用规则”的整条过程。** 当前工程已有三战场、大小机体、逐机行动、持续作业、增援、预演与结算。报告暴露的是：这些能力没有稳定地形成清楚的选择，说明有时还在说错话，动作与环境也没有把结果演出来。

因此继续保留现有工程；从动作定义、对象能力、预测结果、关卡出题和演出制作一起整改。美术和手感从第一批就参与，不能排在“功能完成以后”。

本稿依据 Grok 的上、下册及本地配套正文，已通读正文、附录、规格表并检查重点图解；另核对当前工作树的动作、预览、输入、部署、敌方计划和演出代码。本次形成的是**实施设计和任务对应表，尚未改动游戏代码，也没有把报告的试玩结果冒充为本次亲自试玩**。

## 先改掉我的研究和交付方式

这份报告好读，是因为它在回答玩家遇到的具体事情。它把截图中的位置圈出来，把动作拆成前后过程，把建议和现状分开；读者不用先学工程术语，就能判断问题是否存在、建议是否有用。

例如，“城防预告不清楚”仍然很笼统。报告 AI08 给出的是：**确认框写 A 供电 −1，玩家点结束回合，随即城防 1→0、任务失败；玩家没有被告知这个 −1 会结束整局。** 这句话同时交代了操作、误解和后果。

再如，报告没有停在“工程动作缺乏打击感”。JC01 把隔离墙拆成收臂、发射、飞行、落地、固定、残留；每一步都能看到与现在的差别。它提出的数值仍需调试，但制作人员已经知道要做什么。

| 我过去经常怎么写 | 为什么没帮到你 | 以后对应怎么交付 |
|---|---|---|
| “已支持联动、已接入反馈，检查通过” | 描述的是代码存在，无法说明玩起来怎样 | 先给一段实际操作：玩家改了哪一手，哪里因此得救，哪里仍要处理 |
| “统一视觉语言、增强层次” | 没有具体画面，做完也无法判断 | 同机位对照；指出要改哪个轮廓、材质、标记及动作阶段 |
| 列很多机制名和限制 | 把理解成本留给读者 | 用一组对比说明：现在可以选什么，两种选择各改变什么 |
| 回答缺点时继续增加功能 | 没解释原来的功能为什么不好用 | 查清是规则错误、信息错误、操作阻力、局面无趣，还是演出不足，再改对应部分 |
| 用测试数量、截图数量证明完成 | 自动检查不能证明玩家能理解，也不能证明动作好看 | 分别记录规则一致性、真实键鼠体验、正常镜头观感和听感；缺哪项就不写哪项通过 |

**我的问题不只是文风：我常把“实现了某个接口”当成“解决了玩家的问题”，然后用总结性语言跳过中间的证明。** 后续每项改动都必须有“玩家遇到什么 → 为什么 → 具体怎么改 → 操作后看什么”的证据，代码细节放在后面。报告有推断和待验证的内容，我也需要保留这种诚实，而不是整份照单全收。

## 通用机制先解决四个断点

### 1. 一种能力究竟对什么对象做什么

当前 `tactical_contract.gd` 已在整理通用定义，但它把所有 `force > 0` 都添加为 `displace`。拘束索和吊装都带力值，实际却不是“把目标推一格”。`round_inspect_diagram.gd` 又使用固定命中格与固定长度的箭头；技能小舞台则让不同动作对着同一个目标循环。于是功能越多，说明越容易失真。

应把招式分成可以组合的明确部分，而不是用伤害、力值和动作名字猜含义：

| 部分 | 要表达的内容 | 直接解决的问题 |
|---|---|---|
| 机体身体与机动 | 占地、质量、地面/悬浮/飞行、通行与落地条件、移动预算 | 2×2 不能按中心一点寻路；飞行不等于无视所有实体 |
| 工具与挂载 | 手、吊具、千斤顶、支撑结构、发射器、弹药与备件 | 角色能做什么由装备和能力决定，不能走到剧情点就突然会修理 |
| 目标与形状 | 自身、单体、目标格、双直线、扇面、十字、作用对象类别 | 双肩炮不是 L 形三格，变形也不是零伤害近战 |
| 效果步骤 | 伤害、推拉、拘束、吊运、护盾、修复、生成、变形、改变连接 | 力值只回答能否搬动/控制，不能代替具体动作 |
| 时间与承诺 | 立即、蓄力、持续、解除；锁定方向/格子/接触/架设条件 | 被推开后究竟继续打、打空，还是取消，事先可判断 |
| 结果与来源 | 谁做的、影响谁、在哪一格、为什么抵消/碰撞/失效、引起哪条后续变化 | 同一次结果可以用于棋盘标记、血条、演出、结算与回看 |

效果对单位、敌人、设施和任务物件共用；能否生效由对象属性判断。例如护盾可以给敌人，吊具可以搬有吊点且未超载的货物，顶推可以改变敌机或可移动障碍的位置。承重、锚定、绝缘、易燃、浮空等属性必须有看得见的形态或检查提示。

**通用不等于人人技能相同。** 共用的是判定；各机体的装备、作用形状、代价和动作不同。两台机体都能支撑，可以一台擅长持续承重，另一台消耗部署件形成临时支撑。没有必要为了去重，把合理的物理能力硬删掉。

### 2. 说明、预览和实战必须讲同一件事

保留 `RoundRules.simulate()` 的确定性试算，向它收拢完整命令的合法性与结果。技能说明的小棋盘也使用真实沙盒局面试算：有实际施法者、目标、障碍与占地，不再画一个固定箭头充数。

同一条命令依次产生：可执行路径与落点 → 即时结果 → 在已公开承诺下的回合末结果。三个时间层分开呈现，不能把下一次预计掉血伪装成刚刚已经掉血。

首批必须逐个核对报告 FX01–FX15：钻头推两格、扇面三格、双肩炮两线、拘束不位移、吊运两阶段、群体护场、修复、变形、导弹波及设施、蓄力释放，以及坠落导致市政损失。完整 18 招的示意与实际受影响格集合、伤害、位移终点一致；对 2×2 单位明确同一次范围攻击的去重规则。

**预览不能消耗任何资源；执行只扣一次。** 预览不可直接修改正在玩的状态。演出完成与否也不能决定游戏规则是否生效。

### 3. 地图要提出可以比较的选择

现有增援、环境和跨区系统都保留。问题是这些元素没有充分参与同一组选择：目标很远、危险地形离交战点太远、当前编队缺少适合的工具，都会把策略变成走路和等回合。

重摆关卡时先检查三件事：第一回合能改变哪条真实威胁；同一个问题是否有两种不同代价的解法；选择之后另一区是否出现一个值得安排的机会或代价。不是把每个空格都填成危险地形，也不是保证每回合都能把敌人推死。

| 工作面 | 要形成的选择（新关卡设计目标，尚未实测成立） | 可复用的底层能力 |
|---|---|---|
| A 供能前庭 | 击退啮线体保母线；部署隔离物接弹；或抢先接通后承担局部损坏。持续蓄炮威胁与电路位置构成取舍 | 推位、射线阻挡、供电连接、架设承诺 |
| B 跨渠桥座 | 支撑承重保通行；加盾抗过本轮；或搬开/限制拆桥工机。水与护栏放进实际交战位置 | 支撑、护盾、吊运/拘束、坠落与落点 |
| C 环下装卸站 | 搬走货柜保全物资；破坏货柜换速度但损失资源；切断错误工令/牵引关系释放车辆 | 可搬运物、破坏产物、控制器与权限、运输路线 |

三图尺寸按局面调，不直接全部改成 8×8。保留 2×2 的回转和降落空间，减少的是无目的的路程。推荐与自由部署都要检查能力覆盖；缺工具时提前显示可用替代办法和调度到达时间，不能出击后才发现只能等某一台专用机。

敌人按“它要改变什么”区分：咬断供能、架设轰击、拘束载荷、保护同群、占据通道。增援位置和时机要参与这个局面，而不是远处不断加血包。先用确定性的候选行动评分选择有效威胁，再公开承诺；**承诺后不能为了变聪明偷偷追着玩家改招**。玩家造成的打空、误射、断供和堵住增援，正是应保留的解法。

### 4. 三个战场要在空间和因果上连起来

总览需要一条连续的城市承运结构，局部视图能看见相邻桥段、管线或吊臂，不能像三块不相干的棋盘。运输方向由同一条世界坐标路线投影到各图；字母 A/B/C 不承担左右方向。

底层把联动定义为设施/控制器的输入输出关系：电源接通 → 相关装置可工作；夹持解除 → 载荷可移动；支撑失效 → 桥段承重条件改变。关卡只配置连接对象和目标，不把“在 A 做某事就改 B 的变量”散写在界面里。

纪存负责可见的调度与跨区资源分配；白鸢负责比较这一手前后的公开后果，基础预览始终可用；七海负责查证旧令、提交核验和限定范围的撤令途径。**她不是万能开锁角色**：当前设定中没有代哥写权限，不能凭一个技能替城市授权。

立体玩法值得做，但先做一条完整的“吊运载荷跨区、改变道路/威胁”样板，再扩展离散高度、支撑坍塌和空地关系。高度必须同时进入寻路、落点、预览和表现，不能先把棋盘抬高、让人以为能落下去，规则却仍是平面。

## 玩家会怎样操作和看懂后果

**自由光标是常态。** 悬停看对象与威胁；左键选机体后立即出现可达边界，绿线路径随光标走；点击合法落点就移动。选招后悬停看实际效果，点击执行。右键退回上一步，Ctrl＋鼠标继续用于相机。无风险普通动作不再叠多层确认。

自动走近必须检验完整动作：能否绕过障碍、整个占地能否站下、到达后是否仍能出手、资源是否足够。可以完成时一次预览“路线＋动作”；不能完成时指出缺少的移动、视线、工具或落点。不能把“先走一格但仍办不到”包装成可执行的调度。

| 玩家此刻在做什么 | 棋盘上直接出现什么 | 此刻不该出现什么 |
|---|---|---|
| 没选人，扫视局面 | 关键保护对象、有限的威胁标记；悬停展开攻击者—目标关系 | 全敌人说明段落、全部路线同时铺满 |
| 选择移动 | 完整占地虚影、绿色路线、剩余移动；不可达处的具体原因 | 满盘高饱和填色、逐格停顿的奔跑 |
| 瞄准钻头/推拉 | 每段位移、终点、碰撞双方、坠落符号；受影响血格闪烁 | 只画一根没有落点含义的箭头 |
| 瞄准护盾/拘束/修复 | 受保护范围、将取消的移动、实际修复血格及备件消耗 | 通用攻击火花、零伤害近战标签 |
| 这一手改变敌方威胁 | 原本会受伤的对象上，原威胁变成清楚的“已挡/已错开/已中断” | 只在右侧多写一行结果 |
| 将误伤关键设施或损失市政机 | 对象本身高亮、具体损失和任务影响；再次点击同一目标确认 | 只检查我方机体掉血，不检查设施/运输/声誉损失 |
| 结束回合 | 明确“本回合末”：谁将伤害谁，城防是否归零，增援是待入场还是已入场 | 只写母线 −1，却省略它将导致失败 |

常驻 HUD 只保留目标与整体危险、区域切换、当前机体的动作入口、回合操作。机体/地形/敌人规则留给悬停和按住 I；技能短动画按需展开，不能常开遮棋盘。跨区卡只突出“远端需要处理的后果”和可定位入口，不再塞一份小型百科。

敌方阶段按一个完整因果播放：来源 → 轨迹/移动 → 命中或被阻止 → 受影响对象变化。同区域连续事件少切镜头；跨区先说明为什么切。失败那一击演完并留下结果，才进入结算。普通回合小结短暂显示，可展开回看；**不采纳每轮都强迫点掉小结的做法**，避免刚减少的点击又加回来。

## 美术和手感按实际画面制作

![报告 PL17：供能柜的现状与建议造型](../../../../../captures/gamezai-playtest-20261007-v4/shots/PL17_方块到造型_供能柜.png)

*这张是报告的设计示意，不是已落地的游戏资产。它说明应如何通过高瓷瓶、散热片和台基，让远处的设备看起来就是变电设备。*

采用报告的轮廓—结构—细节方法。首批同步重做供能柜、货柜、路障、桥段、断口、地块底座；每类制作完好、受损、毁坏形态。看得见的倒角、厚度、凹槽和构件要靠几何；涂装、磨损、面板细节用统一绘制尺度的贴图。继续使用有说服力的材质，避免又退回纯色方盒，也避免照片纹理与机甲绘制风格相互打架。

色彩采用报告的分层原则，**不直接整套套用夜班暗灰方案**。基于已有项目原画建立有色的工业日景：A 的陶瓷/铜/涂装设备，B 的水体与冷色桁架，C 的褪色货柜与起重结构形成区域识别；控制大面积亮白，机体保留各自涂装。环境与信息标记用形状、明度、动态和面积共同区分，不能靠给所有机体重新刷一条相同颜色解决。

两项检查必须同时通过：关掉 HUD、保持正常战棋距离，场景仍能读出材质与结构；打开战术标记后，机体、可达范围、威胁和保护目标又能迅速分开。放大截图好看不算通过。

![报告 JC02：起手、命中、受击、声音与血条的配合](../../../../../captures/gamezai-playtest-20261007-v4/shots/JC02_一次命中时间轴.png)

*报告时长是调试起点，不是行业标准。它的价值是把“打击感”拆成能制作、能复核的阶段。*

演出先建立动作时钟，再做逐招脚本。移动沿合法通道连续行进；命中才有必要停顿。推两格在中间发生碰撞时体现两个因果节点，但不让普通奔跑重新变成逐格挪动。暂停、加速、跳过只能改变播放，不能改变结果。

| 样板动作 | 必须做出的画面 | 必须核对的规则 |
|---|---|---|
| 预算二号部署隔离墙 | 从对应挂载取件/发射，轨迹与落影，落地固定，耐久部件变化，敌弹被接住 | 墙有实体、耐久和阻挡作用；预览先展示被截断的攻击 |
| 社勇王近战 | 支撑脚、转髋、肩肘、闭拳、接触、收势；威力来自完整运动链 | 伤害、推位与自身保护分别结算和表现；掌、拳、手刀不能混用 |
| 王者双肩炮与钻头 | 肩部转轴和炮口方向合理；右手钻头连续连接；后坐与钻进表现不同 | 双直线/第一阻挡物与两格推移各按定义执行，2×2 攻击起点正确 |
| 雷翎光束与导弹 | 瞄准—瞬时射线与弧线飞行—爆心/邻格明显不同 | 贯穿/阻挡、中心/溅射、设施误伤真实一致，不能用文案虚构推力 |
| 灰崎拘束、货柜护场/吊运 | 连接点、绷紧方向、护场边缘、载荷重心和承载结构可见 | 拘束限制什么、护盾覆盖谁、吊装质量上限与落点条件可查 |

六台先形成六种操作判断：社勇王进入接触位置解决一串威胁；王者用大占地与蓄炮换覆盖，飞行负责通行但需要合法落点；雷翎在射线与范围爆炸之间选择；预算二号用有限备件构造与修复；灰崎控制移动而不随意毁掉市政对象；货柜领袖护送、承载和改变通路。再将相同制作标准覆盖全部可选机体，不能只把推荐六台做好。

身体比例采用既定规格，保留 1×1 小型/标准、2×2 大型的视觉区分。每台沿既有“设定图—Blender 整理—贴图—骨骼—对应动作—游戏内表现”流程审查。不同外形允许不同，骨骼完整度、材质精度、足底接地、挂载连接和镜头可读性必须一致。馆守 Z 的右前臂缺失继续保留。

声音做起手、接触材质、低频重量/尾音的搭配，配合敌方阶段的停顿。报告没有录到系统音，不能据此断言现有音效全坏，也不能用“音频文件存在”证明好听。验收录制正常速度的带声操作，并提供震屏减弱/关闭。

## 分六批做，每批交付完整的可感知变化

| 批次 | 实际制作范围 | 通过的标准 |
|---|---|---|
| 1 · 把一手棋做实 | 明确动作效果、真实技能示意、完整走近计划；同时完成隔离墙及受保护设施的模型、预览、发射、拦截、声音 | 玩家悬停就知道墙会挡哪一炮；点一次完成合法计划；正常镜头能看到取件、落地、挡住，实战与预览一致 |
| 2 · 看得清整个回合 | 完整风险预告、市政损失、敌人有效承诺、敌方阶段与失败演出、全量回看；完成设施三态、语义标记和 HUD 减负 | 玩家在提交前能指出致败来源；暂停来得及使用，失败后说得清是哪一击；无整盘染色/面板互挡 |
| 3 · 让地图真正出题 | 重摆三区首两回合；部署能力检查、贴近交战的地形、目的明确的增援；三类场景造型与材质同步覆盖 | 不靠教程指名某机体，也能在首回合改变威胁；各区至少两种有不同代价的解法；自由编队不会遇到未告知的唯一工具死锁 |
| 4 · 做出机体差别 | 六台核心动作样板扩展到完整可选阵容；不同武器形状、保护/控制/工程的组合；飞行/变形/搬运差异；角色反馈与必杀切入 | 隐去招式名仍能看出拳、钻、炮、束、导弹、吊具；选不同机体能改变解法；所有可选单位达到同档 3D 制作水平 |
| 5 · 做实跨区与结构 | 棋盘内调度、到达时间/行动预算、连续城市路线、首条跨区结构操作；高度规则和对应预览一起加入 | 玩家能说明此处动作如何改变另一图；换一张测试地图仍成立；转相机不改变规则或隐藏致命条件 |
| 6 · 恢复人物在战斗中的作用 | 纪存/白鸢/七海的能力职责、出席人物与对白、少量固定指令、名场面演出；不先引入随机牌堆 | 人物改变一个明确选择且代价可预览；未出击者不冒充在场；不强迫每个普通动作看长过场 |

批次是依赖顺序，不是把后五批忘掉。第一批内部的规则、交互和美术同时推进；整轮结束时六批都要有实施或明确设计复核记录。未来随机卡组、完整空战燃料/雷达、十二套立体结构机制、触屏操作属于后续扩展，不能混进本轮“完成”的口径。

每批保留改前/改后同局面、同机位的带声实机录像。录制时关闭自动演示，真实点击、移动光标、取消和切区；人工复核与规则检查分别记录。前三回合必须由未看代码的人试玩，重点问“这一下会影响谁”“为什么失败/为什么要切区”，而不是只问有没有通关。

## 给实施者的接线位置

下面是当前代码入口；描述的是待改职责，不是说这些改动已经存在。沿现有函数分步迁移，不另起一套战斗内核。

| 入口 | 该承担的职责 |
|---|---|
| `rounds/tactical_contract.gd`、`round_armaments.gd` | 明确能力、工具、装备、目标形状、时间和效果步骤；取消由力值猜动作的映射 |
| `rounds/round_rules.gd::reason/approach/simulate/attack_shape/ability` | 完整计划验证、不可变试算、按对象属性执行、连锁来源；使规则能在无工务城专有对象的测试图运行 |
| `rounds/round_inspect_diagram.gd`、`round_skill_stage.gd` | 用真实沙盒结果绘制技能图与演出；取消固定目标/通用攻击循环；按需实例化与暂停，避免说明卡持续吃帧 |
| `rounds/round_cursor.gd`、`round_stage.gd`、`round_hud.gd` | 自由光标、整条走近计划、风险确认、信息分层、键盘焦点、Ctrl 手势；避免预览重复试算阻塞点击 |
| `rounds/round_brief.gd`、`tactical_feedback.gd` | 区分本手/回合末/条件未来，统一血条、箭头、取消威胁、损失与致败来源；一个事件解释一条因果 |
| `rounds/round_rules.gd::plan_enemies/enemy_phase/spawn` | 有效计划、公开且稳定的顺序、增援压力、发布后兑现承诺 |
| `rounds/round_data.gd`、`round_operation.gd` | 可替换的地图、目标和连接配置；部署能力检查；将剧情对象引用留在关卡层 |
| `fixture_art.gd`、`ground_relief.gd`、`rounds/round_world.gd` | 实体轮廓、地面结构、三态资产、语义覆盖层、正常镜头尺寸和遮挡 |
| `model_motion.gd` 及逐机动作资源、反馈与音频层 | 挂载锚点、支撑/握拳/变形运动链、动作阶段、受击方向、材质声和击破；UI 和音频不被命中顿帧一起冻结 |

核心命令建议逐步收敛为四个记录：动作定义、玩家请求、可执行计划、结果事件。计划中保存完整路线、施法位置、方向/落点、资源与承诺；结果中保存来源事件、受影响对象、前后值、阻挡/取消原因和后续连接变化。先适配现有字典结构，不要求全仓库一次重写。

缓存按状态版本、所选单位/装备形态、命令和敌方承诺版本失效。鼠标经过同一目标不反复生成模型或跑整轮；即时结果先显示，回合末比较完成后再呈现，并标明计算状态。以目标机器真实帧耗时评估，不能靠删效果掩盖卡顿。

新增机制必须通过迁移检查：交换机体名称、替换同能力装备、挪到另一张地图，行为仍然成立；2×2、飞行、免疫、友方设施、空目标、连锁与取消都覆盖。每个失败案例都回到报告图号对应的实际画面复核，不能只关测试表。

## 几项必须克制的新增设计

人物、机魂、结构与空战很值得恢复，但每项要增加选择，不能只增加等待或弹窗。雷翎“单数回合不能开火”、满气势强制拒绝、抽不到牌就不能处理当前威胁，都不宜直接采用。可以改成玩家事先选择的射击/标定/蓄力取舍，或公开的角色条件与替代方案。

飞行先把已有能力做实：跨越允许的地形、完整占地的落点、空运能力、转场时间和动作预算。更复杂的高度、燃料、雷达、空对地体系另做一个可验证样板，再推广。旧“几拍到达”不能直接搬入逐机回合，要明确抵达阶段、剩余移动和主行动，防止跨图刷新行动。

失败压力通过敌人、位置、顺序和可用反制设计；不靠隐藏“每轮城防最多扣 2”保护玩家。报告的尺寸、明度、秒数、工期与辨认率是建议或该次测量，均不当成已经验证的产品标准。

七海权限、社勇王核心/合体与主体 AI、馆守断臂等按当前 Canon 解释；报告引用的历史设计和新增卡牌仍是候选。这里是战斗 Demo 改造，不回写已接受 Reader，不把玩法试验变成新的剧情事实。
