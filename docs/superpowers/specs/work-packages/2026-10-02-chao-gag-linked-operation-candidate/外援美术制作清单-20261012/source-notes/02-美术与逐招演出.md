## 10月12日制作路线调整：把精力放在设计与招牌表现上

按用户本轮明确要求，以下口径优先于旧稿可能被理解为“每机每招单独制作、逐对精密接触”的描述。52包的玩法和呈现范围保留；改变的是生产方式。

| 对象 | 采用的制作方式 | 仍须保证的表现 |
|---|---|---|
| 全环境楼房、厂房、车站及大构件 | 先出符合视觉总参考的设计图；按图制作低多边形实体、UV、贴图和材质 | 现代工业尺度、可信立面、材质差异、正常镜头层次；不是把一张透视图竖成广告牌 |
| 棋盘内居民楼、电力/工程设施、列车 | 同样图先行；受损外壳、开关、闸门、吊臂、转台、车轮按规则需要少量分件 | 占格、遮挡、破坏和简单运动真实；供能/断电、开合、旋转、移动有对应事件反馈 |
| 标准机体动作 | 使用可复用的待机、移动、操作、持物、射击、受击动作家族；每种骨架一次适配 | 保留原机体比例；手型、武器、重量、节奏与效果对应。共享骨骼动作不等于共享所有技能效果 |
| 无牌天冲拳、体术机拳脚及少数招牌演出 | 从合适参考或库动作起步，再单独编排必要部分 | 转髋、支撑脚、拳掌刀、蓄力与收势有明确差异；投入集中在玩家能识别的招牌上 |
| 机体—机体、机体—设施接触 | 规则事件决定后果；出手者、目标、环境分别处理自己的动画/状态，共用高度档、武器挂点和有限方向修正 | 正常镜头动作成立、没有明显反关节/严重穿插；不建立双方单位配对参数表，不以毫米接触或连续物理碰撞为常规门槛 |

## 1. 统一制作水平，保留机体自己的长相

<!-- PLAN_FIGURE_END -->


用户要求的统一是质量、材质表达、动画和尺度口径一致，不是把所有机体染成场景的颜色。场景采用有结构、有风格化材质的工业科幻模型；机体保留各自涂装与形态；HUD 是现代仪表界面。三者用共同光向、边缘处理、清晰度和受力反馈衔接。

不直接采用报告“去掉全部贴图、统一纯色”的捷径。照片扫描地面的高频噪声确实应去掉，但要替换成受控的风格化纹理：金属拉丝方向、分片色差、接缝、磨损、油迹、承重材料。凹槽、坑沿、底座、轨道不能只画在一张平面纹理上。

### 调色先定层次，再定色值

| 区域 | 场景气质与材料 | 大形与地标 | 与机体、UI 的分离 |
|---|---|---|---|
| A 供能前庭 | 钢青绿电气柜、混凝土米色、少量铜与陶瓷；中明度日照 | 分级电站台基、瓷瓶阵列、电缆沟 | 中性地面托住红白机；琥珀仅在供电/受保护设施状态强调 |
| B 跨渠桥座 | 钢蓝桁架、矿物青水面、冷色阴影；潮湿但不阴暗 | 真桥墩、桥下检修层、断裂桥缘 | 水/深度形成大面积色块，桥面不做一排刺眼白条 |
| C 环下装卸站 | 瓦红与褪蓝货箱、偏蓝灰甲板、铜金吊机局部 | 长箱错层、龙门吊、下沉转盘、轨道 | 暖货箱只作实体涂装，不发出“敌意红”光；轨顶与枕木有材质差 |

三套报告配色都留作色稿比较：夜班是任务变体，白昼提供空间通透感，霓虹只用于特定远景或敌设施。主版不选“全暗蓝灰”，也不选“大白屋顶＋荧光按钮”。绝对 L* 数值不按截图机械照搬；在相同镜头、曝光、显示尺寸下看角色、危险、背景能否分开。

角色美术不能靠全员降饱和来消除冲突。人类立绘统一胸像裁切、眼线、头肩占比、光向、描边与展示框；战棋头像使用专门的头肩构图。仍有二维占位的常规参战机进入模型、贴图、骨骼、动作制作，不以朝向相机的贴片假装完成。

| 7 值班室/避难点 | 雨棚、楼梯、门窗、屋顶设备、居民光点 | 这是有人设施而非电柜；受威胁/安全后的短气泡与灯光可见但不挡操作 |
| 8 撤离车 | 保留转向架，收敛到主副两色＋深窗带，明确车头与前照灯 | 知道往哪开、载了谁、卡在什么位置；列车方向与城市总览一致 |
| 9 转盘 | 下沉轮廓、环轨、锁销、旋转接缝，停止位有定位标 | 能看出哪些格会被带走、转到哪一档、哪条线路接通 |
| 10 交接点 | 有方向的 chevron、区号、出入口结构与预留落位 | 区别普通可移动格；地面/空运通道有图标和方向 |
| 11 电缆槽/供能线 | 凹槽与接口为几何，电流仅沿实际连通关系流动 | 复位→得电→能操作的过程可沿线追踪；断线位置看得见 |
| 12 远景/城市构件 | 大型环柱、厂房、管线构成同一城市；减少细碎噪点，用空气透视拉开层次 | 三张图属于同城但有不同功能；远景不抢战术标记，不一律压成黑剪影 |

报告八条造型规则均应用，但比例随资产调整：脚印守格、剪影破方、按阻挡功能分高度、放大可读倒角、剪影/结构/贴花三级细节、收敛明暗、地面有厚度、损坏改造型。**世界米数不直接决定战棋模型比例；净空与阻挡也不能从视觉高度临时猜。**

**2026-10-12尺寸补充（用户决定）：** 敌我及中立单位共用小型单格、标准单格、2×2、3×3和巨构局部的表达档位；普通敌体不再额外缩小。人物/机器犬等微型对象约占四分之一格的平面面积，显式剧情尺寸保留例外。当前实现由`unit_scale.gd`统一等比适配，长条身体不再受仅针对敌种的狭小横向上限限制；显示分类不改占格、质量、净空、移动或伤害。工务城当前试值、实际正常镜头对照和余项记入B16原体验记录；不把这些数值反写成全项目工程米数。

当前项目使用 Compatibility 渲染路径；报告也指出其 Decal 节点方案有兼容问题。实施先验证现有运行路径，贴花可用共面偏移的网格/材质图集，不因新增贴花功能贸然换渲染器。边缘、阴影、透明层和骨骼材质必须在目标 Mac 上检查。

## 3. 语义色和形状各有职责

| 含义 | 首选表现 | 限制 |
|---|---|---|
| 可达 | 青色细格边与角标 | 不整盘铺浅绿；低透明度填充只限当前落点附近 |
| 本机路线 | 绿色流向线＋空心落脚点 | 按用户既有操作习惯；与互动绿色用形状区分；流向始终起点→终点 |
| 敌方威胁 | 珊瑚红斜纹落点＋对应弹道/近战箭头 | 场景装饰红不采用同样高亮；敌人涂装不强制全改品红 |
| 推移/碰撞 | 带暗描边的大方向箭头＋落点虚影＋碰撞符号 | 可用局部白/暖白，不铺大片白底；箭头长度按真实推距 |
| 受保护对象 | 琥珀盾/城市图标＋被瞄准时脉冲 | 黄黑工业标线允许保留为低对比装饰，但不用同样动态图形 |
| 可操作接口 | 绿色工具/插头图标＋对象底座短脉冲 | 仅在选中有能力机体/悬停时突出，不全场同时发光 |
| 跨区 | 紫色方向标＋A/B/C 和抵达阶段 | 不依赖紫色本身区分敌我；跨区箭头有源与目的地 |
| 选中/已行动/蓄力 | 脚底环、空实行动点、武器蓄能与落点图 | 机体脚不漂移；已行动不等于全机变灰黑 |

灰度、三类色觉模拟、缩小截图和动态背景都要检查。报告色值作为候选 token，选定后集中管理；环境和机体仍有自己的配色，不把战术色当全场涂装。

## 4. 动画的 11 层，不靠单一大爆炸补救

| 层 | 怎么做 | 何时算完成 |
|---|---|---|
| Idle | 呼吸、伺服微动、头部观察、附件延迟；不同状态和不同相位 | 默认全景看得出活着；脚底固定，无透明躯干与闪烁 |
| 预备 | 握拳/掌/手刀分型，重心、转髋、工具展开、炮架锁定 | 手型正确；回旋踢有支撑脚→髋→身体旋转，膝盖不反关节 |
| 轨迹 | 真弹体、光束核心、曳光、弧线阴影、发射机关 | 从正确炮口/手部发出，停在真实阻挡位置 |
| 命中 | 接触帧、受击姿态、闪光、分级顿帧、伤害血条 | 护盾吸收与真伤不同；无伤拘束不能假装爆炸扣血 |
| 产物 | 工具/地面模块→运输/展开→落地/固定→规则就绪 | 墙、补片、盾锚、桥板各有来路，不在 sync 时提前弹出 |
| 推撞 | 受力、滑行/踉跄、碰撞双方响应、痕迹 | 动画落点与完整占地一致；无碰撞的连续推进不机械逐格停顿 |
| 失能/死亡 | 承重丧失、倾倒、涉水沉降、碎裂、残骸 | 机体失能可救与彻底击毁可分；规则残骸有清理行为 |
| 镜头 | 定向推回、短推近、跨区因果衔接 | 不遮目标、不抢用户拖拽；强度为零真不动 |
| UI | 血槽受损段闪动、护盾量减少、被取消威胁划除 | 数字与模型在同一接触事件更新，无提前扣血 |
| 声音 | 瞬态、材质、低频、尾音；单位机关音与环境音分层 | 闭眼能区别击中/格挡/落地/碰撞/失能；重复采样不机械 |
| 节奏 | 世界、特效、UI、音频有明确时钟类别与倍率 | 快进/暂停/跳过不漏事件；慢放不拖累鼠标和 UI |

G1–G12 全部进入施工表。G12 先建立可控时钟，G1 产物与 G2/G3/G4 同时形成样板；声音、碰撞、击破、回放跟随同一事件，不在最后补一条通用音效。

## 7. 制作与观感验收

每套动作录正常速度、快进、连锁三种完整片段，目标 60fps；若采集未达到就报告实际帧率，不拿 15fps 判断 0.08 秒顿帧。要包含输入光标和系统音频，不只提交挑出来的冲击帧。

本关接触与恢复时长逐招按08表执行，连锁共用短停顿而非每个目标都完整播放一遍。试玩若需改值，升版本后同步图、音画cue和验收基线。镜头震动、推近、闪烁可分别降低，减少动态模式保留结果箭头和血条，不牺牲规则信息。

最终核验同时包括：关 HUD 的场景图、正常 HUD 的盘面、悬停目标、实际攻击全程、场景受损后、回合末。逐个检查细节遮挡、颜色混淆、透明残影、脚底漂移、拳掌手刀、膝髋、炮管与钻头连接。

盲辨不是让测试者记住名字。先问“这一招造成了什么”，再问“这两台的打法有什么区别”；最后才用 18 招识别率作为辅助指标。六机遮名辨识固定10人60题，身份≥48/60、每机≥7/10，因果≥54/60；18招逐招还须说明效果。人数、误认项与录像必须公开，不拿一个熟悉代码的人辨出来当成功。
