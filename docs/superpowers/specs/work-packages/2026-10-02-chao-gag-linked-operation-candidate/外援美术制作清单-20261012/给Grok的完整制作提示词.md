## 4. 每个对象先理解身份和IP，再画

每台机体先回答：它来自哪个作品或机甲谱系，在本作是谁，有什么性格和职业，为什么这样战斗，哪些原IP特征构成辨识，哪些部分已经被本作重新设计。

有明确IP来源时，实际查看对应原机的图像资料。生图或绘制要求至少同时包含：

- 原作品/家族名，以及实际使用的参考图。
- 至少三项应保留的识别特征，例如轮廓、头胸重心、翼/载具关系、装备与动作气质。
- 本作身份、职业、性格和当前形态。
- 本作结构改造与用户明确不能画错的部位。
- 固定美术参考所规定的画法、材质与色彩组织。

**原IP参考决定“它是哪一类机体”，美术参考决定“用什么方式画出来”。两者都要用。**不能把所有机体洗成同一种泛用科幻机器人，也不能把原作整机直接搬过来后改名。作品家族参考不等于已经锁定唯一原型；项目原创人物和敌体没有固定外部映射时，不硬编一个。

特别注意这些已经明确的要求，其他条目仍须逐项阅读：

- 旧拳王有Real Steel式机器人拳击和师徒气质，站姿、护拳、肩胯与重心必须像拳手。
- 馆守Z保留旧超级系、魔神系的份量，原右前臂已毁，不能为对称重新长回。M15轮式旧守护者是它的导览终端，与M03同一主体，不是另一台机魂。

## 5. 需要建模的资产，必须按这条链制作

**设定图 → 结构母版 → 同源正交三视图 → 分件/关节/形态与状态 → 建模 → UV与真实贴图 → 必要绑定和动作。**

二维外援也必须完成前四步，交到模型制作方能据图工作。具体文件名按逐文件清单；以下是制作要求，不是另加一套重复文件。

1. **设定图**：先把角色身份、轮廓、主色、装备与气质画清楚，交`concept.png`。不靠极端透视、烟尘和强光掩盖设计。
2. **结构母版**：整理选定方案为完整、中性姿态的`design_master.png`；明确四肢、关节、武器、背包、接口与材质分区。建立稳定的`design_id`和`revision`，在`design_record.json`记录。
3. **同源三视图**：基于这一个母版画正面、自身右侧、背面及对齐总板。地面、头顶、肩胯膝等关键高度对齐，所有视图同一尺度、同一装备、同一颜色分区。不是三次独立生图拼在一起；如果头型、炮数、膝盖、翼根或身体厚度不一致，先修到一致。
4. **分件与状态**：画清必要挂点、活动轴、收纳、展开和被遮挡的结构。非对称对象补左侧，飞机/宽翼/大型背包按清单补顶视。变形、合体要有同一套零件的迁移表和中间态；子件从母体派生并注明复用来源，不重新发明另一套。

全部环境建筑，以及楼房、电力设施、工程设施和列车，也按先设计图、再低模的方式制作。需要前/侧/背/顶、层高、底座、屋顶、必要活动件；损毁态说明哪些体积消失、哪些楼板和断面露出。**半毁坏楼房不能仍盖完整楼顶贴面。**低模保留可见轮廓、凹凸、破口与遮挡，小尺度窗框、接缝和磨损主要进入贴图。不要凭文字堆盒子当最终建筑。

三视图是可制作的设计交接，不是工业制造图纸：不追求每一颗螺丝、柜内线路或毫厘接触。图像生成可以辅助，但同一设计的前后左右必须经过实际编辑与检查。原尺寸与战棋显示档分开，不因为设定米数而把单位画得看不见。

若承担三维：先对照母版与三视完成低模和正常镜头体量检查，再做UV、真实贴图、材质和必要骨架。交`technical/source_design.json`记录所依据设计版本、视图文件及摘要，并交旋转预览。单张设定图不是UV贴图；不要将假光照烘死在底色。可编辑模型源、GLB、纹理、挂点和骨架等按技术附包交付。

纯人物头像、表情、二维立绘、UI、图标和纯效果不强套三视建模。真正要建模的地图人物或机器犬再补它的简化三视。

## 6. 画面、动作与效果的质量要求

- 配色遵循固定视觉参考：明快、有主次、有科幻机甲游戏气质。不要统一刷成灰青，也不要靠大面积高亮纯白和霓虹把画面撑亮。每台机体保留自己的英雄涂装；环境、单位、战术标记有清楚分工。
- 现代机甲城市要有可信楼层、门窗、屋顶、工业结构和设施用途。地面有材质与空间层次，不能只有平板纹理；建筑不是一排小屋或方盒。
- 敌我共用微型、小型单格、标准单格、2×2、3×3及巨构局部的显示档。普通敌人不能像巨大机器人脚边的小狗；人、机器犬等微型对象才用约四分之一格面积表达。不要让真实米数妨碍棋盘可读性。
- 人物与机体都统一制作精度、材质表达和图像清晰度，各自外形仍应不同。头像专门做头肩构图，不能把整张全身图缩进去。多表情和立绘保持脸型、眼线、下颌、头部显示尺度与脚点一致。
- 常规待机、走跑、操作、举持、射击、受击优先按动作家族复用，按体型和装备调整。无牌天冲拳、旧拳王等体术机和招牌动作值得定制。不要逐机重造全部标准动画，也不要为每对敌我对象维护精确接触参数。
- 单位各自响应动作事件：出手方、受击方、环境和特效各处理自己的状态。普通维修有手部动作，柜体有灯光/能量/状态变化就可以；不做无人关心的打开柜门逐根接线。
- 拳击、刀斩、贯穿射线、爆破导弹、持续燃烧、护盾、牵引和碰撞有不同形状、节奏和作用范围。效果在正常战棋镜头下看得见，又不遮住目标和落位；不是每招同一团小火花。
- 战术图形要表达目标、轨迹、范围、位移、碰撞、预计耐久和取消的威胁。地面标记遵守3D空间；敌方目标光墙可用标准高度透明红墙，不需要与每栋楼通高。数值、文字、曲线长度和规则方向由游戏生成，不烘焙进图。
- HUD组件按默认、探索、选中、瞄准、执行等状态设计，中文和快捷键独立排版；使用一致的图标、边距与视觉层级，不做一堆彼此无关的装饰框。

## 7. 制作顺序与内部检查

先做一组能检验方向的素材：**M05完全版王者、E01啮线体、H01纪存、B01有人避难楼、X06右臂巨钻效果、G16敌方目标光墙**。用固定参考、现有正常战棋机位资料做同场构图对照，检查比例、色块、材质和信息层级，然后修正并扩展到全部清单。

这组是你自己的执行校准，不是要求用户逐批替你查漏，也不是最终只交六项。未通过的做法不能批量复制；同一主要缺陷连续两次没有改善，改参考使用、视图统一或制作方法，不继续堆相同细节。

每项检查身份、原IP识别、结构、左右、视图一致性、用途裁切、状态差异和透明边缘。动作或效果检查连续过程，不能以一帧漂亮截图代替。至少在1440×900和1920×1080的正常战棋构图中检查可读性；未接入游戏的合成对照明确标为“构图试排”，不能冒充实机证明。

源文件必须真实：PSD/KRA确实可编辑分层，SVG确实是可编辑图形；不要改后缀、伪造模型或将一张压平图片包装成完整制作源。工具确有限制就记录缺件和恢复方法，继续不受影响的项目，不用占位品宣布完成。
