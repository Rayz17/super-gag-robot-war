## 机体差异怎样体现在选择中

下表包含本轮新增/重接的部分与继续沿用的既有能力。它们不是本轮全部重新发明的机制。

| 机体 | 作战区别 | 代价与限制 |
| --- | --- | --- |
| 无牌一号 | 截击、正蹬向前推位；把目标推离攻击位置或推入缺口 | 近身，需要选择接敌位置；推力不足推不动重物 |
| 旧拳王 | 勾拳侧推，撞击额外 +1；与直线正蹬形成不同落点 | 重拳跨回合蓄力；侧推方向与出手方向有关 |
| 完全版王者 | 2×2 占地、基础飞行移动 5；钻进强推、双线肩炮 | 飞越低障和机体不等于能停在上面；落点必须容下完整四格。高墙、限高和实体建筑仍限制路线，肩炮需要蓄力 |
| 白色样机 | 贯通光束穿过两体 | 单体伤害较低；实体阻挡会截断射线 |
| 雷翎 | 飞行狙击留下标定，给后续队友制造破甲机会；爆破导弹覆盖十字范围 | 射线有方向限制；导弹消耗弹药，爆心附近的友方与设施也会受影响 |
| 歌翼可变机 | 震荡空爆：爆心受伤，四邻主要被吹离；可变形飞行 | 震荡与普通伤害导弹的取舍不同，不能把四邻推移误读成等量杀伤 |
| 预算二号 | 液压顶推零直接伤害、推力 3；维修与焊筑隔墙 | 不凭关卡临时得到战斗技能；维修受备件、距离等限制，顶推仍可能造成碰撞或坠落 |
| 市政吊装机 | 吊运指定落点、牵引、承重 | 受吊重和有效落点限制；需要为落点留出空间 |
| 消防架桥机 | 涉水、耐火、泡沫灭火及保护，可铺桥 | 保护效果也能施加给敌方；铺桥与维修占用资源/行动 |
| 灰崎警备机 | 拘束限制步进、隔墙改变射线 | 锁住脚步不自动取消对方攻击；要核对它的枪口和攻击落点 |
| 镜星 | 标定破甲、干扰承诺 | 协同价值依赖下一台机体的出手次序 |
| 货柜领袖 | 相邻群盾、重物搬移、变形 | 群盾依赖站位；大件搬移仍需要有效落点 |
| 馆守 Z | 牵引、持续承重 | 托桥占住本机，需有人保护或接替；移动/受扰会改变承重条件 |
| 社勇王 | 近战冲拳自护、扇面终式 | 强攻会改变站位和周边受击关系；终式需要准备 |

实际效果统一由 `round_rules.spec()` 输出。`round_armaments.gd` 保存机体作战定位、机动类别和装备特性；`round_data.gd` 保留机体资源、工具能力、占地及关卡部署数据。后续扩展可以继续增加装备特性，不需要把“维修这座桥”写成所有人的临时招式。

## 盘面上读得到的因果

**悬停正蹬目标：**目标血格闪烁 → 粗箭头指向将到达的格子 → 原来的攻击若落空，受保护对象旁显示“少受 1”。移动和攻击分别消耗自己的预算。

**勾拳让两敌相撞：**箭头转向侧面碰撞格 → 撞击符号显示两者分别损失多少 → 两台血槽各自闪烁。护盾抵挡和剩余血量会参与实际数值，不能把名义伤害重复写到两个目标上。

**先推、再由队友打：**位移制造本回合失衡 → 换另一台攻击时显示接力加伤；标定则显示接力破甲。这些效果来自实际模拟事件，预览与结算共用规则。

**爆破与贯穿：**导弹先给出十字覆盖与燃料着火区域，发射时沿弧线飞行，爆炸伴随火团、烟尘、冲击环和碎片；贯穿光束沿实际射线连续通过受击目标。近战用短促接触冲击、勾拳弧迹与身体前压，工程动作用工具杆/焊接效果。

**跨区炮：**A 的炮架上出现指向 B 的预告，B 的桥路落点出现来自 A 的靶标。蓄力“下轮”不会被混算成本轮已经扣掉的耐久。

## 目标与失败条件

本关要让载着 24 人的列车沿 **C 车站 → B 桥路 → 安全出口** 前进。A 负责为行车与桥区抢修供电，C 的馈电柜还可以解除 A 的跨区炮威胁。

- 列车被毁会使救援失败；全队失能且没有待返回的调度机体，也会失败。
- 母线被毁会断电、停车并暂停需要供电的抢修；它可以被维修，不等于立刻判负。
- 桥路受损可以抢修，也可由承重机持续托举。托举机撤开后的影响必须一起预览。
- 轨道上的单位、货物与缺口都是实际阻塞；任务图显示当前最先阻塞的位置，点击可定位。
- 本轮额外修正：旧实现只记住“复位过母线”，设备被毁后仍持续供电。现在供电同时检查开关状态与设备耐久，预览、环境危险、维修作业和列车结算保持一致。

## 鼠标与镜头

| 操作 | 效果 |
| --- | --- |
| 左键机体 → 移动光标 → 左键终点 | 范围、绿线路线和虚影预览；点击直接移动 |
| 底部选招 → 悬停目标 → 左键 | 范围示意、血量/位移/环境后果；点击执行 |
| 右键 | 退出瞄准，再次右键取消选中 |
| Ctrl + 左拖 | 旋转镜头，不移动机体 |
| Ctrl + Shift + 拖动，或 Ctrl + 中拖 | 平移镜头 |
| Ctrl + 滚轮 | 缩放镜头 |
| 按住 I | 展开光标对象的详细规则 |

macOS 中 Godot 会先把 Ctrl 左键转译为右键事件，因而不能同时用相同事件区分“物理 Ctrl 左拖”和“物理 Ctrl 右拖”。本版以 Ctrl 左拖旋转为准，平移使用上表两个明确的组合；松开 Ctrl 早于鼠标也不会意外下达移动命令。可核对 [Godot 的 macOS 鼠标处理源码](https://github.com/godotengine/godot/blob/4.5/platform/macos/godot_content_view.mm#L422)。
