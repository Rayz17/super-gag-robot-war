让同一套规则，成为玩家能读懂的动作

这轮同时修规则结构和操作语言。工务城是验收场景；机体、装备、意图、作用对象与事件才是可复用的底层。

保留什么，重新建立什么

保留三战场、逐机行动、公开敌方承诺、跨区任务、3D 机体和既有动作资源。重新建立一个明确的连接：装备如何影响任意对象，规则如何生成后果，玩家又如何用同一组符号预览和确认后果。

单位属性 / 能力＋装备：轨迹 × 效果 × 代价＋地形 / 设施 / 其他单位→纯结算 → 事件与状态→悬停 / 执行 / 回看
单位契约

占地、移动方式、质量、移动预算、主行动、工具与状态相互独立。2×2 的通行和落点检查完整占地；飞行跨越低障但不能重叠落地。

装备契约

接触、直线、贯穿、十字、扇面等几何，组合伤害、定向推移、护盾、标定与自护。力量决定能否推动，推距单独声明，不靠暗含加伤制造组合。

任务契约

任务给出目标、控制器、供能依赖、持续工作、运输路径；机体由自身工具决定能否执行。这一轮已将供电、运输阻塞和工作条件从设施名称判断中抽出；工务城的剧情教学与结算叙事仍属于关卡层。

一回合的规则与玩家承诺

  • 每台机体拥有独立移动额度与一次主行动；移动成本不与“拍数”混加。玩家逐手操作，世界只在结束回合推进。
  • 蓄力使用原装备数据：开始时消耗本轮行动及弹药/能量，之后按配置轮数准备；释放再消耗主行动，不重复支付弹药。持续作业会占住工位，可被位移/失能中断。
  • 敌方承诺区分：方向随位移平移、固定落格、必须接触、必须架设。效果产生什么变化由绑定规则决定，不能一概把“推走”画成“攻击取消”。
  • 机体、敌人、可作用设施共享伤害/护盾/推移判定。敌我护盾、友军误伤、碰撞、坠落、连爆都是同一组规则的结果。
  • 组合首先改变位置、射线、可达空间、保护范围和任务条件；本轮去除了无条件的“推后换人打就 +1”。显式标定与拳击机的碰撞能力保留并写进说明。

机体装备收束

不机械地把所有角色裁成同样两招。保留有明确不同决策用途的招牌、功能动作和少量蓄力终式；移除没有角色依据的重复护盾和重拳。工程工具按能力提供，不是走到剧情点就凭空学会。

明确取舍

  • Ctrl 保留镜头控制，详情用 I；没有照搬参考作的 Ctrl 绑定。
  • 敌方阶段自动逐条播放，允许停、快进、回看；没有要求玩家为每个敌人多点一次“下一条”。
  • 地图编号不是物理地理顺序：运输确为 C→B→出口，A 是上游供电。路线实线和依赖虚线不能混成 A→B→C。
  • 本轮保留完整撤回以便打磨战局。是否改为有限回滚，属于玩法风险/承诺设计，不能拿减少点击作理由暗改。
  • 力量与推距分开配置。没有采用“力量减重量”把所有武器自动变成三格推；重型阻力必须在光标预览里清楚表达。
  • 没有强行铺满每个空格。大体积机体的通行、调位、爆破安全区同样需要空间。

验证与边界

规则、输入、画面与直接操作记录见 本轮检查结果。独立测试场 X 使用新机体 ID、新装备 ID，没有工务城运输也能完成规则、蓄力与预告；输入回归使用真实 Godot 窗口，覆盖 Ctrl、连续移动、悬停、I、Space、回执和回放。

这些检查证明的是当前实现与规则一致，不证明已经达到《陷阵之志》的手感、全 roster 长期平衡或全部美术完成度。武器说明目前是统一机制动画；不等同于每台完整招式影片。场景与14台机体的美术资源仍沿用既有3D资产，未在本轮宣称全部重制。事件回看目前覆盖本次运行，未加入跨会话的事件存档。选择与悬停响应已记录，但复杂刷新仍有约130毫秒的尖峰，不能称为完全无卡顿。
