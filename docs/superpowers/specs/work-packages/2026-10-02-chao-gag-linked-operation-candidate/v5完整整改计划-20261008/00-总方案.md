**这次整改要交付的体验是：玩家看一眼盘面就知道危险在哪里，动一台机体就能改变局面，动作结束后能看懂自己解决了什么；换一台机体、换一个战场，解法也随之改变。**

报告的核心判断成立：我们已有可运行的三战场规则，却没有把规则组织成好读、好操作、有区别、有回报的战术选择。补几处提示、换一种配色、再添几个技能，都不足以解决这个问题。

本计划覆盖完整报告，包括美术、关卡、立体结构、手感、全部招式、敌人、人物与机魂、空地体系、原有系统的恢复，以及具体 bug。上一版方案保留为历史阅读稿；**本目录成为 v5 整改的主计划**。初稿交付分析和施工设计；现在已按首关范围接入第一版代码。具体实现、原生操作记录和未关闭项见第12册，原计划的完整验收门槛仍保留。

## 1. 为什么现在的 demo 不好玩

### 不是所有失败都发生在同一层

| 玩家实际遇到的事 | 根本原因 | 必须同时改的部分 |
|---|---|---|
| 点拘束索，图示说把敌人推走，实际只是锁步 | 说明在根据“力量”猜效果；图示模板没有真实空间关系 | 动作效果定义、目标预览、招式卡和实际演出一起改 |
| 选择墙、维修、吊运，像是在用同一招 | 共用工程线条，没有工具、产物来路、受力或持续状态 | 规则可以复用，动作脚本、模型机关和声音要区分 |
| 到了目标附近仍不能操作，还提示“先移动” | 可走近、能操作、占地、净空和工具资格没有形成同一个检查结果 | 通用目标求解与失败原因；不能只补一句提示 |
| 有很大棋盘，大部分时间却只是在赶路 | 敌人、危险、可利用地形和任务节点彼此太远 | 重新设计有效交战区与第一回合选项，而非单纯加敌人 |
| 看见下一步会扣血，却不知道哪一手能取消它 | 只呈现一个最终总数，没有比较操作前后的因果变化 | 本招后果、被取消的威胁、剩余威胁分开显示 |
| 三个区都在结算，人却只看见一处，随后失败 | 播放和镜头没有围绕因果事件组织；失败切走太早 | 事件回放、跨区定位、致败预告和回合小结 |
| 机体很多，但换谁都差不多 | 有技能目录，缺少装备、身体、代价、形状、人物选择之间的稳定关系 | 谱系和能力组合；用同一组局面比较不同小队 |
| 模型、地面、头像、界面像拼起来的 | 精度、形状层次和绘制方式不一致；颜色只在逐处调亮调暗 | 一套制作标准、三种场景气质、逐资产重做与正常镜头检查 |

**因此整改的单位不是“一个按钮”或“一个招式特效”，而是一个完整的玩家选择。** 例如“把工机从桥边拉开”必须同时说明：它为什么能被拉、拉到哪里、是否碰撞、是否仍然攻击、桥因此少受多少伤、市政保全是否受损，然后把这件事演出来。

### 报告与当前工程要分开看

报告主要记录 10 月 7 日的一组编队、前三回合及补充测试。它给出了很好的问题证据，但不是所有编队、所有武器和当前工作树的完整验收。

- 已有基础：逐机即时行动、三战场、2×2 王者、增援、地形、护盾、推撞、跨区调度、预演和事件帧。保留并整合。
- 已有但不能据此说好用：通用走近函数、日志回看、可选歌翼、状态词汇、技能合同。重点检查入口是否一致、说明是否正确、效果是否足够清楚。
- 确认的设计断点：拘束和吊运被力量字段误归为位移；招式格子图固定形状；小舞台不演真实目标关系。统一读取一个数据源仍不够，那个数据源必须表达正确的动作。
- 尚待复现：进程退出原因、个别第一次点击无效、音效真实听感和部分未打出的碰撞。报告没录到系统音频，不能把“没听见”写成“没有音效”。

本轮对照了当前 `round_rules.gd`、`tactical_contract.gd`、`round_armaments.gd`、`round_operation.gd` 等文件，并核对了人物权限与身份。后续施工先留存版本和复现状态，再决定改动量，不能把报告的旧状态直接标成当前 bug。

## 2. 保留什么，真正重建什么

保留现在的三战场工程、3D 资产、骨骼动作、任务信号、存档与规则模拟。以现有逐机回合作为本次整改的运行基线；不会在修 UI 的途中又暗中换回全队时间轴。动作定义与结算阶段解耦，未来若比较固定时间窗玩法，另用相同局面验证，不把两种行动预算混写在同一个界面里。

需要重建的是四个共同基础：

1. **规则能表达动作本身。** 伤害、推移、拘束、吊运、造物、修复、护盾、形态、支撑各有明确效果，敌我、设施和地形使用相同的作用规则。
2. **每个后果有来源。** 一次操作生成可追溯的结果：谁打了谁、在哪里碰撞、什么供电断了、哪条攻击失效。预演、执行、回看都消费这份结果。
3. **机体由能力构成。** 身体规格、移动方式、装备接口、人物搭档、机魂意愿共同决定能做什么。任务只能提供可操作的对象与目标，不能凭机体名字临时赠送万能工程按钮。
4. **关卡组合通用规则。** 电网、桥、列车、吊机、掩体、危险区和刷怪口组成局面；至少有战斗、保全、调度等不同处理方式，而非按顺序点三个指定设施。

## 3. 改完后，一回合应该是什么样

本关的可复算路线见[07§5](07-首关施工规格.html#section-5)，相应题面见下图。图是施工平面，不是实机完成证明。

![首关三张题面：坐标、占地、障碍与联动](图解/G16-首关三张题面.png)

玩家先在A接电，在C关闭敌炮专线，王者因此可以去保护A的避难所；B预算把工机安全推开，再让货柜撑桥；C雷翎炸开箱和敌人，同时明确承受列车2点友伤。结果是城防7、桥4、车4，列车向东走4格。

另一种部署能把列车保到6，但要承受城防降到6、桥降到1，留下更多敌人。两案的路线和费用都列在07中；用这种可比较的代价检验玩法，不能只写“玩家可以有多种选择”。

## 4. 对报告建议的具体判断

完整覆盖意味着每项有明确处理，不意味着把所有建议原样塞进同一局。

| 报告建议 | 本次处理与理由 | 对应工作 |
|---|---|---|
| 三图统一缩到 8×8 | **调整。** 缩短无效距离，保留不同地图尺寸；2×2 单位要有回转和绕路空间。用首回合有效行动数与威胁密度检验，8×8 是比较样本 | L01、E03 |
| 每回合城防最多损失 2、初始改为 7 | **不采用隐藏伤害上限。** 用敌人配置、保护路径和公开难度参数调压力；本关固定7，扣点映射见07；后续关另配，不能在UI端截断损失 | E03 |
| 三个区按回合强制解锁 | **调整为教学聚焦。** 开局推荐当前最重要的一手，允许自由切区；关卡中的实际封锁另有实体原因 | U07、L02 |
| 全场改纯色、去掉贴图，立绘统一降饱和 | **调整。** 保留用户要求的材质可信度和角色原有涂装；去掉照片噪声与混乱高光，制作风格化纹理、几何厚度和结构阴影 | A01–A04 |

## 5. 完整施工路线

美术与手感从第一阶段开工，不等所有系统完成后再“补皮”。下列阶段是内部交付顺序，**不是每完成一小段就让用户接手找问题**。

| 阶段 | 要得到的完整结果 | 进入下一阶段的条件 |
|---|---|---|
| 0 复现与统一规格 | 固定报告对应 build；13 个 bug 分类；18 招规则快照；可重复的困难局面 | 现状、待复现、建议分开；每个问题能定位 |
| 1 可信的一手棋 | 通用效果、目标求解、鼠标操作、预演与结算一致；一块完成度足够的场景与动作样板同时制作 | 拘束、炮线、推撞、误伤、调度等核心选择不说错话；Ctrl 不误下令 |
| 2 整场可读可操作 | 精简 HUD、敌方分段回放、全部 18 招演出、三个场景基础资产、本关6台机体质量统一 | 正常镜头可识别；无卡顿和残影；每招所做之事可复述 |
| 3 三战场值得调度 | 新布局、敌种与增援组合、多解目标链、保全与强攻差别、完整结算 | 至少三种编队/路线完成；有跨区选择而非固定流程；失败原因可追溯 |
| 4 立体与空地组合 | 9 条空间基础规则、12 种结构机制、空地能力与反制，先独立试验再加入合适任务 | 2×2 占地、遮挡、坠落、结构连锁均可预测；不靠转镜头才发现致命信息 |
| 5 人物与机体的身份 | 精神、搭档、机魂反提案、招牌装备、名场面、关系与成长；随机卡组完成对照验证 | 换人物或装备确实改变打法，新增操作负担可控；不让人物性格成为隐藏惩罚 |
| 6 全量集成与体验验收 | 主救援任务、立体变体、战斗压力变体；图文/视频证据及完整缺陷清单 | 通用规则、手感、美术、声音、首玩理解分别达标；未完成项不隐藏 |

上述是全量路线，第一批范围只到07定义的六机救援；阶段4、5不是首关上线的前置条件。其设计与素材准备可提前进行；涉及相同文件的代码变更按依赖整合。报告中的人日/周数没有当作承诺：先用阶段 1 样板测出资产与开发实际产能，再给排期范围和依赖，不用猜测日期掩盖工作量。

## 6. 这轮计划如何避免再次“写得很好，做得很粗”

- 每个工作包都要交付规则、玩家界面和运行证据，不能只交代码接口。
- 全部报告条目保留编号或章节位置。S/M/L 与 O/H 是重叠规格，关联同一工作，不重复虚增完成量。
- 主循环、画面和音效各自有硬检查。自动测试通过不代表手感、美术或玩家理解通过。
- 复用的旧功能必须重新接入当前状态、费用与事件系统。搬一个旧通讯面板过来，不等于人物机制恢复。
- 扩展性用第二种任务验证：换设施、机体名字和区域编号，规则仍能工作。只在工务城脚本里增加特殊判断，不算完成。
- “新手能否说明这一手改变了什么”要实际观察。第一次测试先不给提示；失败时记录他看哪里、误点哪里、误解什么，不用讲解把测试带过关。
- 原报告中未证实的声音、退出原因、动作帧数继续标明边界。人设、玩法候选和已接受剧情分别管理，不把新技能写成既有剧情事实。

正文中“报告观察”来自该次试玩；“当前代码”来自本轮只读检查；“整改设计”是这里作出的方案判断。报告引用的外部访谈和其他游戏具体数值没有在本轮全部重新独立核验，因此不将它们包装成新的实测事实。
