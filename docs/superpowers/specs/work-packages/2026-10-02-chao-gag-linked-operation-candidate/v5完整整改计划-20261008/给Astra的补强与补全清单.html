给 Astra 的补强与补全清单
（对 v5 整改计划第二轮）

读者：Astra。对照物：Game仔批评稿《对 Astra-v5 整改计划的批评与建议》、Astra 已出的 07-首关施工规格／08-图形与手感施工表、条目 01–09 与计划数据，以及 box 内实机对标／design_gap 关于人·卡·魂·梗的原判。本页只写「第二轮已接住什么、还缺什么规格」，不要求立刻改代码。

1. 开篇：这一轮已接住什么 · 还缺什么

已接住（三句）。 批评稿「下一稿必须补的三样」里，定稿数字、同时冲突、三区成题，已分别钉进 07§2、07§7、07§4；城防 7／7、桥座 4、拆解工机 5、顶推力量 3 推 1、架设炮对桥 2 伤、地面调度「一个阶段间隔」等都写成施工值，不再标「先试／待选并列值」。

打击感与示意误导：08§1 给出选中／非法点击／移动等可测时点，§2 给出 18 招「首接触帧／结果完成帧／可接下个命令帧」，§3 把 FX01–FX15 逐张换成新例局与精确结果——正好回应批评「没有逐帧验收稿」「没有逐招改图法」。

批评保留的六点底线（意图冻结、同一结果源、效果动词拆分、损失分账、先算调度、致败一击可回看）被 07§9 明确写进首关证明清单；§8 也撤回了把「再听一遍」改成接力加速的假恢复命名。

还缺（三句）。 批评「没接住」里的人这一层——精神指令整层、角色卡、机魂、各机体招牌梗——在 07§8 仍多半标「待后续／不列本关完成项／不以一句对话算已恢复」；条目 08 十条精神里，除纪存通讯与常驻预演外，多数仍是「候选」，未形成可在首关或下一专关验收的整层规格。

条目 09《卡组与成长对照》正文几乎仍是对照实验写法，且 07§1 写明「随机牌堆……全员成长不进入首关依赖」——覆盖表有 CARD-01–12，但不等于卡组层已可施工验收。

计划核对结果.json 记 specific_designs 331、unique_authored_designs 236；计划数据.json 里 coverage 499 条状态一律「待实施／验证；未改游戏代码」。多数分册条目统一加了「本关施工定值：见 07／08」页脚，清单体量很大，但首关可过项仍集中在 07／08 已钉死的那几块——不要用覆盖条数代替通过项。

核对锚点（本页判断均对过文件原话）：

  • 07 开篇：「数值注明为样本的」那一轮缺口成立；本册「把这三件事确定下来」。
  • 07§8：「完整范围没有删除，但首关可玩、系统已恢复、全量完成是三个不同结论。」
  • 07§1：「随机牌堆、十二种机构全集、3×3单位、燃料、拆装炮台和全员成长不进入首关依赖；它们在原清单中仍为后续待实施项。」
  • 计划数据.json detail_summary.status：「首关施工值已补定；游戏待实施；其余系统保留后续范围」；顶层 status：「计划已编制，游戏未实施」。
已够：07§2 定稿数字 已够：07§7 同时冲突 已够：07§4 三区成题 已够：08 帧表与 FX 已够：07§9 六条底线 不够：精神整层 不够：角色卡 不够：卡组／成长 不够：机魂 不够：招牌梗

2. 优先级 A · 必须补全（人·卡·魂·梗）

批评稿「精神、角色卡、机魂、机体梗没有恢复方案」原判仍然成立的部分：第二轮用 07§8 做了边界声明与假恢复撤回，但还没有把报告 §7 要的「已经丢的人和梗接回来」写成可过验收的合同。下面五条每条都按同一模板：缺口 → 现状原文 → 建议补成什么才算可验收 → 建议放在哪一册／哪关。

A1 · 精神指令整层

缺口是什么 报告要的是出席人物各带限次精神、可预演费用、战前可见；工务城丢失后人物对战斗几乎没有按钮。第二轮只把「再听一遍」撤回假恢复，并落到本关一次纪存通讯；其余 SPIRIT 多数仍是候选／后续，构不成「整层」。 现状原文 批评：「报告 §7.4(b) 把『再听一遍』的文档效果写成『本轮公开一台机的隐藏状态与真实意愿』。Astra 03 的候选把它改成『限次协调一次已有接口的当轮接力交接』。这是另一条规则，不是把旧指令接回来。」
07§8：「撤回该改名方案：接力加速移出本关，『再听一遍』恢复为听取机体状态与真实意愿。……这是保留人物动词的透明信息改编，不能称逐字恢复旧机制。」同表：「七海署名／记录｜……条件与身份待后续专关落实；不列本关完成项。」
条目 08 各条仍写「每场 1 次候选」；页脚统一「本关施工定值：见 07／08」。design_gap／报告 §7.4(b) 样本：纪存「再听一遍」、七海「以我的名字」「记录在案」、白鸢「预演」「补一页」、兜灯「硬停」、豪司×社勇王「先吵一句」等。 建议补成什么规格才算可验收 一页「精神层合同」即可，至少钉死：
  1. 在场表：本关／专关出席人物名单 → 每人 0–2 条精神 ID；不在场不能用其口吻与次数。
  2. 费用与限次：哪些信息类常驻免费（与 07§8「白鸢预演……常驻免费」一致），哪些每战限次；提交前取消不扣，成功提交才耗次（条目 07 DG-SYS01 已有方向句，需落成表）。
  3. 效果合同：每条写目标资格、作用 phase、对 SimulationResult 的改写字段、失败原因句；禁止用「燃魂」「硬停」四字代替参数。
  4. UI 入口：沿用旧「战场通讯」双页签方向（design_gap：指挥塔·人物能力／精神指令），但写清挂在人物头像下还是目标旁——与角色卡入口不打架。
  5. 首关子集：明确本关只验收哪几条（建议：SPIRIT-1 纪存通讯 + SPIRIT-4 常驻预演）；其余标「专关 P02」并给出专关 ID，避免十条并列却零条可过。
 建议放在哪 主规格写入扩写后的 07§8 或新册「09b-精神层施工表」；条目 08 十条改为该表的明细行。首关 GW-RESCUE-R1 只挂子集；七海署名／记录进后续「许可／证据」专关（与 07§8 表一致）。

A2 · 角色卡（确定指令入口）

缺口是什么 批评指出角色卡在 03 里分成配置 A「确定的调度令」与配置 B「随机牌堆」，结论留到以后比较——等于没有可点的人物动作合同。第二轮 07§8 只写了方向句，没有卡面字段与验收局。 现状原文 批评：「角色卡在 03『7. 卡牌层如何完整处理而不制造新负担』里分成配置 A……和配置 B……，结论留到以后比较。」
07§8 表：「角色卡｜先把确定指令作为人物头像下的动作入口；不引入抽牌、能量和弃牌｜确定指令先做；随机牌组属于报告建议的对照项。」 建议补成什么规格才算可验收
  1. 配置 A 的卡面字段表：id、人物、目标过滤器、费用（限次／通讯）、效果指针（可复用 SPIRIT／CommandModifier）、每战次数、灰态原因。
  2. 入口与互斥：头像下动作 vs 精神面板 vs 机体招式栏；同一效果不得三处各算一次恢复。
  3. 一局验收：指定出席 2–3 人，打开头像能看到确定指令；点一次改变预演结果；不引入能量条与弃牌区。
  4. 明确写：配置 B 随机牌堆不是角色卡恢复的验收条件（与批评「对照实验可以以后做，不能算恢复」对齐）。
 建议放在哪 扩写 07§8「角色卡」行成可配置表；或在条目 09 之前单列「确定指令（配置 A）施工页」，与 CARD-*-随机对照分开。首关可先挂纪存一条，证明入口存在。

A3 · 卡组／成长（条目 09）

缺口是什么 条目 09 十二项仍是对照规格；07 已将其剔出首关依赖。若下一稿仍只加「见 07／08」页脚，覆盖表会继续显示 CARD-01–12「有回应」，但无人能回答「对照实验何时开、通过标准是什么」。 现状原文 条目 09 开篇：「确定指令与随机牌组分开验证；不让抽牌成为基本动作的门槛。」补记：「未进六机救援的系统仍属后续，不能因条目存在就标成恢复或完成。」
07§1：「随机牌堆……全员成长不进入首关依赖。」§8：「不把随机卡组或新接力规则说成旧设计复原。」
design_gap／报告 §7.4(c)：文档没有「杀戮尖塔」机制全文，只有「卡牌／卡组构筑式惊喜」目标——整节本就是【建议】，更需要单独的对照实验规格，而不是混进「系统已恢复」。 建议补成什么规格才算可验收
  1. 单独一页「P04 对照实验计划」：局面种子、编队、测量表（选择多样性、无效牌率、每回合额外点击数），以及采用／不采用的裁决门槛。
  2. CARD-01–12 每条补「对照局步骤」与「失败样子」；现在多是设计句 + 代码入口，缺少可跑的一局脚本。
  3. 成长（CARD-11 等）与 credits／reputation 的挂钩表：奖救援／保全／任务，不只击杀（与 03§6、条目 07 PERSON-04 方向一致），并写清不进首关的版本号。
  4. 验收禁止用语：「卡组系统已恢复」。允许用语：「配置 B 对照局按种子 S 跑通，指标落在区间……，裁决为采用／搁置」。
 建议放在哪 保留条目 09 为对照分册，但增加卷首「实验计划」与「与首关依赖切割表」。工作包仍走 P03（确定指令）／P04（随机对照），不要并进 GW-RESCUE-R1 通过条件。

A4 · 机魂（含双主体协商）

缺口是什么 机魂是世界观支柱，战斗里仍看不到可预演的意志。第二轮只声明「提交前公开、不随机夺权」，没有拒绝条件表与反提案命令字段——不足以称系统可验收。 现状原文 批评：「机魂在系统表里写明是新机制，不是恢复。」
07§8：「机魂与双主体协商｜拒绝条件、反提案需在提交前公开；不随机抢走玩家控制权｜现阶段不以一句对话算系统已恢复。」
03§6：「机魂四态为接受、附条件接受、拒绝、反提案。……『王者满气势就强制乱放大招』不能作为默认人格。」
design_gap／报告 §7.4(d)、D9：四道门「信息／权限／物理／驾驶者与机魂接受」；机魂给意志不给数值；拒绝条件须公开写在机体卡上。 建议补成什么规格才算可验收
  1. 每台机魂机一张意愿卡：触发条件（公开）、四态返回值、反提案 Command 模板、可用哪条精神说服一次。
  2. 预演时机能：提交前算出 consent，并在预览条显示原因；同状态执行不得事后反悔（DG-SYS04 已有分析句，需落成字段）。
  3. 首关最小集：建议只做社勇王「危险扇面 → 双主体协商」一条可演示路径（与 SIG-1／SPIRIT-6 对齐），其余机魂标专关。
  4. 验收句示例：「预演可见拒绝原因与替代动作；接受反提案后费用不变；条件被新事件破坏时计划过期重验。」反例：「结算时才弹一句台词。」
 建议放在哪 条目 07 DG-SYS04／PERSON 相关条升格为「机魂施工表」；首关只引用社勇王一条。完整七机意愿放在 R03／P05 专关，并在总方案阶段表用「首关可玩／系统已恢复／全量完成」三分法记账。

A5 · 招牌梗（一台机一个可辨认规则）

缺口是什么 批评原判：SIG 条目停在「处理决定」，报告 §7.4(a)「审批章」等未收成定稿合同。第二轮 07§8 对社勇「审批章」、王者卸装、雷翎抢拍等仍写「梗规则仍未恢复／不算本批通过」。18 招合同 ≠ 招牌梗恢复。 现状原文 批评：「条目07『SIG-1 · 社勇王』的处理决定是『把救援承诺、双主体协商与爆发联系起来』，没有写成可实现的招牌规则（报告 §7.4(a) 的『审批章』那一格没有被收成定稿合同）。其余机体同样停留在处理决定。」
07§1 表：「机体梗、合体、卡组不能仅凭已有技能名字算恢复。」§8：「社勇王『审批章』……梗规则仍未恢复，不能用『救援承诺』四字掩盖。」「雷翎轮换节拍｜不采用奇数轮硬禁开火……抢拍名场面尚未恢复。」
design_gap 验收方向：「盲测：只看招式说出机体，正确率 ≥ 80%」；「一台机一个招牌规则」。 建议补成什么规格才算可验收 六机（本关编制）各一行定稿合同，列至少：
  1. 文档锚点（entities／fable5 原文短句，缺则写「文档未提及／原创」）。
  2. 招牌规则（改变射界／位置／保护／保全方式之一，不只伤害 +1）。
  3. 本关用哪一招／哪一接口体现；与 18 招帧表、FX 图的交叉引用。
  4. 一局盲测题：遮蔽机体名，只给招式预览，受试者能否指认。
明确不采用项也要保留（如雷翎奇数轮禁开火——00／07 已拒），并写替代的可辨认规则，避免「拒绝旧案」后空窗。 建议放在哪 在 07 增「§8b 六机招牌定稿表」，或扩写条目 07「七台招牌重建」让 SIG-1–6 从处理决定升到与 07§2 同级的施工值。合体／卸装全流程可标后续，但本关六机每台至少 1 条可辨认规则要进「首关可玩」或紧随的「系统已恢复」门槛，不能无限留在处理决定。

3. 优先级 B · 应补强

这些不是批评「下一稿必须补的三样」里的硬缺口（那三样第二轮已交），但会让计划读起来「页数很多、通过项很少」，或让施工参数再次漂回「先试／样本」。

B1 · 美术如何收成关卡规则（不只资产目录）

批评原文：「报告要的不是再列一批资产名。……到『这一关哪一格靠剪影破格才读得懂、哪一条高度差是必须用的解』：文件里没有。G10 的图注自己写了『这是战役空间关系草图，不是三个浮岛的美术』。」

第二轮 07 已给出 10×8 三区题面与设施坐标，但条目 02 的 ART／ASSET 仍偏风格、配色、资产层级。建议补一张关卡可读性施工表（可附在 07 或条目 02 卷首）：

  • 对本关每一道题，指出哪个造型／高度差／剪影在预演里让玩家读懂因果（例：B 桥未对齐时，桥面与水位的剪影差；C 专线柜到 A 炮的馈电线在 2D 叠加层上的画法）。
  • 语义色只服务当前操作提示（条目 ART02 已有分层句），再加「本关三题各用哪一条语义色／地标」。
  • 验收：无提前提示的首玩，能指认 A／B／C 各欠什么（07§9 ③）——美术项必须能指出「靠哪一块画面读出来」，不能只交资产清单。

B2 · 331 条与首关依赖怎么收口

批评早已写：「索引写『331 条具体回应』『52 个工作包』。……覆盖表不能代替这一关的题面。」第二轮用 07／08 收住了题面，但数据层仍是：

  • 计划核对结果.json：specific_designs 331，unique_authored_designs 236，work_packages 52；limitations 写明「This is a static plan check, not game implementation or player acceptance。」
  • 计划数据.json coverage 499 条（含 168 条「章节／来源」索引）状态一律「待实施／验证；未改游戏代码」；52 个工作包状态一律「待实施；本次交付为计划」。
  • 分册条目普遍挂同一句「本关施工定值：见 07／08……若上文保留旧的试调数字，以该施工规格为准」——有指向是好事，但若正文仍是目录级句子，覆盖勾选不会变成通过项。

建议收口方式（纸面即可）：

  1. 在 index／00 增加「首关依赖闭包」表：只列 GW-RESCUE-R1 通过所必需的条目 ID（数字、冲突、三题、18 招帧／FX、六条底线、精神子集、六机招牌最小集）。
