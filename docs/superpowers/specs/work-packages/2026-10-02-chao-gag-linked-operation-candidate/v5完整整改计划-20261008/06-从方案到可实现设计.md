不能继续在“这是供电柜”“这是王者”“这是工务城B区”的判断里加特例。需要分开五种职责，让另一个任务也能配置出来。

| 层 | 它决定什么 | 它不应该决定什么 | 本轮落点 |
|---|---|---|---|
| 对象与空间 | 谁在什么结构面，占几格，有多重，能否移动、导电、燃烧、承重 | 因为名叫某机就免疫一切地形 | 身体规格、设施属性、结构面与支撑图 |
| 装备与效果 | 射程、形状、命中、推距、工具资格、费用、持续时间 | 为当前剧情临时送给机体一个万能维修键 | 最终动作合同、显式效果序列 |
| 命令与阶段 | 路线是否可行、动作何时发生、当前还有多少预算 | 把动画几秒当成几拍行动消耗 | 统一接近求解、主行动、准备/持续/在途状态 |
| 任务与身份 | 保护谁、什么构成推进/失败、市政资产损失、权限条件 | 跳过物理规则直接让列车穿过货箱 | 条件图、事件订阅、身份与证据 |
| 呈现与输入 | 玩家如何发现、选择、预演、执行、回看 | 自己再算一份伤害、猜这招该画推箭头 | 鼠标四态、结果绘制器、事件演出与音频 |

这些层可以在一个工程内逐步重构，不要求拆成五套服务。先保留当前快照和规则入口，把一个完整样板贯通，之后迁移其余动作。旧版四拍模式与逐机模式用明确入口区分，旧存档加规则版本，不能让同一存档半数动作按拍、半数按回合运行。

拟定的数据接口如下。玩家不用看这些字段；它们的作用是防止说明、图形、效果各说各话。

| 记录 | 必须包含的字段 | 为什么需要 |
|---|---|---|
| `ObjectState` | 唯一身份、阵营、保全身份、脚印、质量、结构面、生命/盾/装甲、能力标签 | 同一工机可以敌对却需要保全；四格机是一个对象而不是四个受伤对象 |
| `ResolvedActionSpec` | 形态/装备/模块来源、目标资格、射程、作用形状、有序效果、费用、时间状态、挂点和演出类型 | `force=3`只能表示力，不能被示意图偷换成推3格或推1格 |
| `Command` | 发起者、动作、目标、方向、载荷/落点等参数、自动接近路线、状态版本 | 一次输入能够完整复现；不依赖鼠标最后停在哪或当前哪个UI面板还开着 |
| `SimulationResult` | 合法性与原因、接近计划、事件序列、终态、即时差值、下一敌阶段差值、风险、未知部分 | 预演、提交、图示与回看读取同一份结果；不同时间的伤害不混算 |
| `Event` | 顺位、来源、目标、前后值、阶段、地区/结构面、父事件、规则版本 | 能说清第二次爆炸从哪里来、哪一手救了桥、哪台工机为什么损失 |
| `PresentationCue` | 对应事件、起手/接触/就绪时点、挂点、动作、特效、声音、镜头强度 | 伤害发生时血条、音效与受击同步；跳过只改变播放，不改变结果 |

## 2. 一手棋从输入到反馈，完整走一遍

本节保留为独立规则回归例局，坐标与终止条件不是07首关配置。首关桥座失效可修复、首次城防−2，不单因断桥立即宣告任务失败。

建立一个固定测试局，既用来开发，也用来录制用户能看懂的样片：

| 对象 | 初始状态 |
|---|---|
| 桥 | B区 `(4,2)`，耐久4、无盾；是任务通路的一部分 |
| 拆解工机 | B区 `(3,2)`，耐久5、质量3、市政保全对象；已经准备好，本敌阶段将接触拆桥3伤 |
| 架设炮 | A区，已承诺本敌阶段向同一桥打2伤；拆解后执行 |
| 预算二号 | B区 `(2,3)`，剩余移动3、主行动1；液压顶推力量3、推1、无直接伤害 |
| 空位 | `(3,3)`可站、`(3,1)`有稳定支撑；其余与这手无关的对象不参与 |

不作为：桥先受3再受2，耐久 `4→1→0`，超出耐久的伤害不额外计成“负一耐久”。预计伤害总额为5，实际掉耐久4；任务失败条件按桥毁后的路线可恢复性判定。本测试局约定桥毁即救援失败，正式任务不应把所有普通设施损坏都当失败。

玩家选择顶推时，光标停在工机上，求解器找到 `(2,3)→(3,3)` 的接近路线，从南向北推到 `(3,1)`。界面应同时给出：绿色走位线、目标向北大箭头、落点虚影、工机HP不变、拆解接触线划除，以及“桥来袭伤害5→2；市政损失0”。

| 顺序 | 规则发生什么 | 玩家看到什么 |
|---|---|---|
| 悬停 | 在克隆状态中求路线与效果，不改真实状态 | 路线、推向、取消的拆解、仍有效的A炮线；移动将余2 |
| 点击目标 | 重验状态版本；整体命令合法；扣移动1、主行动1 | 无风险则不再确认；预算二号连续跑向出手位 |
| 工具接触 | 工机受推，无直接扣血；终点有承重 | 支脚抵地、活塞推伸、工机连续滑到新格，不能播成拳爆 |
| 状态变化 | 接触依赖失效；拆解承诺保留记录但当前无效 | 旧拆解线划除，桥预扣由5改2；非致死保全标保持 |
| 玩家继续 | 预算二号余2移动、无主行动；其他机可选 | 选招收起，仍可移动；下一处急事是A炮或桥防护 |
| 敌方阶段 | 拆解因接触失效不伤桥；A炮仍打2，桥 `4→2` | 两个不同结果按顺位播放：一个失效原因，一个真实炮击 |
| 小结 | 消去一条3伤来袭；桥原会掉4归零，现在实际掉2；没有市政损失 | 实绩与下轮预告分栏，点桥损伤可回到A炮来源 |

这才是一手完整的“做了什么、为什么有效、还缺什么”，而不是“机体走到一个坐标”。其中自动接近、位移、接触中断、市政身份、跨区威胁，全部是通用规则。

同局还要测试两种替案：

- **只给桥中心盾2：** 拆解3先减到1点HP损失，之后炮2，桥最终 `4→1`。这是一种可行保桥方法，但工机仍在拆解位置，而且群盾可能顺便保护邻接工机。预演不能说所有攻击都取消。
- **只用伤2光束打工机：** 工机仍剩3HP，拆解照常，桥仍有致败风险。界面必须指出“打中了，但没有解除威胁”，不能用爆炸演出假装解题成功。

## 3. 规则顺序、异常和撤回要一次讲清

初始统一顺序是：命令资格→路径途中事件→动作效果序列→对象生命变化→支撑/地形重算→派生连锁→任务条件更新。某武器需要先推再伤时，在它的效果序列明确声明，不能在动画里临时倒过来。

首关统一采用“原始伤害→有效护甲/护群减免→盾值吸收→HP减少”。标定只绕过声明的护群，不绕自身装甲和盾。环境/坠落是否吃护甲在该效果上定义。盾为本案的数值池，不把“盾2”一会儿解释成挡两次攻击、一会儿解释成挡两点伤。临时支撑不叫盾，也不混入HP。

两条双炮线是两个伤害效果，可以各命中同一大机一次；单个十字爆心覆盖大机三格仍只算一次该爆心伤害。多枚独立导弹是否可叠中必须写进武器合同。这样规则来自效果次数，不来自循环遍历格子的次数。

| 情况 | 明确处理 |
|---|---|
| 鼠标预演后别人改变状态 | 提交时版本重验，重新展示变化；不执行过期命令 |
| 普通命令从一开始就不合法 | 不走、不扣费；指明障碍、距离、资格或资源原因 |
| 已公示防空反应使途中受伤 | 这是命令已含的风险，不是假失败；按事件顺序执行，若失能则停止后续动作 |
| 路径本身安全，但终点入敌炮区 | 允许安排，显示后续风险；不把“危险”当成“不可达” |
| 多机争同一格 | 逐机模式以当前状态计算；已占位后下一机重算路线。同批强推与运输预留/坍塌则按07§7，不能用后手重算代替 |
| 双目标操作选了一半 | 右键退一个参数；未提交不扣任何费 |
| 移动撤回 | 仅可撤无不可逆事件、无后续命令依赖的最近移动；否则给真实原因 |
| 整回合重置 | 恢复全部快照、随机种子、资源、牌堆、人物费用、链路和事件；禁止半回滚 |
| 快进或跳过 | 保持同一事件序列与终态；快进不能漏造物、漏音效清理或留下半透明身体 |

## 4. 鼠标与界面需要制作到什么程度

输入分发先检查模态风险窗和UI命中，再检查已捕获的相机手势，最后才派发棋盘命令。Ctrl按下开始的拖动直到鼠标释放都属于相机，即使先松Ctrl，也不能把抬鼠标解释成移动。

普通“选机→移光标→左键落点”只需要两次点击；“已选机→选技能→移光标→左键目标”也只增加选招与提交。不能把每条动作统一包装成先选单、再选择、再撤回/确认。风险确认和吊运第二目标是必要的额外步骤，必须在操作记录里单独统计。

| 图形组件 | 出现时机与位置 | 内容与退出 | 具体制作件 |
|---|---|---|---|
| 对象简卡 | 未点击即可随悬停；自动躲开对象和屏幕边 | 名称、关键特性、当前能做什么；移开即收 | 九宫格背板、指针锚点、3级字型、I详情提示 |
| 角色选择 | 点地图模型或脚底任一可识别区域 | 可达外缘、绿色路径、头像状态；右键退出 | 模型投影拾取、脚印边框、统一头像裁切 |
| 目标效果 | 技能瞄准当前对象附近 | 血槽闪段、盾损、推移虚影、碰撞/坠落、被取消威胁 | 每种效果的图标与生成器，来源连线 |
| 技能短卡 | 当前机体选择态 | 2–4主招，特殊接口贴目标；无展开的大百科 | 动作类图标、耗费标、准备/持续状态角标 |
| 危险确认 | 只有实质友伤、保全损失或已知致败等 | 冻住当前预览，列对象与代价；确认或退回瞄准 | 清楚危险背板、两个可焦点按钮、Enter映射 |
| 回合摘要 | 顶部短条/结束回合展开 | 当前保护值、预计变化、各区最急威胁 | 城防/桥/车不同单位图标，不混无名0/2 |
| 敌方回放 | 规则已提交后的播放态 | 暂停、速度、跳过、当前来源；详情可看但不发命令 | 同事件时间轴、源/目标镜头、可定位小结 |
| 三区联动 | 操作确实改到另一工作面时 | 源到目标短脉冲，目标缩略窗；玩家点击才切主镜头 | 区缩略画面、连接箭头、阻塞条件差值 |

默认字级和大小先按1080p制作样板，再到用户RMBP实际窗口与125%字号验证。预览线需有暗描边，文字背板要足够实，不能靠全局变暗提升可读性。常驻战术叠层只占需要的局部，机体与设施材质仍看得清。

性能验收同时记录：输入时间、状态变更时间、范围显示时间、第一次可见反馈帧。鼠标快划多个目标时，旧计算不能覆盖新目标；缓存按地图版本、单位预算、动作变体与目标失效。只修掉选择卡顿而每帧同步生成大3D小舞台，仍不算通过。

## 5. 一套资产怎样从“有图”走到可用

所有正式可选机体使用同一制作完成标准：来源图/设计稿→三维身体→贴图与材质→骨骼和挂点→待机/移动/受击/失能→各招动作→头像和UI状态→正常棋盘距离验证。不是要求长得相同，也不允许细致3D与简陋2D贴片混在一个阵容。

场景资产必须同时交付正常视距和近景效果。地板不仅有底色纹理，还要有边厚、伸缩缝、排水槽与断口；建筑按供电、承重、交通的功能构造。正常镜头的轮廓优先于盲目增加小螺丝。照片噪点需整理到风格化材质里，不能靠删掉所有贴图统一。

| 制作包 | 必交资产 | 与规则的连接 | 不接受的替代 |
|---|---|---|---|
| 12类场景物 | 模块网格、共享图集、材质参数、损毁态、碰撞/承重面 | 破损/失电/承重条件真实驱动外观 | 所有物体换色立方体、只有烟没损坏 |
| 14机共同动作 | 站立呼吸、连续跑/滑行、朝向转换、受击、失能、恢复 | 与脚印、移动路径、生命状态同步 | 程序摇头代替动作、脚底漂移、透明残影 |
| 18招报告样本 | 每招关键姿态、武器挂点、命中点、收势、效果、声音 | 对应其最终动作合同与事件时点 | 全部套挥拳，工程对象凭空出现 |
| 其余8机特色 | 每机至少一个有明确代价的招牌动作，以及配套基础动作 | 同样走规则、图卡、预演、回放 | 只在选人页列名，或只借另一机的整套动作 |
| 人物表达 | 一致头肩比例、在场头像、情境表情、短通讯与台词触发 | 驾驶员/机魂/现场/远程身份 | 缺席人物主持现场、每次点击强播对白 |

动作样板首先选择四种容易暴露系统问题的动词：预算墙、灰崎拘束、王者双炮、货柜护场。它们分别验证产物、持续控制、双射线/蓄力、大范围支援。四招都在常规镜头有效后，再扩到全部18招，不能拿一张必杀特写代替其他动作完成。

本关18招采用08的独立接触/恢复时钟；目标是能看见蓄、放、停、收又不等待空白。修复只有缺1HP就不播假三段加血，盾吸收不播装甲碎裂，推不动要有受阻反馈。声音至少拆启动、接触、材质、低频和尾音；录像必须录入音频才能评审声音。

## 6. 关卡把系统组织成什么局面

不把12种机关和20条空地规则一次塞进主救援关。每个工作面先挑两三种最能表达职责的材料，其他机制进入结构变体或独立测试场，然后组合验证。

| 区域 | 核心冲突 | 工程解法 | 战斗解法 | 混合解法与代价 |
|---|---|---|---|---|
| A供能前庭 | 供电抢修与架设炮形成时间压力 | 修母线、改供电路、操作馈电柜 | 清架设体/啮线体，获得安全施工时间 | 先顶敌脱架→工程机修；消耗两机行动但保设备 |
| B跨渠桥 | 桥受拆解与炮击，必须维持承载 | 临时撑、永久修、控制水位、替换支点 | 杀拆解者、用敌炮误伤、断敌脚下支撑 | 给市政工机盾后控位，保全但耗盾与时间 |
| C装卸站 | 车被牵引和货箱双重阻塞，增援逼近 | 解令/关停、吊箱、运输备件 | 摧毁阻碍，清空增援波 | 灰崎关停工机、货柜护车；省市政损失但需保护施工者 |

初期局面要求玩家第一回合至少能完成一次完整因果，而不是所有机先走两轮。敌人发布前会找合法命中、避低收益危险、评估同伴；发布后坚持承诺。玩家改变地形、方向和供能，才创造打空、误伤与连爆。不能让AI为了躲玩家每次新动作，实时把题目改掉。

增援按入口、批次、到达阶段公开。初始波只有一项陌生规则，下一波加入第二种角色形成搭配；困难不等于同屏塞满高血敌。歼灭后不无限生成敌人抹掉战斗路线的价值：波次数和撤退条件在任务配置中明示。清场后剩工程无压力时，允许玩家明确确认连续执行已合法的收尾步骤，不要求无意义逐轮点结束。

安全空格也有用：它们容纳避险、四格降落、转弯、载客和绕路。关卡验收不是“功能地块占比越高越好”，而是同一元素能参与多少不同的合理选择。首轮必须近，不代表整张地图必须小；外轮廓可以承担机动和地标，交战核心不能散。

三套验证任务分别证明：主救援的手感与多解、结构变体的上下层与机构、环城阻击的战斗压力与大范围连锁。第三套使用同一效果与任务条件框架，不加入“若关卡叫工务城就……”的新判断。

## 7. 施工如何防止计划再次被做粗

每个工作包不仅产出代码，还需把关联的逐项设计编号填回交付记录。一个条目涉及规则、视觉、动作和输入时，四者都完成才具备评审条件；其中一项空着就不能写“已优化”。

| 交付栏 | 应填写的具体证据 |
|---|---|
| 来源与决定 | 报告编号、原问题、采纳/调整/澄清；与本计划不同须说明变更理由 |
| 规则 | 配置/接口、可重放初态、命令、事件和终态；正常与反例 |
| 交互 | 从自由探索开始的真实鼠标录像，点击/撤回/失败反馈与等待时间 |
| 画面与声音 | 常规视距前后、动作全过程、受损态、降低动态模式、有声录制 |
| 跨系统影响 | 换编队、切区、模块/形态改变、旧存档版本、快进/跳过 |
| 玩家理解 | 未讲解时能否说出保护对象、敌意、这手改变、下一步；哪里仍误解 |

首个集成检查不只看“四招通过测试”，还要从标题→部署→首轮→跨区→敌方阶段→回合小结跑完真实输入。后面的检查逐渐扩大到14机、18招、三任务。最终保留所有未过项和实际人数、帧率、延迟数据，不把自己能操作过关当作人类体验合格。

## 8. 拟修改入口与替换边界

下表是施工定位，不代表这些函数已经新建。各报告条目的具体入口还在逐项设计册列出。

| 现有区域 | 计划修改 | 保留与迁移方式 |
|---|---|---|
| `tactical_contract.gd`、`round_armaments.gd` | 显式动作类型、费用/持续状态、装备解析 | 保留有效规则，移除从force推断推移的表达捷径；旧字段做版本化转换 |
| `round_rules.gd`、空间/棋盘规则 | 统一接近、快照模拟、事件来源、多格/多面、稳定敌顺位 | 不把预演和正式结算拆成两套；旧固定场景条件迁到数据 |
| `round_stage.gd`、`round_cursor.gd`、HUD/overlay | 输入四态、Ctrl手势、目标浮卡、棋盘后果、区摘要 | 复用现有拾取和窗口，删除多余普通确认；不重做一套平行UI |
| `round_inspect_diagram.gd`、`round_skill_stage.gd` | 真实Fixture生成的小图和可选3D示范 | 废除固定5×3与通用挥击回落，未知类型直接显式缺件 |
| `round_world.gd`、`model_motion.gd`、effects | 连续移动、完整身体动作、部件挂点、演出时钟与三态资产 | 保留可用骨骼/材质/场地资产；不再次退回2D棋子或简单色块 |
| 任务、身份、人物与卡组数据 | 条件图、出席、授权、机魂提案、确定指令与随机对照 | 不改已接受Reader；玩法Candidate先独立验证 |
| 拟新增音频与验收工具 | 事件音频层、输入测时、可重放样本、完整日志 | 使用实际录制确认，不以静态截图证明声音/手感 |

完成本册、逐项设计册和图解，意味着方案已细化到可以逐条评审和安排施工；不意味着游戏、美术资产或玩家体验已经改完。
