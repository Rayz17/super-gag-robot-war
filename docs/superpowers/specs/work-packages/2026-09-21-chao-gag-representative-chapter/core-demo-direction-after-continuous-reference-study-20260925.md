# 核心 demo 改造假设：从 V6 的「排表」转为「战场上做出一条因果」

2026-09-25 · **历史 Candidate 草稿。** 本页三段式木桶街赛局、固定时长和“施工决定”均已被[连续观看多段完整流程后的修订案](core-demo-srpg-story-integration-after-full-episode-study-20260925.md)撤回；以下保留旧推理供对照，不作为施工依据。不是已实现版本、玩家验收或 Canon 变更。对照入口：[第 11 号读招与接力 V6](readability-v6.md)；此前的 [《Demonschool》全系列取样报告](demonschool-reference-study-20260925.md)只可用于广度扫描。

## 当前假设

下一件产品不是再增加一个打法表、再写更多结算说明，也不是照抄《Demonschool》的自动攻击。制作一场 **可独立试玩的木桶街演练赛局**：玩家看见敌机即将攻击谁、落在哪里；用无牌一号、旧拳王、馆守 Z 的一台机先改变敌人的位置或出手条件；地图直接显示这一改变会为另一台机创造什么机会；玩家愿意时再接上第二台；一次提交后，机体用可辨认的身体动作把预演的结果打出来。直接猛攻、接拳保全、诱敌侧袭都应能赢，但付出和观感不同。战场、人物、吐槽与机体招牌动作必须成为这一局的可感知部分，而不是胜利后的说明文字。

这场赛局是 **C02/木桶街的独立 Candidate 体验件设想**，不替正式 Reader 决定剧情赛果，也不借演练给任一角色增加 Canon 能力。保留第 9、10、11 号入口供同局面比较；新入口另编号。目标是一段约 10–15 分钟的**端到端可玩体验**，这个时长是设计预算，须由真实玩家试玩修正。下面各项在扩大参考研究和实际对照前均不能作为已定施工方案。

## V6 具体差在哪里，哪些必须保留

第 11 号不是空壳：同一个解析器驱动预演与结算；敌机轮首先承诺计划；读招有未知分支；限次抱架、接拳、推位和等真实推位发生后的双机接力都已有规则；可点攻击格、可撤销、可看 5 拍细节、可用人物/精神能力，且机体视角能旋转平移缩放。105 项规则与 259 项原生窗口检查表明这些**技术行为**有可复现基础，不能误写成毫无机制。详情在 [V6 实施记录](readability-v6.md)。

用户实玩所指出的差距依然成立：玩家往往先要选机体、模式、路线、拳向、招式、目标、出手格、队友顺序，再读损益文字；最重要的「我把它推走后谁能接」「它的拳落在哪里」「这一挡到底有没有意义」没有成为战场上的第一层视觉语言。V6 有战术逻辑，却要求玩家先像开发者一样填写它。五拍表和全队模板过早进入主流程，让「思考」变成资料整理。团队模板在固定探针里能轻松连胜，玩家手排又常败；这不是把按钮做漂亮就会消失的策略失衡。

还有一个核心机制债：V6 虽统一敌方承诺与情报，但逐机依然是 5/4/5/4 拍分段交锋，团队是一个 5 拍段；玩家换操作方式时模拟时间也变了。新的核心 demo 应只用**一份轮首承诺、一个 5 拍结算段**；每台机仍可单独、顺手地编辑，但大家一次提交。旧逐机模式留在版本选择器，作为可比较的历史玩法，而非偷偷更换 V6 的规则。人物能力不应替玩家自动算出最优解：白鸢只展开真实未知分支，纪存调整明确的出手时点，精神指令改变命中/风险边界；收益仍由玩家的局部选择产生。

## 一场局的内容：由「对拳」长出「队伍」

不做三张只是换胜利条件的地图。新赛局用同一块可辨识的木桶街展演场，从短冲突进入完整团队局面：

1. **第一段：一机读招（约 1–2 分钟）。** 无牌一号面对会宣告直拳或横扫的近战机。开局明示其起手方向、目标和预计接触格；玩家用快拳、接拳反击或撤步任取其一。每一种结果即时成立，不因没有选教程指定答案而作废。此段验证「危险从哪来」「我怎样指一个格」是否一眼明白。
2. **第二段：两机制造机会（约 3–4 分钟）。** 旧拳王进入同一地图；一个敌机会冲向预告落点，另一台对侧面施压。玩家可以让无牌推位，再接受地图上出现的「接这一下」邀请；也可以让旧拳王预先站到**敌方未来落点旁**，瞄准该格，而不是只能瞄当前机体；或选择稳守，保留招式资源。此段验证晚到机体能否合法后击、占位是否改变结果、两种路线是否明显不同。
3. **第三段：三机破阵兼护场（约 4–6 分钟）。** 馆守 Z 进入，重装机和射手造成两处同时威胁；场边一个明确的演练道具/护场点会在敌方计划兑现时受损。下一轮有一次**事先可见的场地扫线**，它让原本方便接拳的站位变危险，玩家须决定立即打断、换到侧翼或由馆守护住目标；扫线只改变这一轮的取舍，不用重复刷多轮大面积红格。主要目标为在轮限内压制/推出重装机，附带目标是保住护场点；不要求清光每台靶机。玩家可莽攻换速度但承受道具损失、用馆守接弹换安全、诱敌空拳造破绽后天冲拳打出舞台级结果。具体角色/道具称谓与剧情接法需再对照已验收 Reader，本件只验证游戏局面，不暗中改写正式赛果。
4. **收束（约 1 分钟）。** 只对真实战果短演：谁护住了场地、谁接上了那拳、是否用过天冲拳。角色吐槽魔玩界「限定色/完全武装」之类，本场不用名台词问答锁。对白根据实际事件读取，避免玩家用了招却被台词否认。可回放关键一拍并立即再试另一打法。

约 9–13 分钟操作加短演出，预留到 10–15 分钟；时间是待试玩的预算。三段不是三个菜单入口，也不是开局连续灌三页教学：前段的机体、场地和操作习惯留到后段，玩家感觉同一场事在升温。开场战场镜头给机体和舞台体积，切近景只为重要接触；执行后一定回到玩家之前的镜头方位。

## 玩家实际怎样操作一回合

**空闲战场**只常驻任务目标/剩余回合、必要的场地危险、当前选中机体的小状态和「执行/撤销」。不铺全员耐久、整队能力、逐拍表和每个可能收益。光标可自由移动，鼠标、方向键或手柄都能选格；悬停敌机时展开「它要打谁/哪格」「何时出手」「不确定的部分」，点击才进入详情。红色线必须有**起点、箭头、终点与命中格**，并与真正释放事件对应，不能只是抽象红线。威胁格在机体脚下，不遮住模型。

**给一台机下令**：选我方机体 → 指目的格（也可原地） → 地图显示根据机体和落点最直接的行动/目标格。此时玩家能一键改「快拳/接拳/虚晃/天冲拳」，也能点空格预瞄敌方预计落点、转拳向；详细射程/成本按需展开。投影至少同时标出自身停位、实际出手格、敌人预计格、推后格和护场点变化。没有合法命中便显示「落空：目标将在第 3 拍离开此格」之类可行动的原因；未知敌招只显示条件结果，绝不把内部读到的实招标成必定命中。

**接队友**：当已排动作按规则真正能制造机会时，受影响格旁出现一次「旧拳王 · 接这一下」；点它自动放一条*可编辑且合法*的后手草稿，明示要花掉旧拳王这一轮行动。玩家可以改后手落点/招式/瞄准格，或不接。没有机会不弹虚假连携提示。三机都可独立选，也可只操一台；未下令机体执行可见的待命/抱架默认行为。*不再用全队「破阵合击」按钮替玩家选完路线和目标。*

**执行**：一次提交这轮已排指令与冻结敌方承诺。内部沿用 5 拍、真实蓄势/走位/接触次序；平时不用先学「一拍、二拍、三拍」才能打。规划的关键因果按战场预演兑现：推位要看见起点/落点，接拳要先受力再回击，打断要看见对方已起势但来不及释放。若同拍双方攻击同时结算，画面用整拍慢放/双向接触，不能错峰播成「先打倒所以对方没出拳」的假规则。失败也给地图留一条短的原因标注，详细 5 拍回放按键打开。

建议的界面状态关系：

```text
自由看战场 ──选敌机──> 敌方意图卡（对象、落点、接触格、确定/未知）
     │
     └──选友机──> 指落点／出手格 ──> 地图因果预演 ──> 可选邀请队友
                                    │                  │
                                    └────撤销/改令──────┘
                                             │
                                        执行整轮计划
                                             │
                                 身体动作＋场地结果＋短反应
```

全队顺序、伤害拆解、人物能力、精神指令在选中/展开时出现；角色能力菜单可用方形头像，剧情对白用最新有效人物素材的半身像。执行镜头中关掉规划线与堆叠说明，结果字幕有固定安全区，不盖脸、机体或下一个点选位置。镜头/面板关闭后主战场不留下空洞。

**一屏构图约束**：地图占主要面积，默认斜俯视能同时看清三机、场地边界和护场点；左上角只留目标和剩余轮数，选中者的小状态贴近机体/光标，右侧弹一张当前对象卡（先写「正准备打谁、落哪格」，再给具体数值），下缘只留撤销/执行及当前招式快捷项。人物与精神能力从选中友机的菜单打开，不常驻一整条按钮。规划层必须贴在地表、模型永远压在其上；弹窗按安全区避让，窄窗口不能靠缩小字体硬塞。要用实机截图在常用两种尺寸核对文字、机体和格子始终可读。

## 战术必须由一套规则产出不同收益

这里不是给玩家三段预录路线，而是让同一单位、位置、出手时点、状态窗口和场地后果组合出结果。新赛局只验以下四类可重复的规则关系；招式伤害不是区别的唯一来源。

| 玩家办法 | 成立条件与显性的代价 | 必须产生的不同感觉和结果 |
|---|---|---|
| **正面抢攻** | 快拳能在对方蓄势前碰到；目标不被友方先推走 | 最少操作、最快削血/清路，拳与受击反应利落；若只是削血，仍可能吃射手或护场点损失。它是正经解法，不强迫每人先做连携谜题。 |
| **接拳反击 / 护卫** | 玩家选定真正会受击的格和朝向；共用每轮一次的反应机会，耗体力 | 用身体承受并改变对手姿态，降低己方/道具损失，再反击；不能在侧背受击时凭按钮白拿收益。声音、架势、镜头停顿与快拳明显不同。 |
| **诱敌露破绽 → 天冲拳** | 目标确属会抢拳的行为类型，虚晃在视野和射程内，撤步格执行时仍空；敌方拳真实落空才授予短暂破绽 | 先冒一次风险、下一次打出高回报的位移/破甲/招牌镜头；稳重敌机或堵死撤步格会破局，白鸢预测可减少误判而不代替玩家虚晃。 |
| **侧袭 / 推位接力 / 护场** | 一机到预告落点侧面并瞄该格；或前手真实推至后手拳区且后手仍有合法出手拍；要取舍机体行动与护场点 | 对重装正面防御有特殊收益、可改变射手视线/目标；整条链能在战场上看见，失败也指出是「敌人先动」「推位超出拳区」「友军占位」哪一条件断了。 |

解析事件统一写成「谁在第几拍、从何格作用于何格/何对象、依何条件、付何成本、产生何状态/位移/任务变化」。预览、真实结算、战后短评和动画都读同一事件，不各写一套近似规则。人物能力只改事件的情报/时机/命中条件。这样保留未来非战斗任务的接口：例如「一机引开巡检 → 门口露出窗口 → 另一机取证」仍用对象、窗口、时点和后果，玩家仍是点对象和落点，而不是重复执行工程小动作。

核心 demo 的难度不能由一个万能团队模板解决。至少在相同开局中可复现三条玩家主动选择的路线：快攻能赢但可能丢护场目标，防守/护卫能保场但慢一轮，诱敌/侧袭在条件满足时更高效且可打招牌动作。数值差别须靠实玩调，不先写死「哪条最优」；失败允许合理回退，不用为了剧情强行吞掉打中或胜利。

## 美术与手感不是后期贴皮

从《Demonschool》取 **2D 人物负责情绪、3D 场地/巨物负责空间与规模、规划和执行的视觉状态切换**；不取它的像素角色比例、校园界面或巨大 Boss 的所有做法。《陷阵之志》取 **地图上准确的敌方意图、对象/建筑后果和短回合取舍**；不把机甲仅画成统计小棋子。超 GAG 仍要保留有身份的三维机体、旧片/魔玩文化的梗、招牌机体动作与近景摄影。

要优先制作的是**这一局的视觉语法**：一个能读出街景、边界和护场点的场地；无牌、旧拳王、馆守与重装对手的清晰轮廓；四种不靠文字也能认出的动作轮廓（快拳短促前冲、接拳架势—吸收—回击、虚晃抖肩—撤步、天冲拳完整踏步蓄力）；击中、被抱架、推走、落空、打断、破甲有不同接触反馈。地图机体不是每回合只滑一格然后弹数字。关键连锁第一次触发时用短近景特写，再回地图；普通回合保持节奏，提供快速演出设置。音效打击层次须实际试听比较，本次视频研究没有完成声音判断。

技术链继续以 **Godot 为唯一交互和判定运行时**。现有 V6 解析器与版本选择器是基础；Blender 负责统一比例、硬表面轮廓、关节与接触点，Meshy 只做可审查的初模候选，不能把下载模型直接塞进现有动作体系。所有战场动作的实际命中和位移用 Godot 实时演出。LibTV/视频切片只用于已确定起止姿势的开场、首次大招或固定剧情镜头；可变目标/伤害/落点不得烘进单一片段。现有分工和未验证边界见 [美术与制作方案](production.md)。不为本件再做第二套 Three.js 战斗运行时。

## 原施工顺序与验收门槛（已撤回）

以下是旧版施工设想，已由[修订案](core-demo-srpg-story-integration-after-full-episode-study-20260925.md)覆盖；旧版不宣布 V6 已通过。

1. **先把规则冻结成可对照试局。** 从第 11 号复制一份新候选，统一一个 5 拍轮，保留敌方轮首承诺和既有反应/推位/接力规则。做四个确定性局面：正面重拳、防守反击、敌方未来落点侧袭、推位后接力；再加护场目标。预览/结算必须一致，未知分支不得偷读，挡位/空挥有可复现原因。先让三种路线的收益和代价不同，再调 AI 与数值。不能以模板自动赢作为通过。
2. **做战场直接操作。** 完整键鼠/手柄路径先实现「选机—点落点—点目标/预测格—一键改招—撤销—执行」。把敌方对象/目标/时点画在机体和地图上；只有相关对象被选中时展开细节。移除主流程的全队排表负担，保留可呼出的五拍拆解供高手和 QA。把「接这一下」做成真正可取消、可改、消耗一人行动的局部邀请。
3. **同场做视觉与音频打样。** 用真实或可替换的三维机体完成四个动作轮廓、接触/位移/落空、镜头回位和一段天冲拳。第一批只为本局需要的机体制作材质和场地。每次换模型用同一动作/镜头夹具对比，不能以零件数代替造型品质；做有声/静音两轮实玩，记录命中可辨识度。
4. **嵌入一局的剧情与幽默。** 开场给关系和事件、关键战果触发 1–2 句人物回应、结尾按实际打法/护场结果变化。文字不是规则解释墙；战场上的机体行为先说明因果，台词再提供角色味道。最新有效人物立绘由源图裁半身并清干净碎片，能力卡使用小方像。
5. **同人同局 A/B 试玩。** 第 9、10、11 号及新入口保留。让至少一名未参与开发的人先不看说明直接玩，再由项目主人比较；记录首次有效指令、理解敌意图的方式、能否主动用出第二种打法、是否看懂每次落空/接力/护场损失、是否愿意立刻再玩。用操作日志和玩家复述核对，而不只看脚本胜率。完成第 1–4 步并通过这一步，才考虑扩关卡/机体/剧情。

本件的**失败判据**也提前写清：如果首次体验仍要求先懂五拍表才能行动；如果玩家无法指出威胁会落在哪格；如果推进、侧袭、接拳的不同结果只在结算文字出现；如果新入口依靠自动团队模板取胜；如果完成一局后玩家觉得 3D 机体没有招式身份——就继续打磨同一局，不把 V7 宣告为核心玩法定案，更不拿增加剧情或美术数量掩盖问题。

便捷性的施工目标可直接测：从自由光标完成一次普通有效行动，默认只需「选机—指格—执行」三次主动选择；改招至多多一次选择，出现真接力后接受队友邀请至多多两次。它们是**界面验收目标**，不是游戏必须替玩家决定落点/打法。参与实玩的新玩家若必须靠口头讲解才能找到攻击格、若二机接力要反复开关面板或若一局无法从反馈学会第二种打法，就不通过。
