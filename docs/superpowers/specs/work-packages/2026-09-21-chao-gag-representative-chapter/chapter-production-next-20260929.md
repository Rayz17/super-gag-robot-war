# 从练兵场回到木桶街章节

2026-09-29 · 下一阶段制作建议。依据用户“战斗 Demo 已有一部分可玩性，不应继续长期停在这里”的反馈。不是全剧缩编、故事重写或正式 Runtime 晋升。

下一阶段的主要交付，应当从“同一场训练战的新版本”转为“一段可以连续游玩的木桶街经历”。已有战斗保留为公式台的战术样板和回归场；本轮批准的材质修复继续做，但普通美术精修不再阻塞章节组织。阻塞推进的仍是无法移动、预告与执行不一致、错误结算、存档丢状态等实际问题。

## 原案要做的事与当前缺口

原案的产品承诺是：带着活的机器人博物馆旅行，认识、招待并与机器人伙伴并肩，亲手打出他们原本打不出来的名场面。木桶街不是一张格斗场，而是一次为了让万机馆继续启航而参赛、学拳、认识旧片中人物、共同救场并带伙伴回家的经历。

| 原案环节 | 当前已有的可复用成果 | 尚未做成的玩家经历 |
|---|---|---|
| 到港与街区生活 | P 包可行走前场、人物交谈、绘制场景、进场过渡 | 转子故障为什么让人留下；合作社、商品展示与报名如何在空间里吸引玩家 |
| 比赛与学习 | 逐机/团队、读招、预定格瞄准、接力、指挥/精神能力、机体动作与练习 | 资格赛、非计分教学、正式比赛各自的目标、能力阶段和人物关系；现有群战不能直接充当原剧情 |
| 作品与人物 | 人物立绘、对白系统、条件化战后回应 | 旧片、补件和人的反应共同让玩家认识无牌、王者、旧拳王、白鸢与赵梅；玩梗应落在具体物件和事件上 |
| 非战斗合作 | 空间、路径、意图、事件及任务判定的技术基础 | 救场中的较少但有效的决定，区别于再打掉一队靶机，也区别于繁琐的承重施工表 |
| 带着变化离开 | P 的战果回执与三段流程接入 | 新伙伴真实住进馆内，转子与纪念物可见，保存/继续后状态仍在，下一次出发受其影响 |

当前 P 输入、构建器与运行代码证明的是“前场—独立演练—短收束”，不是整章。其入口仍保留，供直接打磨战斗；不要为了章节化删掉玩家已经玩出的自由打法。

## 第一份交付：到港—报名—资格赛—回到工房

以 C02E01 为主要故事输入，使用现有公式台运行器，新增有连续状态的章节包。先让这段有明确的开始、行动理由和收束，再往后接，不等全章所有模型都做好才第一次玩通。

1. **到港后能亲自进入木桶街。** 用一段紧凑演出交代万机馆暂时走不了、冠军奖品能解决问题。随后交还控制；报名处、模型摊、工房由路标、人物行为和空间关系引导。主通路清楚，可选逛街不成为读下一句台词的门槛。
2. **在具体东西上看到这个游戏的趣味。** 展示王者的全武装和商品宣传，让强大与好笑同时成立；让无牌的来历通过修补痕迹、人的叫法和它自己的反应显露。采用 Reader 中的具体笑话和人物行动，不写百科解释墙，不临时新增一套经营小游戏。
3. **把资格赛做成一次有理由的战斗。** 目标是通过阻挡去敲铃。利用已有移动、意图、击退、绕行和镜头能力；至少让绕侧抢进与引开守卫产生能看见的不同过程。此时不提前发放后续学成的天冲拳，也不让还没正式到场的白鸢提供战斗能力。
4. **比赛结束后回到同一地方。** 根据真实结果恢复站位、人物回应与报名/晋级状态，接向工房与下一场事件。原文中“没能完成的拳”若需演出，清楚划分演出和玩家控制，不能让玩家以为按键失效。
5. **能中断、保存、继续。** 支持从场景或战斗检查点继续；探索过的对象、已发生的对白、比赛状态不因重开丢失。战败重试回到正确局面，不多扣资源、不重复领奖。

这一交付的验收对象是连续游玩本身：第一次接触的人能说明为什么参赛，能自己到达报名/比赛入口，能完成一种自己的进场办法，能记住至少一处人物行为或文化笑点，并能在战后看到自己的行动留下的变化。不会以“多接了几个公式”作为完成标准。

## 再分两段补成原案章节

| 次序 | 制作对象 | 主要新增价值与限制 |
|---|---|---|
| 第二段 | 师徒训练、放映旧片、后续正式交手 | 用地图动作、片段、停顿和对白让人喜欢角色；训练失败与比赛胜负各有含义。非计分指导战尚未完成天冲拳，不能直接套用可赢的练习。现有体术、招式辨识和读招在故事中获得用途 |
| 第三段 | 王者决赛、货运环救场、返馆启航 | 王者的全武装和作战习惯形成新的敌我差异；比赛、事故救场分别结算。救场只保留关键落脚/拳路/支援决定，其余队友自主动作持续可见。结尾将转子、伙伴、作品与训练区真实带回馆内 |

完整木桶街是中期内容目标，第一段不是整章完成。旧工作包的 50–65 分钟是初始编排预算，没有实玩测量支撑；本次不以凑时长或再给全游戏规定 18–24 话来定义规模。

章内故事依据当前 C02 用户接受的五话 Reader。游戏改编中的交互窗口、自由战斗与固定赛果如何接合，要逐场标明差异；不擅改角色去向、事故原因和比赛结果。独立演练的“全部能力可用”不会自动成为剧情人物此时已会的能力。

## 公式台怎样从这里扩展

采用“完成一段真实经历，再把经过检验的能力复用到另一段”的顺序。第一段联动探索、叙事、战术、结算；旧片与维修来历需要时补调查；章末返馆和出发补 Hub、世界路线。不是把七个互不相干的功能演示排成菜单。

共享接口以现有运行器与事实交接为基础：场景入口/返回点、角色与热点、对话条件、任务目标、战斗结果、物件/人物变化、存档。只在更换关卡内容确实需要时提取模块，不先停下来重写一套通用引擎。沿用 140 的七公式范围、每公式实质不同输入与多公式组合验证要求。

七公式也不能全靠木桶街证明：本章没有自然用途的能力继续用其他有效章节场景验证。原 O 包承重、路线等已有工程成果保留；是否在新章节使用，要由剧情与趣味决定，不为了复用代码强行加入操作。

## 制作顺序与停止无尽回修的办法

- **眼前收尾**：保存 v11.2 对照；修复宽大建筑表面的 UV/贴图接入、材质差异；保留甲板与机体分色、规划可读性及练习结算修复。
- **主制作线切换**：先做上述第一段的完整流程与必要资产。当前练兵场持续保留为快速战斗入口，新增问题能在此复现，不让每次修拳脚都要求重走剧情。
- **质量与内容同时落地**：每段交付都带场景活动、演出、对白、声音和可操作后果。不是先做一整章文字按钮，再把表现统一排到最后。
- **战斗只因真实场景需要扩充**：资格赛需要的通路和守卫、决赛需要的王者武装、救场需要的支援对象，分别驱动功能。没有新场景理由时，不继续堆招式数量、机体数量和计划模式。
- **完整玩通后再估全项目产能**：记录新增场景与复用场景的实际成本，检查资产及公式是否真的省工。当前不能从单场训练战推断整部游戏的预算和成功概率。
