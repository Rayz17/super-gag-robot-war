# 群战交互补充研究：顺序、局部操作与地图因果

2026-09-22 · 接续 [前四组实机研究](group-interaction-research.md)

本轮回答两个问题：参考是否覆盖了足够成熟的战术游戏；低操作负担与深层连锁是否一定冲突。材料是 B 站三段连续实机的**顺序抽帧精读**，再用开发者资料核对具体规则。不是只读 Wiki 或评论，也不是亲手操作或完整听看通关录像。

## 《陷阵之志》：结果复杂，入口可以很少

**画面观察。** 00:31–00:40，敌人的攻击方向和火山地块警告保留在地图上；00:43 切到角色细节，而非一直展开所有单位参数。00:49–01:49，玩家换武器与目标，连锁伤害标记、炮击弧线、推移方向直接落在受影响对象附近。01:52–01:58 的攻击改变现场火焰；02:19 结束回合后，地形危险与敌人行动依次兑现，02:34 可见阻止敌人出现的结果。后面仍有重新选机和反复预览，这也说明三台机不等于没有推敲成本。

**官方依据。** [Subset Games 作品页](https://www.subsetgames.com/itb.html)明确介绍敌方攻击预告，以及民用建筑与机甲电力的关系。这里的趣味不仅是打掉敌人血量，也来自改变一次已知攻击将影响谁。

**适用于我们。** 敌人锁定的攻击位置、推退落点、任务对象的危险必须留在地图关系中。让“把他推开”同时改变敌人的命中对象或保护结果，才能产生超过伤害数字的收益。

**不照搬。** 不把所有未知计划永久公开，也不把每关做成唯一解谜题。否则白鸢预测、读招成长和机器人大战式的压倒性招式都会失去空间。

示例接触表：[移动、出招与世界变化](../../../../../artifacts/research/comparison-followup-20260922/itb-03.jpg)。

## 《幽浮 2》：逐台操作也能留下之后发生的事

**画面观察。** 01:01–01:43，移动范围和路径随当前士兵切换，下令后立即有人动起来，没有先展开全队时刻表。01:46–01:55，敌方行动通过阶段提示和镜头呈现。02:04–02:16，从区域预览到投掷近景、冰冻效果，再回到地图；02:43–02:49 的机体射击同样回到实际局面。当前单位的动作集中在下方，多单位状态仍可在场景中辨认。复杂时血条和图标也会拥挤，并非任何布局都值得照搬。

**官方依据。** [2K 官方扩展手册](https://downloads.2kgames.com/xcom2/manuals/asia/XCOM_2_Extended_Manual_(English)_XB1(For_SG.HK.KR).pdf)第 3–4 页说明：通常每回合两点行动、蓝黄移动范围、上下文动作，以及警戒对穿越视野的敌人触发射击，并有相应限制。**本次片段没有覆盖一次完整的警戒伏击**，所以警戒链的规则来自手册，而不是宣称从这段视频里看到了。

**适用于我们。** 一台机可以先留下“符合条件才出手”的状态，之后由敌人或另一台机改变局面触发。玩家不必给每个触发填写具体第几拍，但必须知道保护谁、看住哪里、触发成本和失效条件。机体开始动、完成动作、回到地图应形成短而清楚的反馈。

**不照搬。** 命中概率、掩体图标、弹药与职业技能不能整套叠到拳路系统上。借鉴的是命令聚焦和条件行动，不是额外添加一整套军事模拟参数。

示例接触表：[区域预览、短镜头和控制返回](../../../../../artifacts/research/comparison-followup-20260922/xcom-03.jpg)。

## 《博德之门 3》：顺序与场景对象一起形成策略

**画面观察。** 07:01–07:11，上方保持行动顺序头像，切换操作者时下方动作随之改变。07:37–07:45 的路径、移动和结果直接兑现；07:49–08:15 又切换角色及召唤物，动作条和可用能力差异清楚。07:57 的区域冰面让能力后果留在场景中；08:23 前后的资源/反应选择是局部出现。约 09:07 战斗结束后回到同一片场景继续探索。另一方面，07:13–07:19 打开的大背包、后段密集技能栏说明大型成功作品同样有学习负担，不能把其完整 UI 当作我们的答案。

**官方依据。** Larian 的 [2020 年战斗与潜行开发说明](https://baldursgate3.game/news/a-little-about-combat-stealth_3)介绍相邻同方行动位的协同，以及场景中的推落、光照、潜行与回合模式。它是早期设计资料，不当作当前版本所有细则的证明。视频能确认顺序头像、角色切换与场景反馈；仅凭抽帧不能恢复玩家每次切换的全部资源状态。

**适用于我们。** 让玩家在有限的一组相关单位之间调整配合，保持当前谁可行动清楚；同一地图上的对象也可以参与规则。非战斗任务可复用“选择对象 → 可用动作 → 现场状态改变”，无需另外学习一套工程操作表。

**不照搬。** 不加入同等规模的技能栏、背包、豁免和先攻细则。我们需要的是少量相互作用产生多种后果，而不是先增加选项数量。

示例接触表：[角色切换与场景效果](../../../../../artifacts/research/comparison-followup-20260922/bg3-04.jpg)。

## 综合判断与仍缺的验证

七款片段合起来，已经支持三个具体方向：**常用命令围绕当前机体；战术关系在地图上可读；复杂配合按条件发生或由玩家局部组织。** 它们没有证明 v3 当前的固定敌人队列最好，也没有证明全队同步应被删除。

因此先保留各版，下一候选在相同规则下减少交互负担，再验证局部连锁和信息能力的接入。现有样本还不足以判断长期成长、十几台机的负担、完整关卡节奏或组合套路的耐玩程度；不继续把这些问题写成“已调研完成”。当前具体施工顺序统一回到 [工作包施工表](README.md#7-从这个包往后怎样工作)，避免研究产生另一套互相竞争的计划。
