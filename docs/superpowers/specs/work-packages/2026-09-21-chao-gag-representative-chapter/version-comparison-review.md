## 直接比较体验

在项目根目录双击 [试玩版本选择.command](../../../../../试玩版本选择.command)。这是原生 Godot 选择窗口；网页里的文件链接不会自动执行脚本，可在 Finder 中双击。也可在项目根运行 `./试玩版本选择.command`。

1. 点版本旁的“开始体验”，或按数字键 1–5。
2. 游戏内 **F10** 返回选择窗口；若 Mac 将功能键设为媒体键，用 **Fn＋F10**。直接关闭该游戏窗口也可以返回。
3. v2 / v3 上方可共同选择“重装破阵、护送突围、清场演练”。其余版本有各自原来的场景。

未完成对局不续存；各版操作记录分别保存。切换不会关闭此前单独启动的开发版游戏。

| 入口 | 这版怎样操作 | 值得比较的优点 | 必须知道的差异 |
|---|---|---|---|
| 1 交替单挑 | 选落点、招式，再看敌方响应 | 直接交替的节奏；接重拳、返劲天冲拳、压制与出界 | 早期 1v1 规则，数值不同于短计划版 |
| 2 短计划单挑 v5 | 观察敌人，设置一台机的路线、拳向和招式，双方按拍执行 | 读招、侧击、打断、反击；预测与精神指令；人物通讯、动作特写 | 已保留的单机场合基线；不需要先管理整支队伍 |
| 3 全队编排 v1 | 分别安排三台机，再共同执行 | 全队同步与逐机计划、护卫、预测 | **历史复原**：恢复四份历史脚本，共用动作和美术采用本次保留版本，不是当时整个工程的逐字节快照 |
| 4 战术组合群战 v2 | 先选组合，可逐台修改，随后全队共同执行 | 虚晃破绽、连锁、角色能力、多种任务 | 保留完整组合空间，也保留编排负担，不能把按钮变少等同于好玩 |
| 5 逐机直操群战 v3 | 地图试走、点目标、出招；当前一机与一敌短交锋，邻机可接应 | 光标和身体反馈、拳向与血条、直接选目标、局部协作 | 暂未接回人物能力、精神、全队同步；敌人逐次响应也改变了行动收益 |

先比较 **2 → 4 → 5** 就能看到“单机计划、全队计划、逐机交锋”的主要区别；1 和 3 用于回看更早的感觉。v2 / v3 可用相同任务比较，但其行动规则和资源结算不同，**不能将分数、受伤或回合数当作只改 UI 的严格对照**。

## 哪些变化需要纠正认识

核对当前脚本、历史副本与校验清单后，师徒 v5 的受保护文件仍保持原样；v2 的主要场景也保留着。这次另外拷出运行依赖，解决了“入口还在，但未来共用脚本改动使旧版跟着变化”的问题。

v3 的变化不止菜单：

- **行动节奏变了。** 玩家自由选择尚未行动的友机；每次由固定队列中的一台敌机共同响应。三台友机用完后，第四台及其余敌机收尾。它不是按速度属性排出的统一先后手。
- **情报价值变了。** v3 公开当前响应计划，暂时拿掉了部分情报不确定性。于是白鸢、纪存、精神指令与识招成长原先的价值尚未完整存在。
- **协作的成本变了。** 邻机接应每轮一次，花体力而不占它的主要行动；这会改变总行动收益。它与 v2 中为队友单独编排一个动作不是同一成本。
- **远期配合缩短了。** 多机同步时序让位于当前一组短交锋，容易理解一些，但全队创造并利用机会的跨度也变小。

这些削减可以用于检验操作，却不足以支撑“新框架全面更好”的判断。固定敌方响应队列也是试验规则，不能不加解释地成为正式战斗底层。

## 应当保住的东西

| 来源 | 保留理由 | 下一版怎样承接，而非堆回主界面 |
|---|---|---|
| v5 的读招、拳向、打断、反击 | 玩家通过观察和选择改变对抗结果 | 普通战斗仍能看见敌人准备做什么；详细预演按需打开，信息不完全时明确标出可能范围 |
| v5 的人物与精神能力 | 角色能力应改变可掌握的信息或可用行动 | 选中机体后呼出；次数、消耗、角色头像留在能力菜单，使用结果回到地图表达 |
| v2 的破绽与连锁 | 先手确实为后手创造条件，才有“这一串是我打出来的” | 普通一机可以完成行动；想配合时，再加入有关的第二台，不要求每次先编辑全队 |
| v3 的目标选择与空间反馈 | 手里控制的是机体，不能只有表格 | 脚下可达范围、目标方向、伤害与推退落点附着在地图上；减少试走后重复走一遍的时间 |
| 原来的机体和人物身份 | 超 GAG 的价值包括跨作品改演与文化笑点 | 后续招式、接应与台词必须体现具体身份，不能只剩通用数值和训练敌人 |

**我的推荐方向：默认逐台操作，协作时才临时组织局部计划；保留情报、反制和角色能力。** 这是下一候选的设计方向，还不是已经做好的第六版。单挑的短计划也继续存在，不为追求群战统一界面而删除。

## 下一轮只做三个可比较的改进

1. **让行动顺序看得懂。** 出手前只标明当前谁响应、谁还没行动、是否有敌方收尾。敌人蓄势、朝向和目标留在地图上。先验证表达，再决定是否换顺序算法；不同时新增速度、随机先手和复杂时间线。
2. **保留规则，缩短普通操作。** 从 v2 的相同初始状态与结算规则出发，验证“选机 → 落点 → 目标/招式”的单机入口；原计划编辑器仍能打开。这样能分清收益来自操作改善还是规则被削弱。v3 继续作为局部交锋对照。
3. **只打磨一组主动连锁。** 同一破阵场景中，对照直接强攻和“虚晃引出破绽 → 队友重击”。协作的加入应少一次菜单往返，并在现场明确显示谁造机会、谁接上。条件不满足时要能解释失败；普通攻击仍是有效选择。通过后再接回其余人物能力，保持旧版随时可比较。

验看的是玩家能否自然完成一轮、能否从动作看出因果、是否愿意再换一种打法。点选次数与用时可以记录，但不是越少越好，也不能由规则测试代替好玩。保护、诱导、移位、机会持续与任务状态可继续共用于非战斗关；固定的敌人响应队列不应强加给所有非战斗任务。

## 参考研究补到了哪里

原四组视频足以提出操作实验，**不足以确定整个战斗框架**。这轮补看了《博德之门 3》《幽浮 2：天选者之战》《陷阵之志》的 B 站实机片段，分别补充顺序与场景交互、单机命令与反馈、地图威胁与位移后果。具体时间码、可观察事实、官方机制依据和不宜照搬之处见 [补充研究](reference-followup.md)。

结论不是改成其中某款游戏，而是把“少做全队表格”和“仍能创造复杂局面”分开处理。更多有名游戏不会自动填平当前交互问题；下一次研究应继续针对未解决的动作或决策，而不是扩一份名单。
