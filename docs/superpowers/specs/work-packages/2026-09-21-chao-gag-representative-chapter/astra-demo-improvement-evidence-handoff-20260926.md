## 一句话判断

**足以启动一轮有边界、可与第 11 号 V6 同局面对照的改进；不足以承诺已经掌握最终美术风格、音效打击感或完整游戏体验。**需要同时验证剧情—战斗接续与群战的低负担编排，再把二者接成真正的代表性切片，而不是继续扩机体、关卡或说明文案。这个切片是全 Demo 的质量门，不是把《超改》缩成普通 1v1 战棋；既有版本和群战玩法都应保留。

## 用户补充后必须纳入的三项设计输入

### 1. 战斗 HUD 是决策工具，而非资料墙

原速复核[P2 教学战 05:30](https://www.bilibili.com/video/BV1FtyPBdExD/?p=2&t=330)和[约 06:26](https://www.bilibili.com/video/BV1FtyPBdExD/?p=2&t=386)：左下双人肖像卡各有三格生命和个人黄色充能条；选中 Faye 时右侧临时资料显示 `HP 2/3`，选中 Namako 时显示 `HP 3/3`；左下另一排圆点显示**全队共享的剩余行动预算**，右下只有一个明显的执行入口。左上保留当前关目标／回合；选中才展开单体招式详情，执行阶段让格网和资料让出舞台。P31 四人局仍用左下队伍卡与共享资源列，但拥挤边界需要单独检查。上述能证实此录像段的三格呈现，**尚未逐一核实整个游戏每个角色都固定三点生命**。

对第 11 号的设计转化：地图常态只留**当前任务、选中对象的危险、底部紧凑的我方队伍卡和行动预算**；机体受击／充能变化在相应卡和机体附近同步短暂反馈。V6 现有的是每机体行动承诺、个人体力与全队气势，**还不是可在队员间自由分配的共享 AP 池**；先把本轮尚可安排的行动清楚呈现，若要试真正共享 AP，必须作为独立机制对照。指向机体时才展开当前耐久、护架、体力、招式和状态；指向敌机时才展开可观察意图及不确定分支；精神指令／指挥塔能力进入单独呼出层，使用次数不在战场上永久占位。规划要有足够空间展示机体、落点、威胁与因果；执行和剧情对白各切换为更轻的 HUD。机体增多时队伍卡须有可切换或折叠方案，不能在顶部横排复制每台机体的大血槽。**把现行 28 点耐久改成三格生命是另一个规则实验**，不能为了抄布局顺手改数值：重拳、接拳、护架、恢复、出界与胜负条件都要重新平衡。

### 2. 一小段前置剧情必须把玩家带进这场战斗

参照[《Demonschool》P3 的课堂／调查／电脑房连续段](https://www.bilibili.com/video/BV1FtyPBdExD/?p=3)及[连续研究记录](core-demo-srpg-story-integration-after-full-episode-study-20260925.md)：它让人物在地点里交谈，随后同一房间的物件成为交战对象，战后回到已发生变化的地点。Astra 的剧情体验件应从**当前 C02E02 Reader**提炼一个短前场：在木桶街工房／红环，让玩家看见无牌尚不能把接住的力量送出去、旧拳王主动提出指导战及角色对这件事的反应；再由机体入场镜头直接转进可操作战场。对白调用最新版干净半身像，人物焦点清楚；战中短句只对已发生的接触回应；战后回同一地点接住关系与玩梗，不弹一页解释结算。前场具体台词、时长、可跳过方式应交给接手者与试玩决定，不能让 UI 草稿反向改写 Reader。E02 是**不计胜负的指导战**，无牌此时尚未真正命中旧拳王；前置戏和结果都不能误写成已经学会完整版天冲拳。

### 3. 预演和执行都要有可辨认的招式演出

用户指出的核心缺口成立：V6 已在[`combat_motion.gd`](../../../../../game-godot/scripts/candidate/c02_squad_v6/combat_motion.gd)和[`rigged_motion.gd`](../../../../../game-godot/scripts/candidate/c02_squad_v6/rigged_motion.gd)给快拳、踏步冲拳、反击、重击、横扫、特殊技不同姿态和时值，但**试玩画面里的动作轮廓仍不够清楚**；当前网格、名牌、字幕和远镜头也在争夺接触焦点。代码里“招式不同”不能替代常规视角下“玩家看得出不同”。

《陷阵之志》的实见操作链是“选中武器→地图标作用区与预期伤害／推位→确认后光束沿方向命中并留结果”；《Demonschool》P2 的规划显示人物起始／候选落点、影响格与队伍行动点，执行把格网退掉，让连击、推拉和大字效／角色动势占据焦点。转化到本项目应有**两层同源演出**：规划时选招即播放可迅速取消的短姿势／运动轨迹示意，地图同时预告攻击线、推位终点、可能碰撞、耗费与确定／条件性后果；执行时才播放完整的起势、脚步、拳路、接触、受力、位移与收招。已知结果的预览与实战由同一事件数据驱动；未知敌招保持分支，不把预测画成必成动画。空挥、被挡、接住、打断也各有明显动作，不能全由文字结算替代。

Astra 可先对**快拳／接拳反击／踏步冲拳／横扫／天冲拳未完成动作**做一张“远景轮廓—地图预告—执行接触—受击结果”的招式矩阵。规划示意不需要每次播完整特写；普通招式在默认战术视角就应凭重心、手臂轨迹、作用区域和敌机反应分辨，大招才用较长焦点镜头。C02E02 的无牌只能演“接住→蓄势→试踏步→拳停／落空”；可玩规则验证入口里的完整招式试验必须另标 Candidate，不得伪装为这场 Reader 已发生的事实。静音且遮掉招式名时，初看者仍应能分辨至少这几类动作和击中／落空，是必要的视觉验收；之后再检验声音、节奏和输入手感。

## 从证据得到的设计判断，不是既定答案

- **剧情推进**：一段戏应让地点因人物行为和交锋而改变含义。C02 可用工房/红环的进场、试拳、战后同地回应来验证；对白只提炼玩家已经看见或亲手造成的事实，不把梗概解释墙搬进战中。
- **SRPG 与交互**：地图是主要决策面；敌人要到哪、谁能推开、谁能接拳，先在空间上看见，再按需展开招式/拳向/不确定分支。保持 V6 的真实时间、碰撞、推位和伤害判定；UI 表达试验与规则改动分开，以便知道改进来自哪里。不要让预演文案保证未知拳路必然成功。
- **编排与爽感**：一次“推开→接拳”必须由动作起势、脚底承重、接触、受击方向、短镜头及返回战场共同证明；关掉结算字幕仍应看出先后和因果。同拍结算不能通过错开动画伪造另一套时间规则。音效与主观重量感留待有声实机评审。
- **美术**：当前首要问题是机体身份、场地构图、尺度、光色、动作及 UI 视觉层级未形成一套语言；高面数、Meshy 或更长特写不是独立解法。Godot 保持实时交互，Meshy／现成模型提供可替换的外形候选，Blender 处理统一比例、拳姿、骨架与材质，LibTV 切片用于镜头节奏研究；是否经济有效须以**下一台替换件的修模工时与战术视角成片**验证，工具名称不等于质量证明。先做少量机体与一处场景的一致性样片，再决定批量资产路线。用户要求的“超改”玩梗、熟悉 IP 的名场面再创作、模玩界与机甲文化吐槽，不能在简化交互时丢掉。

## 交给 Astra 的建议验证工作包

在用户另行授权施工后，保留第 11 号基线，另开可切换 Candidate 入口。交接给 Astra 的首轮不是扩章，而是两个互相约束的固定局面：

1. **剧情体验件：C02E02 旧拳王指导战。** 以当前 Reader 为准，做短前置戏→红环战斗→短现场回应；验证对白／半身像、场景、入场镜头、未完成天冲拳的动作与玩家操作如何接续。这里不计胜负，也不允许无牌真正打中旧拳王。这件检验剧情与 1v1 可读性。
2. **群战系统件：第 11 号 V6 的固定接力和 3 对 4 状态。** 先在同一初始状态只改 HUD、规划动效和执行镜头，比较 UI 轻重与招式识别；此层可用“无牌推开→旧拳王接这一下”作为动作样板，再试低点击的地图情境指令，但保留进阶招式、拳向、读招不确定性和版本入口。这件检验共享行动预算、多人预演、空间因果与手感。其阵容和结果是**规则 Candidate**，不能作为 C02E02 正式发生的群战。

两件都能成立后，Astra 再从有权威来源的群战剧情选择一场，设计真正包含**前置剧情与全队编排**的产品切片；不得把现有 V6 的拼盘阵容直接贴进旧拳王指导战。两个局面均须处理机体轮廓、材质、光色、地点身份、遮住接触点的名牌与战后回地图；动作、特效、镜头和声音要共同承载结果，不以更长说明文字代替。不可把这轮样板当作缩小整部游戏的决定。
