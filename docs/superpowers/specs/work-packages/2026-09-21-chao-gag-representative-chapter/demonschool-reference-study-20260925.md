# 《Demonschool》流程实机研究：怎样让群战规划有手感

2026-09-25 · 参考研究／Candidate 设计输入。研究对象是用户提供的 [B 站 55 P 流程系列](https://www.bilibili.com/video/BV1FtyPBdExD/?p=2)，对照本项目[第 11 号「读招与接力 v6」](readability-v6.md)。本页不修改现行战斗规则、剧情 Canon 或试玩入口。

**判断：这是目前最贴近超 GAG 群战难题的完整作品参考。** 用户提出“有 80–90% 可学”，若指 **规划／执行的交互语法、空间因果的展示、少量信息常驻、人物与战场美术的分工、关卡节奏**，这个判断很有根据。若指整套战斗数值、敌情透明度、校园日程或绘画风格原样移植，则不成立：超 GAG 的机体招式、读招不确定性、人物能力、文化梗和可操作的机器人动作仍须自己设计。最关键的区别是，《Demonschool》先做出了“一个落点就能引发行动”的低摩擦入口；我们目前让玩家先理解路线、拳向、出手格、拍数、队友次序及敌人计划，才能得到一次清楚的结果。

## 研究覆盖及证据边界

- 系列共 55 P、约 **14 小时 37 分**。P1 是预告，P2–P53 包含主流程及大量战斗、剧情和探索，P54–P55 是结局汇总；上传时间为 2025-11-21，紧接 [2025-11-19 发售](https://press.necrosoftgames.com/demonschool/)。P45 的上传标题从上一 P 的“(42)”跳到“(44)”，因此不能证明上传者没有漏掉一节。逐 P 时长、来源链接与取样数见[系列索引](../../../../../artifacts/research/demonschool-20260925/series-index.tsv)。
- 对 **55 P 全部**按约 90 秒间隔顺序抽帧，共生成 583 帧并按分 P 查看接触表；对 P2 教学、P3 早期 Boss、P20 锅炉关、P31 巨口 Boss、P40 多场地 Boss 另做 2–15 秒间隔的连续抽帧。保留了六张代表性[接触表](../../../../../artifacts/research/demonschool-20260925/)和两张 720p 原尺寸局面。这能可靠判断画面状态、关卡节奏、目标与危险区；它不是逐秒看完 14 小时，也不是亲手操作。P2 是 480p，选取的 P31/P40 帧另核对了 720p；其余多数是 360p，后段小字和精确点按数不据此推断。
- 本次未完成音轨试听，因而不把音效好坏、输入响应时延、真实键鼠手感写成亲测结论。开发者的[声音开发日志说明](https://steamcommunity.com/app/1900250/allnews/)可作待验证线索，不能替代试听。
- 流程视频反映发售初期状态。开发者 2026 年的[更新日志](https://steamcommunity.com/app/1900250/allnews/)已补入鼠标单独操作、对话历史、战斗反馈和预览修正等；视频中任何便利或缺陷都不能无条件等同于 2026-09-25 的最新版。

以下用“**画面**”标示直接从系列视频观察到的事实；“**开发者**”标示一手说明；“**转化**”是针对超 GAG 的设计判断。主创在[访谈](https://www.rpgfan.com/feature/demonschool-interview-brandon-sheffield/)中说，战斗原型是“尽量小的战术谜题”，希望减少点击；他认为最大挑战之一恰恰是 **如何沟通结果和组织 UI**。游戏与《陷阵之志》的可读危险区有明显亲缘感，不过他明确说，阶段与行动战斗的主要启发是《战场女武神》，不宜把它简化为“《陷阵之志》加剧情”。

## 实际战斗循环：空间指令、可撤回的编排、一次结算

| 阶段 | 从实机看到了什么 | 规则上的作用 |
|---|---|---|
| 开局／布阵 | 先在单独界面选择至多四名上场角色；战斗目标在上角，Boss 有整条长血槽。[P31 04:50–05:30](https://www.bilibili.com/video/BV1FtyPBdExD/?p=31&t=290) | 阵容是局前选择，不在每一步混入巨大的角色菜单。目标是判断方案优劣的参照。 |
| 规划 | 场景被压暗、格线提亮；选角色后，落点、会波及的格子、敌方危险区和选中对象资料出现。底部显示角色小卡与行动资源点。[P2 04:42–05:20](https://www.bilibili.com/video/BV1FtyPBdExD/?p=2&t=282) | 玩家主要选择 **谁到哪里**，不是先过“移动→招式→目标→确认”的多层菜单。进入敌人／空格／机关附近，情境动作随位置发生；特殊能力仍有单独入口。此“移动即动作”也由[开发者资料](https://press.necrosoftgames.com/demonschool/)明确确认。 |
| 推演／撤回 | 同一个规划阶段可以接着安排其他角色，预览伤害、推拉、受击格与组合；计划尚未执行时可回退。[P2 05:06–05:50](https://www.bilibili.com/video/BV1FtyPBdExD/?p=2&t=306) | 允许试验“先推到某格，再让另一人打”，使解谜的思考发生在地图对象之间。撤回降低试错惩罚，但不会消除思考时间。 |
| 执行 | 点画面一角的“行动”后，格线和长篇解释退场，角色冲刺、推拉、连击、受击和特效在实体场景中连续兑现，再回到下一轮规划。[P2 05:56–06:22](https://www.bilibili.com/video/BV1FtyPBdExD/?p=2&t=356) | 玩家先看到“我预判了什么”，再看到“身体上到底发生了什么”；一次执行成为视觉奖励。开发者亦明确说明规划可撤回、行动阶段重叠演出。 |
| 任务结算 | P2 教学明示“击败 8 名敌人、3 回合内完成可得高评级”；后续关卡继续给出回合／目标、Boss 血槽和局内危险区。[P2 05:52](https://www.bilibili.com/video/BV1FtyPBdExD/?p=2&t=352) | 局面的主要问题可被一句话说清，不要求玩家先算一份全队时刻表。 |

教学在 P2 **05:06–05:22** 让玩家先降低一名敌人的防御，再用侧移和两名角色的攻击串起结果；05:44–05:50 又明确要求把敌人推到队友身上形成连击。这是在教一条 **空间因果链**，而不是只讲按钮术语。P2 **06:22** 又弹出较长的要点总结，说明它仍依赖大量文字教学；减少点击不等于零学习成本。实机连续规划时会反复挪动落点；视频不能支持“每轮只点几下”这一精确说法。[对应画面 1](../../../../../artifacts/research/demonschool-20260925/p02-tutorial-combo.jpg)、[画面 2](../../../../../artifacts/research/demonschool-20260925/p02-objective-execute.jpg)。

## 从前期到结局，战术题目如何变化

| 代表片段 | 画面可核查的变化 | 对体验的意义与限度 |
|---|---|---|
| [P2 35:10–42:00](https://www.bilibili.com/video/BV1FtyPBdExD/?p=2&t=2110) 及 54:10–62:00 | 常规三至四人局反复在规划格网和实体场景之间切换；敌人、同伴与推拉后果仍在同一小地图上，而非铺出一整排每单位的回合表。 | 它证明同一入口可支持多人局；也能看到玩家确会在规划里花时间调整，不应把流程称作纯即时爽游。 |
| [P3 03:30–07:30](https://www.bilibili.com/video/BV1FtyPBdExD/?p=3&t=210) 和 [P8 24:00–31:00](https://www.bilibili.com/video/BV1FtyPBdExD/?p=8&t=1440) | Boss 成为高出小角色许多的三维舞台存在，红色斜纹危险带改变落点选择，受击／技能后回到同一局面。 | 让危险“属于那个怪物和场景”，不只是顶栏字句；小角色与巨物的比例本身是战术提醒。 |
| [P20 03:15–10:00](https://www.bilibili.com/video/BV1FtyPBdExD/?p=20&t=195) 锅炉 | 工业炉、熔岩格、连续红色危险带和敌人动作叠在空间里；同一个规划－执行循环需要绕开不同的场地风险。[画面](../../../../../artifacts/research/demonschool-20260925/p20-boiler-hazard.jpg) | 差异来自任务地形和危险时机，而不必每关增设一种菜单。危险区有图形、色彩和节奏，不只靠“敌人将攻击”的说明。 |
| [P25 01:30–04:30](https://www.bilibili.com/video/BV1FtyPBdExD/?p=25&t=90) | 环形舞台／扇区性质的危险区，与常见长方形棋盘的视觉和安全路径不同。 | 关卡可重组空间题型；但这种特制关卡生产成本高，不能无约束扩张。 |
| [P31 04:50–19:30](https://www.bilibili.com/video/BV1FtyPBdExD/?p=31&t=290) 巨口 | 长血槽、占据背景的口与爪、分阶段的危险条纹／地面标记；规划中的格网与执行中的木栈道清楚切换。[画面](../../../../../artifacts/research/demonschool-20260925/p31-mouth-boss.jpg) | 规模感和规则来源统一。但这个 Boss 约十多分钟仍在反复规划、执行；“快节奏”在高难关不是无条件成立。 |
| [P40 03:20–12:10](https://www.bilibili.com/video/BV1FtyPBdExD/?p=40&t=200) | 同场出现分开的交战场地和切换控件，危险区与多轮状态变换；底部依旧保留小队卡、行动资源与一个执行按钮。[画面](../../../../../artifacts/research/demonschool-20260925/p40-multifield-boss.jpg) | 复杂度可放进关卡结构，而不是把主界面改成复杂表格；同时这类局面明显更费理解，不能当作新手标准关。 |
| [P53 00:00–20:00](https://www.bilibili.com/video/BV1FtyPBdExD/?p=53) 与 [P54–55](https://www.bilibili.com/video/BV1FtyPBdExD/?p=54) | 终盘串接强烈视觉变化的多段交战与大体型敌人，后两 P 另展示人物结局。[概览](../../../../../artifacts/research/demonschool-20260925/p53-finale-overview.jpg) | 系统的“规划→执行”核心没有再换一套；大结局的差别主要由舞台、敌型、角色和叙事规模承担。不能从抽帧评价每条结局的完整叙事质量。 |

P16、P17、P19、P22、P26、P39 等分 P 里，战斗明显少于对话、闲逛、个人事件或钓鱼一类轻活动。主创的[访谈](https://www.rpgfan.com/feature/demonschool-interview-brandon-sheffield/)也说明按周、日、时段拆故事，希望约 15 分钟的游玩能拿到一个新信息。这条叙事节奏比“每个节点都打一场”值得借鉴；学校时间表、钓鱼、做饭和大量社交支线本身并不是超 GAG 的必需品。我们可让一节戏的任务目的、人物关系和机器人梗改变下一场地图问题，不把这些内容仅当战斗之间的解释文本。

战斗外另有独立的角色档案、技能装配、日程、商店与岛屿地图界面，P20 **01:00–02:00**、P25 **00:00–07:30** 和 P45 **04:30** 可见。它们把成长、编队与任务选择放在交战前后，不要求每一步都打开成长树。主创在[开发日志说明](https://steamcommunity.com/app/1900250/allnews/)中称战斗刻意不用传统等级／经验点；我们不必照搬这个选择。机体改造、驾驶员经验与精神指令可以保留，但应在“选机－预演－执行”的地图操作之外分层呈现。

## 美术与 UI：它让信息在恰当时刻出现

| 画面层 | 直接观察／一手说明 | 超 GAG 可转化的规则 |
|---|---|---|
| 战场世界 | 2D 人物小精灵叠在有明确光色和体积的 3D 场景；强敌常以更完整的 3D 体量进入画面。主创称这是“人间 2D／魔界 3D”的构思，并以一台虚构的 Saturn 后继主机规则约束材质与画法。[访谈](https://www.rpgfan.com/feature/demonschool-interview-brandon-sheffield/)、[开发者作品页](https://press.necrosoftgames.com/demonschool/) | 不学“把机体都变成像素小人”，学 **有成本上限的统一视觉规则**：保留 Godot 3D 机体，人物用最新版 2D 半身像；仅关键招式和 Boss 使用近景镜头、特效与高规格动作。 |
| 战术层 | 规划时白色格线、黄色影响格、蓝色当前／可选格、红色斜纹危险区形成层级；选中对象才出现详细卡。执行时网格和说明收起。 | 一套语义固定的地图标记，优先让玩家指着某格说出“谁去、击中谁、推到哪里、危险从哪里来”。格子遮机体、名牌压路的旧问题必须以层级和避让修，不靠加说明。 |
| 人物层 | 战斗里底部是小头像卡，剧情时才上大幅立绘和整块对白；打出组合或关键技能时可见漫画式特写和字体动势。 | 延续用户已指定的区分：能力菜单用方头像，通讯／对白用最新版干净抠图的半身像。不要再把同一头像重复放两次，也不要把战中对白塞在顶栏。 |
| 界面节奏 | 世界探索只留目标和少量指示；布阵、角色培养、地图、剧情对白各自调用专门界面。战斗仍有信息密度，但并不把角色档案、五拍过程、四队血条和规则提示永久铺满画面。 | 主界面应按 **自由看场→点选机体→预演→执行→结果** 改变密度。只保留当前判断需要的数据；详细战报和能力次数由检查／菜单调出。 |
| 色彩与识别 | 不同场景用强烈冷暖、粉绿和深色舞台构成“恐怖片”氛围；格线与危险标记跨场景保持一致。[开发者作品页](https://press.necrosoftgames.com/demonschool/)把 70 年代意大利恐怖电影光色列为明确方向。 | 超 GAG 应建立自己的“玩具盒／机甲演出／文化吐槽”视觉词汇，再规定威胁、落点、保护对象、技能和剧情的固定配色。不能简单套用 Demonschool 的霓虹恐怖片表皮。 |

在 [P31 05:40 的 720p 原帧](../../../../../artifacts/research/demonschool-20260925/p31-planning-ui-720.jpg)里，可直接核对这个层级：顶部只给本关目标与长条 Boss 状态，左下四张头像卡与行动资源点，右下单个执行按钮；位置关系、危险条纹和这一次的落点占据画面中心。[P40 07:50 的原帧](../../../../../artifacts/research/demonschool-20260925/p40-threat-ui-720.jpg)则能看到多人、多敌、两个场地局部与多个危险标记同时存在时，画面已经接近拥挤边缘。值得学的是按当前判断显示信息，不是照搬它每个图标的位置或字级。

它的完成度来自 **美术约束、状态分工和演出节奏**，不是“素材很高级”这一个因素。对我们的低成本路线，Meshy 或现成模型适合提供试装壳，Blender 适合清理骨架、拳姿和材质，Godot 负责战场、镜头和交互；大招前后留固定镜头位置／时长、普通招式有各自动作差异，比无限增加模型面数更有用。LibTV 可继续做参考视频切片和镜头节奏分析，但研究切片不会自动变成游戏内可用动画。此段是本项目制作建议，不是对《Demonschool》引擎或其资产流程的事实陈述。

## 第 11 号的真实差距及该保留的长处

对照第 11 号的[群战实际截图](../../../../../artifacts/c02_readability_v6/runtime/04-team-timeline.png)与[规则说明](readability-v6.md)：

| 问题 | 第 11 号目前怎样 | 从《Demonschool》学什么；我们仍要保住什么 |
|---|---|---|
| 决策入口 | 先理解落点、拳向、出手格、五拍表和两种时间制度；团队模板有时比人手决策更有效。 | 默认先点机体与意图落点，就在地图上得到情境攻击与结果；撤回再试。**保留**手动拳向、招式、预测位置和复杂计划为展开项，不让模板替玩家选最优解。 |
| 画面焦点 | 顶部两条说明、每机名牌／血条、红线与右侧五拍同时可见，地图和动作被挤小。 | 规划时显示必要格线及目标威胁；执行时退掉说明和表格，只留下必要血量与结果。**保留**机体本体、不同拳法和大招特写的价值。 |
| 协作因果 | “双机接力”已经能表现先推后打，但要玩家读懂顺序、限制和失败条件，结果仍偏文字。 | 第一个推位落点形成“队友可接”的地图邀请；点队友时直接显示它赶到的格子、能击中的格子、会多花的资源及其失败条件。**保留**第 11 号的真实位移／障碍／同拍判定，绝不做无条件连击倍率。 |
| 敌人意图 | 轮首承诺与分支情报存在，但直线、名牌和五拍说明需要玩家翻译。 | 让敌机正在指向的机体、压迫格、行动可能分支贴在战场上。**保留**白鸢预测、读招成长和未知分支；不要照搬全知、零误差的纯谜题。 |
| 关卡目标 | 破阵、突围、遭遇战已有不同规则；视觉舞台与敌型仍近似。 | 每关一句可读目标 + 一个会改变站位／时机的场地题目；同一战斗规则服务“保护、引诱、开路、阻止”等任务。**保留**名场面与玩梗导致的特殊结果，避免把非战斗任务做成繁琐工程操作。 |
| 美术生产 | 3D 基础已经能打，普通招式区分和场景冲击力不足。 | 用场景色光、不同机体体态与动作、关键接触时的运镜构成差异；人物肖像仅在剧情／能力时上场。**保留**可替换的 Godot 3D 机体路线，不因这个参考推翻引擎。 |

**不宜照搬的部分。** 它有明确的谜题／评级导向；P31、P40 的玩家仍在长时间调试最优落点，甚至大段思考后只换来数秒执行。如果我们把每场都做成“找唯一最高分解”，会重新落入用户已经指出的多米诺搭建疲惫。主创也承认角色普通招式有重合，各角色主要靠特殊招式和气质区分；超 GAG 的机体身份、拳路和“这一拳”的文化梗需要比它更强的动作差异。[主创访谈](https://www.rpgfan.com/feature/demonschool-interview-brandon-sheffield/)只说明原本意图，视频说明实际高复杂度关仍有操作／理解成本。视频里主要是固定构图，我没有找到能证明其自由转轴／平移手感的片段；我们的机体战场仍须保留已加入的镜头操作，并验证旋转后格子、光标和目标投影的准确性。[2026 年官方更新](https://steamcommunity.com/app/1900250/allnews/)持续修复战斗预览与执行不一致、对象重叠等问题，也提醒我们不能把复杂组合当作天然可靠的系统。

## 建议的下一轮：在保留版本的前提下做一版“空间指令”对照

这是**候选实验**，不是把 11 号直接替换，更不是取消单挑、逐机或团队模式。先分别验证“只是界面更会说话”和“操作规则确实更轻”两件事。

1. **同规则 UI 对照。** 保留第 11 号机制和局面，另开入口：默认只显示战场目标、已选机体的状态、小队可用资源及执行键。点机体后才显威胁和可达格，悬停／摇杆指到格上才显位移、命中、推位与不确定分支；五拍表改成可呼出的“详细推演”，战报战后可查。此步不改变伤害、时序或敌人算法，才能辨认纯表达收益。
2. **情境指令原型。** 在同样的三种局面中，普通攻击采用“选择机体→选择目的格或目标格→地图直接预览／提交”；招式、拳向、精神指令保留为有意义时展开的修饰。计划可连续撤回。推位刚好创造后拳机会时，地图上出现可点击的“接这一下”，而不是要求玩家先打开全队表。真正执行仍按既有结果判定；预演不承诺未知分支的成功。
3. **呈现一条有分量的连锁。** 在木桶街 1v1、三机对多机、非战斗开路／保护目标各做一题：先看敌情／环境，再让一个动作改变另一人的机会，执行后用机体姿势、位移轨迹、着点、接触和短镜头还原因果。普通招式必须有辨识度，大招特写保留。剧情／吐槽根据**实际使用过的招式与结果**触发，避免“天冲拳用了，台词还说没用”的旧错误。
4. **玩家测试决定取舍。** 用相同初始状态和任务，分别试玩第 11 号与新入口；记录完成第一条有效指令所需时间、主动撤回次数、达成一次双机连锁所需操作、是否能说清危险区与因果、是否愿意再试第二种打法。脚本测试只能验证确定性和 UI 不撒谎，不能代替玩家说“好玩”。如减少点击后仍只剩求解器，就要改关卡收益与身体反馈，而不是继续把表格折起来。

下一步最值得动的是 **规划视图／战场视图的分工，以及“点一格发生什么”的情境预览**。美术和镜头以它为中心服务：玩家的预判在执行时兑现，动作才有奖赏感。第 11 号底层读招、双机接力、分支情报、同拍规则是有用的资产，不因找到更好参考就清零。

战斗与非战斗任务可以共用一条底层事件语法：**行动者、到达位置、作用对象、所改变的状态、触发条件、成本与现场反馈**。战斗时可以是“推开敌机→露出侧面→队友接拳”；任务时可以是“压住门→通路出现→队友护送目标通过”。玩家仍然只需指出对象和去处，系统在地图上预览结果；我们应避免把“支撑、承重、搬运”的工程小动作拆成多次重复点选。这是针对本项目的候选设计，不是声称《Demonschool》已经实现了同一种非战斗关。
