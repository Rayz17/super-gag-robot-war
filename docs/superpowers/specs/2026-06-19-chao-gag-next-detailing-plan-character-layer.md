# 《超GAG机器人大战：万机残响》下一阶段细化计划与参战人物层审计 v0.1

> 本文回答两个问题：第一，现有文档暴露出了哪些结构问题；第二，下一步应该如何从“机体/作品投射池”推进到“有名字、有关系、有梗点、有跨作品互动的人物层”。

## 1. 当前文档状态

现有核心文档已经完成四层内容：

| 文档 | 已解决 | 未解决 |
| --- | --- | --- |
| 游戏框架设定 Bible | 世界观、G.A.G.、机魂、群星合唱体、玩法支柱、技术路线 | 缺少参战人物群像的具体名单和人物互动表 |

结论：我们已经有了“机器人大战的舞台”和“参战作品候选”，但还缺“机器人大战的人”。没有这一层，玩家只能看到机体梗，无法获得 SRW 最重要的角色化学反应。

补充进展：人物层 v0.1 已拆出结构化数据，剧情场景层也已推进到 [剧情线场景扩写 v0.1](./2026-06-19-chao-gag-storyline-scene-expansion.md) 和 [剧情数据说明](./data/story/README.md)。当前后续重点从“人物梗点从何而来”转向“反派个人戏、支线隐藏话和 Demo 对白级脚本如何落地”。

## 2. 暴露出来的问题

### 2.1 下一步优先级冲突

不同文档里的下一步目前有三种说法：

- 商业蓝图建议拆 `chapters.tsv`、`roster_packages.tsv`、`stage_crossovers.tsv`、`units.tsv`、`pilots.tsv`、`gag_hooks.tsv` 等 11 张表。
- 参战候选储备建议先做 `roster_candidates.tsv` 和 `crossover_reaction_matrix.tsv`。
- 参战 Bible 建议先做 `roster_packages.tsv` 和 `stage_crossovers.tsv`。

这些都对，但缺少排序。正确顺序应改为：

1. 先做 `character_archetypes.tsv` 和 `pilot_cast.tsv`，确定人物层。
2. 再做 `roster_packages.tsv`，确认每个参战包承载哪些人物关系。
3. 再做 `gag_hooks.tsv`，把梗点绑定到人物、关系和战斗触发。
4. 再做 `stage_crossovers.tsv`，让每话的跨作品互动有具体角色可说话。
5. 最后做 `units.tsv` 和数值/美术规格。

原因很简单：机战的爽点不是“某台机体在场”，而是“某个角色驾驶某台机体，在某个价值冲突里和另一个角色说出只有他们能说的话”。

### 2.2 参战规模口径不一致

参战 Bible 仍写“24 个核心包 + 8 个隐藏包”，候选储备已经升级为“32 个核心包 + 12 个隐藏包 + 16 个图鉴/NPC/敌方王牌包”。需要统一：

- **策划储备口径**：32 + 12 + 16。
- **商业版首发目标口径**：24 到 32 个核心参战包，按制作能力裁剪。
- **垂直切片口径**：6 个参战包，验证人物、机体、梗点、战斗和剧情联动。

后续所有表都应保留 `scope` 字段：`demo`、`core`、`secret`、`npc`、`dlc_pool`。

### 2.3 主角团过强，参战人物层过弱

目前主角团有生活面、价值面、关系面、长弧线；参战角色只有“代表角色”一列。这会导致一个问题：主角团像真实角色，参战人物像标签。

修正原则：

- 每个核心参战包不只配 1 个角色，而是配一个**人物组**。
- 每个人物组至少包含 4 类角色：主驾驶/核心 AI、宿敌或对手、支援/整备/舰桥、生活关系锚点。
- 重要参战包还要有粉丝化身、企业化身、作者化身或现实世界对应者。

### 2.4 人物梗点尚未拆源

现在的梗点多来自机体和名场面，例如合体、同步率、红色更快、时间错配、审批大招。人物梗点应单独拆出来源：

| 梗点来源 | 说明 | 游戏内转译方式 |
| --- | --- | --- |
| 人物原型梗 | 逃避少年、红面具、热血笨蛋、冷白少女、舰长妈妈、战争转学生、失败父亲、冷幽默 AI | 改成原创人物性格、习惯、关系创伤 |
| 关系结构梗 | 父子不理解、宿敌互照、三角恋、师徒传承、双人共感、作者与角色、公司与机魂 | 变成关系共鸣、说得条件、离队/归队事件 |
| SRW 系统梗 | 说得、隐藏加入、援护台词、同作品补正、精神指令、合体攻击、后继机、换乘、BGM 覆盖 | 变成轻量玩法和特殊对话触发 |
| 玩家社区梗 | 名台词二创、弹幕、梗图、空耳、剧情争议、名场面反转 | 只保留结构和语气，不照搬原句 |
| 制作生态梗 | 监督风格、机设癖好、作画 Pose、腰斩、重制、剧场版补完、商品化争议 | 变成作者遗迹、原画修罗场、模型厂商支线 |
| 模型商品梗 | 胶价、限定、重涂、补件、预购、官图欺诈、隐藏水口、魔改 | 变成模型圣地和企业/平台剧情 |
| 现实机器人梗 | 发布会演示、摔倒、后空翻、开门、进厂打工、PPT 承诺、训练数据 | 变成现实机魂的笨拙尊严 |
| 中文童年梗 | 国产机器人动画、儿童频道、页游、玩具广告、地方化配音记忆 | 变成小镇 NPC、隐藏机体和生活喜剧 |

人物梗点不能只是“他说了一句像原作的话”。它必须满足三条：

- 玩家能 get 到原型。
- 法务上不是复制表达。
- 在剧情里改变关系、战斗或选择。

### 2.5 梗点压过人物的风险

候选池列了很多高热梗，但梗一旦不绑定人物，就会变成廉价联想。

控制规则：

- 每个梗点必须绑定一个角色伤口、价值冲突或关系变化。
- 一个角色不能只靠梗成立，至少要有一个反梗时刻。
- 高热梗必须设置代价。例如强制同步很爽，但会降低远星理解度；命令语很好用，但会增加操控债；照本宣科原典台词能加成，但会触发圣徒锁定。

### 2.6 数据表还缺“互动边”

现在我们有候选包，但缺“边”。机战味最强的不是节点，而是边：

- 红面具和黑棋王座谈“面具是否让人自由”。
- 逃避少年和双人驾驶员谈“同步是不是暴力”。
- 冷幽默 AI 和现实小机器人谈“机器如何安慰人”。
- 魔神整备孙女和模型修复师谈“玩具是否也有灵魂”。
- 失败父亲和迟到英雄谈“错过的人还能不能修复关系”。

下一阶段必须建立 `character_interactions.tsv`，专门记录这些边。

## 3. 新的下一阶段目标

下一阶段目标不是继续扩世界观，而是完成**参战人物层 v0.1**。

交付物：

1. `character_archetypes.tsv`：人物原型、梗点来源、法务距离、可变形方式。
2. `pilot_cast.tsv`：首批参战人物名单，含原创名、内部锚点、所属参战包、角色定位、机体关系、长弧线。
3. `character_interactions.tsv`：人物之间的跨作品互动边，说得、援护、吵架、感情、宿敌、师徒。
4. `gag_hooks.tsv`：人物梗点触发条件、玩法效果、风险备注。
5. `chapter_character_matrix.tsv`：每章登场哪些主角团、参战角色、反派和 NPC。
6. `demo_character_slice.tsv`：垂直切片只选哪些角色，如何证明人物层成立。

## 4. 参战人物包规格

每个核心参战包必须拆成一个人物包。标准字段如下：

| 字段 | 说明 |
| --- | --- |
| `package_id` | 所属参战包，例如 R03 白舰纪元 |
| `internal_anchor` | 内部投射锚点，只给团队看 |
| `public_name` | 游戏内原创人物名 |
| `role_type` | 主驾驶、宿敌、支援、舰长、整备、平民、AI、作者、企业、粉丝、隐藏 |
| `unit_link` | 关联机体或系统 |
| `meme_sources` | 人物梗点来源，按原型梗、关系梗、SRW梗、社区梗等分类 |
| `daily_face` | 日常生活面 |
| `wound` | 角色伤口 |
| `belief` | 他相信机器人是什么 |
| `arc` | 长弧线 |
| `crossover_targets` | 最应该互动的其他人物 |
| `route_function` | 加入、离队、隐藏、说得、结局、支线 |
| `legal_guardrail` | 不能碰的原作表达边界 |

## 6. 人物梗点生成公式

每个人物梗点按五步生成：

1. **抽原型结构**  
   例如红面具不是某个具体角色，而是“戴面具的宿敌/导师/政治身份/逃避自我”的结构。

2. **抽玩家共同记忆**  
   例如红色更快、修正掌、宿敌单挑、身份谜、名场面登场。

3. **放进本作价值冲突**  
   在《超GAG》里，红面具要讨论的不是原作复刻，而是“面具能不能保护一个人不被 G.A.G. 模板化”。

4. **绑定战斗或关系触发**  
   红面具与黑棋王座同场时触发“面具论”；与白舰少年同场时触发宿敌说得；与企业档案官同场时触发身份合规审查。

5. **设置反梗或代价**  
   红色移动加成会提高燃料消耗；面具隐藏身份会降低同伴信任；宿敌单挑可能导致撤退目标失败。

这样梗点才会变成游戏体验，而不是引用。

- `character_interactions.tsv`
- `crossover_reaction_matrix.tsv`

优先做 60 条互动边：

- 20 条战前对话。
- 15 条援护/合体/特殊战斗台词。
- 10 条说得/临时敌对。
- 10 条船内日常。
- 5 条终局回收。

验收：

- 每条边都回答：他们为什么有话可说？这次对话改变什么？

### 第4步：人物梗点表

产出：

- `gag_hooks.tsv`

字段：

- `gag_id`
- `character_id`
- `package_id`
- `meme_source_type`
- `trigger_condition`
- `surface_joke`
- `deeper_function`
- `gameplay_effect`
- `legal_guardrail`

验收：

- 梗点不以“复读名台词”为合格。
- 每个梗都要有剧情功能或战斗功能。

### 第5步：章节人物装配

产出：

- `chapter_character_matrix.tsv`
- 重写第1到第5章的人物登场表。

验收：

- 每章至少有 3 个参战包人物发生跨包互动。
- 每章至少有 1 个非主角团角色获得生活面或关系弧线推进。

### 第6步：Demo 人物切片

产出：

- `demo_character_slice.tsv`
- 90 分钟 Demo 的人物名单、登场顺序、梗点触发、战斗台词和情感回收。

建议 Demo 人物：

- 主角团：纪存、唐胶、陆衡、七海。
- 参战人物：兜灯、旧守护者、豪司、奥柏、查仔、跌跌。
- 反派/NPC：企业回收官、展会孩子、现实机器理性派代表。

验收：

- 玩家在 90 分钟内能感到：这不是原创队伍孤军奋战，而是一个机器人文化群像正在聚集。
