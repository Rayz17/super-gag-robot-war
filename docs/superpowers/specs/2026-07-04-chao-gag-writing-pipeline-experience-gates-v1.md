# 《超GAG机器人大战》写作工作流体验门禁迁移 v1.0

状态：工作流与canon迁移说明。不是剧情正文，也不是台本。

## 背景

V28 C01-C03 证明 packet-first ELO 可以防止漏字段、漏账本和多话混写，但也暴露出新的问题：字段完整不等于故事好看。前三章已经能讲清万机馆、模型街、原型工房、证词和授权边界，却仍可能让玩家感觉“设定不错，但不像一款机器人大战开局，也没有立刻想打下一章”。

因此 V29 以后，写作工作流需要把“玩家体验承诺”提升为门禁，而不是留到最终润色。

## 迁移原则

1. **事实canon之外，新增体验canon。**  
   角色、机体、场景、首登时点仍由canon约束；但开局必须提供机战爽感、关系钩子、宏大阴影和继续游玩动机，也成为可查询的canon要求。

2. **pipeline 不只查字段，还要查读感。**  
   一话即使有机体、玩法、关系、敌方收益，也可能失败。失败原因可能是没有玩家钩子、没有PV级画面、关系像账本、宏大线缺席，或抽象议题没有转化成戏剧动作。

3. **Episode Loop 增加 C01-C03 开局试玩审查。**  
   第三章后必须专门审查前三章是否足以作为试玩开局，而不是只做普通 prefix review。

4. **输出分成开发包和可读稿。**  
   Episode Packet 是制作源稿；Reader Synopsis 是给用户和编剧连读判断故事魅力的稿层。问“有意思吗”时，不应只读 packet 字段。

5. **全剧机体/IP素材必须和开局钩子池分离。**  
   C01-C03开局钩子池只能补关系、PV场面、异常阴影和锚件。全剧参战机体、IP投射、话级机体密度必须查全剧参战机体/IP映射素材池 v0.2、`v29_roster_bible_reserve_backfill_pool_v0_1.tsv`、`v29_roster_ip_first_appearance_candidate_pool_v0_1.tsv` 和 V26 两张矩阵。参战Bible/Reserve回填池优先提供主机体、宿敌、后继机、隐藏机和代表性支援单位，并携带IP母题、剧情映射、名场面和台词锚点；首登候选池补足规则机、场景巨机、敌方模块和功能单位。模型盒、展签、框体、维修单、说明书、证词展台不计入机体密度。

6. **每话必须有“首次出现”的IP映射机体/单位。**  
   “新增出现”只统计本次写作运行中第一次出场；旧机复出、常规支援复出、同一机体再次上场，只能写入 `repeat_returns_not_counted`，不能冒充新增。每话至少 1 台、默认 2 台首次出现的 IP 映射机体/机体单位/敌方模块/场景巨机；除过场/纯经营轻话外，至少 1 台优先来自参战Bible/Reserve回填池的参战包级候选。重点话目标 2-4 台。同一机体只有在出现独立命名的新形态、新武装、新驾驶/支援关系、新合体位置或新玩法功能时，才可按“新形态”再计一次。候选池只提供可选素材，不规定每话固定出场名单。

7. **审稿角色升级。**  
   子agent/审稿角色除 showrunner、mecha、gameplay、relationship、protagonist、canon_asset 外，还要加入机器人动画/PV监督、商业开局制作人、宏大谜团监督和玩家兴趣代表。

8. **真实证词进入素材层，但不替代机器人大战承重。**  
   真实机器人/模型/游戏爱好者案例可以直接作为万机馆证词和现实共鸣使用，例如“千寺狐/牛牛与母亲接力模型零件订单”；但 direct 用法必须记录来源、使用模式、敏感边界和发布前授权/署名/特别鸣谢复核。真实证词负责让玩家相信热爱曾经被人认真生活过，不能替代参战机体、IP名场面、战斗玩法、主角成长或原创人物关系。

9. **顶层价值必须拆成可演出的价值轴。**  
   “机器人文化值得被承认”太宽，容易写成口号。V31后写顶层命题、远星、索引、开馆权、真实证词、终局或体验承诺板时，先查 `robot_culture_value_axes_v0_1.tsv`。粗糙译本共存、热爱责任、非人之物尊重、反唯一正确模板、小物件文明尺度和不齐声文明语言都必须被转成场面、玩法、敌方误用和角色选择；关键话若只剩一句升华，应回到 Pressure Board 重建。

## 新增体验门禁

每个关键 episode 至少回答：

| 门禁 | 通过标准 | 不通过症状 |
| --- | --- | --- |
| 读者/玩家钩子 | 本话结束后有具体继续动机：机体、关系、谜团、危险、奖励或路线后果 | 只写“主题推进”“进入下一话” |
| PV级机体画面 | 有能剪进预告的机器动作、出击、变形、防御、失败、觉醒或地图尺度变化 | 只有锚件、展签、变量表或概念 |
| 机体密度分层 | 至少两项可计入机体/单位/模块/场景巨机曝光，锚件另列 | 把模型盒、框体、展签、维修单当机体 |
| 首次出现IP机体 | 本话至少1台、默认2台首次出现的IP映射机体/单位/敌方模块/场景巨机，并明确回填池/候选池来源行和本次运行首登状态 | 用旧机复出、支援复出、锚件或展签冒充新增；把候选池误当逐话固定排班 |
| 参战包级承重 | 除过场/纯经营轻话外，本话新增中至少1台优先来自参战Bible/Reserve回填池，且其IP母题、名场面或台词锚点进入剧情/玩法 | 连续使用功能模块、规则机、场景机关填充，玩家看不到主机体、宿敌、后继机、隐藏机或代表性支援单位 |
| 真实证词边界 | 使用真实公开案例时明确case_id、来源、使用模式、具体物件、敏感边界和发布前授权/署名复核；不直接使用时可降级为虚构化现实母题 | 把真实悲剧当催泪按钮；让现实人物成为战斗单位；没有来源、授权复核或尊重边界；用真实故事替代机体/IP和主角行动 |
| 顶层价值场面化 | 查 `robot_culture_value_axes_v0_1.tsv`，记录本话选用或跳过理由；选用后有场面、玩法、角色选择、机体动作、敌方误用和后续债务 | 只写“共同语言”“热爱值得承认”“机器人文化有意义”等结论；价值轴没有改变战斗、关系、敌方收益或终局状态 |
| 关系情绪事件 | 成年/主角团关系出现误会、吸引、吃醋、体谅、牺牲、救场、伤害或危险选择 | 只有权限、水印、债务、共同责任 |
| 宏大阴影 | G.A.G./索引/远星/旧灾变/万机馆隐藏尺度以可见事件出现 | 只有后期名词或背景说明 |
| 议题转戏剧 | 授权、证词、标签、价格、公共信托等议题变成人、机体、地图、损失、救援、胜利或敌方收益 | 像策展理念汇报 |

## C01-C03 开局试玩审查

完成 C03 后必须写 `reviews/C01-C03-opening-arc-review.md`，或在 C03 prefix review 中加入同等章节。

审查问题：

- 如果试玩停在 C03，玩家为什么会想继续 C04？
- 前三章是否证明这是机器人战棋/机战游戏？
- 至少三张 PV 级机器人画面是什么？
- 哪段成年/主角团关系已经有牵引力？
- G.A.G./索引/远星/旧灾变是否形成更大阴影？
- 是否已有可连续阅读的 Reader Synopsis，而不是只靠 packet 字段？

如果结论是“设定完整但不够抓人”，不能直接推进 C04。必须开回归票据、做 C01-C03 趣味性增强补丁，或明确标为用户审稿决策。

## 使用顺序

1. 写或重写一话前，先查 canon 和体验canon。
2. 组织 Context Pack 时必须先引入全剧参战机体/IP映射素材池 v0.2、`v29_roster_bible_reserve_backfill_pool_v0_1.tsv`、`v29_roster_ip_first_appearance_candidate_pool_v0_1.tsv` 和 V26 两张矩阵；C01-C03开局钩子池只作为关系、PV场面、异常阴影和锚件辅助。
3. 写模型街、原型工房、现实机器、迟到回信、远星展、终局开馆或现实共鸣泪点时，同时查 `real_world_resonance_cases_v0_1.tsv`。若使用RWR001这类真实案例，packet 和 ledger 都要写明 `direct_with_attribution_review`、来源和敏感边界；若不适合直接使用，改用 `inspired_or_fictionalized` 母题。
4. 写顶层命题、远星、索引、开馆权战争、终局或本话主题升华时，同时查 `robot_culture_value_axes_v0_1.tsv`；packet 必须记录选用或跳过理由，选用后写入 `robot_culture_value_axis_ledger`。
5. 生成 Episode Packet 时填入体验字段。
6. 子agent审稿时至少覆盖体验角色。
7. 章节组装后生成 Reader Synopsis 或确保章节稿可连续阅读。
8. C03 后运行 Opening Arc Review，再决定是否推进 C04。

## 禁用方式

- 不得把“以后会补机体/关系/宏大感”当成前三章通过理由。
- 不得把锚件、模型、展签、UI表格当成真实机体密度。
- 不得让功能模块、规则机和场景机关长期替代参战包级主机体、宿敌、后继机、隐藏机或代表性支援单位。
- 不得把旧机常规复出、重复支援、二次露面写成“本话新增机体”；这些只能列入 `repeat_returns_not_counted`。
- 不得用“权限、水印、债务、共同责任”替代感情戏。
- 不得让 G.A.G./索引/远星只作为后期名词。
- 不得让用户只看开发 packet 判断故事是否有趣。
- 不得把真实人物的离世、家属接力、遗物和订单写成狗血消费；不得让现实证词抢走虚构角色的行动责任；不得在未记录来源和发布复核时直接使用真实案例。
- 不得把顶层价值当作末尾升华句；不得机械给每话贴价值轴标签；不得让“共同语言”退化为统一口号、远星盖章认可或全员大合唱。
