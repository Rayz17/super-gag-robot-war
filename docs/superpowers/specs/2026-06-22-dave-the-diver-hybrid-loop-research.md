# 《潜水员戴夫》混合玩法循环调研 v0.1

> 本文目的不是把《潜水员戴夫》的题材、职业或具体玩法搬进《超GAG机器人大战》，而是拆解它为什么能把探索、经营、小游戏、任务、养成和剧情塞进同一款游戏里仍然成立。  
> 结论将进入 [多元游玩体验策划](./2026-06-22-chao-gag-hybrid-play-experience-design.md) 和 `data/gameplay` 结构表。

---

## 0. 摘要

《潜水员戴夫》的关键不是“玩法很多”，而是它有一个极清楚的回流结构：

```mermaid
flowchart LR
  A["白天主动探索<br/>风险、采集、任务、谜题"] --> B["获得素材 / 情报 / 新角色"]
  B --> C["夜间经营<br/>菜单、服务、客流、收益"]
  C --> D["升级装备 / 解锁区域 / 推进关系"]
  D --> A

  B --> E["短小游戏 / VIP需求 / 支线系统"]
  E --> C
  E --> D
```

玩家在一个时段里只处理一种压力：白天探索面对风险和容量限制，夜晚经营面对节奏和效率压力。大量小游戏存在，但每个小游戏都很短、很好懂，并且要么服务任务，要么服务经营，要么服务角色关系。真正可借鉴的是这三点：

1. **双主循环**：主动探索负责拿资源，经营/整备负责把资源变成钱、关系、升级和下一次探索能力。
2. **轻量多玩法**：小游戏不追求成为完整独立游戏，而是作为剧情动作、任务仪式或资源转换器出现。
3. **内容回流**：每个新系统都必须回到主循环，不能只是炫技式插入。

对《超GAG机器人大战》的转译是：

```mermaid
flowchart LR
  A["残响域 / 城市 / 展馆探索"] --> B["零件、资料、机魂碎片、证据"]
  B --> C["万机馆开馆 / 整备 / 策展"]
  C --> D["资金、信任、机体状态、战斗修正"]
  D --> E["SRPG关卡"]
  E --> F["战后记录、角色关系、路线变量"]
  F --> A
```

SRPG仍然是主要冲突解决器。多玩法层的职责是让章节之间有生活、有准备、有荒诞的机器人文化细节，并把“梗点”变成可操作的小事件。

## 2. 《戴夫》的结构拆解

### 2.1 白天探索：主动风险与容量压力

白天潜水段可以理解成实时探索/采集/轻动作的混合体。它的核心压力不是复杂连招，而是：

- 玩家要在有限氧气、背包重量、敌对生物和路线长度之间取舍。
- 每次下潜都有明确目标，但地图和素材让玩家愿意临时绕路。
- 探索结果不是抽象货币，而是晚上能直接被看见、被卖出、被评价的食材。
- 装备升级会改变下一次探索的边界，例如更深、更久、更安全、更高价值。

这说明“动作探索”不一定要做成硬核平台跳跃或格斗。只要有可读风险、短期目标、容量限制和回流收益，就能形成足够强的行动感。

### 2.2 夜晚经营：把资源变成戏剧和经济

夜间经营段把白天的结果转换成：

- 收益：钱、评价、解锁。
- 角色关系：客人、厨师、员工、VIP 和支线角色。
- 成长目标：升级菜谱、雇佣员工、提高服务效率。
- 压力切换：从探索风险变成服务节奏。

它的妙处是“换心流”：玩家白天紧张地拿素材，晚上忙着把素材兑现。两个段落互相解释对方的意义。

### 2.3 支线系统：缓解压力而不是抢主菜

鱼场、农场、派遣、收藏、宠物式养成、小游戏、VIP任务等系统不需要都很深。它们主要承担四种功能：

1. **缓解重复劳动**：稳定提供一部分素材，减少玩家必须反复刷同一区域的压力。
2. **制造角色牵引**：新 NPC 以一种系统需求进入玩家生活，而不是只在剧情里说话。
3. **提供短期目标**：今天做完这件小事，晚上就能看到一点变化。
4. **让世界变宽**：玩家感觉自己经营的是一个不断扩大的生活圈。

### 2.4 小游戏：一口吃掉的变奏

《戴夫》的小游戏密度很高，但多数小游戏遵循三条规则：

- **短**：通常是一段任务、一场服务、一段演出，而不是永久替代核心玩法。
- **明确**：玩家一眼知道输入是什么，胜负由少量规则决定。
- **有上下文**：小游戏来自某个角色、某个任务、某个菜谱、某个海域谜题或某个奇怪日常。

这对《超GAG》尤其重要。机器人文化的梗点很多，不能都变成对白。正确做法是让梗点变成短动作：修模型、校准同步率、审批合体、护送量产机、抢救旧录像、阻止封存流程。

### 2.5 玩法模块盘点

| 模块 | 在《戴夫》中的作用 | 设计价值 | 《超GAG》对应转译 |
| --- | --- | --- | --- |
| 实时探索/采集 | 下潜、移动、捕捞、规避危险、带回素材 | 给玩家主动性、风险和路线选择 | 残响域深潜、城市废墟扫描、旧黑匣子资料回收 |
| 容量/氧气限制 | 限制下潜时长和携带收益 | 让每次探索有取舍，而不是无限搜刮 | 信号氧气、机魂噪声、热量、背包容量 |
| 夜间经营 | 把白天素材变成收入、评价和升级 | 让资源有可见的社会回响 | 万机馆开馆、策展、接待、留言、赞助和清算检查 |
| 装备升级 | 改变探索深度、效率和安全边界 | 形成下一次行动的期待 | 机体整备、工具升级、扫描器、展舰设施 |
| 鱼场/农场/派遣 | 稳定产出素材，降低重复劳动 | 扩展生活圈并缓解刷取压力 | 展品养护、机魂稳定室、支援小队派遣 |
| 角色/VIP任务 | 用短任务让 NPC 进入主循环 | 让任务和系统服务角色记忆 | 参战包个人事件、隐藏机体支线、清算白名单事件 |
| 解谜/机关 | 作为海底谜团和区域推进 | 改变节奏，给玩家“发现”感 | 旧影像修复、索引深潜、作者遗迹分镜排序 |
| Boss/动作挑战 | 提供局部高压和强记忆点 | 让主线有身体性冲突 | 轻格斗共鸣、巨大化灾害避险、同步压差危机 |
| 收藏/图鉴 | 把反复行动沉淀为完成感 | 让世界看起来可持续探索 | 战后剪报、机魂图鉴、展品档案、留言墙 |
| DLC式扩展 | 新区域、新村庄、新餐厅、新农场和新装备继续扩张循环 | 证明混合玩法能延展，也提示系统膨胀风险 | 商业版可逐章扩展，但首版必须先锁模板池 |

## 3. 可借鉴原则

### 原则 A：一主一副，不是十个主菜

《超GAG》不能把 SRPG、横版过关、格斗、经营、解谜、音游都做成同等体量。应采用：

- **主菜**：SRPG/战棋，负责关键冲突、角色觉悟、机体表现和章节高潮。
- **副循环**：万机馆经营/整备，负责资源转换、角色日常、成长和节奏缓冲。
- **变奏**：残响深潜、修复、谈判、节奏、轻格斗等，负责章节新鲜感和剧情动作化。

### 原则 B：每个小玩法都必须有输出契约

小玩法不是“好玩就行”，必须写清输出到哪里：

| 输出类型 | 例子 |
| --- | --- |
| 战斗修正 | 首回合护盾、保护目标耐久、敌方意图延迟、撤退路线提前开放 |
| 经营资源 | 资金、观众信任、馆藏热度、赞助额度、维修件 |
| 剧情变量 | 万机馆家感、企业信任、现实机魂信任、路线债、黑展柜共鸣 |
| 叙事许可 | 解锁说得台词、隐藏支援、临时合体、非致命胜利条件 |

如果某个小玩法没有输出契约，就该删掉或并入剧情演出。

### 原则 C：玩法换肤不如压力换型

《戴夫》最有效的切换不是“画面换了”，而是玩家压力换了：

- 探索段：路线、容量、风险。
- 经营段：时间、效率、菜单。
- 小游戏段：反应、判断、记忆、节奏。

《超GAG》的对应关系应该是：

- 残响深潜：信号、热量、背包、机魂噪声。
- 万机馆经营：展陈、客流、舆论、清算压力。
- 修复小游戏：零件顺序、稳定度、不可逆损伤。
- 谈判小游戏：证据、话术、风险标签。
- SRPG：站位、敌方意图、保护目标、资源承诺。

### 原则 D：用系统表现世界观

《戴夫》的海是“会产出”的，餐厅是“会回应”的。  
《超GAG》的万机馆也必须如此：

- 展品不是背景板，而是可修、可讲解、可被封存、可被抢救的对象。
- 机魂不是设定词，而是会影响修复难度、战斗援护、路线变量的系统状态。
- 观众不是路人，而是会给留言、投诉、捐赠、传播谣言和触发支线的压力来源。
- 清算部不是只会派兵，而是会用白名单、保险、版权、城市安全协议改变玩法边界。

### 原则 E：扩展要靠模板复用

《戴夫》能承受大量小玩法，是因为很多内容复用了基础输入：移动、瞄准、选择、服务、升级、短 QTE、对话选择。  
《超GAG》应该先做 8 到 12 个可复用模板，而不是为每章手写完全不同的游戏。

## 4. 不适合照搬的地方

| 《戴夫》做法 | 为什么不能照搬 | 《超GAG》替代方案 |
| --- | --- | --- |
| 寿司店经营 | 题材不对，且会抢走机器人博物馆的身份 | 万机馆开馆经营：策展、接待、舆论、赞助、封存压力 |
| 水下物理和鱼类生态 | 本项目没有海洋题材资产基础 | 残响域/资料层/城市废墟探索，用信号、热量和噪声模拟风险 |
| 大量一次性小游戏 | 制作成本高，容易像杂耍 | 少量模板，多章换叙事包装和规则参数 |
| 经营收入直接堆钱 | 机战项目若只堆钱，会削弱角色关系 | 资金只是资源之一，必须并列观众信任、机魂稳定、资料完整度 |
| DLC 式不断加系统 | 长线产品可以扩张，初版不能过早膨胀 | 商业版先锁 8 到 12 模板，垂直切片只做 3 个 |

## 5. 给《超GAG》的直接启发

### 5.1 “潜水”转译为残响深潜

玩家不是下海，而是进入 G.A.G. 的残响域、旧硬盘、展品记忆、城市摄像头碎片或机魂梦境。  
核心动词：

- 横版/俯视移动。
- 扫描残响点。
- 避开噪声、清算探针、过载热区。
- 在容量限制内带回零件、证据、台词碎片和机魂数据。

### 5.2 “寿司店”转译为万机馆开馆

玩家不是卖料理，而是开馆、策展和接待：

- 选择今日开放展岛。
- 安排角色当讲解员、维修员、安保或直播回应。
- 处理游客留言、投诉、赞助、媒体和清算检查。
- 把白天/战后带回的展品碎片转成展陈、升级和剧情信任。

### 5.3 “鱼场/农场”转译为展品养护和支援派遣

长期系统不应该逼玩家每天做重复劳动，而应提供缓冲：

- 展品养护：旧机体、模型、AI 核和录像带会缓慢恢复，产出稳定的小资源。
- 支援派遣：非出击角色去跑赞助、找零件、做社区修理、安抚观众。
- 机魂稳定室：用战后残响喂养机魂状态，影响援护、说得和隐藏加入。

### 5.4 “VIP任务”转译为参战包个人事件

每个参战包不只在战场上出现，也通过短玩法进入日常：

- 钢拳擂台：轻格斗/格挡反击小游戏，表达“失败父亲修复”。
- 勇气株式会社：审批合体/安全盖章小游戏，表达“勇气与流程”的笑点。
- 第0次站立：重心校准小游戏，表达现实机器的笨拙尊严。
- 原典圣堂：节奏打断/仪式截拍小游戏，表达粉丝爱与囚笼。

## 6. 设计风险

| 风险 | 表现 | 约束 |
| --- | --- | --- |
| 拼盘化 | 玩家觉得每章都在玩不相关的小游戏 | 每个小玩法必须写入 `hybrid_activity_catalog.tsv`，绑定故事用途和输出契约 |
| SRPG被稀释 | 关键冲突在小游戏里解决，战棋变成例行清怪 | 小玩法只改变战棋条件，章节高潮仍由 SRPG 或地图态事件承载 |
| 制作爆炸 | 每个梗点都想做专属玩法 | 先做模板，后做章节包装；一章最多新增一个新模板 |
| 数值失控 | 经营、探索、战斗各自产生资源，互相污染 | 资源分层：资金、维修件、信任、机魂稳定、资料完整度各有用途 |
| 节奏拖沓 | 玩家被迫每日清单化 | 所有非主线日常都可跳过或自动结算，手动游玩给更好结果但不锁主线 |

## 7. 调研结论

《潜水员戴夫》值得学习的不是某个小游戏，而是一种“宽内容、窄压力、强回流”的组织方法：

- 宽内容：题材、角色、任务和小游戏很多。
- 窄压力：每个时段只让玩家处理一种核心压力。
- 强回流：所有系统都回到探索、经营、升级、解锁和角色关系。

《超GAG机器人大战》的多玩法层应服务三件事：

1. 让玩家在战棋之外喜欢万机馆，觉得这里真的是一个会开门、会受伤、会被抢救的地方。
2. 让机器人文化梗点变成短动作，而不只是台词彩蛋。
3. 让 SRPG 关卡更有准备感和后果感，而不是每话剧情后直接开打。
