## 1. 一句话结论

《Into the Breach》的高级感不来自复杂美术，而来自“所有重要信息都贴在战场上，并且行动前能看见后果”。

它的 UI 核心不是面板，而是一套战斗语法：

```text
敌人先声明意图 -> 玩家查看地图后果 -> 选择单位 -> 预览移动/攻击/推拉/伤害 -> 承诺行动 -> 地图立即更新 -> 敌方按已声明顺序结算
```

这对《超GAG》非常关键。我们现在的 demo 仍然会像网页，原因不是“没有像素美术”，而是地图没有承担主要叙事和规则信息：敌人想干什么、我能阻止什么、我行动后会发生什么，都还太依赖文字。

## 2. 屏幕结构

《Into the Breach》的战斗画面是一个极强的“边缘 HUD + 中央地图”结构。

### 2.1 中央地图

中央地图占画面约七成，是绝对主视觉。地图通常是一个小型等距岛屿棋盘，边界清楚，不需要滚屏，不需要小地图。

关键点：

- 地图小，决策密度高。
- 地形不是装饰：水、山、森林、沙地、冰、建筑、电力设施都会改变规则。
- 建筑物是生命线，不是背景。官方页面明确强调 civilian buildings power your mechs，城市损伤就是总体生命线损伤。
- 敌人意图直接画在地图上：红色受击格、攻击箭头、目标标记。
- 玩家技能结果也画在地图上：伤害数字、推动方向、范围格、目标高亮。

### 2.2 左侧单位栏

左侧不是网页式角色列表，而是“本回合可操作棋子状态栏”：

- 三台机体竖排。
- 每台机体显示小头像/机体剪影、血量格、行动状态。
- 当前选中单位有明显黄框。
- 已死亡或失效单位直接灰掉，状态反馈非常硬。

对《超GAG》的启示：左侧应显示纪存、兜灯、豪司、唐胶的“机体状态小队列”，而不是右侧大段角色说明。它要承担战斗时的队伍读取功能。

### 2.3 左上行动按钮

左上角有大号 `End Turn`，旁边有 `Undo Move`、`Reset Turn`。

这几个按钮的价值很大：

- `End Turn` 是本回合的最终承诺，永远醒目。
- `Undo Move` 表示移动是可撤销的，降低试错成本。
- 攻击不可随意撤销，因此移动和开火在心理上被明确区分。
- `Reset Turn` 是有限资源，给玩家一次“我看错局面了”的保险。

对《超GAG》的启示：我们应该提供“撤销移动”，但不能撤销已经确认的攻击/cut-in；可以把 `Reset Turn` 魔改成“时间线复盘”“旧守护者回滚一次闭馆记录”。

### 2.4 顶部生命线

顶部是 `POWER GRID` 和 `GRID DEFENSE`。

这不是普通 HP 条。它把“城市/平民/基础设施”抽象成全局生命线，让每一次敌人打建筑都变成玩家心里的压力。

对《超GAG》的启示：

- 法务警报战不能只显示我方 HP。
- 顶部应有“留言墙完整度 / 观众安全 / 0号门锁 / 万机馆供电”之类的全局保护条。
- 这些条应比敌人 HP 更重要，因为玩家不是来清怪的，是来守住牵挂和秘密的。

### 2.5 右上任务栏

右上是极短任务信息：

- Victory in N turns.
- Bonus Objectives.
- 已完成目标直接划线或点亮。

它不解释世界观，不写长说明，只告诉玩家“这关怎么赢、什么是额外好结果”。

对《超GAG》的启示：右侧目标应该压缩成短文本，例如：

- 守住留言墙 4 回合。
- 阻止 0号门锁归零。
- 不让观众路线被封。
- 额外：让豪司在不破坏展柜的情况下击退回收框体。

### 2.6 底部当前单位卡

左下是当前单位/驾驶员/武器技能栏，右下是当前地形或对象 tooltip。

这很重要：底部区域只显示“当前焦点相关信息”，而不是常驻大说明。

对《超GAG》的启示：

- 左下：当前机体、驾驶员、HP/EN/SP、气力、武器/精神小图标。
- 右下：当前光标格的地形/物件/敌意图说明。
- 不要把剧情解释、档案文本、系统说明堆在战斗常驻面板上。

## 3. 地图表现

### 3.1 小棋盘高密度

《Into the Breach》的地图常见感觉是 8x8 左右的小岛。小不是简陋，而是让每个格子都重要。

小地图带来三个好处：

- 玩家一眼看完整局，不需要 UI 帮他“找目标”。
- 敌方意图、建筑、地形、单位站位能同时被看见。
- 每一步位移都可能改变全局结果。

《超GAG》当前战斗地图如果做成“大展馆平面图”，会天然稀释决策。更适合的做法是：每一场战斗发生在一个小型 set-piece。

例子：

- 留言墙前：7x7 或 8x8，中心是留言墙，左右是展柜，后方是观众撤离线。
- 0号侧廊门口：窄长棋盘，门锁/管线/消防门是关键格。
- 馆守Z脚边：2x2 巨型单位占位，玩家围绕其腿部和展台移动。

### 3.2 等距岛屿感

《Into the Breach》的等距小岛让地图像“一个可阅读的棋盘模型”。它的格子、边界、高低差、建筑轮廓都很清楚。

《超GAG》不一定要完全等距，但应学习这几点：

- 战斗场景必须有清楚外轮廓，不要像无限大网格。
- 地形 tile 要带主题：展柜、地砖、消防门、水渍、电缆、观众通道、封存线。
- 建筑和目标物要有体积，不是单纯图标。
- 可互动对象的位置要一眼看出。

### 3.3 敌方意图层

敌人不是“下回合突然行动”，而是先把要打的位置声明出来。

常见表现：

- 红色受击格。
- 箭头表示攻击方向。
- 目标格或目标单位高亮。
- 顶部 `Attack Order` 表示敌方结算顺序。

《超GAG》应把敌意图魔改为：

- 法务封存线：红白条纹覆盖格，下一回合封印该格武器/物件。
- 回收框体：箭头指向展品或留言墙，下一回合拖走/压碎。
- 灭火无人机：扇形喷雾区，能灭火但会损伤纸质留言。
- 清算部扫描器：锁定 0号门，进度条削减门锁。
- 舆论弹幕/版权函：影响机体武器名，导致“正式名称不可用”。

重点：意图必须画在地图上，右侧文字只是补充。

## 4. 操作特点

### 4.1 玩家回合是一道“解局题”

《Into the Breach》的敌人不是为了藏信息赢玩家，而是把攻击计划公开，让玩家用三台机体解开局面。

因此它的操作手感不是“走格子打怪”，而是：

```text
先读敌意图
再找最大威胁
再试移动/攻击结果
再用推、拉、挡、击杀、碰撞、地形改变来重排局面
最后按 End Turn 看结算
```

《超GAG》的战斗如果只让玩家“移动后攻击敌人 HP”，会浪费 Into the Breach 最值得学的部分。我们应该让每关有 2-4 个明确威胁，玩家用机体梗能力解除。

例子：

- 豪司：把法务框体打退一格，撞到消防门，解除留言墙攻击。
- 兜灯：给馆守Z降温，也能封住一格漏电地形。
- 唐胶：放模型胶带陷阱，让敌人攻击顺序延后。
- 纪存：改名解除封印，把“不可用武器”临时改成民间叫法。

### 4.2 预览比菜单更重要

《Into the Breach》不是先弹复杂菜单，而是把后果直接铺在地图上：

- 移动范围格。
- 攻击范围格。
- 伤害数字。
- 推动箭头。
- 被波及对象。
- 地形变化提示。

这正是我们当前 demo 欠缺的地方。我们的战斗预测窗口已经有雏形，但还需要地图层同步显示：

- 预计伤害数字浮在目标头上。
- 推拉方向箭头画在目标格旁。
- 被解除的敌意图变暗或打勾。
- 被误伤的展品/观众路线用警告图标闪烁。

### 4.3 撤销移动，锁定攻击

《Into the Breach》允许撤销移动，但攻击确认后进入不可撤销状态。这让玩家愿意探索空间方案，又对真正行动保持紧张。

《超GAG》应继承这个心理节奏：

- 选择单位后，移动到新格可以撤销。
- 打开攻击/精神/技能 forecast 时仍可返回。
- 确认攻击后进入 cut-in，不可撤销。
- 攻击后地图状态立即改变，敌意图同步更新。

### 4.4 反馈很短，但都有效

官方 GIF 和截图显示，《Into the Breach》的动画非常克制：单位短位移、攻击方向、命中闪烁、地形变化、状态更新。它不靠长演出，而靠每个反馈都服务规则。

《超GAG》要同时继承 SRW 的仪式感和 ITB 的清晰反馈：

- 普通攻击：短 cut-in 或地图内打击，不超过 1.5 秒。
- 关键武器/合体/名场面：进入大 pose cut-in。
- 所有攻击后都要回到地图，并立刻显示敌意图变化。
- 如果攻击很帅但玩家不知道解除什么威胁，仍然失败。

## 5. 与 SRW 的差异

不能把《Into the Breach》直接照搬进《超GAG》。

### 5.1 ITB 更像战术谜题

它强调确定性、短回合、少单位、小地图、清楚后果。

### 5.2 SRW 更像角色舞台

SRW 强调机体成长、驾驶员台词、武器演出、命中回避、援护、气力、特殊交战、章节剧情。

### 5.3 《超GAG》的融合方向

适合采用：

- ITB 的敌意图和保护目标。
- SRW 的机体/驾驶员/精神/气力/特殊台词。
- Wargroove/Advance Wars 的清晰像素战棋地图。

不适合采用：

- ITB 的极端低角色表达。
- SRW 的全灭清怪式冗长地图。
- 网页式右侧长说明面板。

融合后的目标循环应是：

```text
剧情给出牵挂
地图把牵挂放成目标物
敌人公开要伤害哪个牵挂
玩家用机体能力解除意图
攻击/援护/cut-in 给角色爽点
回合结束按意图结算
战后档案解释这场保护的意义
```

## 6. 对当前 demo 的直接改造建议

### 6.1 战斗画面重新分区

建议下一版战斗 HUD：

```text
┌──────────────────────────────────────────────┐
│ 万机馆供电/留言墙/0号门锁     清算顺序  回合 │
├───────┬──────────────────────────────┬───────┤
│ 小队列 │          小型战斗地图          │ 目标栏 │
│ HP/EN │   敌意图、范围、数字、箭头      │ 3条内 │
├───────┴──────────────┬───────────────┴───────┤
│ 当前机体/武器/精神     │ 当前地形/目标/预测摘要 │
└──────────────────────┴───────────────────────┘
```

原则：

- 地图至少占 65% 视觉注意力。
- 目标栏最多三行。
- 右下只显示当前格 tooltip，不写故事说明。
- 详细剧情回到对话/档案，不留在战斗常驻 UI。

### 6.2 战斗地图缩小

法务警报战建议从现在的展厅大地图改成 8x8：

- 中央偏左：留言墙，2 格宽。
- 下方：观众撤离线。
- 右侧：0号侧廊门。
- 左上：馆守Z脚边或展柜。
- 敌人从两侧进入，意图分别压留言墙、0号门和观众路线。

### 6.3 敌意图必须成为第一视觉

需要在地图层增加：

- 红白封存线 tile overlay。
- 攻击/拖拽方向箭头。
- 清算顺序编号。
- 被威胁目标的闪烁边框。
- 解除后意图变灰/碎裂。

### 6.4 Forecast 需要地图化

当前 forecast 不能只在面板里显示。

要增加：

- 目标上方伤害数字。
- 推拉箭头。
- “解除封存”图标。
- 误伤警告。
- 结果后的目标 HP/锁定值变化。

### 6.5 引入撤销移动

状态机需要区分：

- `selected`：选中单位。
- `previewMove`：查看可移动格。
- `movedPending`：移动后未行动，可撤销。
- `command`：选择攻击/精神/待机。
- `forecast`：确认前预览。
- `committed`：攻击/cut-in，不能撤销。

### 6.6 一场战斗的谜题目标

第一场不要设计成“打死两个敌人”。应设计成：

- 主目标：守住留言墙 4 回合，或击退执行封存的关键框体。
- 失败条件：留言墙完整度归零 / 0号门锁归零 / 观众路线被堵死。
- 奖励目标：不破坏展柜；不让法务扫描器读到0号门；豪司用推击解除一次封存线。

这样玩家会自然理解：战斗是谁打谁，为什么打，目标是什么。

## 7. 《超GAG》可借用的梗点机制

把机器人粉丝梗变成 ITB 式解局能力：

| 角色/机体 | ITB 式玩法 | 梗点表达 |
| --- | --- | --- |
| 纪存 / 策展指挥机 | 改名解除一个封存意图 | 民间叫法打败正式版权名 |
| 豪司 / 勇拳试作机 | 近战打退、撞击、保护建筑 | 超级系“先喊再打”的爽感 |
| 兜灯 / 工具支援机 | 修理、降温、给目标加护盾 | 维修工比驾驶员更懂机体 |
| 唐胶 / 拼装陷阱机 | 放置陷阱、胶带固定、延迟敌意图 | 模型玩家用胶水拯救世界 |
| 旧守护者 / 馆守Z | 巨型单位占 2x2，能挡线但会过热 | 老机体第一次站起来 |
| 七海 / 清算部 | 敌方意图 UI 的“礼貌威胁”播报 | 法务措辞变成攻击预告 |

## 8. 验收标准

下一版如果说“学到了 Into the Breach”，必须满足：

1. 玩家不看文字说明，也能看出敌人下回合要打哪里。
2. 玩家移动前能看到移动范围，移动后能撤销。
3. 玩家攻击前能看到伤害、推拉、误伤、解除意图。
4. 地图目标物比敌人 HP 更显眼。
5. 每回合都有一个“解局压力”，不是清怪拖时间。
6. 战斗 HUD 贴边服务地图，不能再让右侧长文本抢走视觉中心。
7. 攻击动画短，但地图结果必须立刻清晰。

## 9. 关键设计判断

《Into the Breach》真正值得学的不是“像素小人”或“等距地图”，而是它把 UI、规则、地图和目标压成了一个东西：

```text
地图本身就是 UI。
敌意图本身就是剧情压力。
预测本身就是操作说明。
保护目标本身就是情感目标。
```

《超GAG》要想从“网页式战棋 demo”变成“能卖的机器人粉丝向游戏”，第一优先级就是让万机馆战斗地图承担叙事和规则，而不是让说明文字替地图说话。

### 10.1 视频讲解强化了“地图可读性”

B 站讲解视频有弹幕、字幕和讲解遮挡，但即使这样，《Into the Breach》的战斗画面仍然能读出核心信息。这说明它的 UI 信息优先级非常强。

在样本 `video_02` 中，画面同时出现：

- 敌方攻击格：红色斜纹覆盖目标格。
- 伤害数字：大号数字直接贴在受击点。
- 单位血条：绿条在单位上方，不需要查面板。
- 建筑目标：城市建筑以立体 tile 形式存在，天然比普通地形显眼。
- 地形阻隔：山、水、建筑形成移动和攻击约束。

这证明“敌意图必须画在地图上”不是锦上添花，而是 Into the Breach 能被讲解视频、弹幕、压缩画质仍然读懂的根本原因。

### 10.2 讲解视频暴露了一个更重要的表达原则

视频字幕在讲“处在四个格子上的任何物种都会被秒杀”时，画面上正好出现红格、伤害数字和多单位站位。规则说明没有脱离画面，而是紧贴画面发生。

《超GAG》的任务讲解也应该如此：

- 不要在战前写长段说明“法务封存线会怎样”。
- 应该让七海播报一句“清算线将在下回合覆盖这四格”，同时地图上出现红白条纹封存格和编号。
- 玩家第一次看到规则时，规则就应该落在一个真实威胁上，例如留言墙、观众撤离线、0号门锁。

### 10.3 `video_04` 展示了最关键的 forecast 结构

样本 `video_04` 里，玩家行动前已经能看到：

- 我方单位高亮。
- 敌方红色攻击格。
- 橙色/黄色行动结果格。
- 大号伤害数字 `2`。
- 攻击/推击方向。
- 右侧目标栏保持极短，只显示胜利/奖励目标。

这是一种“地图化 forecast”。面板不是没有，而是让位给地图。

《超GAG》当前 forecast 如果只显示在右侧文字/面板，就还是会像网页。下一版必须把 forecast 拆成地图层符号：

| Forecast 信息 | 地图表现 |
| --- | --- |
| 伤害 | 目标头顶大号数字 |
| 推/拉方向 | 箭头从目标格指向落点 |
| 解除敌意图 | 红白封存格变灰或碎裂 |
| 误伤 | 展柜/留言墙/观众路线闪黄警告 |
| 击破 | 敌方单位出现骷髅/爆裂/灰化预览 |
| 资源消耗 | 左下武器格 EN/弹数减少预览 |

### 10.4 `video_03` 展示了管理界面为何不像网页

样本 `video_03` 切到机甲资料/整备界面。它不是 HTML 表单式列表，而是一个游戏面板：

- 左侧是机甲详情卡。
- 中央是生命值、移动力、经验和武器槽。
- 右侧是驾驶员头像与技能栏。
- 背景仍然是世界地图/区域选择，不是白底页面。

这对《超GAG》的管理界面很重要。移动格纳库不应该是“单位卡片 + 按钮列表”，而应该像一个机体舱位面板：

- 机体卡仍有焦点框。
- 武器/精神/部件用槽位表达。
- 驾驶员头像和机体剪影分栏。
- 当前任务地图或万机馆剖面作为背景，让整备仍然属于游戏世界。

### 10.5 `video_05` 和 `video_06` 展示剧情如何贴回地图

样本 `video_05` 是大 silhouette + 头像台词框，任务动词非常明确：“打开一个虫洞”。样本 `video_06` 随即回到地图，棋盘变暗、烟雾/空间效果覆盖目标区域，角色头像台词框悬在地图上。

这说明 Into the Breach 的剧情不是长篇解释，而是：

```text
一句任务动词 -> 地图出现异常 -> 角色短台词确认风险 -> 玩家进入操作
```

《超GAG》第一章可以直接借这个节奏：

```text
七海：清算部将在下回合封存留言墙。
地图：留言墙前四格出现红白封存线，清算顺序编号 1/2。
旧守护者：那样做会把未归档留言一起抹掉。
纪存：那就别让它走到下回合。
玩家获得操作权。
```

这样剧情、目标、敌意图和操作会连成一件事。

### 10.6 对下一版 Demo 的新增硬要求

结合 B 站视频观察，新增以下验收项：

1. 首次出现新规则时，必须同步在地图上出现一个真实威胁，不允许只弹说明框。
2. 战前剧情每段最多服务一个地图动词，例如“封存”“拖走”“开门”“降温”“撤离”。
3. 地图 forecast 必须能在视频压缩画质下读懂：颜色、数字、箭头、图标都要足够大。
4. 管理界面也要保持游戏壳：焦点框、槽位、头像、机体剪影、任务背景，不使用网页式卡片列表。
5. 剧情台词框可以悬浮在地图事件附近，让玩家知道这句话指向哪个格子/目标物。
