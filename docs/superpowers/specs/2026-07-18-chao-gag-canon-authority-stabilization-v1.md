# 《超GAG机器人大战》Canon权威层稳定化 v1

> 日期：2026-07-18  
> 状态：`implemented / validation_required_on_every_migration`  
> 目标：减少冗余、过时和冲突对创作的反向约束，同时保留全部可追溯历史。

## 一、为什么必须改

旧 Canon 不是单纯“内容多”，而是四类东西共用一个默认入口：

1. 已确认的角色、空间、机体和 Runtime 规则。
2. 当前创作工作稿。
3. 未通过的未来章节、50问题解法和场面候选。
4. 已替代版本、工作流、制作合同和图谱历史。

迁移前的主要症状：

- `entities.tsv` 548行中有464行使用 `needs_review`，同一状态同时表示“真候选”“已在当前章节出现但未清状态”“研究或工作流概念”。
- 默认 `canon-query C04` 同时检索 Canon、文档注册、节点、边、术语和Watchlist，输出约5234行。
- C04 v4尚未通过，却已被写进纪存、七海、白鸢等核心根条目和无状态的 Hook 表。
- C02/C03当前稿、V25/V31旧稿、V35.8合同和C04候选各自拥有一套“当前”措辞。
- 同一主体的角色ID、参战包ID和生命周期ID依靠备注解释，没有机器可读关系。
- Design Graph README仍把C04写成v2 `user_review_ready`，与唯一生产状态页冲突。
- 图谱有三处端点命名漂移；两条美术锁的来源路径已经移动。

结果不是信息更完整，而是任何写作会话都可能从海量命中中随机选中一套旧答案。

## 二、本次裁决

### 1. Canon采用四层权威

- `hard`：稳定身份、空间、容量、Runtime和已锁美术。
- `working`：C01-C03等已采用创作，以及当前可迁移设计。
- `candidate`：C04回嵌稿、未来章节、关系桥段、素材和未锁资产。
- `history`：旧Runtime、已替代场景、废弃别名和历史来源。

统一裁决写入 `data/canon/authority_manifest.tsv`，旧表内的 `status` 不再承担跨表权威判断。

### 2. 默认查询只返回当前 Canon

`scripts/canon-query.sh <query>` 现在只搜索 Canon 数据并返回 Hard + Working。设计图谱、候选和历史需要显式调用：

```bash
scripts/canon-query.sh candidate C04
scripts/canon-query.sh history V31-C01E03-BATTLE
scripts/canon-query.sh index C04
scripts/canon-query.sh audit C04
```

迁移后：

- 全部纳管记录：925。
- 默认 `C04`：6条当前关联，约119行；内容主要是C03交接、空间谱系锚和明确的旧排期风险。
- 候选 `C04`：113条，可显式取得五话场景、候选机体、关系Hook与机制。
- 默认查询不再返回图谱的数千条边和文档索引。

### 3. 根角色只保存稳定身份

纪存、七海、白鸢的根条目已退回截至C03成立的身份、欲望、能力边界和关系方向：

- 不再预先断言百相驾驶结果、十二切片、主铸井换根、手伤或正式战术席。
- C04具体机制保留在 `creative_candidate` 概念、五话场景和候选Hook中。
- 白鸢当前只会把分镜、传感、地形与机体数据整理为可讨论预演；真实动作仍由驾驶员、机体和工程链执行。
- 方舟T正式人格化出场不再错误锁在旧C04；C03折叠探测器明确不等于方舟T本人。

### 4. 重复ID改为显式关系

`identity_links.tsv` 当前记录：

- 跌跌角色身份与V35机体生命周期。
- 机器犬通用机体条目与生命周期。
- 影子陪练机通用候选条目与生命周期。
- 方舟T角色身份与参战包。
- 馆守Z旧ID到V35生命周期ID的废弃别名。

重复数据层可以继续存在，但不能再靠“读者应该懂”解释。

## 三、保留而未删除的内容

本次没有删除旧资料：

- 437条实体仍为Candidate，供未来章节、素材吸收和重构使用。
- 41条记录明确进入History。
- C04五话v4仍是唯一候选物理骨架，但没有升为Working。
- V16、50问题、IP/名场面/意难平和模玩生态研究继续由写作Pipeline与章节Pack调用，不进入默认世界实体查询。
- Design Graph仍保存全部文档、节点、边和Watchlist，只是不再冒充默认Canon。

## 四、仍需持续治理的风险

### P1：旧行内仍存在混合权威字段

例如展区覆盖表中的空间映射较稳定，`first_major_unlock`却可能随大纲改变。v1先把谱系覆盖、藏品关系和终端设计降为Working；后续若频繁冲突，应把“空间事实”和“章节排期”拆成两张表。

### P1：候选实体仍然过多

437条Candidate不再污染默认查询，但其中仍混有：

- 真正的世界/机体候选。
- 写作流程、版本合同和素材池入口。
- 旧版本概念的重复包装。

后续治理应按使用频率逐批迁出“创作材料目录”，不需要为本次迁移一次性删除。

### P1：美术锁大多尚未锁

116条美术记录中，仍有大量 `no_art_yet` 与 `needs_art_lock`。权威分层只防止候选美术反向锁故事，不会自动补齐资产设计。

### P2：图谱状态词仍很自由

图谱现有状态和关系类型是历史累积的开放词汇。v1只修端点和当前指针；若要进一步机器推理，应另做Graph Schema治理，不应再次把图谱状态塞进Canon权威。

## 五、维护流程

每次 Canon 迁移：

1. 修改源TSV或 `authority_overrides.tsv`。
2. 更新受影响的Current Canon Pack、生产状态页和图谱索引。
3. 运行生成器和校验器。
4. 仅在通过后让其他会话使用新结果。

```bash
python3 scripts/build_canon_authority_manifest.py
python3 scripts/check_canon_authority.py
scripts/canon-smoke-test.sh
```

如果某个创作方案明显优于当前Working Canon，应提交迁移，而不是为了“合规”缩小剧情。
