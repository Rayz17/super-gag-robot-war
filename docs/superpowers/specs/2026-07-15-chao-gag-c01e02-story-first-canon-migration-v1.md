## 1. Reason

旧候选层虽然已经具备“四令、火场、七海撤令、消防机、勇拳预告和白函压场”，但仍存在六个会破坏单次游玩因果与后续高潮的问题：

1. 二十九名撤离对象、三名馆内工作人员与后续桥上人员缺少唯一人口快照，E03容易凭空生成人群。
2. 七海一句撤令被写成同时恢复门、泵、风阀和公共支援，越过了她实际拥有的权限。
3. 玩家仍在“数据中心/商业展层”或人命/馆藏之间做抽象二选一，削弱火场常识和E04真正的载荷取舍。
4. 消防架桥机只有概念性铺桥，缺少足以构成本话机体高潮的全身动作与地图物理。
5. 豪司和勇拳在E02提前到场承梁，消费了E03的首次越权、首次有效动作与勇者人物峰。
6. 成功、失败和中间回合状态没有唯一提交点，失败重试可能把人口、伤痕或权限半套带入E03。

## 3. Unique E02 End Snapshot

E02成功后必须原子提交，R1-R4失败从SRPG设置重试且零持久化；R5失败只从本地检查点重试，二十九人不再重救，但同样不得提前写入故事状态。

- 原始29名撤离对象全部在楼外四个固定安全格；C3照看组完整，D5仍含E01同一名维修员。
- 纪存、唐胶、兜灯仍在馆内侧；两名城市消防接驳员在29人离楼后进入，不属于开场32人或万机馆编制。
- 七海已公开撤销本人东侧高压锁并停权；`QH_SYSTEM_WRITE=DISABLED`，`CITY_FIRE_RESCUE_SUPPORT=ACTIVE`。
- B1泵由跌跌机械工序与兜灯低压旁路恢复为手动低压；馆守Z主动力、胸灯和右臂仍保持E01连接/停机状态。
- 共同写入的只是公共消防/撤离层；完整移动脊柱、B2与馆体全图仍未公开。
- 供水总管热变形为唯一代表路线伤痕；商业后勤风道局部烧损，档案主库处于紧急冷却。
- 消防架桥机SEG3已反折成支撑，左前腿过载；它仍是城市职业支援机，不在本话首次控制或入队。
- 勇拳试作机保持封闭运输、许可灯灭、压力零、本体零位移；豪司尚未到场。
- 白函仅以远程语音、重框投影、区域改报和中庭落点预量出现，无格、无HP、不可受击；完整身体首战留E03。
- 敌方获得公共消防图、消防桥接口、七海撤令模式和“救援可改报为资产迁移”的样本。

## 4. Runtime And Production Contract

- 固定地图为`12x14`、八邻接且斜向不得穿角；R1-R4采用`小机 -> 工作人员 -> 消防支援 -> 工具机 -> 撤离自动移动 -> 环境 -> 本地守卫/回执`顺序。缺桥、C3拆分、烟值越线、泵序错误或人口漂移均有可到达失败态。
- 四个撤离Token为`A11 + B10 + C3 + D5 = 29`，按声明路径和同步优先级在R4分别到达四个楼外固定安全格；跌跌退入馆内泵站检修凹位，不随Token瞬移出楼。
- R1桥段是`SEG1 -> SEG2 -> SEG3`唯一合法联合施工序列，不伪装成等价顺序选择。R2在护人水幕与抢先冲洗之间作一次明示代价选择，R3以配对动作闭合；R4点池清零。
- R5只处理29人离楼后的次梁坠落和馆内五人退路；两名接驳员沿声明路线入内后，城市消防才为新险情另发1点。消防架桥机在固定Rig内反折SEG3承梁，左前悬挂只在原格内压缩/滑移；勇拳只发出被机外继电截断的自动防坠请求。
- 冷却针车、切割标尺机必须有夹轨底盘、实体接触、受力与反冲，但无HP、人格或独立王牌待遇。
- 馆守Z只有被动温感/低压继电，不得有身体动作；白函无身体；勇拳无动画动作；消防架桥机使用一套完整固定地图支援Rig。
- HUD在R1-R4显示四Token端点、C3、泵、烟值、AP/点池与工具意图，R5改为五人退路且保留`29/29楼外`。唯一制作事实源为`C01E02-runtime-contract-v1.tsv`和`C01E02-graybox-constants-v1.tsv`。
- 白函远程结尾之后，快照与全部V35键必须在同一事务写入；后续校验只读，不得形成第二个提交点。
