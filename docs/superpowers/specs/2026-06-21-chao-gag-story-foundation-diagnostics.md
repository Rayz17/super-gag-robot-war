# 《超GAG机器人大战：万机残响》剧情根基诊断与加固 v0.1

> 本文承接框架 Bible、商业版内容蓝图、剧情线场景扩写、第一章台本包，以及主程序对话中关于第一章、七海动机、Godot 交互容器的最新口径。目标不是改写主线，而是把当前大纲暴露出的结构风险固化为后续编剧、关卡和图谱可检查的根基表。

## 1. 总体判断

当前大纲成立，不需要推翻。

本作最强的根基是：把机器人文化、粉丝记忆、真实机器数据、AI 生成与末世废土合成一个原创机器人文化神话，并用“原初统一 / 算法统一 / 后天合唱”搭起终局哲学。万机馆作为主角共同体也很稳，它天然能承载剧情、收集、角色生活、档案和战斗整备。

当前主要风险不是“没有想法”，而是想法太多、抽象层太强，容易在台本中滑向设定朗诵。后续每章必须被压回五个问题：

| 问题 | 检查点 |
| --- | --- |
| 本章想证明什么 | 不能只重复“爱变成控制”或“个体很重要” |
| 玩家具体做什么 | 必须落到探索顺序、保护目标、撤退、非致命、说得、改写代价或资源取舍 |
| 谁被改变 | 至少一个具体角色或关系发生不可逆变化 |
| 什么被保留/删除/改写 | 必须能进入闭馆记录、档案记录或路线债 |
| 设定如何被看见 | 抽象概念必须有地图规则、UI语言、物件、台词和后果 |

## 3. 关键加固口径

### 3.1 G.A.G. 不是万能许愿机

G.A.G. 可以索引、提取、唤醒、封存、清噪、模板化和调谐机魂，但它必须依赖载体。载体可以是展柜、旧录像、模型件、真实机器训练数据、服务器镜像、观众留言、战斗记录或仍被人反复记起的名字。

因此，第一章保护留言墙、右臂旧件、0号侧廊和档案服务器不是情绪性目标，而是世界观硬规则：这些东西是机魂残响可以稳定存在的锚点。若锚点被合法封存或删除，G.A.G. 未必“杀死”机魂，但会把它压成不可被角色和玩家理解的噪声。

### 3.2 第二幕要避免同题反复

第5-8章都涉及叙事权，但各自必须分工明确：

| 章 | 控制来源 | 不能写成 |
| --- | --- | --- |
| 第5章 宇宙世纪城 | 军方和战史把人压成英雄/撤退污点 | 又一场“原典不能改” |
| 第6章 作者遗迹 | 作者以爱和责任控制角色 | 创作者都是坏人 |
| 第7章 原典圣堂 | 粉丝因害怕失去共同语言而钉死作品 | 嘲笑原典厨 |
| 第8章 清算都市 | 企业用真实灾难责任换取静音权 | 单纯版权恶棍 |

这四章的玩法目标也要不同：第5章偏撤退和战报传递，第6章偏阻止剧本轨道，第7章偏打断仪式但不击坠狂信者，第8章偏同时控制风险、保护万机馆和减少城市损伤。

### 3.3 反派必须先有人味，再有系统性

目前阵营压力强，反派个人戏偏薄。七海已经通过“风险封存”和白名单事件立住方向，其余主要反派也需要至少四类场景：生活场、压力场、行动场、后果场。反派不是为了讲主题而出现，而是要让玩家短暂理解：如果站在他的位置，他为什么会觉得自己不是错的。

### 3.4 终局抽象必须有表现语法

第9-12章最危险的是把“算法统一、原初统一、后天合唱”讲成哲学讲座。后续必须遵守：

- 索引天使通过“修正 UI、最优模板、复制玩家常用战法、清除缺点”出现。
- 群星合唱体通过“同步、时间错位、不可击破目标、个体台词被合并”出现。
- 后天合唱通过“保留跑调、失败记录、错字、私心、互相误解后的援护”出现。
- 真结局不是群星被爱感化，而是群星第一次记录原初统一无法自行推导的东西。

## 4. 对第一章的当前要求

第一章结构不改，但执行要更克制：

| 话 | 唯一优先目标 |
| --- | --- |
| 1-1 今日闭馆后 | 让玩家喜欢万机馆，还没逛够 |
| 1-2 法务警报 | 让玩家理解代哥是合法风险封存，并保护刚喜欢上的东西 |
| 1-3 展厅里的旧守护者 | 让旧守护者从导览规则回到馆守Z本体 |
| 1-4 流亡展舰 | 没有胜利，只有把能开的灯带走 |

0号侧廊、馆长、纪存身份、远星和 G.A.G. 深层谜题都可以埋，但不能抢第一章的情绪任务。

## 5. 后续使用规则

1. 写任何章节大纲前，先查 `story_chapter_diagnostics.tsv`。
2. 写任何 G.A.G. 或索引天使能力前，先查 `gag_capability_boundaries.tsv`。
3. 写反派登场、说得、临时同盟或结局前，先查 `antagonist_personal_scene_seeds.tsv`。
4. 写第9-12章时，必须把 `finale_expression_grammar.tsv` 中的抽象概念转成具体地图规则、UI语言或角色动作。
5. 任何新增关键口径继续同步图谱索引、节点、关系和风险表。
