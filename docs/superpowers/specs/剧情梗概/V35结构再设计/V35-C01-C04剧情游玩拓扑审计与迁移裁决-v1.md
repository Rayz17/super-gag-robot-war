## 一、总裁决

三层分离方向正确，但原生产链少了一个对象层：它知道一话里有哪些SRPG和结算，却没有先判断这些SRPG究竟属于同一个Operation、几个Encounter，以及Episode切点是否只是Checkpoint。

本轮结论不是“每话都取消结算”，而是区分三种真实结果：

1. **Encounter完成**：例如资格赛、半决赛、夺回四组工具，可以庆祝并保存局部结果；
2. **Phase优势**：例如盾拍击倒、地面壳击破、黄金重锤首击，只改变下一阶段状态；
3. **Mission Clear**：主要世界冲突真正结束，才允许永久奖励、完整战后状态和Hub回收。

已新增`story_play_topology`为L4正式门：导演板、战斗预案、物理板完成后先锁定Operation与IncidentState，再写完整章纲。它只约束游戏承载，不向纯剧情Reader回灌UI、阶段名和状态字段。

## 三、C01审计

### 3.1 Reader连续性成立

已验收Reader从未把盾拍写成终战：E02末BREAKER重新起身；E03明确从“刚用重盾拍翻”继续；地面壳破裂后飞行核心升空并同步外海小体；E04核心继续追舰，最终毁灭后警报才解除。

盾牌的故事链也已经完整：E01先展示退役重盾；E02馆守Z从展位取盾；E03裂盾仍随身；E04它被带回泊位、承担掩护和着舰承载，最后完全碎裂。不存在“下一局凭空自带盾”的Reader问题。

### 3.2 制作层缺陷

旧战斗预案把E02写成“胜利”，把E03写成“完整Boss关”，并允许地面壳“奖励与击破反馈正常结算”；旧L4.5又要求双拳破甲后先出现击破结算。单独看每句话都想保护爽点，连起来却会把Boss换形误演成Mission Clear。

裁决如下：

- E02盾拍：`phase_transition + episode_cut + checkpoint`；可以出现“击倒成功”“居民区暂时安全”，不能发永久战果。
- E03地面壳毁灭：`encounter_complete + episode_cut + checkpoint`；地面Encounter在此结束，E04启动离港Encounter，但两者仍属于同一Operation并继承同一IncidentState。允许强烈第一形态击破反馈，但战斗UI必须明确核心仍在、任务继续。
- E04核心毁灭：本Operation唯一`mission_clear`。
- E02-E03使用同一张可滚动旧广场/街区棋盘，建筑、道路和破坏态保留；E04换到出航走廊与海岸空域，但继续同一Operation。
- 盾是E02地图物件，拾取后成为馆守Z装备状态；E03继承损伤；E04显式拆回泊位并最终碎裂。存档必须序列化持有者、完整度和所在地图对象状态。

### 3.3 小型异星体

当前Reader在E01写明十几个小型接触点被海防挡在城外，E03飞行核心显形后才让它们第一次同步转向。因而“E02已有一批弱小体同场”会改变敌群首登与升级表达，不能只在游戏层静默增加。方案见独立用户决策包。

## 四、C02审计

### 4.1 两种完成态同时存在

C02证明“一话可含多个Encounter”：E03有两场不同半决赛；E04的冠军战在话中以3:2真实结束，随后才开始自愿终幕演出和外轨事故。

赛事Operation在3:2时可以Mission Clear，冠军结果永久成立。但事故发生得太快，不允许回Hub、免费修复右拳、重装完全版王者或重置货运环。事故是第二个Operation，从E04跨到E05。

### 4.2 现行材料的优缺点

现行Reader与L4.5已经明确E05从同一时刻开始、没有免费复位，故事层无须改。独立游戏流程也把E04事故和E05救场写成连续因果，但仍按Episode分标题，缺少可执行的共享IncidentState。

新增拓扑表固定：比分、伤势、全装状态、外轨裂口、舞台炮、万机馆承接位置和货柜领袖牵引全部跨话继承。E05只能在故事允许的工程操作中改变这些状态。

## 五、C03审计

### 5.1 主危机跨E01-E03

E01解除万机馆永久固定，但衡令带走四组附件；E02夺回附件，但衡令借冲击越线并升起巨环；E03才拆掉它与城市的物理连接。三话是同一城市危机的三段，而非三个互不相关的任务。

- E01：局部Encounter完成，夜间Checkpoint；衡令、工具、城市停摆和万机馆损伤继续。
- E02：夺件是真胜利，衡令越线是主动反击；切话时巨环已经启动，不恢复编成。
- E03：社勇王合体、首锤、停下第二锤和全员拆战场属于同一Boss Encounter的三个Phase；衡令虽逃走，却已失去工务城接口，允许完整Mission Clear。
- E04：第二天开始新的无敌军巨构Operation，玩家把战斗成果变成公共泊位。它不是为了“每话一战”追加的假敌袭。

### 5.2 地图裁决

E01-E03均为户外城市战，采用可滚动棋盘；城市建筑、道路、环轨、巨环和城梁是地图内容。地图可以因地点变化换区，但城梁位置、巨环形态、城市破坏与机体伤势必须继承。固定小屏只保留给驾驶舱、观察席和封闭工位ADV。

## 六、C04审计

### 6.1 三板没有故事级冲突

当前导演板、战斗预案和物理板已经建立：E01局部得胜、E02制造选择、E03撤离失地、E04终战夺回。它们没有要求每话都重置人物动机或敌人能力，也没有改变章职责、敌人首登、人物关系结果或永久损毁。

缺口在后台映射：预案仍称“三场完整SRPG”，E01和E03各自写胜利条件，若直接交给关卡制作，容易把E01当整章Boss Clear、把E03撤离后恢复全员再开一局。

### 6.2 现行拓扑

- 整章只有一个断冠Operation。
- E01是第一轮Encounter完成：断冠暂退、工位保住，可以庆祝和存档，但不发断冠终战奖励。
- E02是战时制造间奏：产能、战损和断冠学习都继续；它不是脱离危机的免费Hub日。
- E03第二轮Encounter以撤离成功收束；断冠控制外环、铸环竖起，只有`episode_cut + checkpoint + operational_pause`。
- E04是同一Operation的反攻Encounter。凌晨准备会允许有来源的现场整备，不允许百相补回右臂、地方旗舰全修或敌方忘掉E01样本。
- 独臂百相贯穿冠环、断冠撤退且铸环恢复控制后，才触发唯一Mission Clear。

本轮只新增拓扑桥接，不重写当前候选C04导演板、战斗预案和物理板，并保持它们现有封存阶段与Candidate权限原状；后续完整章纲必须读取该表。

## 八、哪些文件没有改，为什么

- C01-C03纯剧情Reader：故事连续性成立，拓扑错误属于制作层，重写会无端使用户验收失效。
- C01-C03已封存旧L4/L4.5：保留为当时设计证据；本审计与新拓扑表对Operation、Checkpoint和Mission Clear拥有后发裁决权。未来若重制游戏流程，以新表为准。
- C04导演板、战斗预案、物理板：没有重大故事冲突；直接改动已封存三板会造成无收益失效。新拓扑作为它们共同的下游门。
- Godot、美术和Runtime：本轮只输出可执行接口，不进入实现。

跨Operation承接现已进入机器字段：每行以`story_unit_ids`绑定本话故事单元，新Operation首行用`carry_from_state`指向更早Operation的`state_out`。C02赛事至事故、事故至离港，以及C03衡令危机至归港校正均已建立显式承接；字段为空、来源不存在或错误地指回同一Operation时不得封存。
