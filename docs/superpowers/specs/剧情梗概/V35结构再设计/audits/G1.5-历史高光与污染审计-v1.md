# G1.5 历史高光与污染审计 v1

> 审计席：G1.5 历史高光与用户认可功能审计席  
> 日期：2026-08-03  
> 文档性质：History / Candidate 输入审计，不是 Canon，不产生新事实，不分配新章号  
> 审计范围：V15、V16、V16.1、V22.10，以及相关高光迁移表、压力测试、继承裁决、用户事实裁决、Fable/Codex 复审与人声门禁  
> 唯一用途：为后续全剧结构再设计提供“可迁移场面功能”和“必须隔离的污染”

## 0. 审计结论

1. **Current 事实与历史高光必须分账。** 截至本审计所依据的最新用户事实裁决，只有 C01、C03 获 A 档认可，可按裁决范围进入 `FIXED_PAST`；C02 没有获认可的 Current 剧情发动机，只保留素材与桥接义务；C04、C05 只保留 B 档候选功能，不得当作已发生事实。
2. **V16/V16.1 的用户认可对象是功能族，不是旧稿事实包。** 可继承的是连续追番发动机、外放奇观、先爽后反噬、关系误伤、IP 情感投射、玩法后果和界面级败北；旧地点、旧顺序、旧台词、旧参数、旧人物到场时点均不随之继承。
3. **V22.10 的用户认可对象是“厚度恢复法”。** 可继承的是多谱系同场、每台机体有独立动作理由、强敌方案先显得强大且诱人、必要合体对抗全挂完全版、慢车与小物件累计泪点；旧篇幅、旧队伍编制、旧资产数量和旧落点不继承。
4. **V15 是有效诊断库，不是五十条生成模板。** 它准确指出了“太暖、太小、太像指标表、关系不改变战局、胜负不改变玩法”等病灶；若把五十条逐项塞进每话，会立刻复发为 KPI 写作。
5. **真正值得迁移的不是名场面外壳，而是因果形状。** 本稿将高光拆为 55 个语义功能项；人物、地点、机体、物件、玩法载体与落点均可重写，只有冲突发动方式、情感代价和可见后果需要保真。
6. **旧稿污染分三类。** 一类与 Current 直接冲突；一类是 AI 味坏句式；一类是会把所有章节压成同一台机器的机械结构。三类都不得因为“以前很燃”而回流。

## 1. 权威防火墙

### 1.1 事实层级

| 层级 | 本审计中的含义 | 可否写成已发生事实 |
|---|---|---|
| `FIXED_PAST` | 用户已明确认可且机器裁决允许提升的过去事实 | 可以，但只能在裁决给定范围内 |
| `MUST_ANSWER_PROMISE` | Current 已经立下、后文必须回应的承诺 | 可以作为约束，不可自行发明答案 |
| `USER_LIKED_FUNCTION` | 后续权威材料明确认定用户曾认可的“好看机制/场面功能族” | 不可以；只能迁移功能 |
| `CANDIDATE_MATERIAL` | 历史稿中仍有创作价值的具体场面、物件或玩法候选 | 不可以；必须重新过人物、因果和 Canon 门禁 |
| `RESEARCH_ONLY` | 诊断、比较、压力测试或外部复审意见 | 不可以；只能帮助判断 |
| `RETIRED_CONTAMINANT` | 已与 Current 冲突，或已证明会造成机械化/坏人声的旧内容 | 不可以；默认隔离 |

### 1.3 “用户认可”证据口径

- 可以称为用户认可：后续继承裁决、生产状态或设计图明确点名的 V16/V16.1 功能族，以及 V22.10 的厚度、多谱系和高光恢复法。
- 不可以称为用户认可：某一句旧台词、某个精确动作、某个旧章号、某个参数、某个资产清单，除非用户事实裁决另有明确登记。
- 本文把功能族标为 `USER_LIKED_FUNCTION`；功能族下面的具体旧场面如果没有单独认可，仍标 `CANDIDATE_MATERIAL`。
- 历史稿“曾有效”只表示它在压力测试中解决了某种戏剧问题，不表示它已经成为 Current。

### 2.1 四个主版本的净判定

| 版本 | 历史上真正解决的问题 | 最值得保留 | 最危险的误读 |

## 7. 迁移约束与 G2 交接

### 7.1 每个高光 ID 的使用门槛

1. **先定承载人物。** 说明是谁想要什么、为什么非现在不可、他具体做了什么；不能先选名场面再抓角色填空。
2. **再定同一因果。** 机战、关系、IP、玩法与泪点若不能争夺同一对象，就应删线而不是并排列满。
3. **保留诱惑。** 对手方案必须真有用，主角的拒绝必须损失某种好东西。
4. **后果可见。** 至少一个身体、空间、机体、界面、支援或关系状态跨场景保留。
5. **允许胜利永久成立。** 不得为了维持压力把每个高光都反向判错。
6. **资产先分层。** 完整可玩机、短时支援、背景剪影、传闻/展品分别处理，厚度不等于全资产化。
7. **功能与外壳分离。** 旧台词、旧参数、旧章号、旧到场时点、旧机体名单默认全部可变。
8. **最终回到 Current 校验。** 采用前重新查询 Canon authority；本审计不能为任何冲突项背书。

### 7.2 建议的处置动词

后续结构稿引用本审计 ID 时，只能使用以下处置动词，并补一句理由：

| 处置 | 含义 |
|---|---|
| `PRESERVE_FUNCTION` | 保留因果功能，全部重写外壳 |
| `FUSE` | 与另一个功能合并为同一动作，避免栏目并排 |
| `REASSIGN` | 更换承载人物/机体/地点，但不改变功能核心 |
| `DEFER` | 当前无依赖或会抢主线，延后但不承诺具体落点 |
| `DROP` | 与 Current、人物主轴、资产或节奏不相容，明确丢弃 |

### 7.3 不得锁旧章号的执行格式

后续任何采用记录应写成：

`功能 ID + 承载人物 + 争夺对象 + 可见后果 + 依赖 + 当前状态 + 落点 UNASSIGNED`

不得写成：

`把旧某章整段搬到新某章`、`恢复旧八话结构`、`按 V15 第 N 条给每话补一个爆点`。
