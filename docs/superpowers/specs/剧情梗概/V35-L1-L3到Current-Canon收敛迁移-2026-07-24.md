# V35 L1-L3 到 Current Canon 收敛迁移

> Status: `working_canon_migration`
>
> Date: `2026-07-24`
>
> Scope: Current Canon、C01第四层输入、C12旧高光池与Design Graph

> 2026-07-26补充：本文件记录的第一次收敛继续负责皇影与零号捷径退役；其中C01白函主战、断臂桥、载荷二选一、陆衡随舰和36小时窗口已由《V35 C01用户审定故事回迁与Canon收敛》进一步替代。

## 一、为什么要迁移

V35的L1体验宪章、L2总发动机与L3结构母盘已经成为Working上位依据，C01则正在重新补齐第四层。审计发现，默认Current Canon仍把旧V35.9 Reader、Runtime和资产合同里的若干局部发明当成当前事实，其中最明显的是：

- `黑展柜皇影残压`被登记为C01首显、C12回收的未来机体；
- `0号侧廊共振轻触`被扩写成能够取回三枚活动核心、把跌跌设备化并夺走多人停止权的完整捷径机制；
- C01E04场景、资产锁、继承包和C12高光锁互相引用，使这些设计即使不在L1-L3和新C01对齐卡中，也会被后续写作自动恢复。

这类条目不是Hard事实，而是旧章节为了填补局部因果临时创造的实现。继续保留为Current，会使L4预生产被旧Reader反向约束，也会让未来章节为一个尚未被总纲需要的角色和资产支付成本。

## 二、收敛原则

Canon不会被清空成只有L1-L3。Current仍由四类内容组成：

1. 用户确认的身份、空间、物理容量和世界机制；
2. L1-L3已经Working的体验、总发动机和结构职责；
3. C01-C03已经确认、且不会妨碍逐章重编的最小故事事实；
4. 由当前L4重新封存后产生的章节事实。

以下内容不得仅因旧稿曾经通过局部审查而继续占据Current：

- 尚未完成当前L4的逐场实现、Runtime常量和一次性装置；
- 只存在于旧Reader、旧Pressure Board或旧资产合同中的未来角色；
- 为解释局部机关而新增、但没有上层职责和后续生命周期的机制；
- 已被新章级对齐卡明确省略或替代的细节。

旧材料保留为History，仍可用于追溯和打捞高光，但默认查询和新写作不能把它当成必须兑现的承诺。

## 三、本轮裁决

### 3.1 黑展柜皇影

`MECHA_BLACK_SHOWCASE_EMPEROR_SHADOW`、`CONCEPT_BLACK_SHOWCASE_SHADOW_PRESSURE`与美术锁`CML042`降为History。

- C01不再出现黑展柜睁眼、黑框扩张、卡住右锁泊臂或拘束回压。
- C12不再承担“皇影停拳、首控或隐藏后继”的回收义务。
- 旧黑展柜图片、V31/V35.9 Reader、Runtime与资产矩阵继续保留，身份是历史探索资产。
- 以后若全剧结构重新需要馆守Z的暗面机体，必须重新完成角色功能、机魂载体、机体尺寸、驾驶/控制、IP投射、章节生命周期与资产收益设计，不能直接复活`皇影`旧名和旧动作。

### 3.2 0号侧廊与零号捷径

保留：

- `0号侧廊`作为万机馆真实存在但未开放的空间；
- 纪存对旧馆深层和自身来历的疑问；
- C01只产生异常感、旧地图矛盾或普通物理痕迹，不解释答案。

退役：

- 三枚活动核心；
- 把跌跌重分类为运输设备；
- 灰掉兜灯、旧守护者或其他人的停止权；
- 要求纪存永久独占管理；
- 通过一次测试证明“效率会夺走关系”的完整装置寓言。

`CONCEPT_ZERO_CORRIDOR_RESONANCE_TOUCH`降为History。C01E04的现实选择改由时间、供能、载荷固定和城市撤离条件推动，不再由零号捷径先给出超高效方案再让纪存拔桥。

### 3.3 C01E04仍然成立的最小事实

- 万机馆失去原址，旧移动底盘解除固定并进入低功率巡航；
- 馆守Z保持18米独立实机；原右臂永久留在旧址，本体进入阶段性单臂状态，后续新右臂仍按L3生命周期成长；
- 纪存、唐胶、兜灯、陆衡作为必要操作员随舰，普通观众、儿童、消防员和豪司不随舰；
- 代表路线带走生活维持设备与实体独有馆藏，档案主库留置，只保留关键冷备；
- 舰上旧制接口只够维持约三十六小时，木桶旧件市成为下一站；
- 七海不在馆内，仍处停权和调查状态；
- 万机馆只完成移动展舰形态，不提前暴走、站立成人形或获得完整战舰火力。

火锁回写模块与风险标记无人机降为Candidate关卡方案。它们可以在C01 L4战斗预案中重新竞争席位，但不再是Current世界事实。

### 3.4 C01旧Runtime与工具敌机

C01四个Current场景改为“最小故事事实”，不再保存旧Reader的回合数、人数站位、原子快照键、固定工具敌机、精确伤势和地图格数。

- `V355-C01E01`只锁闭馆路线、29名观众汇到前厅、四方接管与起火；
- `V355-C01E02`只锁观众离楼、七海停权、消防架桥机旧伤与白函入场；
- `V355-C01E03`只锁馆守Z大胜、勇拳临控、断臂留址与白函带样本撤退；
- `V355-C01E04`只锁失馆、四名操作员、载荷结果、单臂馆守Z、低功率起航与木桶街。

采样贴片、重型路径框、冷却针车、切割标尺机全部降为Candidate。封存无人机的既有美术锁可以继续保留，但出场章节、战斗职责和Runtime仍要重新排定。

以下旧Runtime门槛不再是Current：

- 七海通讯必须由0号侧廊异响解锁；
- 旧封存无人机首战的固定语气与场次。

以下规则继续保留，但按新上层事实修正：

- 豪司在C01前两话不能作为可操作战斗单位；
- 七海C01不在馆内；
- 二十七年前原初灾变不得误写成七年前，七年前只属于共身改革事故。

### 3.5 0号侧廊表达边界

`0号侧廊`和B2残响接口层仍是Current空间，但不再自带以下实现：

- 固定的“未知声音”角色；
- 必须出现的黑展柜；
- 0号开启臂和倒计时开门；
- 由异常声音解锁七海通讯；
- C01E04自动显示完整残响终端页。

当前只要求玩家在C01确认“旧地图与真实空间对不上，纪存对此有异常感”。L4可以从声音、地图缺页、空气流动、灰尘断线、旧门锁痕迹等表达中择一；选中的表达通过预生产与演出门后，才升为Current。

### 3.6 旧十二章数据

`CONCEPT_MISSION_BALANCE_TARGETS`与`CONCEPT_CHAPTER_CONTENT_BUDGET`降为History。它们保留低改/正常/高改三队验收、内容必须核算容量等方法，但旧十二章的逐章数字不能进入当前二十二章结构。

`CONCEPT_V35_5_OPENING_PRESSURE_BOARD`降为History；`CONCEPT_V35_5_OPENING_ROUTE_MAP`降为Candidate。六站闭馆、高光与“移动必须有现实理由”可以继续打捞，旧十槽十一话、固定地图节点和Runtime不再有约束力。

### 3.7 C02-C03 Creative Working的精度

C02、C03的章级结果继续是Creative Working，但八个场景行只保存L3已经审定的故事骨架：

- 哪些人物和机体正式出现、加入、离开或留下；
- 唐胶维修史、白鸢登舰、陆衡失去资质、七海实体登舰等不可逆人物结果；
- 模型锚不凭空长成巨机、白鸢分镜必须由现实执行者落地等稳定机制；
- 木桶街到工务城、工务城到天空铸环的直接发动关系。

旧Reader中的控制中继数量、关节松动角度、承重槽动作、资源键、临时支架和逐阶段战术全部移出Current。C02、C03重新进入L4时，可以保留成立的高光，但必须重新通过章级预生产、导演板、物理站位和战斗预案。

与这十二个场景绑定而被提升为Working的角色、机体、敌人、地点和终端视图也遵守同一精度：只保存身份、能力边界、首次出现/加入、章末归属和L3明确要求的不可逆结果；旧Reader的精确招式、伤位、关节动作、回合数、装置名、地形路线和资源键不得藏在实体行或Hard美术锁里继续生效。

## 四、章节实现与Canon的边界

C01的旧E01支持场景、Runtime细节、Reader和资产合同继续作为重编输入。当前L4未完成以前：

- 它们不能凭“文件存在”或旧PASS覆盖章级对齐卡；
- 新预生产只能继承本迁移第三节列出的最小事实；
- 若L4采用新的、更清楚的因果，必须更新场景行和继承包后再封存；
- Runtime与已制作样例是否保留，由后续L6迁移单独决定，不能反向锁死故事。

以后每章进入预生产以前，必须做一次同样的“上层职责 / Current事实 / 旧实现”三分审计。没有上层职责、没有当前人物或机体生命周期、只由旧实现自我引用的项目，应先降级再创作。

## 六、验收

迁移完成后必须满足：

1. `scripts/canon-query.sh 皇影`在默认Current查询中无结果；
2. `scripts/canon-query.sh history 皇影`能够追溯旧条目；
3. 默认查询`0号侧廊`只返回空间或未解谜团，不返回零号捷径机制；
4. C01预生产模型不含皇影、三枚活动核心和停止权装置；
5. C12高光锁不再要求皇影停拳；
6. Canon authority构建、检查与smoke全部通过；
7. C01 story-chain重新封存`series_alignment`、`preproduction_model`与`preproduction_table`，不沿用失效哈希；导演板及其后续阶段保持失效。
8. C01四个Current场景不再引用旧Reader、Runtime、Graybox或资产矩阵作为当前来源；
9. 当前Canon不再把十二章预算、固定零号声音、0号开启臂或C01工具敌机当成必然事实。
