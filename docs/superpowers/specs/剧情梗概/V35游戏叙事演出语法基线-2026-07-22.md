# V35游戏叙事演出语法基线

> Status: `working_production_writing_interface_v1 / non_canon`
>
> 日期：2026-07-22
>
> 作用：补齐第四层“剧情在文字里成立，但玩家无法从游戏中看见”的缺口。本基线属于写作与制作接口，不定义世界事实，不替代Canon、关卡设计、台本或正式分镜。

## 一、层级边界

第四层章级总纲必须决定：

- 玩家在什么顺序里经历场面；
- 每个关键事实有哪些可见证据；
- 场面暂由ADV、探索、地图事件、SRPG、短动画、Cut-in、终端UI、经营/小游戏或舰内事件中的哪一种承载；
- 哪些信息此刻必须懂，哪些只需产生疑问，哪些仍是作者后台真相；
- 场面最低需要哪些人物、机体、背景、状态差分和特殊资产；
- 删掉梗概旁白后，玩家是否仍能复述当前目标、转折和结果。

在进入这些场面判断前，章级预生产模型必须先决定：

- 本章真实存在的人物、机体、敌人、关键物件和空间；
- 驾驶、机魂、AI、导航、武装与权限分别由谁控制；
- 新能力的输入、输出、执行身体、限制和代价；
- 远景可读的大动作及明确禁止的临时能力；
- 哪些轮廓、地图、控制链与奇观需要低精度视觉预演。

第四层不决定：

- 具体机位、镜头焦段与逐镜时长；
- 完整台词、配音停顿和表演细节；
- Cut-in秒数、动画逐帧动作；
- 敌军数值、回合数、AI与最终胜负平衡；
- 每一项美术资产的技术规格。

第四层通过后，进入独立的`章级演出承载规划`：

```text
章级对齐与发动机
-> 章级预生产模型
-> 导演板 / 战斗预案 / 必要物理板
-> 章级完整剧情总纲
-> 章级演出承载规划
-> 逐话Episode Reader
-> 关键场表演与对白简报
-> 台本初稿
-> 角色声线分离 / 人类声线与去AI味门
-> 分镜 / 地图事件 / 战斗设计 / 资产任务
```

Episode Reader不再写成小说式梗概，而按玩家实际流程标注`ADV / 探索 / 地图事件 / SRPG / 战中通讯 / 短动画 / 舰内事件 / 结算`。

### 1.1 视觉预演门

预演只验证“能否看懂、能否摆下、能否制作”，不等于正式美术：

- 普通关系章使用既有地图和人物站位即可；
- 新地点、单台新主力、一次新变形或两种尺度交叉，补俯视灰盒、尺度轮廓与三至四格动作草图；
- 新巨构、多尺寸机体同场、母舰/机体变形、机魂空间与现实交叉、新能力决定胜负、三方以上混战、地形决胜或高成本Boss，必须在完整总纲前完成尺度板、俯视/剖面灰盒、控制链、四至八格奇观板与SRPG阶段切换图。

若低精度预演无法用普通图形说清楚，不能把复杂度转移给Reader里的机械说明；应先缩减空间、动作、同时运行的规则或资产形态。

## 二、项目可稳定使用的演出语法

| 语法 | 适合表达 | 相对成本 | 第四层需要锁定 | 第四层不要提前写 |
| --- | --- | --- | --- | --- |
| ADV对话 | 人物欲望、争执、暧昧、知识来源、选择前压力 | 低至中 | 出场者、地点、关系动作、当场必须说清的事实 | 完整逐句台词和全部表情切换 |
| 舰内自由活动/可选事件 | 日常、生活喜剧、关系余波、可选分支 | 低至中 | 可访问区域、触发条件、是否影响主线状态 | 所有闲聊文本 |
| 可操作探索 | 空间厚度、线索发现、模型/实机检视、角色走位 | 中 | 路线、交互物、玩家发现顺序 | 全场景物件清单 |
| 地图事件/引擎短演出 | 单位入场、地形变化、门开启、巨物移动、状态切换 | 低至中 | 前后地图状态、谁执行、玩家能否一眼看懂 | 复杂电影级连续动作 |
| SRPG战斗 | 冲突、单位关系、战术选择、机体能力与角色决定 | 中至高 | 一句目标、地图轮廓、核心规则、阶段变化、可操作单位 | 精确数值和全机逐步走位 |
| 战中通讯 | 即时反应、误解、敌我变化、关系支援、目标重定义 | 低 | 谁能听见、触发节点、它改变什么 | 长篇背景讲解 |
| 必杀Cut-in | 名机体、名场面语法、关系合击、机器人动画爽点 | 中 | 触发条件、动作概念、情绪意义 | 完整分镜、帧数和最终台词 |
| 短动画 | 首次变形/合体、母舰起航、牺牲、世界级奇观 | 高 | 动画前后可复用状态、必须看清的两三个大动作 | 逐镜表和技术实现 |
| 终端/UI资料 | 短数据、证件真伪、地图、明确选项、收集回看 | 低 | 玩家必须读取的最少字段、与现实动作的连接 | 用日志替人物完成高潮 |
| “本次开放资料” | 话末/章末整理已经演出的阶段性知识、保留误解与修订史 | 低 | 资料状态、可见来源、当前可信度、未来修订窗口 | 用资料卡补足主因果或提前公布后台真相 |
| 经营/整备/小游戏 | 开馆、布展、修件、训练、调律、资源和分支 | 中 | 输入、玩家动作、可见结果、怎样转入主剧情 | 详细经济数值 |
| 战后结算 | 永久奖励、损伤、加入/离队、分支差分 | 低 | 哪些结果必须显式出现 | 用结算页代替人物情绪回收 |

高成本短动画应留给真正改变作品尺度的节点。能够用地图状态、单位动作和一次Cut-in说清的内容，不升级成连续动画；必须依赖连续近景才能理解的精密工程动作，不作为SRPG主高潮。

## 三、第四层可见性门

章节导演板中的每个关键场面至少填写以下内容：

| 字段 | 必须回答 |
| --- | --- |
| 场面与观众目标 | 玩家进入这场时想知道或想完成什么 |
| 玩家可见证据 | 具体看见、听见、操作或比较到什么，不写抽象结论 |
| 暂定演出载体 | ADV、探索、地图事件、SRPG、短动画、UI等 |
| 当场必须理解 | 不懂便无法继续当前故事或玩法的信息 |
| 允许留下疑问 | 此刻只需觉得异常、危险或有情感意味的部分 |
| 作者后台真相 | 角色与玩家尚不能知道、不得泄漏进对白的信息 |
| 最低资产需求 | 人物、机体、背景、状态差分、UI或一次性特殊资产 |
| 旁白删除测试 | 删除作者解释后，玩家能否复述原因、动作与结果 |

不要求每个日常过门都填表。以下场面必须过门：

- 章级发动机首次显形；
- 新机制或新能力第一次生效；
- 主要敌人首次改变战场；
- 关系破裂、牺牲、告白、背叛、误解与和解资格；
- 分支选择与长期后果；
- 主要机体首登、首控、合体、变形、升级、离队或死亡；
- 章级高潮与下一章发动器。

## 四、信息表达优先级

同一事实优先按以下顺序表达：

1. **人物或机体做出改变局面的动作。**
2. **地图、身体、环境或关系出现可见后果。**
3. **人物对具体听众作出短反应。**
4. **UI补足玩家必须知道的最少数据。**
5. **终端资料供愿意深挖者回看。**

禁止反向使用：先让终端念完设定，再让人物照说明执行；先由旁白宣布某段关系，再补一个象征性动作；先发明专有名词，再要求玩家把名词当作危机。

### 4.1 阶段性公开资料门

每章导演板按[《万机馆“本次开放资料”系统》](../2026-07-26-chao-gag-current-open-information-system-v1.md)记录每话的`必须理解 / 可以怀疑 / 必须隐藏 / 候选开放资料 / 来源 / 可信度 / 修订窗口`。一话可以没有资料卡，不能按配额凑卡。

若下一场需要玩家先读资料页才知道谁在何处、谁控制机体、为什么会战斗或一个决定造成了什么结果，资料页不得发布，场面退回导演板。Canon保存后台真实事实；“馆内推定”和“当事人口述”不得写回Canon成为世界真相。

## 五、跨尺度与战中叙事规则

- 普通人与巨机可以交叉剪辑，但同一SRPG阶段只保留一个主尺度。普通人的关键选择通过ADV、岗位支援、阶段过场或战中通讯进入，不让玩家在巨脚之间操作人类棋子理解主冲突。
- 巨体高潮优先使用整机位移、变形、合体、承受、贯穿、托举、坠落和地图改形等远景可读动作。厘米级开缝、锁舌、接口回弹只作因果后台。
- 角色关系若会改变战斗，必须对应可见的援护、拒绝、误击、换位、停火、入队、离队或目标改变；不能只在结算页增加关系值。
- 战中通讯每次只承担一个功能：报目标、表达情绪、揭露误解或改变阵营。背景史放在战前ADV、探索或战后回看。

## 六、常见失败与退回规则

出现以下任一情况，场面退回导演板或战斗预案：

- 只有梗概旁白知道为什么发生，现场角色没有信息来源；
- 纸、模型、名字、合同、分镜或数据越过执行身体直接改变现实；
- 一场SRPG同时要求追踪三层地形、普通人、巨机、移动建筑和多套权限；
- 高光依赖一连串微小零件动作，俯视图与Cut-in均无法看懂；
- 关系伤害只由作者说“她误会了”，当事人没有看见、听见或采取行动；
- 新设定必须靠角色念百科才能进入剧情；
- 同一短动画需要大量只用一次的机械形态或背景资产；
- 章级总纲通过依赖附录解释，Reader正文独立阅读仍不成立。

若问题来自“实体不存在、控制者不明、空间放不下、能力没有执行身体或高潮没有可读大动作”，再向前退回章级预生产模型；导演板和物理板不得现场发明装置补洞。

处理顺序：先简化动作或减少同时运行的线；再更换载体；必要时拆话；最后才增加一句解释。不得以增加术语和日志补洞。

## 七、C01-C04示范口径

- **C01机魂/G.A.G.**：由展馆分类、勇拳有人驾驶、馆守Z人格回体、黑匣子重播和万机馆群体响应逐步展示，不设置百科讲解场。
- **C02平台生态**：由转子涨价、运输架单向离城、充电位合并、空管拒认、取件飞艇按旧合同收货表现；合同正文只保留最低信息。
- **C03陆衡旧程序**：至少需要旧版本对比、现实机器被锁直、陆衡承认删去现场读取以及新规则改变机体动作四项可见证据。
- **C04米拉/艾达**：观星廊建立亲密；机构以`R-04`称呼造成伤口；黑城出击把记忆交换变成现实威胁；艾达开甲、米拉选择射击目标完成What-if。不得只写“她们曾经相爱”。

## 八、人类声线与去AI味接口

第四层不提前写完整对白，但所有关键ADV、关系场、喜剧场和高风险战中通讯，必须在导演板或演出承载规划中留下最少四项：

- 谁正在逼谁回应，双方各自想得到或躲开什么；
- 双方此刻知道、误以为和不知道什么；
- 哪个决定必须由身体、物件、机体或距离变化完成，不能让台词代替物理因果；
- 本场允许留下什么误会、难堪、欲望或半句话，不自动用金句总结主题。

进入Episode Reader和台本后，读取[《人类声线与去AI味生产门》](../research/2026-07-23-chao-gag-human-voice-dialogue-gate-v1.md)，按以下顺序执行：

1. 写关键场表演与对白简报；
2. 让相关角色只凭有限认知形成各自的说话压力；
3. 由单一主笔完成初稿；
4. 先复核因果与信息来源，再逐角色做声线分离；
5. 运行隐名、互换、听众、关声和朗读五项语义测试；
6. 最后运行确定性句式、术语密度、重复和退化检查。

机器没有报警不等于台词自然。不得靠增加语气词、省略号、方言、错字或“若有所思”括注伪造人味；若一句话承担了新设定、控制权或物理结果，应退回预生产模型、导演板或场面合同，而不是润色。

## 九、章级演出承载规划的后续交付

完整剧情总纲获准后，每章另建`Cxx-章级演出承载规划.md`，至少包含：

1. 玩家实际经历顺序；
2. ADV、探索、SRPG、动画、舰内事件和结算的切换；
3. 战中通讯与地图阶段触发点；
4. 高成本动画峰值与资产复用；
5. 主线与可选关系/生活事件分配；
6. 哪些梗概信息需要改成环境证据、人物对白或UI；
7. “本次开放资料”的开放时机、自动/主动阅读方式、图文资产与修订表现；
8. 进入Episode Reader前仍未解决的表现风险。

该规划只在章级总纲通过后制作。当前C01-C04三板复审只锁“证据与载体”，不提前写正式分镜。
