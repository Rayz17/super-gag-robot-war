## 2. 剩余阻断问题

### R2-B1 “至少三类广播”仍会压平四种合法结果

停止码为必选时，合法成功仍有四种：停止+自名+伤损、停止+自名+需要、停止+伤损+需要、四类全开。它们对S08的意义不同：缺“需要”会降低民间补给响应，缺“伤损”会增强恐慌剪辑，缺“自名”会提高索引聚类，四类全开则增加位置暴露。当前执行与适配器只写通用成功规则，仍会丢失这个差异。

**修改：** 新增4条广播成功profile；执行与S08适配器扩为`80入口 x 2白鸢状态 x 6补给profile x 4广播profile = 3840`，另加6硬失败。每个profile写明缺失项、当下收益、索引收益与S08债。

### R2-B2 关系拓扑仍只有解析器，没有精确运行引用

不需要把3840条再乘25导致无意义爆表，但每条S08适配器必须带`REQUIRED_EXACT_RUNTIME_C11_SIDECAR_ID`，并指向25条S07 relationship sidecar解析，证明关系状态没有被路线名覆盖。

## 3. 制作密度问题

14418个非空白字符和12个因果beat超过普通单话板。它作为非法线高潮不应机械拆成两个作者槽，否则会把共同身份诱惑与原声反噬分开；但后续Episode Packet若把12个beat全做成独立ADV场景，会拖慢节奏并增加资产。

**修改：** 明确同一作者槽的两个生产段：

- A段T0-T4：城市关灯、资源选择、四塔夺回、共同身份诱惑、第一次停火。
- B段T5-T9：恐慌反剪、白鸢互斥目标、铁友拒炮、灰鸥推船、七海追责、舰队协议离境。

两个段共用一张外港地图、同一套单位状态和连续回合，不新增Episode编号。后续若Packet时长仍超预算，可做上下半关卡而非改写成两个故事。
