# 章节直写与轻量质检方法 v1

> Status: `active_candidate_method_for_C02`
>
> Applies to: `V35.9/rebuild`的创作重写层

## 为什么改方法

C01逐话Loop证明了Story-First、唯一继承状态和制作校验有价值，也证明了普通一话反复调用多席审稿、Runtime与Graybox会产生巨大成本，并容易把创作重新压成字段修补。C01 v3.1的直接整章重写在剧感、人物和可读性上明显更好，因此C02开始采用“创作集中、质检后置”的轻量方法。

## 创作顺序

1. **冻结前章创作继承包。** 只给创作层硬事实、人物伤口、资源预算、不可回流项与少量锁定高光，不把全部合同字段当提纲。
2. **先定整章发动机和能量波形。** 明确章目标、对手欲望、每话独有类型、主角与机体变化、章末必然去向。若三槽容不下真实运动，允许提出话数迁移。
3. **整章连续直写。** 一次完成代表路线的可读故事；每话写清场面过程、人物尝试、机体欲望、玩家行为、反转、高潮和余波。写作时可以查看前文，但不在正文里填合同表。
4. **只做一次整章结构审稿。** 从编剧、机器人文化/机战玩家、游戏制作、人物关系、Canon/物理五个角度集中检查。只处理根因和明显漏项，不做多轮礼仪性补强。
5. **局部修订，不整章推倒。** 发动机错才重写；场面薄、角色漏、玩法不清、设定冲突则定点修。保留已经成立的台词、画面和节奏。
6. **再拆制作层。** 可读稿稳定后，逐话补ADV、探索、SRPG、战斗内演出、舰内日常、结算状态、机体生命周期和资产重点。
7. **最后回填Canon与图谱。** 已确认差异迁入Working Canon；尚待用户确认的差异登记为Candidate Canon和Watchlist，不静默覆盖Runtime或美术锁。

## 每话最低创作证据

这些不是定量配额，而是防止漏掉作品核心的检查面：

- 有一个具体人物或机体在今天非做不可的事。
- 有具身对手、灾害、竞争者或亲密关系主动阻止它。
- 玩家知道本话主要怎么玩，战斗或多玩法会改变剧情而不是附带发生。
- 至少有一台新机体通过动作、欲望、声音或战绩被记住，不以盒子、标签和道具冒充。
- 纪存、七海、白鸢、唐胶、兜灯、陆衡等在场角色必须做事；非本话承重者可以少，但不能连续消失。
- 关系场面必须改变后续合作、误会、身体边界、信任或任务选择。
- 至少一个机器人动画或机甲文化快感由完整过程构成；名台词可以短引、误记或原样短锚，但必须贴合人物和场面。
- 小规则若没有连接人命、机体状态、钱、名誉、关系或路线，只降为普通细节，不称作大选择。

## 章级审稿问题

- 四话连读是否像同一件事不断升级，而不是四份主题报告？
- 每话的类型、地形、主机体、高潮动作和余味是否可区分？
- 是否至少有一场胜利、欢笑、亲密或机器人浪漫完整成立，没有当场被“债务”取消？
- 新机体是否有后续去向：常驻、客将、条件回收、留地、敌方逃走或升级窗口？
- 主角是否凭能力、欲望和选择推动故事，而不是靠反复犯错、审批或受苦？
- 感情线是否进入同一场事件，七海和白鸢是否各自有不依赖纪存的专业立场？
- 章末下一站是否由资源、人物、敌方和谜团共同造成，不是终端突然给出坐标？
- 资产规模是否集中在可复用的大轮廓、形态和场景，不用密集机械小动作制造一次性成本？

## Loop的新职责

Episode Loop只承担以下工作：

- 检查前后状态和伏笔是否断裂；
- 在章末连续阅读C01至当前章，定位最早根因；
- 同一根因最多三轮，三轮后记问题账本并保留最优版；
- 生产拆分、Canon、索引、资产和后续继承是否闭合。

Loop不再承担逐段生成剧情，也不因为字段齐全判定故事好看。
