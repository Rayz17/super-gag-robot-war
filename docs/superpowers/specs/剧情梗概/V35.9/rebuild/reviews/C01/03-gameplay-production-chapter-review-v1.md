## 四个判断

1. **ADV/探索/SRPG：清晰。** 每话都知道何时调查、何时决定、何时上棋盘；E02后半与E04阶段数过多，但不是模式辨认失败。
2. **玩法递进：规模成立，教学复用不足。** 小机占位救援 -> 职业机施工与共享图 -> 巨神/Boss改变地图 -> 整馆成为单位，升级很漂亮；问题是每话都新增一组专用UI、专用单位和专用结算，玩家学到的稳定核心动作少于制作团队要新增的系统。
3. **规则吞戏：从E02开始成立。** `C3/D5`、`R5`、支援点、`BRAVE_FIST_BEAM_CLAIMED`、英文身体态和多次“全部检查变绿”属于制作证明，不属于连续Reader。E02撤令、E03切筋和E04起身足够有戏，不需要每次都把防作弊证明带进正文。
4. **产能：局部失控，尚可降载。** 风险不主要是立绘数量，而是四话连续制作不同的地图重投影、上下文UI、分支资源、失败恢复和专用动画。若把Reader每个动作都实现成通用系统，C01会变成四个vertical slice，而不是一章可复用的SRPG基础。

## 旧Reader对照

旧稿省字，但把E02施工、E03断臂和E04起航压成结果句，玩家几乎不知道自己如何参与，且E04仍有“馆内有人未撤/人员模块参与取舍”的旧口径。新版显著提升了可玩过程、空间重量和伤痕连续性，不能退回旧稿；应取旧稿的阅读经济性，不取它的玩法空白。

## 必须补丁

1. 修正v1两处生产触发：E03末与E04初的同一组六锚须标明同刻续接而非再落一次；E04场8“第四锚解除后”改为“六锚全部解除后”。
2. Reader只保留每话一条完整玩法过程、一次中盘翻面和一个失败后果；其余格位、Owner、变量键、回滚证明回归Runtime/Graybox。优先压缩E02共同图至第二次承梁、E04五岗位至城市段的重复验算。
3. 制作排期必须把“通用系统”和“本话脚本动作”分开：复用意图预览、占位、等待/取消、硬停和地图重投影；SEG3反折、飞拳成桥、皇影卡臂等只做受控脚本状态，不再扩成通用编辑器能力。
4. E04在制作锁定前先关闭`CITY_LOCAL`锁臂/回合/热量反例，并以代表路线完成一次全流程预算；三Bundle只允许做同图规则变体，不得再产生三套地图或三套演出资产。

**放行条件**：完成Reader压缩、两处六锚时序修正及E04城市反例修正后，可转`LOCK / PASS`；无需改四话故事发动机，也无需整章重建。
