## 一、制作裁决

这套体验**有明确的好玩核心，也适合做首话**：先用纪存走一小段闭馆路线，再让玩家首控跌跌与机器犬，以“标准救援被预测 -> 主动摔倒占格 -> 巨神只亮一次低热胸灯”完成三回合救援。它不是把剧情贴在战斗前后，而是能让机器的身体特性、纪存的观察力和万机馆的尺度差直接成为解法。

但当前版本仍是**写得很清楚的演出顺序，不是已经闭合的可执行关卡合同**。29人尚未压成固定Token，三回合缺少行动经济与格位证明，跌跌的关键落点在可读稿里先被剧情替玩家选好，胸灯的安全锁与失败条件互相冲突，必交状态`C01_COLLECTION_PRIORITY`缺失。若现在直接进制作，程序、关卡、UI和演出会各自补一套不同答案。

因此本席结论为：

- **Story Core与主玩法幻想：LOCK。** 不需要重写“最后闭馆”或取消三回合小机救援。
- **玩法制作锁：BLOCKER。** 先补一页可执行回合合同、一次V358GAME001适配/迁移、一个原子结算回执。
- **资产形态：PATCH后可控。** 十九区必须是总图与视野承诺，不是十九张地图；29人必须是4枚组Token，不是29个战棋单位。

## 四、Lock

1. `LOCK_GAME_FANTASY`：先逛到“还没看够”，再用最小与最大的机器人完成同一场救援。
2. `LOCK_CONTROLLED_UNITS`：战棋首控只有跌跌、机器犬；馆守Z仅一次场景支援，不提前完整首控。
3. `LOCK_ALL_29_SAFE`：29人全部救出是线性主状态；未成年人不成为可控单位、筹码或危险维修者。
4. `LOCK_ACTIVE_FAILURE_BLOCK`：摔倒不是人格论文，也不是自动Cut-in；它必须成为玩家主动选择的占格命令。
5. `LOCK_NON_EXTERMINATION`：敌方是移动边界和贴片规则，不引入HP全灭教程。
6. `LOCK_LOW_HEAT_SUPPORT`：胸灯低热、一次、可预览、受兜灯硬停约束；不站起、不挥拳、不变成免费大招。
7. `LOCK_NINETEEN_ZONE_PROMISE`：十九区只证明空间容量。首话只做L1六站视野、四项必查，不制作十九个可游玩区。
8. `LOCK_ASSET_BOUNDARY`：社勇王和市政吊装机只做真实远景动作；不做完整HUD、武装、受击和移动集。
9. `LOCK_GRID_IMPLEMENTATION`：路径框用预制格轨与离散状态改通行，不做任意物理墙或运行时重烘导航。
10. `LOCK_STORY_CAUSALITY`：玩家先执行标准救援，敌方因此完成预测；玩家再用失败占格改写规则；胸灯支援暴露旧路由，四令由此进入。玩法动作必须保留这条因果。

## 五、最低原型

### 5.1 探索灰盒

- 一张连续L1灰盒，玩家控制纪存。
- 四个必查交互、两个可选远景；十九区仅为可缩放总图和锁闭层标。
- 不制作29名独立NPC：场景只需少量代表角色与背景人群，战前统一压成4枚组Token。
- 探索输出仅需：`馆藏优先项`、`跌跌记录已读`、`低热支援可用`、`旧消防回线已知`。
- 退出前明确提示“接下来进入三回合救援”，并展示控制权将从纪存切给两台小机。

### 5.2 战棋灰盒

| 项目 | 最低配置 |
|---|---|
| 棋盘 | `8x10`，固定相机；旧门、窄缝、闭馆线、2个回充格、2个路径框传感格、2个挡板角度 |
| 可控 | 跌跌、机器犬；各`一次移动+一次情境动作/回合`，不设攻击和HP |
| 撤离 | 4枚组Token，人数角标合计29；3组自动沿绿线移动，1组绑定机器犬牵引 |
| 敌/机关 | 1个任务关键路径框、2台贴片机；第二路径框只作背景边界，待核心好玩后再升为活动单位 |
| 路径框状态 | `OPEN -> RECLOSING -> JAMMED_ONE_ROUND -> UNANCHORED` |
| 胸灯状态 | `READY -> AIM_PREVIEW -> SPENT`；非法光路为`BLOCKED_BY_DOUDENG` |
| 阶段 | 玩家单位 -> 撤离组自动移动 -> 敌方/环境意图执行 -> 回合回执 |

### 5.3 三回合最小脚本

| 回合 | 玩家动作 | 环境回应 | 当回合学会什么 |
|---|---|---|---|
| R1 标准救援 | 机器犬选择一侧门并开始牵引；跌跌钻缝复位 | 对应贴片机进入；路径框读取标准动作并重新封线 | 开门有可见代价；小尺寸与牵引 |
| R2 规则翻面 | 玩家选择传感格，命令跌跌`主动摔倒占格`；机器犬把需协助组拖入过线前 staging 格 | 路径框进入`JAMMED_ONE_ROUND`，撤离组继续移动 | 玩家用失败动作改地图，而非观看剧情替自己解题 |
| R3 巨小协作 | 玩家预览并确认胸灯角度；控制膜失效后，两小机各自完成过线/回充移动，机器犬完成最后牵引 | 路径框失去附着基准；4组统一结算 | 场景支援、光路安全、目标完成而非全灭 |

```text

C01_COLLECTION_PRIORITY = <existing_legal_enum>
```

## 六、是否真正推动剧情

**答案：结构上能，现稿只完成了约一半的玩家归属。**

已经成立的部分：小机尺寸、牵引、占格和胸灯不是主题装饰；它们正是救人方式。纪存的能力也通过观察声音、路由和空间组织体现，而不是靠反灼给答案。

尚未成立的部分：探索没有实际提交馆藏优先项；R2正确摔倒点被剧情先选；R3容易退化为自动Cut-in；四令无论玩家表现都照常进入。完成`P01-P05`后，玩家会亲手制造标准方案的失败、亲手选择非标准占格、亲手放行受限巨神支援，并把门路、优先项和旧路由暴露交给下一话，玩法才算完整推动剧情。

## 七、最小修法顺序

1. **先补一页执行合同，不改可读剧情。** 写死控制者、4枚Token、行动经济、阶段顺序、R1-R3规则和硬失败。
2. **处理`V358GAME001`上游矛盾。** 不把五台机都塞进E01；将本槽动作收窄到两小机+一次馆守Z支援，并把真正战中翻面写回合同。
3. **补原子状态提交。** 加`C01_COLLECTION_PRIORITY`合法实值，替换`PLAYER_SELECTED`和`IN_EVACUATION_FLOW`等占位回执。
4. **把关键动作交还玩家。** R1由玩家完成标准方案，R2由玩家选择主动摔倒格，R3由玩家确认胸灯光路。
5. **锁首话资产上限后做灰盒。** 先用1个活动路径框、2台贴片机验证是否好玩；验证通过才增加第二路径框和视觉密度。

## 八、通过条件

- 开战前一屏内能回答：玩家控制谁、三回合目标、何时失败、胸灯是谁的权限。
- 每个合法开门选择至少有一条三回合成功路径；若某选择是教学错误，必须事前预告并允许一次撤回。
- 玩家输入而非剧情自动触发`主动摔倒占格`，且能从路径框意图预览理解其作用。
- 29人始终以4枚组Token守恒，结算为29/29、4/4；不生成29套AI、寻路或受击逻辑。
- 胸灯非法光路会被兜灯硬停，不发生隐藏误伤；合法光路效果与消耗可见。
- `C01_COLLECTION_PRIORITY / C01_VISITOR_RESCUE_SEED / JICUN_COLLECTION_ANOMALY_SEED`均提交合法实值，门选择也提交具体枚举。
- 十九区只有一张总图和远景承诺；可游玩资产仍是一张L1连续场景。
- 首轮内部盲玩中，至少4/5名首次玩家在一次可选提示内完成，并能复述“标准救援为何失败、自己如何利用跌跌的摔倒改写路线”。
- 灰盒确认好玩后再锁美术；在此之前不得用增加展区、敌机、机体Cut-in或教程字段掩盖回合合同缺口。

**最终席位结论：`BLOCKER`（制作锁前），`PATCHABLE`（不重建Story Core），上述十项`LOCK`立即保留。**
