## 一、独立结论

C01E02的可读故事成立：七海的命令有正当依据也真的伤人，纪存不用机魂疼痛跳步解题，消防架桥机以职业动作成为本话英雄，白函在释放后才改报救援。这些都应保留，不应退回V35.5的行政说明式场面。

当前不能判`PASS`。阻断不在故事发动机，而在新稿/新输入已经采用了更强口径，但V35.5/V35.8与E03地图仍残留旧口径：

1. E02已正确把29人送出楼，E03活跃地图却仍有“二楼观众/人群过断臂”，且E02没有一个覆盖全部资源的原子E03输入。
2. 七海的第一条系统命令夹带了她无权单独转交的军方泵站状态，SRPG回合表又把“证据闭合”放到公开全图之后。
3. 公共消防图的敌方收益在Reader中很清楚，但结算没有提交V35.7/V35.8要求的`DAIGE_SAMPLE_GAIN / WANJI_INTERNAL_MAP_EXPOSED`，也没有继续锁住`FULL_MOVING_SPINE=NOT_EXPOSED`。
4. 线性代表路线中又出现`VISITOR_SMOKE`人员损失枚举；设施伤痕则与V35.5仍活跃的`data_center|commercial_exhibit`枚举不一致。
5. 初稿选择“勇拳完全静止、豪司只有旧责任卡”，但V35.8动作合同仍强制“启动请求越线后被切断”。
6. 消防架桥机在新稿已是一整话的完整地图支援套件，V35.8资产行却仍是`limited_first_visible_motion_no_full_battle_set`。

## 三、阻断项与最小修法

### B01 E02人数正确，但E03活跃地图仍会凭空生人

**活跃冲突**

- E01正式稿锁定`32 = 29撤离对象 + 纪存/唐胶/兜灯3名核心工作人员`（`C01E01-最后一条闭馆路线-v1.md:63,196,221-226`）；`RT013S`仅提交29人在前厅尚未出楼（`C01E01-runtime-contract-v1.tsv:19`）。
- E02初稿在可读层清楚提交`29/29已出楼，3人仍在馆内`（`:195-207`），结算也是`ALL_29_OUTSIDE_BUILDING + CORE_STAFF_INSIDE=JICUN;TANGJIAO;DOUDENG`（`:331-334`）。
- 活跃C01地图的E03却仍写“封死人群路线”、“把二楼观众和一楼机体切开”、“桥上还有人”（`C01-逐章重构地图-v1.md:46,77,81`）。这与`C01MIG004`及迁移报告“E02先把人员全部脱险”的爆炸半径冲突（`2026-07-15-chao-gag-c01e01-story-first-canon-migration-v1.md:24,67`）。

**最小修法**

- 不得为满足旧E03地图把任何一名撤离对象留回馆内，也不得让小满、阿澄、前厅值守员或维修员重新进入危险区。
- E03断臂桥的人员负载改为“3名核心留馆工作人员 + E02已在西门/装卸坪建立的明确城市消防响应Token”，或只用3人与救援设备。若使用城市消防员，E02原子快照必须给出数量、位置和不计入万机馆乘员的边界。
- 建立唯一`C01E02_PHYSICAL_SNAPSHOT`，成功后一次性提交，失败重试不写部分状态。E03只能读这一快照，不得再从V35.5旧Reader补人。

**关闭证据**

- E03开场人数守恒为`29在建筑外 + 3在馆内`；C3与D5都在安全区。
- C01地图E03不再出现“二楼观众”或无来源人群。
- E03断臂桥上每个人员Token均能回溯E02快照。

### B02 七海只能撤回自己的高压锁，不能越权释放军方泵站

**活跃冲突**

- Canon锁定七海E01只读，第一项改变现场系统的命令留E02（`data/canon/entities.tsv:34`；`data/canon/scenes.tsv:17`）。输入包进一步锁定这条命令是基于缺层图的东侧高压切断（`C01E02-input-carry-v1.md:18,27`）。
- 初稿的首令却同时说“消防泵转本地机械”（`:87`），撤令时又说“泵交本地”（`:173`）。但B1泵原本由军方接管令压到零（`:79`），七海只能撤回她本人签发的东侧高压锁，不能把另一责任主体的泵站权限转给现场。
- Reader顺序是“物证闭合 -> 公开全图 -> 撤令”（`:111-139,163-181`）；SRPG表却在R2先公开全图，R3才让“旧层证据闭合”（`:296-297`）。

**最小修法**

- 第一条系统命令只写为`EAST_HIGH_VOLTAGE_CUT_WITH_WEST_LIFE_SUPPORT_PRESERVED`。“泵转本地”改为现场人员/跌跌在低压支路恢复后完成的机械旁路，不写成七海转交军方权限。
- 七海撤令只释放她的高压锁并保留母线隔离；门、泵、风阀依靠已建立的现场机械动作恢复。
- 回合表调整为R1取三项物证，R2闭合缺层图并公开消防层，R3在完整伤亡预测下撤令。

**关闭证据**

- `QH_FIRST_SYSTEM_COMMAND`只对应一个可审计的东侧高压锁。
- 每个恢复动作都有分离的`issuer / executor / carrier`；七海没有替军方、平台或安全端撤令。
- 物证闭合时点早于全图公开。

### B03 公共消防图有敌方收益，但缺必交回执和暴露上限

**已通过的场面**

- 纪存明知收不回仍公开门、泵、风道、手柄和承重点（`:127-139`）。
- 白函随后用这张图从西门、桥头、B1泵站回溯到馆守Z，预布18米中庭框位（`:235-245`）。这是具体敌方收益，不是结算一句“获得样本”。

**活跃合同缺口**

- Canon场景行要求E02提交`DAIGE_SAMPLE_GAIN;WANJI_INTERNAL_MAP_EXPOSED`（`data/canon/scenes.tsv:99`）；V35.7作者槽和V35.8玩法合同同样要求这两项（`v35_7_author_slot_architecture_v35_7.tsv:3`；`v35_8_slot_gameplay_contract_v35_8.tsv:3`）。
- 初稿只提交自定义`WANJI_INTERNAL_FIRE_MAP=FULLY_EXPOSED_TO_RESCUE_AND_OPPONENT`（`:363`），无`DAIGE_SAMPLE_GAIN`，也未声明新字段与旧稳定ID的映射。
- E01明确提交`FULL_MOVING_SPINE=NOT_EXPOSED`（`C01E01-最后一条闭馆路线-v1.md:234-235`）。E02拒绝了二十七秒整脊道方案（`:123-125`），因此公开的应只是完整消防/撤离层，不是WBM移动脊柱或完整馆体图。

**最小修法**

- 提交`WANJI_INTERNAL_MAP_EXPOSED=PUBLIC_FULL_FIRE_AND_EVAC_LAYER`与`FULL_MOVING_SPINE=NOT_EXPOSED`。
- 提交`DAIGE_SAMPLE_GAIN=FIRE_MAP;FIRE_BRIDGE_INTERFACE;QH_REVERSAL_PATTERN;RESCUE_REFRAMED_AS_ASSET_MIGRATION`。
- 保留初稿中白函预布中庭框位的具体用法，不用上述字段替代场面。

### B04 人员不得重回损失枚举；E04三类载荷必须保留

**活跃冲突**

- `C01MIG004`已锁定人员全救，E04才建立“生活维持设备 / 实体独有馆藏 / 档案服务器”载荷取舍（`2026-07-15-chao-gag-c01e01-story-first-canon-migration-v1.md:24,67`）。
- E02输入锁定商业后勤风道局部烧损，档案主库仍在且只进入紧急冷却（`C01E02-input-carry-v1.md:52-53`）；初稿`:233,346-350`正确承接。
- V35.5活跃场面/状态行仍把E02写成数据中心与商业展层二选一损伤（`V35.5-C01-C03开局Pressure-Board-v35.5.md:196,198`；`v35_5_c01_c03_state_propagation_v35_5.tsv:3`）。
- 初稿SRPG又增加`VISITOR_SMOKE / FIRE_SUPPLY_BURNED / ROUTE_KEY_COMPROMISED`三选一（`:298`），与前文固定线性代表路线、“人员不进损失枚举”冲突；`VISITOR_SMOKE`在Reader中也没有对应分支场面。

**最小修法**

- 本话代表线性路线锁`S02_EVAC_SCAR=FIRE_SUPPLY_BURNED`；`VISITOR_SMOKE`改为硬失败压力，不是合法伤痕选项。
- 结算分开三层：`WEST_FIRE_SUPPLY=HEAT_DEFORMED_LIMITED`、`COMMERCIAL_SERVICE_DUCT=LOCAL_BURN_DAMAGE`、`ARCHIVE_SERVER_BANK=INTACT_EMERGENCY_COOLING`。
- 迁移V35.5的`facility_scar=data_center|commercial_exhibit`与`C01_FACILITY_SCAR`，不得让旧枚举在E03/E04覆盖新状态。
- E04仍必须在人员全脱险后从三类载荷中作出取舍；E02只使档案系统变得更难带走，不得提前把它毁掉或完整冷备。

### B05 勇拳静止方案较强，但不能静默跳过V35.8动作行

**活跃冲突**

- Canon实体锁定：E02只是被封运输状态，E03才由豪司越权驾驶（`data/canon/entities.tsv:492`）；E02输入包更严格地要求豪司只通过数日前的责任卡预显影（`C01E02-input-carry-v1.md:34`）。
- 初稿完整遵守这条（`:211-223`），并把消防职业机的承梁高潮保留给它自己。
- 但V35.8仍强制“启动请求越过安全线即被许可锁切断”（`v35_8_slot_action_delta_v35_8.tsv:7`；`scripts/build_v35_8_slot_loadout.py:1301`）；活跃C01地图也沿用“启动被截断”（`C01-逐章重构地图-v1.md:45,71`）。

**迁移建议**

保留初稿，将E02勇拳事件迁为`TRANSPORT_LOCKED_STATIC_FIRST_VISIBLE / LICENSE_DARK / NO_REQUEST / NO_BODY_ACTION`。E03才提交豪司实名越权、液压起压、肩背承梁和首次有效位移。若上游坚持保留“请求被截断”，则必须给出不让豪司实时登场、不让机体动作的合法请求源；不能只为填字段凭空启机。

### B06 消防架桥机是首显支援，不是首控；完整动作包需重算资产级

**生命周期通过**

- Canon实体将E02记为首伏笔，C03E02才正式出现/首次参战（`data/canon/entities.tsv:479`）；V35.8以`first_visible`精炼这个层级（`v35_8_slot_unit_manifest_v35_8.tsv:9`）。
- 初稿没有把它自由移动入队，而是驾驶员可拒绝指令的联合救援端（`:282`），因此没有偷走C03首控。

**资产冲突**

- V35.8动作行只允许一次可辨识但受限的首显动作，不得提前调用完整战斗套件（`v35_8_slot_action_delta_v35_8.tsv:9`）；资产行为`limited_first_visible_motion_no_full_battle_set`（`v35_8_slot_asset_manifest_v35_8.tsv:9`）。
- 初稿实际要求四腿落地、三段桥、水幕、定点冲洗、反折承梁、左前腿过载与逐回合指令（`:143-161,185,219-223,282,312,375,408`）。这是“完整地图支援动作包”，不再是一次受限首显。

**迁移建议**

- 保留新稿的职业机高潮，将E02资产级升为`FIRST_VISIBLE_SCENE_SUPPORT_FULL_MAP_PACKAGE_NO_FREE_BATTLE_SET`。
- 锁定无HP、无自由移动、无常规攻击/反击；上述动作都围绕同一台场景支援机、同一个稳定腿/桥板Rig复用。
- C03E02仍为首控，C03E04仍为消防队加入；E02不重复计入队或完整战斗集。
- E03必须读取左前腿过载、第三桥板反折和西侧供水受损，不得完整刷新该机。

## 四、已锁PASS的边界

### P01 孩子与维修员

- C3为`2未成年人 + 1前厅值守员`，不可拆；D5为`4需协助成人 + 1维修员`，不新生人员Token（`C01E01-graybox-constants-v1.tsv:13-14`）。

### P02 馆守Z、白函与勇拳的身体时序

- `C01MIG006`在E02被完整保留；切割标尺机只切消防/排火设施和桥铰，没有威胁右臂承力筋（`data/canon/entities.tsv:46,59`）。

### P03 G.A.G.、索引、白框与白函的知识层级

- C01的共享白框只是`INDEX_COMPONENT_ONLY`；V35.7明确锁定C11前不出现索引连续人格第一人称（`v35_7_mystery_slot_binding_v35_7.tsv:5`）。

- 初稿只把G.A.G.写成强行送电可能触发的未知危险，白函仍是可归责的代哥执行载体，两者没有被并成索引幕后人格。

### P04 火场物理预算

除B02/B04外，资源守恒成立：

- 展陈灯因闭馆熄灯，城市电网/维生仍在；七海只切东侧高压，后续回到局部隔离低压。

- 馆守Z没有从胸灯、G.A.G.压力或广播电容偷出主动力。
- 档案主库进入紧急冷却而不是清零，E04载荷时间压力仍存在。
