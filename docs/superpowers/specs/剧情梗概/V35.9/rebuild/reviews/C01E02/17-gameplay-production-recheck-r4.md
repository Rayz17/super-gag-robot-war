## 一、结论先行

`GP3-01..09` 的原始修补均已进入当前正式稿或合同：F2A 已避开机器犬，纪存已走唯一坡道并避开跌跌，A11 禁切角与动态占格规则明确，R2 实体接触回到敌方相位，烟 3 失败链分支化，探索改成固定三证据，C01 地图旧口径也已修正。固定桥序、R2 局部分支、五回合点池、D5 托盘、唯一原子提交及 HUD 均能从当前文件复算。

本轮仍不能给最终 PASS，原因是新增五人退路证明有一处确定的顺序占格错误：`GB039` 声明按“唐胶 > 纪存 > 兜灯 > F2A > F2B”逐人释放，但唐胶路线必经仍被 F2B 占据的 `(3,8)`。现有 checker 只逐条检查路线与静态设备，不模拟五名人类的起点占格，却打印了 `sequential sinks` PASS；r3 纸演据此给出了不成立的顺序证明。

地图几何本身并未软锁，存在合法顺序，例如 `F2B > 唐胶 > 纪存 > 兜灯 > F2A`。因此裁决是小范围 **PATCH**，不是 BLOCK；修补只需改 `GB039` 的释放顺序、补 checker 的人际占格模拟并重跑纸演，不需要重写 Episode 主流程。

## 三、必须修：GP4-01 五人释放顺序撞 F2B

### 3.1 精确证据

1. Runtime `RT033`（Runtime 第39行）和 `GB033`（Graybox 第34行）共同锁定 R5 起点：唐胶在 `(9,8)`，F2B 在 `(3,8)`。
2. `GB039`（Graybox 第40行）锁定唐胶退路：`(9,8)>(8,8)>(7,8)>(6,8)>(5,8)>(4,8)>(3,8)>(2,8)`。
3. 同一 `GB039` 的 production rule 声明释放顺序为 `Tangjiao>Jicun>Doudeng>F2A>F2B`，所以唐胶行动时 F2B 尚停在 `(3,8)`。
4. `GB001`（第2行）与 `GB016`（第17行）明确动态单位会封锁其落点；F2B 不是可穿越的静态背景。
5. 因此唐胶倒数第二步进入 `(3,8)` 时必然撞上 F2B。按当前合同逐步重放的首个错误为：

```text
COLLISION Tangjiao -> (3, 8), occupied by F2B
```

### 3.2 checker 为何漏检

- checker 第159-168行逐条执行 `validate_route`，并只与第144-146行构建的 `static_cells` 求交。
- checker 没有把另外四名人类的当前起点加入每一步 `occupied`，也没有读取或执行 `GB039` 声明的 release order。
- 第169-176行只检查西门终点、纪存唯一坡道和跌跌 `(9,9)`；随后第177行直接打印 `sequential sinks` PASS。
- r3 纸演第65-73行重复了同一错误顺序，因此纸演的 `FIVE_PERSON_EGRESS PASS` 不能作为独立放行证据。

### 3.3 影响

- 若实现按 `GB039` 声明顺序驱动撤离预览或逃生 AI，唐胶会在 `(3,8)` 停住，`RT036G` 所要求的五人退路证明不成立。
- 这不是地图无解：独立枚举当前五条路线可得到合法顺序。最小且保持原叙事优先级的一个是：

```text
F2B > Tangjiao > Jicun > Doudeng > F2A
```

F2B 先从 `(3,8)` 退到 `(2,8)` 并清出 sink；唐胶随后清出侧带；纪存再通过唯一坡道；兜灯走 y6 通道；F2A 最后退到 `(2,7)`。该顺序不进入跌跌 `(9,9)`，也符合动态单位只封目标格、不把正交侧格变墙的规则。

### 3.4 最小修法与复验门槛

1. 在 `GB039` 增加机器可读的合法 `release_order`，至少改为上述已复算顺序。
2. checker 第159-177行增加五人顺序模拟：初始化五个起点；逐步拒绝进入尚未清出的其他人落点；一人到达 `x=2` sink 后才从占格集移除。
3. checker 必须从 Graybox 的机器可读字段取得顺序，不能只在代码中另写一份与 TSV 无绑定的常量。
4. 重跑 checker，并更新纸演中的顺序、原始输出和文件指纹。

验收输出应至少新增一项类似：

```text
FIVE_PERSON_RELEASE PASS: ordered human occupancy, sink clearing, unique ramp, static equipment
```

## 六、checker 覆盖边界

checker 当前还采用若干硬编码镜像：第38-54行手写可走区，第127-132行手写 Token 步数，第144-146行手写静态占格，第195-209行只检查费用关键词。由于本轮输入指纹与纸演完全一致，且上述当前值已人工交叉核对，这些做法没有制造第二个当前失败项。

不过，`GP4-01` 说明 checker 不应再用“每条路线单独合法”替代“多人按声明顺序可执行”。本轮放行所需的最低 checker 修补仅是五人动态占格与 sink 清格模拟；后续可再把步数、静态占格和点池从 TSV 结构化字段解析，降低合同改变后仍全绿的风险。
