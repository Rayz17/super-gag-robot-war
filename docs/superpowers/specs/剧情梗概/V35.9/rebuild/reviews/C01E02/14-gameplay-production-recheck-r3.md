# C01E02 Gameplay / Production 定向复核 r3

- 复核日期：2026-07-15
- 复核席位：Gameplay / Production
- 复核对象：当前磁盘正式稿、Runtime / Graybox TSV、纸演 r2，以及 PB 与 C01 地图的最新下游约束
- 裁决：**PATCH**

## 一、裁决摘要

本轮不能因 `13-runtime-graybox-paper-run-r2.md` 的自评放行。当前版本已经闭合固定桥序列、R2 两条真实局部分支、五回合支援点池、D5 低速撤离托盘、白函后唯一原子提交及 HUD 告知；人口也保持为 `A11+B10+C3+D5=29`，另有 3 名原始成员，F2 不计入 32 人。

但空间合同仍存在三处可执行性硬冲突：

1. F2A 从仍被机器狗占据的 `(1,7)` 起步；
2. 吉村退路穿过跌跌固定占据的 `(9,9)`；
3. 吉村退路绕过 `GB002` 声明的 C/B1 唯一坡道 `(9,8)>(10,9)`。

此外，A11 路线最后一条对角边缺少禁切角所需的正交可走格；失败态中的“热耐久”与 `D5=烟3` 证明、正文中的 R2 相位顺序、探索段“玩家选择”以及 C01 地图旧口径仍未完全对齐。以上项目须在 Runtime / Graybox 下一轮纸演前修正。

## 三、五回合执行链复算

### 3.1 固定桥序列与行动拥有者

- `RT014`：R1 消防相位只有一个合法宏动作，费用 `3`，顺序固定为 `SEG1>SEG2>SEG3`；无效顺序只预览、不扣点。
- `GB004`、`GB005`、`GB020`：消防架桥机四支腿固定，桥段为确定序列，不存在伪装成自由排序的选择。
- 正文 151-153、291、304：镜头和玩法说明均承认固定顺序。

此项可执行。

### 3.2 R2 真实分支

- `RT019` / `GB021`：`WATER_FIRST` 先保人，D 区烟值留在 1，针车进入可接触状态；R3 必须用 1 点冲洗针车。
- `RT020` / `GB022`：`PREEMPTIVE_COOL` 先保工具，D 区烟值到 2；R3 必须用 1 点补迟发水幕。
- `RT025`、`GB030`、`GB031`：两支各自留下不同的 R3 可见后果，再汇合到固定伤痕，不是同结果换文案。
- 正文 167、191、305-306：分支与“局部选择、固定伤痕”均被承认。

此项机械上成立；正文相位顺序仍需按 §5.1 调整。

### 3.3 支援点池

| 回合 | 点池来源 | 消耗 | 终点 |
|---|---|---|---|
| R1 | 初始公共消防 3 点 | 固定桥序列 3 | 0 |
| R2 | 本回合公共消防 1 点 | 二选一 1 | 0 |
| R3 | 本回合公共消防 1 点 | 分支对应补救 1 | 0 |
| R4 | 本回合公共消防 1 点 | D5 低速撤离托盘防护 1 | 0 |
| R5 | F2 入场后新生成 1 点 | 承梁窗口 1 | 0 |

`RT032` 明确 R4 结束不留点；`RT032F` 才在隐藏四枚疏散 Token、AP 已清零后生成 R5 点；`GB024` 禁止把旧点包装成新点。点池本身无透支、无跨回合囤积、无 F2 抢 R4 行动的问题。

### 3.4 D5 低速撤离托盘与人口

- 正文 157：D5 使用既有低速撤离托盘，承载“四名需协助成人 + E01 同一维修员”，明确无驾驶员。
- `RT031`、`RT038`：D5 原有人口不变，提交仍为四成人与一维修员。
- `GB015`、`GB044`：托盘是已上电的复用场景道具，R3/R4 各推进 4 格；无 HP、人格、驾驶员或首次登场计数。
- PB 52：同样把它限定为既有低速托盘。

因此 D5 不引入新单位，人口仍为 `11+10+3+5=29`，加 3 名原始成员为 32；F2、机器狗、跌跌均不进入人口账。

## 四、Runtime / Graybox 前必须修的空间阻断

### GP3-01：F2A 与机器狗在 `(1,7)` 同格

**证据**

- `GB033`：`RobotDog=(1,7)_OUTSIDE`，且无离格端点。
- `GB038`、`RT032F`：F2A 路线从 `(1,7)>(2,7)>(3,7)` 开始。
- `RT032F` 只隐藏 A11、B10、C3、D5 四枚疏散 Token，没有隐藏或移动机器狗。
- 纸演 r2 59-64 只检查 F2 路线连通，没有把机器狗静态占格加入碰撞集。

**最小修法**

在 Runtime 与 Graybox 中二选一并保持正文可见：

1. 给机器狗一个在 F2 入场前离开 `(1,7)` 的确定端点；或
2. 把 F2A 起点改到未占用、与门区连通的格，并重跑碰撞检查。

### GP3-02：吉村路线穿过跌跌固定格

**证据**

- 正文 195、`RT028`、`RT033`、`GB010`、`GB033`：跌跌固定在 `(9,9)` 的保护凹位。
- `GB039`：吉村退路为 `(10,10)>(9,9)>(8,8)>(7,8)>(6,8)>(5,8)`。
- 当前合同没有“跌跌不占格”或“吉村可穿越设备格”的规则。

**最小修法**

保留跌跌 `(9,9)`，将吉村路线改为不穿设备格的合法路线，并在纸演碰撞表中加入机器狗、跌跌、标尺和针车等静态／半静态实体。

### GP3-03：吉村路线绕过 C/B1 唯一坡道

**证据**

- `GB002`：C/B1 只通过坡道边 `(9,8)>(10,9)` 连接。
- `GB039`：吉村却从 `(10,10)>(9,9)>(8,8)` 直接离开 B1，没有经过该坡道边。

**最小修法**

将路线改为例如 `(10,10)>(10,9)>(9,8)>(8,8)>...`，再按实际地形验证每一格；若设计意图不是唯一坡道，则必须先改 `GB002` 的拓扑声明，而不能只让纸演默认对角可达。

### GP3-04：A11 最后一条对角边缺禁切角依据

**证据**

- `GB001`：采用 `EIGHT_NEIGHBOR_NO_CORNER_CUT`，对角移动要求两侧正交格可走。
- `GB012`：A11 末边为 `(2,6)>(1,5)`。
- `GB003` 只声明门格 `(2,6)|(2,7)|(2,8)`；当前可走区定义没有给出该对角边所需的 `(2,5)` 可走依据。
- 纸演 r2 34 只验证相邻步长和落点冲突，没有验证对角边两侧正交格。

**最小修法**

明确 `(2,5)` 为可走格，或改走一条满足禁切角的末段路线；纸演脚本须新增逐条对角边的两侧正交格检查。

### GP3-05：动态占格是否参与“禁切角”没有定义

`GB016` 只禁止同一目标格，没有说明对角移动两侧的正交格若被其他 Token 占据，是否视为“关闭”。按当前优先级复算，R2/R4 存在路径擦肩情形；若动态占格也算关闭，会产生额外非法步。

**最小修法**

在 `GB001` 或 `GB016` 明确禁切角只检查地形，还是同时检查动态占格，并让下一轮纸演按同一口径验证。此项可与上述改路一次处理。

## 五、其余必须修的合同错位

### GP3-06：正文把 R2 敌方接触写在消防选择之前

**证据**

- `RT010`、`GB019`：每回合唯一相位顺序为工作人员 > 消防 > 敌方。
- `RT020`：标尺实体接触在 R2 敌方相位结算。
- 正文 161 已写标尺实际接触／偏转；到正文 167 才说第二回合只剩 1 个消防点并执行 R2 选择。

**最小修法**

把正文 161 的实际接触移到 R2 消防选择之后；或将此前镜头改成尚未结算的敌方意图，并在消防选择后才写实体接触结果。

### GP3-07：失败态“热耐久”与 `D5=烟3` 证明不完整

**证据**

- 正文 313 把“烟／热耐久归零”列为 Token 失败条件。
- `RT040`、`GB017` 只有烟值 Token 失败守卫；`GB018` 的热是环境／梁体结算，不是 Token 热耐久表。
- `GB017` 声称 D5 在 R3 被堵于 `(9,8)` 即到烟 3；但 `WATER_FIRST` 分支从烟 1 加一次为 2，`PREEMPTIVE_COOL` 分支从烟 2 出发且 `RT025` 的迟发水幕应保护 D5，单凭被堵并不能统一推出 3。

**最小修法**

1. 从正文失败态删除不存在的 Token“热耐久”，或在 Runtime / Graybox 补全其可见计量与守卫；
2. 把 D5 烟 3 的触发写成可复算的条件组合，明确迟发水幕覆盖与跳过对应支援的后果，避免把“路线被堵”单独写成必达 3。

### GP3-08：探索段仍有不可玩的“玩家选择”

**证据**

- 正文 111 明说玩家选择从哪道烟薄缝靠近。
- `RT004-RT006` 只有固定的三证据动作；当前 Graybox 也没有探索路线、费用或两个合法入口的定义。
- 正文 272-274 的生产说明把该段定为固定三证据链。

**最小修法**

删除“玩家选择”的交互承诺，改为角色选择／镜头调度；或补一个不改变主合同的两路线局部交互，并写明动作拥有者、费用和汇合端点。

### GP3-09：C01 地图仍保留两条旧口径

**证据**

- C01 地图 47：仍写“最后公共支援保住三名留守者出口”；当前 `RT032/RT032F/RT035` 是 R4 公共点归零、F2 入场后新生 R5 点，且出口关联五人。
- C01 地图 68：把“锁死半开防火门、切断馆守Z胸灯”都归给代哥；当前正文 81 是安全端锁门，代哥只负责切灯并处理平台密钥／军用泵。
- C01 地图 169、180 的民用维护管廊与城市生命线分域已与当前稿一致，不需回退。

**最小修法**

把地图 47 改为“R4 保持通道、F2 入场生成 R5 新点、五人出口受保护”；把地图 68 拆清安全端锁门与代哥切灯／密钥／军用泵的责任边界。

## 六、已闭合、不得回退的项目

1. **固定 Rig**：消防架桥机四支腿固定；脚垫只可原格受力滑移，不产生第五支点。
2. **桥序列**：R1 只有 `SEG1>SEG2>SEG3`，总费用 3；错误输入不扣点。
3. **R2 分支**：保人／保工具各有立即状态与 R3 后续动作，最终只汇合伤痕，不抹平局部后果。
4. **工具实体**：针车、标尺、跌跌都有实体位置、接触与端点；勇拳、馆守Z、白函在部署前均为零行动边界。
5. **D5 托盘**：既有低速撤离托盘只解释移动，不增人口、驾驶员或新资产单位。
6. **R5 新点**：R4 点池先清零；四 Token 隐藏、F2 入场后才创建新点；新点只服务承梁窗口。
7. **HUD**：`GB041/042` 已要求显示当前 R2 选择的即时后果、R3 待办，以及 R4 清零／R5 新生点，玩家能理解资源来源。
8. **唯一提交**：`RT038` 是唯一持久事务，原子写入 E02 快照与全部 V35 键；`RT039` 只读断言。R1-R4 失败不留持久半状态，R5 失败只回局部检查点。
9. **人口账**：29 名疏散者 + 3 名原始成员 = 32；F2、机器狗、跌跌及无驾驶员托盘不计人口。

## 七、下一轮纸演准入条件

完成 GP3-01 至 GP3-09 的最小修补后，必须用当前 Runtime / Graybox 重新纸演，并至少输出以下可追溯检查：

1. 全部移动边的邻接、坡道／门／高差合法性及禁切角两侧格；
2. 每 tick 的 Token 目标格冲突，以及机器狗、跌跌、针车、标尺等静态实体占格；
3. F2A、管理员、记者、姜明、吉村五条退路的起点、终点与唯一拓扑；
4. 两个 R2 分支分别推导到 R3 烟值、工具状态、D5 水幕覆盖和失败守卫；
5. R1-R5 点池、AP 清零、F2 入场和 R5 新点的逐相位日志；
6. 白函部署前后持久键差异，确认仅 `RT038` 产生一次原子提交。

## 八、最终裁决

**PATCH**

当前版本的核心玩法意图已经清楚，资源经济与高潮结构也成立；但 F2A／机器狗同格、吉村／跌跌同格、吉村绕开唯一坡道三项会让现有 12x14 合同无法按字面执行，属于 Runtime / Graybox 前必须修的问题。其余相位、失败态和下游地图错位应与空间修补一并关闭后，再进行 r3 后续纸演与放行。
