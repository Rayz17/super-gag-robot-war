# C01-C05 GLM读稿问题分层回迁与C01执行单

> Status: `working_process_correction_v1`
>
> 目的：把五章合订稿暴露的问题送回最早拥有它的创作层，不再用一轮全文润色同时修结构、演出和对白。

## 一、产物重新定性

`reader/C01-C05连续阅读稿-v1.md`是一次**章级故事源拼接后的连续阅读压力测试快照**。它证明了五章一起读时会出现什么问题，但不是正式Episode Reader，也不再作为任何章节的修改入口。

正式生产顺序改为：

```text
L1主题与体验
-> L2全剧发动机
-> L3结构母盘
-> L4章级完整总纲、预制、导演、物理因果与玩法预案
-> 章级演出承载规划
-> 单话Episode Reader
-> 机械合成章节Reader
-> 跨章连续阅读快照
```

合订稿只能由已经通过的章节Reader生成。任何从合订稿发现的问题，都必须回到最早负责的层修正，再重新生成下游产物。

## 二、GLM意见的正确归属

| 外部读稿意见 | 判断 | 最早拥有层 | 本轮处理 |
| --- | --- | --- | --- |
| 信息与命名角色过载 | 成立 | L4章节导演板 | 不砍机战群像和参战规模；限制每话前景人物、首次报姓名数量和同场发言人数，其余通过背景动作、机体剪影及后续回收建立 |
| 每章都在重复“谁定义机器” | 成立 | L4章引擎与能量波形 | 给每话不同的娱乐发动机，主题由事件汇流，不靠同一辩论反复出现 |
| 平台与商业反派过于单面 | 部分成立 | L4阵营行动与反派维度 | 先让标准系统真正防止一次普通事故，再让它在复杂现场造成伤害；后续章节继续给予价格发现、质量追溯和公共安全的真实收益 |
| 断冠存在感弱 | 成立，但不属于C01 | 对应章节L4反派线 | 后续在其章节补可识别行为、欲望和对我方的私人记忆，不以多写数值解决 |
| 叙事与“玩家控制、格数、回合”混写 | 完全成立 | 章级演出承载规划 | 玩法规则留在预案；Reader只写玩家实际经历的操作、画面和后果，用载体标签区分ADV、探索、SRPG与过场 |
| 人物替作者说主题、金句密度过高 | 成立 | 单话Reader与人声门 | 对白必须有具体听众、当下欲望和未说出口的东西；主题句改成动作、材料判断、误会或后果 |
| 三人关系像摆拍给读者看 | 成立，主要出现在后续章 | 表演与对白简报、单话Reader | 亲密动作必须来自伤势、任务、嫉妒或错误判断，并产生后续反应；删除对称姿势和同时说同一句话的“宣传照式亲密” |
| 应砍掉一半次要角色 | 不直接接受 | L3/L4前景管理 | 机器人大战需要群像和机体生命周期。应砍的是同一场景的姓名、说明和发言负荷，不是删掉长期角色与参战包 |

## 三、C01执行口径

1. C01既有Working故事事实不因这轮审稿自动退役。
2. C01三块L4审查板先统一撤离人数、角色站位、白函双面性和信息揭示边界。
3. 新增`C01-章级演出承载规划.md`，把玩家可见顺序与正式玩法规则分开。
4. C01E01至E04各自成为独立源文件，每次只处理一话。
5. 四话通过后才机械生成C01章节Reader。
6. C01-C05合订稿保持原样，文件头与目录索引标记为压力测试快照；不继续在其中手改。

## 五、本轮停止条件

本轮只在以下条件全部满足后结束：

- C01四话能够按游戏进行顺序连续阅读。
- E01与E02撤离事实、E03桥上五人、E04四名返入者无冲突。
- Reader不再出现格数、回合数、胜败条件或制作层说明。
- 每话有不同的主要乐趣，不靠重复主题句推进。
- 角色声音可辨，唐胶、兜灯、纪存、七海不共享同一套“正确发言”。
- C01章节Reader由脚本生成，五章合订稿不再被声明为当前正文入口。
