# 万机馆“本次开放资料”系统

> Status: `working_story_production_interface_v1 / non_canon`
>
> 日期：2026-07-26
>
> 用途：把故事已经演出来、但不适合继续塞进人物对白的阶段性知识，在话末或章末整理给玩家。它是叙事UI与作者知识管理接口，不是替剧情补洞的百科。

## 一、玩家侧名称

统一使用：

> **万机馆｜本次开放资料**

它由纪存既有的信息终端整理，也会进入万机馆的馆内导览系统。它不是手写笔记本，也不是一个全知旁白。资料只代表当前阶段能够公开、能够确认或正在争议的认识。

## 二、核心规则

1. **故事先成立，资料再整理。** 玩家必须先从行动、画面、操作和人物反应理解当前目标与结果，资料页只补齐名词、关系和阶段性背景。
2. **没有固定配额。** 一话认知发生实质变化时开放一至三张；没有新认识便不发卡。章末另给一页“当前认知快照”。
3. **不提前公布后台真相。** 纪存身世、G.A.G.完整机制、旧馆长责任、索引意识化等只能按剧情进度开放。
4. **允许资料后来被修订。** 新证据出现时保留旧版本、修改者与修改理由，让“认识如何改变”本身成为剧情。
5. **不能替因果补洞。** 若玩家必须先读资料页才能理解下一场为什么发生、谁控制机体或谁作出了决定，该场面必须退回导演板重写。
6. **不用行政文风冒充神秘。** 正文优先使用日常称呼、示意图、照片、机体状态和短句；不以权限、债务、证词、标签堆叠制造重要感。

## 三、资料状态

| 状态 | 含义 | 可否在后文推翻 |
| --- | --- | --- |
| 确认资料 | 已由现场、实物或多个可靠来源确认 | 只能补充，原则上不反转 |
| 馆内推定 | 万机馆依据现有线索给出的最佳解释 | 可以修订或推翻 |
| 当事人口述 | 某位角色愿意公开的个人记忆 | 可以片面、误记或隐瞒 |
| 未确认事项 | 玩家此刻应当注意、但尚无答案的问题 | 后续必须推进或回收 |
| 修订记录 | 对旧资料的增补、更正或争议 | 保留旧版与修改者 |

## 四、第四层揭示矩阵

每章导演板必须为每话填写一张简表：

| 字段 | 回答内容 |
| --- | --- |
| 话末必须理解 | 不懂便无法准确复述本话主因果的事实 |
| 可以产生怀疑 | 本话只需让玩家察觉异常或关系 |
| 必须继续隐藏 | 后台真相和未来高潮，不得泄漏 |
| 候选开放资料 | 零至三张资料卡的题目与一句核心内容 |
| 资料状态 | 确认资料、馆内推定、当事人口述、未确认事项或修订记录 |
| 可见来源 | 现场影像、人物口述、实物、终端读数、公开档案等 |
| 当前可信度 | 高、中、低；说明争议来自哪里 |
| 未来修订窗口 | 哪类事件或哪一阶段可能改写它 |
| 最低资产 | 纯文字、照片、机体三视图、关系图、地图、时间轴或短动图 |

导演板的“玩家可见证据”回答故事怎样让人知道；本矩阵回答故事结束后怎样替玩家整理。两者不能互相替代。

## 五、下游分工

- **L4完整总纲：** 只负责让相应事实真正发生，不在正文后机械附卡。
- **L4.5演出承载：** 决定资料页在哪个结算点开放、是否自动弹出、使用什么视觉资产。
- **Episode Reader：** 标出解锁事件与玩家此刻已知边界，不写成作者百科。
- **台本与UI：** 完成最终短文、标题、图注、修订动画和角色批注。
- **Canon：** 只保存后台真实事实；玩家阶段性认识单独管理，不能把“馆内推定”误升为世界真相。

## 六、角色化修订

资料页可由不同角色留下有限批注，但不能变成群聊：

- 纪存负责整理现场、关联旧馆藏和保留版本。
- 七海补充可公开的制度背景，也会划掉她认为会再次伤人的内容。
- 白鸢用构图、关系图和未来风险提示补充“可能怎样发展”，不能把预演当事实。
- 唐胶补充手修、版本和实物差异，语言应直接、具体。
- 陆衡补充工程边界，必须先用普通话解释，再开放技术附录。
- 索引后期能够尝试自动改写资料；玩家必须看得见谁改了什么。

## 七、C01示范边界

C01章末可以整理：

1. **馆守Z与旧守护者｜确认资料**  
   二者是同一个主体。馆守Z是18米实机，旧守护者是它在馆内生活时使用的称呼；轮式导览终端只是远程眼睛和扬声器。
2. **勇拳试作机｜确认资料**  
   由荒川豪司驾驶，依靠拳甲储存并释放冲击；目前未发现独立机魂，战后已由企业回收。
3. **BREAKER｜馆内推定**  
   地面黑甲只是突入城市的外壳，飞行核心能够指挥同类；它为何转向万机馆仍未确认。
4. **第七次巡展｜确认资料与未确认事项**  
   万机馆恢复旧巡展舰身体并选择继续上路；旧馆长为何预留路线杆、封闭层里还保存什么，仍不公开。

这些资料只能在玩家已经看见馆守Z起身、豪司出击、BREAKER二阶段和万机馆升空以后开放。

## 八、C01-C05的G.A.G.揭示阶梯

前五章不需要用百科解释G.A.G.，但必须让它从“奇怪现象”逐渐变成玩家能够追问的对象：

| 阶段 | 玩家看见什么 | 当时可以怎样理解 | 仍须隐藏 |
| --- | --- | --- | --- |
| C01｜观察 | BREAKER转向万机馆时，停用航路灯自行闪烁；馆守Z在无人启动前把光移向来敌 | 馆内旧系统与机体对同一威胁产生了异常呼应 | G.A.G.名称、机魂生成机制、纪存身世 |
| C03｜命名 | 市政吊装机认回长期使用的吊臂，旧诊断屏显示`G.A.G.局部响应／低置信度` | 灾后技术人员曾经为这种“身体、记忆与关系同时闭合”的现象留下暂定名称 | 这是否等于机魂、谁造成了现象、能否复制 |
| C05｜验证 | 百相副驾在服务器箱离开后仍持续回应；探测器只显示响应留在机体内部 | G.A.G.不是服务器里的程序、外来能源或一次遥控信号；某种新主体已经在百相身体里形成连续性 | 机魂为何不能像人的记忆一样复制、纪存与其为何不同、二十七年前的完整真相 |

使用约束：

- C01的异常不得被角色当场命名，否则神秘感会被解释掉。
- C03只能给出旧诊断标签，不得把“低置信度响应”写成机魂确诊。
- C05第一次允许角色正面说出G.A.G.，但回答必须落在“探测到了持续响应”上，不讲完整宇宙论。
- 后续资料如要推翻或升级这三步，必须保留旧判断及其证据，不能让早期角色显得无故失明。

## 九、验收

一张资料卡通过，必须同时满足：

- 删除它，主线仍然讲得通；
- 阅读它，玩家能更准确地说出“目前知道什么”；
- 它没有把作者后台真相伪装成确认事实；
- 它能在未来被补充或修订，而不是制造新的设定牢笼；
- 它使用的图片、结构图或短文在资产预算内；
- 它没有把模型盒、记录、标签或术语重新推成故事主角。
