# 《超GAG机器人大战》对照《机战Y》开头与第一话影像的重构报告 v0.1

> 资料源：工作区本地视频 `37883481442-1-192.mp4`。  
> 视频信息：27:22，1280x720，30fps，Bilibili 转码。  
> 方法：用 ffprobe 确认元信息；用 ffmpeg 抽取 20 秒间隔全片缩略图、16 张关键帧，按时间线拆解开头、剧情、地图、命令、资料、敌方阶段和剧情回流。

## 1. 总结

这段《机战Y》视频证明了一件事：SRW 的“游戏感”并不只来自华丽战斗动画，也不只来自复杂数值，而来自一套非常稳定的交互语法。

它的核心循环是：

```text
准备选择
  -> 世界观/任务导入
  -> ADV剧情
  -> 地图态剧情
  -> 单位选择
  -> 命令/资料/武器
  -> 移动范围或攻击范围
  -> 战斗预测/确认
  -> 地图结果/敌方阶段
  -> 中途剧情/资料回流
```

当前 Godot demo 的问题不是“没有实现 SRW 的全部系统”，而是连这套语法的主骨架都没有真正落下去。它现在更像“章节流程状态机的可视化工具”：左侧章节节点、右侧变量、中央小场景和底部文本框。它能证明剧情节点能跳转，但不能证明玩家在玩一话机战。

下一版不应该继续往当前界面上补按钮，而应该重构为：

```text
第一屏：任务/整备界面
  -> 战前 ADV
  -> 地图态剧情
  -> 战棋交互主循环
  -> 资料库/角色关系按需打开
  -> 战后报告
```

## 2. 视频时间线观察

### 2.1 00:00-00:40：不是网页式说明，而是游戏入口

视频开头先出现标题菜单、难度选择、主角/机体选择。

关键观察：

- 标题页第一眼就是游戏商品，而不是项目调试界面。
- 难度选择有明确焦点、高亮、确认弹窗。
- 主角选择页同时展示角色、机体、属性和文本说明，玩家在“选择身份”，不是在读表。

对我们的启示：

- Demo 首屏不能是章节节点和后台变量。
- 首屏可以是“临时出击区/移动格纳库”，默认焦点停在“出击：法务警报”。
- 玩家先看见队伍、机体、任务和出击按钮，再进入第一话。

### 2.2 00:40-03:20：黑底世界观字幕用于建立史诗距离

视频用连续黑底文字建立世界观背景。它很传统，但作用明确：先把尺度拉大，再落回角色与地图。

关键观察：

- 字幕不是 UI 说明，而是开场仪式。
- 文本段落有停顿和黑场呼吸，允许玩家接受设定。
- 世界观介绍结束后立刻切入角色画面，避免无限设定堆叠。

对我们的启示：

- 《超GAG》可以保留短开场字幕，但必须短到能服务“今晚闭馆”的情境。
- 世界观开场不应该解释机魂全部概念，只给一个远景钩子：某些被记录的机器人记忆，正在从档案里醒来。

### 2.3 03:20-10:40：ADV 剧情以背景、立绘和短台词推进

视频在 3:20 后进入大量 ADV 剧情：背景图、角色立绘、底部文字框、右侧跳过/记录/自动播放提示。

关键观察：

- 每段台词都有画面语境：道路、角色近景、天空、室内、通信。
- 台词框位置稳定，角色名牌清楚，快捷操作清楚。
- 一段剧情中会穿插静态事件图和动画镜头，不一直用同一种面板。
- 教学/资料弹窗出现时是“覆盖层”，不是常驻主界面。

对我们的启示：

- 第一话 1-1 可以是 ADV + 小地图探索，但必须有“场景图”作为主视觉。
- 角色台词需要依托画面动作，不应该在抽象面板里讲设定。
- 长说明应该进入可选资料弹窗，不能常驻在右侧变量栏。

### 2.4 11:00-13:20：战术地图先承载剧情，再进入操作

11:00 左右第一次进入战术地图。地图上立刻可见城市道路、建筑、敌人、我方单位和目标位置。随后角色立绘压在地图上对话。

关键观察：

- 地图不是“战斗模式专用背景”，而是剧情舞台。
- 角色一边说话，玩家一边看见敌我位置和城市尺度。
- 11:40 左右，地图态剧情仍在继续，但玩家已经理解“接下来要在这里打”。
- 12:20 左右，机体资料/敌机资料可以从地图态打开，说明资料库和战术状态连接紧密。

对我们的启示：

- 第一章的法务封存战必须先在地图上演出：封存线落在哪里、留言墙在哪里、孩子/观众在哪里、馆守Z在哪里。
- 不要先弹“战斗：保护留言墙6回合”按钮；应该让玩家看见留言墙被标记，七海/清算部/旧守护者在地图上对话。
- 剧情与战斗不能是两个割裂模式，必须共用同一张地图状态。

### 2.5 13:20-17:40：资料、单位、武器和地图范围构成操作前的理解层

视频中频繁打开机体资料、人物资料、武器页、单位状态页。复杂数值很多，但它们不乱，因为都围绕“我马上要怎么行动”。

关键观察：

- 武器页有攻击力、射程、EN/弹数、命中、暴击、武器特性。
- 人物/机体资料是玩家主动打开，不是常驻干扰。
- 地图上移动/攻击范围用红蓝格或覆盖层表达。
- 顶部显示敌我阶段、回合、单位数量、支援资源。
- 底部显示地形信息和地形修正。

对我们的启示：

- 当前 Godot demo 的右侧 `museumWarmth`、`blackCaseResonance`、`oldGuardianTrust` 常驻面板是错误方向。
- 这些变量应该被翻译成玩家语言：例如“馆内信任”“0号共鸣”“损毁风险”，并放到战后报告/档案页，而非战斗主界面。
- 战斗主界面必须优先显示：当前单位、HP/EN/士气、武器、射程、目标、地形、敌方意图、胜败条件。

### 2.6 17:40-23:40：真正的战棋循环是“预测、承诺、反馈”

17:40 以后能看到典型战斗循环：玩家阶段、攻击范围、敌方阶段、敌人移动、地图事件、再次回到玩家操作。

关键观察：

- 地图范围覆盖非常清楚：红色区域告诉玩家危险/攻击范围。
- 敌方阶段有显式阶段条，玩家知道自己暂时不能操作。
- 敌方移动不是一行文字，而是在地图上移动，局势发生变化。
- 角色台词会在地图上打断行动，形成中途事件。
- 战斗不是靠“连续结束回合”自动过关，而是玩家必须回应局势。

对我们的启示：

- 法务无人机必须显示下一步“封存线”或“清除目标”。
- 留言墙、观众、0号侧廊、展柜必须成为地图目标，而不是剧情文本。
- 敌方行动要可见：移动、标记、封存、攻击、倒计时，都要在地图上发生。
- 第一场战斗的胜利条件不能只是“守 6 回合”，而应该是“解除三条封存意图，并在第 4 回合前撤离观众”。

### 2.7 24:20 以后：战斗后回到 ADV 和结果页

后段回到背景 ADV、角色对话和 assist result。

关键观察：

- 战斗结果不会孤立结束，而是回到角色关系和系统奖励。
- 结果页不是网页报告，而是游戏内结算。
- 角色关系和支援系统会在结算中被提示。

对我们的启示：

- 《超GAG》的“闭馆记录”应该是游戏内结算页：保住了什么、失去了什么、谁的关系变化、解锁了哪个机魂档案。
- 不要把结算做成变量列表，而要做成“馆内记录/展签/损毁报告”的主题化界面。

## 3. 当前 Godot Demo 的结构性错位

### 3.1 第一屏错位

当前第一屏展示：

- 章节节点。
- 当前 beat 标题。
- 状态与资产变量。
- 底部对话框。

这让玩家第一眼觉得自己在看调试工具。

应改为：

- 任务/整备界面，或直接地图态战前剧情。
- 常驻 UI 只显示玩家要行动所需的信息。
- 章节节点和内部变量完全移出主界面。

### 3.2 剧情和地图没有融合

当前 demo 的剧情是 beat，战斗是 battle，两者通过 `battleId` 切换。视觉上也是“故事面板”和“战斗面板”。

《机战Y》的做法是：地图本身承载剧情，角色立绘和文字框压在地图上。这样玩家一边读剧情，一边理解空间和目标。

应改为：

- 每个战斗关卡先进入地图态剧情。
- 剧情事件可以锁住光标，但地图、单位、目标都已显示。
- 台词推进时相机聚焦到相关单位或目标点。

### 3.3 战斗缺少 forecast 层

当前 Godot demo 有移动、攻击、待机、结束回合，但缺少行动前预测。

应增加：

```text
选单位
  -> 显示单位卡
  -> 移动范围
  -> 移动确认
  -> 行动菜单
  -> 武器列表
  -> 目标 hover 显示 forecast
  -> 确认攻击
  -> 短 cut-in
  -> 地图结果
```

Forecast 至少显示：

- 我方武器名。
- 预计伤害。
- 命中/稳定度。
- 敌方剩余 HP。
- 敌方是否反击或封存。
- 是否解除敌意图。

### 3.4 敌方阶段没有过程感

当前敌方行动主要是模型函数瞬间处理，然后更新一行 `last_event`。

应改为：

- 敌方单位逐个行动。
- 相机移动到敌方单位。
- 显示敌方意图箭头。
- 执行移动/封存/攻击动画。
- 更新目标状态。
- 再交还玩家阶段。

### 3.5 资料库位置错误

当前把 Codex 和变量常驻显示在右侧。SRW 的资料页是玩家主动打开的层级，它服务于理解人物、机体和梗点，而不是抢主界面。

应改为：

- 主界面保留“资料”按钮或快捷键。
- 对单位按检查可打开驾驶员/机体资料。
- 战后解锁“机魂档案”“参战投射梗点”“万机馆展签”。
- 资料页可以百科化，但不能占据战斗主界面。

## 4. 第一章应如何按 SRW Y 语法改

### 4.1 第一话 1-1：今日闭馆后

定位：ADV + 小场景探索，不进正式战斗。

目标：

- 让玩家喜欢万机馆。
- 建立馆守Z 18 米尺度和旧守护者导览机身份。
- 展示多个机器人文化展岛。
- 结尾以火警/法务封存切入 1-2。

形式：

```text
开场短字幕
  -> 前厅背景 ADV
  -> 玩家控制纪存在前厅小地图走动
  -> 调查留言墙、展岛、馆守Z脚边、0号侧廊
  -> 闭馆广播
  -> 火警与封存权限覆盖
  -> 章节标题/To be continued into 1-2
```

注意：

- 不要把第一话压成战斗教程。
- 第一话的“可玩性”来自走动、调查、角色反应和空间建立。
- 每个展岛都要预告一个未来参战投射包或梗点。

### 4.2 第一章 1-2：法务警报

定位：第一场正式战棋教程。

目标：

- 保护留言墙。
- 撤离观众。
- 阻止 0 号侧廊被封存线打开或清除。

形式：

```text
地图态剧情：封存线降下
  -> 胜败条件弹出
  -> 玩家阶段教程：选择纪存/导览机
  -> 敌意图预告：无人机将清除留言墙
  -> 玩家用移动/攻击/挡线解除意图
  -> 第2回合七海插话，目标变化
  -> 第3回合馆守Z胸牌亮起
  -> 战后地图剧情：不是胜利，是还没来得及输
```

系统重点：

- 每个敌人显示下回合要清除/封存的对象。
- 玩家行动的爽点不是全灭，而是把敌方意图拆掉。
- 教程必须用场景事件讲，不用长说明框讲。

### 4.3 第一章 1-3：展厅里的旧守护者

定位：第一台巨型机体正式启动。

目标：

- 让 18 米馆守Z作为 2x2 单位进入地图。
- 让玩家第一次感到“这是机器人大战”。
- 用过热/残缺右臂限制，避免无脑碾压。

形式：

```text
地图态剧情：旧守护者从导览机回到本体
  -> 机体资料页：馆守Z / 18m / 旧右臂损伤
  -> 玩家控制 2x2 馆守Z
  -> 攻击预测显示过热风险
  -> 第一次必杀有短 cut-in
  -> 特定敌人触发兜灯/纪存/旧守护者短台词
  -> 战后右肩冒烟，留言墙只保住一部分
```

系统重点：

- 机体大小必须进入地图规则。
- 馆守Z不是“大数值单位”，而是“保护与损伤的矛盾体”。
- 第一次攻击演出必须成为 demo 的付费感瞬间。

### 4.4 第一章 1-4：流亡展舰

定位：战后整备/结算/移动基地成立。

目标：

- 把战斗结果转化为后续路线资源。
- 让万机馆从地点变成移动基地。
- 建立下一章目标。

形式：

```text
战后 ADV
  -> 闭馆记录结算
  -> 损毁位置地图
  -> 选择救援优先级
  -> 移动格纳库开放
  -> 临时开馆标题
```

系统重点：

- 结算不是变量表，而是展馆损伤报告。
- 玩家选择影响后续基地房间、支线和角色台词。

## 5. Godot 实现层改造建议

### 5.1 保留

可以保留：

- Godot 项目本身。
- `chapter_01.json` 里的角色、台词、战斗数据作为原材料。
- `TacticalModel` 的基础单位、移动、攻击、回合逻辑。
- 现有 smoke test 思路，但要升级为体验状态测试。

### 5.2 必须重写

必须重写：

- `main.gd` 当前的手绘面板主界面。
- 章节 rail、状态变量常驻面板。
- story mode / battle mode 的硬切。
- “点击选项推进”的主要动线。

新的主架构应该是：

```text
GameRoot
  StateManager
    TitleState
    IntermissionState
    AdvState
    MapStoryState
    TacticalState
    BattleCutinState
    ResultState

  MapView
    TileLayer
    UnitLayer
    RangeOverlayLayer
    IntentOverlayLayer
    EventMarkerLayer

  Hud
    PhaseBanner
    ObjectivePanel
    UnitCard
    CommandMenu
    ForecastPanel
    DialogueLayer
    CodexOverlay
```

### 5.3 P0 改造列表

P0 目标：让 10 分钟 demo 第一眼像 SRW-like 游戏。

1. 去掉主界面的章节列表和变量栏。
2. 建立地图态剧情：地图、单位和目标先出现，再叠对话。
3. 增加战术光标和当前格信息。
4. 增加单位卡：驾驶员头像、机体名、HP/EN/士气、可行动状态。
5. 增加敌方意图层：目标、箭头、倒计时。
6. 增加行动菜单：移动、攻击、能力、资料、待机。
7. 增加武器列表和 forecast。
8. 增加敌方阶段逐单位行动动画。
9. 增加短战斗 cut-in。
10. 增加战后“闭馆记录”主题结算。

### 5.4 P1 改造列表

P1 目标：让它有《超GAG》的独特性，而不是普通 SRPG。

1. 法务封存线：敌方意图不是攻击，而是封印武器名/展签/留言。
2. 民间叫法：玩家可用“俗称/梗名”临时解封攻击。
3. 展岛地形：合体台、模型病院、现实机器小舞台、旧影像厅各有地形效果。
4. 角色关系援护：纪存和兜灯、豪司和旧守护者触发特殊台词或援护。
5. 机魂档案：战后解锁资料，但不在战斗主界面喧宾夺主。

## 6. 对现有文档的影响

这次视频研究支持已有文档中的多个判断，但要求更坚决地执行：

- `2026-06-20-srw-like-video-ui-interaction-study.md` 的“预览 -> 承诺 -> 反馈”必须成为 P0，不是愿景。
- `2026-06-20-chao-gag-playable-slice-ui-ux-bible.md` 的“四态界面”需要调整：对话和战斗之间必须增加“地图态剧情”。
- `episode_01_flow.tsv` 里第一话无正式战斗的边界是正确的，但 Godot demo 不应把整章强行压缩成同一个流程界面。
- `chapter_01_episode_flow.tsv` 的 1-2/1-3 战斗节点应补充地图事件、敌方意图、forecast 和中途剧情触发条件。

## 7. 最小可行重做范围

建议不要再做“第一章完整 demo”。先做一个 10-12 分钟高密度垂直切片：

```text
1. 标题/任务入口：30 秒
2. 战前 ADV：90 秒
3. 地图态剧情：90 秒
4. 战棋教学战：5 分钟
5. 馆守Z首次启动 cut-in：60 秒
6. 战后闭馆记录：90 秒
```

这版只覆盖 1-2 和 1-3 的核心瞬间，不再试图把 1-1 到 1-4 全部压进去。

验收标准：

- 玩家 10 秒内知道这是机器人战棋。
- 玩家 30 秒内知道自己要保护什么。
- 玩家第一次行动前能看懂移动范围、敌意图和 forecast。
- 玩家第一次攻击后能看到短但有机器人味的演出。
- 玩家结束试玩后能说出：万机馆是什么、留言墙为什么重要、馆守Z是什么尺度、清算部在做什么。

## 8. 结论

《机战Y》视频给我们的最大修正不是“要复制 SRW 的复杂系统”，而是：

1. 剧情要长在地图上。
2. 资料要按需打开，而不是常驻占屏。
3. 战斗要有预测层。
4. 敌方阶段要可见。
5. 机器人爽点要通过机体资料、地图尺寸、武器演出和特定交战台词一起出现。

当前 Godot demo 证明了我们可以把数据跑通，但它不应该继续作为体验方向。下一步应把它降级为规则模型参考，重做一个“地图态剧情 + forecast 战斗 + 短 cut-in”的真正试玩切片。
